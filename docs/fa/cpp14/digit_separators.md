# جداکننده‌های ارقام در ++C14

## مقدمه

خواندن و بررسی مقادیر عددی بزرگ در کدهای ++C می‌تواند دشوار باشد. برای مثال، تشخیص تعداد صفرهای موجود در عدد `1000000000` یا بررسی بخش‌های مختلف یک مقدار هگزادسیمال طولانی، به‌خصوص در کدهای مربوط به حافظه، زمان، اندازه فایل‌ها و محاسبات مالی، همیشه ساده نیست.

استاندارد ++C14 با معرفی قابلیت Digit Separators امکان استفاده از علامت آپاستروف (`'`) را در میان ارقام یک literal عددی فراهم کرد. این قابلیت خوانایی اعداد را افزایش می‌دهد، بدون آنکه مقدار عددی یا نوع آن را تغییر دهد.

برای مثال، دو literal زیر از نظر مقدار یکسان هستند:

```
int population = 1000000;
int readablePopulation = 1'000'000;
```

در این مثال، مقدار هر دو متغیر برابر با یک میلیون است. علامت آپاستروف صرفاً به خوانایی کد کمک می‌کند و بخشی از مقدار عددی ذخیره‌شده نیست.

نکته مهم این است که Digit Separators یک قابلیت زبانی است که از استاندارد ++C14 به زبان اضافه شده است؛ این قابلیت به کتابخانه استاندارد وابسته نیست و برای استفاده از آن به تابع، کلاس یا header خاصی نیاز ندارید.

## مفهوم Digit Separators در ++C14

قابلیت Digit Separators به برنامه‌نویس اجازه می‌دهد در بخش‌های مختلف یک literal عددی، علامت آپاستروف را میان ارقام قرار دهد تا ساختار عدد واضح‌تر شود.

برای مثال، در کد زیر چند شیوه نمایش یک مقدار یکسان را مشاهده می‌کنید:

```
#include <iostream>

int main() {
    int a = 1000000;
    int b = 1'000'000;
    int c = 10'00'00;

    std::cout << a << '\n';
    std::cout << b << '\n';
    std::cout << c << '\n';
}
```

خروجی برنامه به شکل زیر است:

```
1000000
1000000
1000000
```

در این مثال، هر سه literal مقدار یکسانی دارند؛ زیرا محل قرارگیری جداکننده‌ها بر تفسیر عدد تأثیری نمی‌گذارد.

از نظر نحوی، جداکننده باید میان دو رقم مجاز در همان بخش از literal قرار بگیرد. بنابراین، این قابلیت صرفاً یک قالب‌بندی ظاهری نیست، بلکه بخشی از قواعد نوشتاری literalهای عددی در استاندارد زبان محسوب می‌شود.

## دلیل معرفی جداکننده‌های ارقام

استفاده از این قابلیت چند مزیت عملی دارد:

- افزایش خوانایی: اعداد طولانی به گروه‌های کوچک‌تر تقسیم می‌شوند و بررسی آن‌ها آسان‌تر می‌شود.
- کاهش خطای انسانی: شمارش صفرها و تشخیص مرتبه بزرگی اعداد ساده‌تر خواهد بود.
- شفافیت در نمایش مقادیر فنی: ثابت‌های باینری، هگزادسیمال، اندازه‌های حافظه و مقادیر مربوط به پروتکل‌ها ساختار واضح‌تری پیدا می‌کنند.
- مستندسازی بهتر کد: شیوه گروه‌بندی ارقام می‌تواند قراردادهای خوانایی مورد استفاده در یک پروژه را منعکس کند.

نکته مهم این است که جداکننده‌ها خطاهای منطقی را به‌طور خودکار تشخیص نمی‌دهند. برای مثال، اگر عدد موردنیاز `1'000'000` باشد اما برنامه‌نویس `10'000'000` بنویسد، کد همچنان معتبر است؛ تنها مقدار اشتباه خواهد بود.

## نحوه استفاده از جداکننده‌ها در literalهای عددی

### اعداد صحیح ده‌دهی

رایج‌ترین کاربرد این قابلیت، خواناتر کردن اعداد صحیح ده‌دهی است.

```
int population = 1'250'000;
long long nationalDebt = 12'345'678'901LL;
unsigned int timeoutMilliseconds = 30'000;
```

در این مثال‌ها، جداکننده‌ها صرفاً خواندن اعداد را آسان‌تر می‌کنند و هیچ تأثیری بر نوع یا مقدار آن‌ها ندارند.

برای اعداد صحیح، می‌توان گروه‌بندی سه‌رقمی را به کار برد؛ بااین‌حال، استاندارد زبان چنین الگویی را اجباری نمی‌کند. انتخاب اندازه گروه‌ها به نوع داده و قراردادهای خوانایی پروژه بستگی دارد.

### اعداد هگزادسیمال

در نمایش هگزادسیمال، جداکننده‌ها به‌خصوص برای ثابت‌های طولانی، maskها، شناسه‌ها و مقادیر رجیسترهای سخت‌افزاری مفید هستند.

```
#include <cstdint>

std::uint32_t color = 0xFF'80'40'20;
std::uint64_t identifier = 0x1234'5678'9ABC'DEF0ULL;
std::uint32_t registerMask = 0xFFFF'0000;
```

در مثال اول، مقدار هگزادسیمال از گروه‌های دو رقمی تشکیل شده است که می‌تواند با نمایش بایت‌های یک رنگ سازگار باشد.

در مثال دوم، گروه‌بندی چهاررقمی خواندن شناسه را ساده‌تر می‌کند. در مثال سوم نیز مرز میان بخش‌های مختلف mask واضح‌تر است.

نکته مهم این است که علامت آپاستروف جزئی از نمایش عددی هگزادسیمال نیست و در مقدار نهایی ذخیره نمی‌شود.

### اعداد باینری

در استاندارد ++C14، جداکننده‌ها برای literalهای باینری نیز قابل استفاده هستند. literalهای باینری از استاندارد ++C14 معرفی شدند و با پیشوند `0b` یا `0B` نوشته می‌شوند.

```
#include <cstdint>

std::uint8_t flags = 0b1010'0101;
std::uint16_t permissions = 0b1111'0000'1010'0101;
std::uint32_t bitMask = 0b1111'1111'0000'0000;
```

در این مثال‌ها، گروه‌بندی بیت‌ها بررسی الگوهای باینری را آسان‌تر می‌کند.

برای نمونه، می‌توان بیت‌های یک مقدار را بر اساس اندازه نایبل، بایت یا ساختار یک فیلد در پروتکل گروه‌بندی کرد. البته این گروه‌بندی فقط برای خوانایی است و معنای بیتی جدیدی به مقدار اضافه نمی‌کند.

### اعداد اکتال

در literalهای اکتال نیز می‌توان از جداکننده استفاده کرد. نمایش اکتال با صفر ابتدایی آغاز می‌شود و ارقام مجاز آن از `0` تا `7` هستند.

```
int octalValue = 0'123'456;
```

در این مثال، literal همچنان اکتال است؛ زیرا صفر ابتدایی آن حفظ شده است. مقدار آن در مبنای ده برابر با `42798` است.

نکته مهم این است که جداکننده‌ها نباید باعث اشتباه گرفتن مبنای عدد شوند. برای مثال، `0'123` یک عدد اکتال است، نه یک عدد ده‌دهی که صرفاً با آپاستروف گروه‌بندی شده باشد.

## استفاده از جداکننده‌ها در اعداد اعشاری

قابلیت Digit Separators فقط به اعداد صحیح محدود نیست. در literalهای ممیز شناور نیز می‌توان از آن برای خواناتر کردن بخش صحیح، بخش کسری و ارقام توان استفاده کرد.

### بخش صحیح و کسری

```
double piApproximation = 3.141'592'653'589;
double measurement = 12'345.678'901;
double scientificValue = 1'234.5'678;
```

در این مثال‌ها، جداکننده‌ها بخش‌های مختلف literal را خواناتر می‌کنند، اما هیچ تغییری در مقدار عددی ایجاد نمی‌کنند.

نکته مهم این است که جداکننده باید میان دو رقم قرار گیرد. بنابراین، نمی‌توان آن را مستقیماً در کنار نقطه اعشار قرار داد.

### بخش توان در نمایش علمی

در نمایش علمی، جداکننده می‌تواند میان ارقام توان نیز قرار بگیرد.

```
double smallValue = 1.0e1'0;
double largeValue = 2.5e+1'2;
```

در مثال اول، توان ده برابر با `10` است و مقدار literal معادل \\(1.0 \times 10^{10}\\) خواهد بود.

در مثال دوم، توان ده برابر با `12` است و مقدار literal معادل \\(2.5 \times 10^{12}\\) خواهد بود.

نکته مهم این است که علامت‌های `e`، `E`، `+` و `-` خودشان رقم محسوب نمی‌شوند. بنابراین، جداکننده باید در بخش عددی توان و میان دو رقم آن قرار بگیرد.

## قواعد نحوی و محل‌های مجاز استفاده

قابلیت Digit Separators قواعد مشخصی دارد. شناخت این قواعد برای جلوگیری از خطاهای کامپایل ضروری است.

### قانون قرارگیری میان دو رقم

قاعده اصلی این است که آپاستروف باید میان دو رقم معتبر در یک literal عددی قرار گیرد.

```
int validA = 1'000;
int validB = 12'34'56;
int validC = 0xAB'CD;
int validD = 0b1010'1100;
double validE = 1'234.5'678;
double validF = 1.0e1'2;
```

تمام نمونه‌های بالا از نظر نحوی معتبر هستند.

در مقابل، نمونه‌های زیر نامعتبرند:

```
// Invalid examples
// int a = '1000;
// int b = 1000';
// int c = 1''000;
// int d = 0x'FF;
// double e = 1.'25;
// double f = 1.25'e3;
```

این نمونه‌ها به‌صورت کامنت نوشته شده‌اند تا در صورت کپی کردن مجموعه مثال‌ها، برنامه قابل کامپایل باقی بماند. هر یک از خطوط نامعتبر، در صورت فعال شدن، با قواعد نحوی literalهای عددی سازگار نیست.

دلایل نامعتبر بودن آن‌ها به‌ترتیب عبارت‌اند از قرارگیری جداکننده پیش از اولین رقم، قرارگیری پس از آخرین رقم، استفاده از دو جداکننده متوالی، قرارگیری جداکننده میان پیشوند مبنا و اولین رقم، قرارگیری آن کنار نقطه اعشار و قرارگیری آن میان بخش کسری و نشانگر توان.

### تفاوت جداکننده با فضای خالی

آپاستروف با فاصله یا whitespace یکسان نیست. فاصله نمی‌تواند جایگزین جداکننده درون یک literal عددی شود.

```
int validValue = 1'000;

// This is not one numeric literal:
// int invalidValue = 1 000;
```

در مثال بالا، خط دوم یک literal واحد نمی‌سازد و از نظر نحوی نامعتبر است.

نکته مهم این است که جداکننده بخشی از قواعد نوشتاری literal است؛ بنابراین، نمی‌توان از فاصله، خط جدید یا نشانه‌های دلخواه دیگر برای ایجاد همان اثر استفاده کرد.

## تأثیر جداکننده‌ها بر نوع و مقدار

یکی از مهم‌ترین ویژگی‌های Digit Separators این است که نوع literal، مقدار آن و قواعد انتخاب نوع عددی را تغییر نمی‌دهد.

### تفاوت literal و مقدار زمان اجرا

در کد زیر، دو متغیر از یک نوع هستند و مقدار یکسانی دارند:

```
#include <type_traits>

int a = 1000000;
int b = 1'000'000;

static_assert(std::is_same_v<decltype(a), decltype(b)>);
static_assert(a == b);
```

این مثال از `std::is_same_v` استفاده می‌کند که از ++C17 در دسترس است. خود Digit Separators از ++C14 پشتیبانی می‌شود؛ بنابراین، این نمونه برای کامپایل در حالت ++C17 یا جدیدتر مناسب است.

برای استفاده صرفاً در ++C14 می‌توان بدون وابستگی به قابلیت‌های جدیدتر کتابخانه استاندارد، مقدارها را مقایسه کرد:

```
int a = 1000000;
int b = 1'000'000;

if (a == b) {
    // Both values are equal.
}
```

در هر دو حالت، جداکننده هیچ نقشی در تعیین نوع متغیر یا مقدار نهایی آن ندارد.

### تأثیر بر انتخاب نوع literal

در ++C، نوع literal عددی بر اساس قواعد مربوط به مبنا، پسوند، مقدار و فهرست انواع مجاز تعیین می‌شود. جداکننده این قواعد را تغییر نمی‌دهد.

```
auto a = 1'000;
auto b = 1'000LL;
auto c = 0xFF'FFU;
auto d = 1'000.0;
```

در این مثال‌ها، پسوندهای `LL` و `U` و همچنین ممیز شناور همچنان در تعیین نوع literal نقش دارند. آپاستروف فقط جداکننده ارقام است.

نکته مهم این است که استفاده از جداکننده باعث بزرگ‌تر شدن محدوده نوع عددی نمی‌شود. برای نمونه، اگر یک literal بدون جداکننده خارج از محدوده نوع موردنیاز باشد، اضافه کردن آپاستروف آن را معتبر یا قابل نمایش نمی‌کند.

## کاربردهای عملی در پروژه‌های ++C

### خواناتر کردن اندازه‌های حافظه

در کدهایی که با اندازه بافر، ظرفیت حافظه یا تعداد عناصر سروکار دارند، جداکننده‌ها می‌توانند تشخیص مرتبه بزرگی را آسان‌تر کنند.

```
#include <cstddef>

constexpr std::size_t bufferSize = 1'048'576;
constexpr std::size_t elementCount = 250'000;
```

در این مثال، مقادیر با گروه‌بندی سه‌رقمی نوشته نشده‌اند، بلکه اندازه گروه‌بندی به‌گونه‌ای انتخاب شده است که ساختار عددی و رابطه آن با مقادیر رایج حافظه خواناتر باشد.

نکته مهم این است که `std::size_t` نوع مناسبی برای بسیاری از اندازه‌ها و شمارش‌های وابسته به حافظه است، اما انتخاب نوع همچنان باید با توجه به محدوده مقادیر و نیازهای برنامه انجام شود.

### خواناتر کردن maskها و مقادیر سخت‌افزاری

در برنامه‌نویسی سطح پایین، مقدارهای باینری و هگزادسیمال معمولاً ساختار مشخصی دارند. جداکننده‌ها به نمایش این ساختار کمک می‌کنند.

```
#include <cstdint>

constexpr std::uint32_t readPermission = 0x0000'0001;
constexpr std::uint32_t writePermission = 0x0000'0002;
constexpr std::uint32_t executePermission = 0x0000'0004;

constexpr std::uint32_t permissionMask =
    readPermission | writePermission | executePermission;
```

در این مثال، گروه‌بندی چهاررقمی، جایگاه بیت‌های کم‌ارزش و بخش‌های بالاتر را واضح‌تر می‌کند.

نکته مهم این است که جداکننده‌ها جایگزین تعریف دقیق قراردادهای بیتی نیستند. در سیستم‌های واقعی، اندازه نوع، ترتیب بایت‌ها، نحوه نگاشت بیت‌ها و الزامات سخت‌افزار باید جداگانه بررسی شوند.

### خواناتر کردن ثابت‌های زمانی

در کدهایی که با زمان بر حسب میلی‌ثانیه یا تعداد تکرارها سروکار دارند، گروه‌بندی اعداد به فهم بهتر مقدار کمک می‌کند.

```
constexpr int timeoutMilliseconds = 30'000;
constexpr int retryDelayMilliseconds = 1'500;
constexpr int maximumRetries = 10'000;
```

در این مثال، مشخص است که مقدارها به‌ترتیب سی هزار، هزار و پانصد و ده هزار هستند.

نکته مهم این است که جداکننده‌ها واحد اندازه‌گیری را مشخص نمی‌کنند. برای جلوگیری از ابهام، نام متغیر یا نوع مناسب باید واحد را به‌روشنی بیان کند.

## محدودیت‌ها و اشتباهات رایج

### پشتیبانی استاندارد و حالت کامپایل

قابلیت Digit Separators از ++C14 بخشی از زبان است. بنابراین، کدی که از این قابلیت استفاده می‌کند باید با حالت استاندارد مناسب کامپایل شود و کامپایلر نیز باید از آن استاندارد پشتیبانی کند.

برای مثال، در GCC و Clang می‌توان از گزینه زیر استفاده کرد:

```
g++ -std=c++14 main.cpp -o main
```

همچنین در Clang می‌توان نوشت:

```
clang++ -std=c++14 main.cpp -o main
```

نکته مهم این است که پشتیبانی واقعی به نسخه کامپایلر و تنظیمات آن وابسته است. اگر کد در حالت قدیمی‌تر از ++C14 کامپایل شود، ممکن است جداکننده‌ها به‌عنوان نحو نامعتبر تشخیص داده شوند.

### استفاده نامنظم از گروه‌بندی

اگرچه استاندارد محل قرارگیری جداکننده را به یک الگوی خوانایی خاص محدود نمی‌کند، گروه‌بندی نامنظم می‌تواند خوانایی را کاهش دهد.

```
int clearValue = 123'456'789;
int confusingValue = 12'3456'78'9;
```

هر دو literal از نظر قواعد نحوی می‌توانند معتبر باشند، اما نمونه دوم ساختار عدد را به‌شکل نامنظم نمایش می‌دهد.

نکته مهم این است که گروه‌بندی باید با قراردادهای پروژه سازگار باشد. برای اعداد ده‌دهی، گروه‌های سه‌رقمی معمولاً مناسب هستند؛ درحالی‌که برای مقادیر هگزادسیمال یا باینری، گروه‌بندی بر اساس بایت، نایبل یا ساختار فیلدها ممکن است مفیدتر باشد.

### اشتباه گرفتن جداکننده با علامت نقل‌قول

علامت آپاستروف در زبان ++C کاربردهای دیگری نیز دارد، از جمله در character literalها. بااین‌حال، نقش آن در یک literal عددی با نقش آن در یک character literal متفاوت است.

```
char apostrophe = '\'';
int number = 1'000;
```

در این مثال، خط اول یک کاراکتر آپاستروف را ذخیره می‌کند، درحالی‌که خط دوم یک عدد صحیح با جداکننده ارقام تعریف می‌کند.

نکته مهم این است که قواعد escaping مربوط به character literalها را نباید با قواعد Digit Separators اشتباه گرفت.

### محدودیت در قالب‌بندی و خروجی

جداکننده‌های ارقام بخشی از متن literal در کد منبع هستند و به‌طور خودکار به قالب نمایش عدد در خروجی تبدیل نمی‌شوند.

```
#include <iostream>

int main() {
    int value = 1'000'000;
    std::cout << value << '\n';
}
```

خروجی برنامه به شکل زیر خواهد بود:

```
1000000
```

اگر هدف نمایش عدد با جداکننده در خروجی باشد، باید قالب‌بندی متنی را به‌صورت جداگانه پیاده‌سازی کرد یا از ابزار مناسب قالب‌بندی استفاده کرد. قابلیت Digit Separators چنین کاری انجام نمی‌دهد.

## مقایسه با روش‌های قدیمی‌تر

پیش از ++C14، برنامه‌نویسان معمولاً اعداد را بدون جداکننده می‌نوشتند یا برای بهبود خوانایی، آن‌ها را با توضیحات و نام‌گذاری مناسب همراه می‌کردند.

```
constexpr long long oldStyleValue = 1234567890LL;
constexpr long long modernStyleValue = 1'234'567'890LL;
```

در این مثال، هر دو روش معتبر هستند، اما روش دوم ساختار عدد را آشکارتر می‌کند.

نکته مهم این است که Digit Separators جایگزین نام‌گذاری مناسب، ثابت‌های دارای معنای مشخص یا توضیحات فنی نیستند. این قابلیت فقط خوانایی literal را بهبود می‌دهد و برای مدل‌سازی مفهوم یک مقدار باید همچنان از نام‌ها و انواع مناسب استفاده کرد.

## جمع‌بندی

قابلیت Digit Separators در استاندارد ++C14 راهکاری ساده و مؤثر برای بهبود خوانایی literalهای عددی است. با استفاده از علامت آپاستروف می‌توان اعداد صحیح، اعداد هگزادسیمال، literalهای باینری، اعداد اکتال و مقادیر ممیز شناور را به‌شکل خواناتری نوشت.

مهم‌ترین نکات این قابلیت عبارت‌اند از:

- جداکننده‌ها بخشی از نحو زبان هستند و به header یا کتابخانه خاصی نیاز ندارند.
- آپاستروف باید میان دو رقم مجاز قرار گیرد.
- جداکننده‌ها مقدار، نوع و مبنای literal را تغییر نمی‌دهند.
- گروه‌بندی ارقام باید با قراردادهای خوانایی پروژه سازگار باشد.
- جداکننده‌های موجود در کد منبع به‌طور خودکار در خروجی برنامه نمایش داده نمی‌شوند.
- برای استفاده از این قابلیت، کامپایلر و حالت استاندارد باید از ++C14 یا استانداردهای جدیدتر پشتیبانی کنند.

در نهایت، استفاده از Digit Separators زمانی بیشترین ارزش را دارد که اعداد طولانی، maskهای بیتی، ثابت‌های سخت‌افزاری و مقادیر فنی در کد وجود داشته باشند. رعایت یک قرارداد ثابت برای گروه‌بندی ارقام، خوانایی و نگهداشت‌پذیری کد را در پروژه‌های حرفه‌ای ++C بهبود می‌دهد.
