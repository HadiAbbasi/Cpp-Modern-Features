# معرفی تابع std::exchange در ++C14

## مقدمه

تابع `std::exchange` یکی از ابزارهای مفید کتابخانه استاندارد در ++C14 است که برای جایگزین‌کردن مقدار یک شیء با مقدار جدید و بازگرداندن مقدار قبلی آن طراحی شده است. این تابع به‌ویژه هنگام مدیریت منابع، پیاده‌سازی Move Semantics، انتقال مالکیت و بازنشانی وضعیت اشیاء کاربرد دارد.

ایده اصلی این تابع ساده است: ابتدا مقدار فعلی یک شیء دریافت می‌شود، سپس مقدار جدید در آن قرار می‌گیرد و در نهایت مقدار قبلی به‌عنوان نتیجه بازگردانده می‌شود.

برای مثال، فرض کنید یک متغیر عددی داریم که می‌خواهیم مقدار آن را با صفر جایگزین کنیم و در عین حال مقدار قبلی را نیز نگه داریم. با استفاده از `std::exchange` می‌توان این عملیات را در یک عبارت انجام داد.

```
#include <iostream>
#include <utility>

int main() {
    int value = 42;

    int oldValue = std::exchange(value, 0);

    std::cout << "Old value: " << oldValue << '\n';
    std::cout << "New value: " << value << '\n';
}
```

خروجی برنامه به شکل زیر خواهد بود:

```
Old value: 42
New value: 0
```

در این مثال، مقدار قبلی `value` در متغیر `oldValue` ذخیره شده و مقدار `value` نیز به صفر تغییر کرده است.

## معرفی تابع std::exchange

تابع `std::exchange` در هدر استاندارد `<utility>` تعریف شده و از ++C14 به بعد در دسترس است.

امضای عمومی این تابع به شکل زیر است:

```
template<class T, class U = T>
constexpr T exchange(T& obj, U&& newValue)
    noexcept(/* implementation-dependent condition */);
```

این امضا ساختار کلی تابع را نشان می‌دهد؛ عبارت مربوط به `noexcept` در امضای واقعی استاندارد با شرطی مشخص بر اساس نوع‌ها تعیین می‌شود و صرفاً وابسته به تصمیم دلخواه پیاده‌سازی نیست.

پارامترهای تابع عبارت‌اند از:

- `obj`: ارجاعی به شیئی که مقدار آن باید جایگزین شود.
- `newValue`: مقدار جدیدی که پس از دریافت مقدار قبلی در شیء قرار می‌گیرد.

نوع بازگشتی `T` است؛ بنابراین تابع مقدار قبلی شیء را با نوع `T` بازمی‌گرداند.

### نحوه عملکرد تابع

رفتار مفهومی تابع را می‌توان با کد زیر نمایش داد:

```
template<class T, class U = T>
constexpr T exchange_like(T& obj, U&& newValue) {
    T oldValue = std::move(obj);
    obj = std::forward<U>(newValue);
    return oldValue;
}
```

این کد صرفاً نمونه‌ای آموزشی از رفتار تابع است و جایگزین کامل پیاده‌سازی استاندارد آن نیست.

در این پیاده‌سازی، ابتدا مقدار قبلی شیء با استفاده از `std::move` به متغیر `oldValue` منتقل می‌شود. سپس مقدار جدید با استفاده از `std::forward` در شیء اصلی قرار می‌گیرد و مقدار قبلی بازگردانده می‌شود.

نکته مهم این است که `std::move` به‌تنهایی چیزی را جابه‌جا نمی‌کند؛ بلکه امکان انتخاب عملیات Move را فراهم می‌سازد. نتیجه واقعی به سازندهها و عملگرهای انتساب نوع مورد استفاده بستگی دارد.

## بررسی تفاوت std::exchange با انتساب معمولی

در انتساب معمولی، مقدار جدید در متغیر قرار می‌گیرد؛ اما مقدار قبلی به‌صورت خودکار بازگردانده نمی‌شود.

```
int value = 10;

value = 20;
```

پس از اجرای این کد، مقدار `value` برابر با `20` است و مقدار قبلی آن دیگر مستقیماً در دسترس نیست.

در مقابل، با استفاده از `std::exchange` می‌توان هر دو عملیات را هم‌زمان انجام داد:

```
int value = 10;

int oldValue = std::exchange(value, 20);
```

اکنون مقدار `oldValue` برابر با `10` و مقدار `value` برابر با `20` است.

این تفاوت زمانی اهمیت بیشتری پیدا می‌کند که مقدار قبلی نشان‌دهنده یک منبع، وضعیت داخلی یا مالکیت یک شیء باشد.

## بررسی پارامترهای قالب و Perfect Forwarding

یکی از ویژگی‌های مهم `std::exchange` استفاده از پارامتر قالب `U` و ارجاع به مقدار راست‌مقدار یا `U&&` است.

این طراحی اجازه می‌دهد مقدار جدید از منابع مختلفی دریافت شود؛ برای مثال، از یک مقدار موقت، یک متغیر ثابت یا یک شیء موجود.

```
#include <string>
#include <utility>

int main() {
    std::string value = "old";

    std::string previous = std::exchange(value, "new");

    std::string another = "replacement";
    std::string oldValue = std::exchange(value, another);
}
```

در مثال بالا، رشته `"new"` به‌عنوان مقدار جدید استفاده می‌شود. در فراخوانی دوم نیز مقدار متغیر `another` به `value` اختصاص داده می‌شود.

از آنجا که پارامتر `newValue` از نوع `U&&` است و `U` به‌صورت خودکار استنتاج می‌شود، تابع می‌تواند از قابلیت Perfect Forwarding استفاده کند.

در پیاده‌سازی مفهومی، عبارت `std::forward<U>(newValue)` ارزش‌گذاری اصلی آرگومان را حفظ می‌کند. این موضوع به انتخاب عملیات انتساب مناسب کمک می‌کند.

با این حال، استفاده از `std::exchange` تضمین نمی‌کند که عملیات جایگزینی حتماً بدون کپی انجام شود؛ این مسئله به نوع‌ها، ویژگی‌های انتساب و مقدار ورودی بستگی دارد.

## بررسی تفاوت std::exchange با std::move

دو ابزار `std::exchange` و `std::move` هر دو در سناریوهای مرتبط با Move Semantics کاربرد دارند، اما هدف یکسانی ندارند.

تابع `std::move` یک عبارت را به یک مقدار قابل انتقال تبدیل می‌کند تا عملیات Move در صورت پشتیبانی نوع امکان‌پذیر شود. این تابع به‌تنهایی مقدار متغیر اصلی را تغییر نمی‌دهد.

در مقابل، `std::exchange` مقدار قبلی یک شیء را بازمی‌گرداند و تلاش می‌کند مقدار جدید را در آن قرار دهد.

```
#include <string>
#include <utility>

int main() {
    std::string source = "hello";

    std::string destination = std::move(source);

    int value = 100;
    int oldValue = std::exchange(value, 0);
}
```

در مثال بالا، `std::move` امکان انتقال از `source` به `destination` را فراهم می‌کند. وضعیت `source` پس از این عملیات به رفتار عملیات Move نوع `std::string` وابسته است.

در مقابل، `std::exchange` مقدار قبلی `value` را بازمی‌گرداند و مقدار آن را به صفر تغییر می‌دهد.

## کاربرد در پیاده‌سازی Move Constructor

یکی از کاربردهای مهم `std::exchange` انتقال مالکیت منابع در Move Constructor است.

فرض کنید کلاسی داریم که مالک یک منبع تخصیص‌یافته به‌صورت پویا است. در این شرایط، هنگام انتقال مالکیت باید مقدار اشاره‌گر از شیء مبدأ گرفته شود و شیء مبدأ به وضعیت خالی بازگردد.

```
#include <utility>

class Resource {
public:
    explicit Resource(int* ptr = nullptr)
        : ptr_(ptr) {}

    Resource(const Resource&) = delete;
    Resource& operator=(const Resource&) = delete;

    Resource(Resource&& other) noexcept
        : ptr_(std::exchange(other.ptr_, nullptr)) {}

    ~Resource() {
        delete ptr_;
    }

private:
    int* ptr_;
};
```

در این مثال، هنگام ساخت شیء جدید از یک شیء دیگر، مقدار `other.ptr_` به عضو `ptr_` منتقل می‌شود و اشاره‌گر شیء مبدأ به `nullptr` تغییر می‌کند.

این کار مانع از آن می‌شود که هر دو شیء تصور کنند مالک یک منبع واحد هستند.

البته این کلاس صرفاً نمونه‌ای آموزشی است. در طراحی واقعی، استفاده از `std::unique_ptr` معمولاً انتخاب ایمن‌تر و ساده‌تری برای مدیریت مالکیت منابع پویا است.

## کاربرد در Move Assignment Operator

استفاده از `std::exchange` تنها به Move Constructor محدود نیست و می‌تواند در پیاده‌سازی Move Assignment Operator نیز مفید باشد.

```
#include <utility>

class Resource {
public:
    explicit Resource(int* ptr = nullptr)
        : ptr_(ptr) {}

    Resource(const Resource&) = delete;
    Resource& operator=(const Resource&) = delete;

    Resource(Resource&& other) noexcept
        : ptr_(std::exchange(other.ptr_, nullptr)) {}

    Resource& operator=(Resource&& other) noexcept {
        if (this != &other) {
            delete ptr_;
            ptr_ = std::exchange(other.ptr_, nullptr);
        }

        return *this;
    }

    ~Resource() {
        delete ptr_;
    }

private:
    int* ptr_;
};
```

در این پیاده‌سازی، ابتدا منبع قبلی شیء مقصد آزاد می‌شود و سپس مالکیت منبع شیء مبدأ انتقال می‌یابد.

بررسی `this != &other` برای جلوگیری از آزادسازی اشتباه منبع در انتساب به خود اهمیت دارد.

در طراحی‌های حرفه‌ای، این الگو باید با دقت بیشتری بررسی شود؛ به‌ویژه اگر آزادسازی منابع، تخصیص مجدد حافظه یا عملیات انتساب بتوانند استثنا ایجاد کنند.

## کاربرد در بازنشانی وضعیت متغیرها

یکی از کاربردهای ساده و رایج `std::exchange` بازگرداندن یک متغیر به وضعیت اولیه است، در حالی که مقدار قبلی آن نیز مورد نیاز است.

```
#include <utility>

int main() {
    bool active = true;

    bool wasActive = std::exchange(active, false);
}
```

در این مثال، مقدار قبلی `active` در `wasActive` ذخیره می‌شود و وضعیت `active` به `false` تغییر می‌کند.

این الگو برای پرچم‌های وضعیت، متغیرهای کنترلی و ثبت وضعیت قبلی مفید است.

برای مثال، هنگام پردازش یک رویداد می‌توان وضعیت انتظار را پاک کرد و هم‌زمان تشخیص داد که آیا پیش از آن رویدادی در انتظار بوده است یا خیر.

## کاربرد در مدیریت صف و رویدادها

تابع `std::exchange` می‌تواند برای گرفتن محتوای یک متغیر و جایگزین‌کردن آن با یک مقدار خالی استفاده شود.

```
#include <string>
#include <utility>

int main() {
    std::string pendingMessage = "Process this message";

    std::string message = std::exchange(pendingMessage, {});
}
```

در این مثال، محتوای `pendingMessage` به `message` منتقل می‌شود و رشته اصلی به مقدار خالی تغییر می‌کند.

استفاده از `{}` در این فراخوانی باعث می‌شود مقدار جدید بر اساس نوع مقصد، یعنی `std::string`، تعیین شود.

این روش برای انتقال محتوای موقت، تخلیه بافرها و جابه‌جایی داده‌های در انتظار پردازش مناسب است؛ البته در برنامه‌های چندنخی، برای جلوگیری از Race Condition باید هم‌زمانی دسترسی‌ها نیز مدیریت شود.

## بررسی نوع‌های غیرقابل کپی

تابع `std::exchange` می‌تواند با نوع‌هایی استفاده شود که قابلیت Copy ندارند، به شرط آنکه عملیات مورد نیاز برای انتقال مقدار قبلی، جایگزینی مقدار جدید و بازگرداندن نتیجه معتبر باشند.

برای مثال، نوع `std::unique_ptr` مالکیت انحصاری یک منبع را مدیریت می‌کند و قابلیت Copy ندارد.

```
#include <memory>
#include <utility>

int main() {
    auto first = std::make_unique<int>(42);

    auto previous = std::exchange(
        first,
        std::make_unique<int>(100)
    );
}
```

پس از اجرای این کد، `previous` مالک مقدار قبلی یعنی `42` است و `first` مالک مقدار جدید یعنی `100` خواهد بود.

در این مثال، مالکیت منابع به‌صورت انحصاری حفظ می‌شود و هیچ کپی غیرمجاز از `std::unique_ptr` رخ نمی‌دهد.

## بررسی مقدار بازگشتی و Move Semantics

نوع بازگشتی `std::exchange` برابر با `T` است؛ بنابراین نتیجه تابع یک شیء از نوع `T` خواهد بود.

در بسیاری از موارد، مقدار قبلی از طریق Move Constructor یا سازوکارهای بهینه‌سازی بازگردانده می‌شود. با این حال، نباید فرض کرد که تمام فراخوانی‌ها الزاماً بدون هزینه هستند.

اگر نوع مورد استفاده، عملیات انتقال پرهزینه‌ای داشته باشد یا سازنده و عملگر انتساب آن رفتار خاصی داشته باشند، هزینه اجرای تابع نیز تحت تأثیر قرار می‌گیرد.

به همین دلیل، برای نوع‌های سفارشی باید پیاده‌سازی Move Constructor، Move Assignment Operator و سایر عملیات مرتبط بررسی شود.

## بررسی noexcept و مدیریت استثناها

یکی از نکات مهم درباره `std::exchange`، رفتار آن در برابر استثناها است.

مشخصه `noexcept` این تابع به ویژگی‌های نوع‌ها و عملیات مورد نیاز برای جایگزینی مقدار وابسته است. بنابراین، نباید تصور کرد که استفاده از این تابع همیشه بدون امکان پرتاب استثنا خواهد بود.

اگر عملیات انتساب مقدار جدید استثنا پرتاب کند، ممکن است شیء مقصد پیش از شکست تغییر کرده باشد. در این شرایط، وضعیت نهایی شیء به رفتار عملیات انتساب نوع مورد استفاده وابسته است.

همچنین، استفاده از `std::exchange` در یک Move Constructor که با `noexcept` مشخص شده است باید با دقت انجام شود. اگر عملیات داخلی بتواند استثنا پرتاب کند، مشخص‌کردن نادرست `noexcept` می‌تواند در زمان اجرا به فراخوانی `std::terminate` منجر شود.

برای طراحی ایمن، بهتر است ویژگی‌های استثناپذیری نوع‌های مورد استفاده بررسی شوند و مشخصه‌های `noexcept` بر اساس رفتار واقعی عملیات تعیین شوند.

## بررسی محدودیت‌ها و خطاهای رایج

تابع `std::exchange` ابزار قدرتمندی است، اما استفاده نادرست از آن می‌تواند به خطاهای منطقی یا مشکلات مدیریت منابع منجر شود.

### استفاده از مقدار نامناسب برای بازنشانی

مقدار جدید باید با نوع شیء مقصد سازگار باشد و عملیات انتساب معتبر را پشتیبانی کند.

برای مثال، اگر یک اشاره‌گر خام را به `nullptr` تغییر می‌دهیم، باید اطمینان داشته باشیم که وضعیت جدید با قرارداد مالکیت و طول عمر منبع سازگار است.

### فرض انتقال بدون هزینه

استفاده از `std::exchange` تضمین نمی‌کند که عملیات انتقال هیچ هزینه‌ای نداشته باشد. هزینه واقعی به نوع داده و عملیات تعریف‌شده برای آن وابسته است.

### نادیده‌گرفتن وضعیت شیء مبدأ

پس از استفاده از `std::exchange`، شیء اصلی با مقدار جدید جایگزین می‌شود. بنابراین، کدهای بعدی نباید همچنان به مقدار قبلی آن متکی باشند.

### استفاده نامناسب در کد چندنخی

عملیات `std::exchange` به‌خودی‌خود اتمیک نیست. اگر چند Thread به یک متغیر مشترک دسترسی داشته باشند، استفاده هم‌زمان بدون سازوکار همگام‌سازی مناسب می‌تواند باعث Race Condition شود.

برای متغیرهای اتمیک، باید از عملیات متناسب با نوع اتمیک استفاده کرد و الزامات Memory Ordering را نیز در نظر گرفت.

## مقایسه با روش‌های جایگزین

انتخاب میان `std::exchange`، انتساب معمولی و انتقال با `std::move` به هدف عملیات بستگی دارد.

| ویژگی                 | `std::exchange`      | انتساب معمولی                  | `std::move`                   |
| --------------------- | -------------------- | ------------------------------ | ----------------------------- |
| جایگزینی مقدار        | بله                  | بله                            | به‌تنهایی خیر                 |
| بازگرداندن مقدار قبلی | بله                  | خیر                            | خیر                           |
| انتقال مالکیت         | در صورت پشتیبانی نوع | وابسته به نوع و مقدار سمت راست | صرفاً فراهم‌کردن امکان انتقال |
| نیاز به `<utility>`   | بله                  | خیر                            | بله                           |
| نسخه استاندارد        | ++C14                | از نسخه‌های اولیه ++C          | ++C11                         |

در این جدول، منظور از انتقال مالکیت، رفتار حاصل از عملیات واقعی نوع مورد استفاده است؛ نه تضمینی مستقل که صرفاً از نام تابع ناشی شود.

## نکات طراحی برای توسعه‌دهندگان حرفه‌ای

در طراحی APIها و کلاس‌های سفارشی، استفاده از `std::exchange` زمانی ارزشمند است که دریافت مقدار قبلی و بازنشانی یا جایگزینی آن، دو بخش از یک عملیات منطقی واحد باشند.

برای نمونه، در پیاده‌سازی کلاس‌های مدیریت‌کننده منابع، تخلیه بافرها، انتقال وضعیت داخلی و مدیریت مقادیر موقت، این تابع می‌تواند کد را خواناتر کند.

با این حال، بهتر است از استفاده بیش‌ازحد از آن در عبارت‌های پیچیده خودداری شود. اگر عملیات جانبی متعدد، مدیریت استثناها یا چند مرحله وابسته وجود دارد، شکستن کد به چند دستور واضح می‌تواند خوانایی و قابلیت نگهداری را افزایش دهد.

همچنین، هنگام طراحی کلاس‌های مالک منابع، استفاده از ابزارهای RAII مانند `std::unique_ptr` و `std::vector` معمولاً از مدیریت دستی حافظه ایمن‌تر است. تابع `std::exchange` باید در خدمت طراحی صحیح مالکیت باشد، نه جایگزینی برای آن.

## جمع‌بندی

تابع `std::exchange` که از ++C14 به کتابخانه استاندارد اضافه شده است، راهی ساده و مؤثر برای جایگزین‌کردن مقدار یک شیء و دریافت مقدار قبلی آن فراهم می‌کند.

مهم‌ترین کاربردهای این تابع عبارت‌اند از:

- انتقال مالکیت منابع در Move Constructor و Move Assignment Operator.
- بازنشانی پرچم‌ها و وضعیت‌های داخلی.
- تخلیه متغیرهای حاوی داده‌های موقت.
- انتقال مقدار از نوع‌های غیرقابل کپی که عملیات انتقال را پشتیبانی می‌کنند.
- ساده‌سازی کدهایی که دریافت مقدار قبلی و جایگزینی مقدار جدید را هم‌زمان انجام می‌دهند.

در نهایت، استفاده صحیح از `std::exchange` مستلزم شناخت Move Semantics، رفتار عملیات انتساب، ویژگی‌های `noexcept` و قرارداد مالکیت نوع مورد استفاده است. زمانی که این ملاحظات رعایت شوند، این تابع می‌تواند کد ++C را خواناتر، موجزتر و در بسیاری از سناریوها قابل نگهداری‌تر کند.
