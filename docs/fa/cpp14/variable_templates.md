# آشنایی با Variable Templates در ++C14

## مقدمه

قابلیت `Variable Templates` از استاندارد ++C14 به زبان اضافه شد و امکان تعریف متغیرها یا ثابت‌هایی را فراهم می‌کند که نوع یا مقدارشان به پارامترهای قالب (Template Parameters) وابسته است. پیش از این قابلیت، برای بیان مقدار وابسته به نوع معمولاً از `static constexpr` اعضای کلاس‌های قالبی یا ساختارهای کمکی مانند `std::integral_constant` استفاده می‌شد.

با `Variable Templates` می‌توان یک مقدار وابسته به نوع را مستقیم و بدون ساختن یک کلاس کمکی تعریف کرد. این قابلیت بخشی از زبان است، نه یک قابلیت مستقل از کتابخانه استاندارد.

## مفهوم و انگیزه

فرض کنید می‌خواهیم برای هر نوع عددی، ثابت `pi` با نوع همان نوع در دسترس باشد. در استاندارد ++C11 می‌توان از یک کلاس قالبی استفاده کرد، اما در ++C14 تعریف متغیر قالبی ساده‌تر است:

```cpp
template <typename T>
constexpr T pi = T(3.1415926535897932385L);
```

در این مثال، `T` پارامتر نوع است و هر نمونه‌سازی از `pi<T>` یک متغیر مستقل با نوع `T` ایجاد می‌کند. برای نمونه، `pi<float>` و `pi<double>` دو نمونه متفاوت هستند.

کاربرد اصلی این ویژگی، بیان مقادیر ثابت، تنظیمات و داده‌های وابسته به نوع به شکلی خواناتر از الگوهای قدیمی‌تر است. با این حال، قالب متغیر به‌خودی‌خود الگوریتمی را عمومی نمی‌کند؛ فقط امکان پارامتری‌کردن تعریف متغیر را فراهم می‌سازد.

## نحو پایه

شکل کلی تعریف چنین است:

```cpp
template <template-parameter-list>
decl-specifiers variable-name = initializer;
```

در این نحو، فهرست پارامترها می‌تواند شامل پارامترهای نوع، پارامترهای غیرنوعی (Non-type Template Parameters) یا ترکیبی از آن‌ها باشد. تعریف باید یک نوع و مقداردهی معتبر برای هر نمونه‌سازی داشته باشد.

یک نمونه ساده:

```cpp
template <typename T>
constexpr bool is_pointer_v = false;

template <typename T>
constexpr bool is_pointer_v<T*> = true;
```

این نمونه از Partial Specialization برای تشخیص اشاره‌گرها استفاده می‌کند. برای `is_pointer_v<int>` مقدار `false` و برای `is_pointer_v<int*>` مقدار `true` خواهد بود.

## تفاوت با متغیر معمولی و اعضای static

متغیر معمولی نمی‌تواند مستقیماً با پارامتر قالب تعریف شود. در مقابل، `Variable Template` برای هر مجموعه پارامتر قالب نمونه‌سازی می‌شود.

```cpp
template <typename T>
inline constexpr bool always_true_v = true;
```

کلیدواژه `inline` در این مثال از ++C17 در دسترس است، بنابراین این تعریف در حالت استاندارد ++C14 قابل استفاده نیست. اگر هدف سازگاری با ++C14 باشد، باید آن را حذف کرد:

```cpp
template <typename T>
constexpr bool always_true_v = true;
```

اعضای `static` در کلاس قالبی نیز می‌توانند مقادیر وابسته به نوع داشته باشند، اما استفاده از آن‌ها معمولاً نیازمند نام کلاس و عضو است:

```cpp
template <typename T>
struct traits {
    static constexpr bool value = true;
};

bool a = traits<int>::value;
```

با قالب متغیر می‌توان همان ایده را مستقیم‌تر بیان کرد:

```cpp
template <typename T>
constexpr bool value_v = true;

bool b = value_v<int>;
```

## کاربرد در Type Traits

یکی از رایج‌ترین کاربردها، ساختن رابط ساده‌تر برای Type Traits است. در کتابخانه استاندارد ++C14، نام‌هایی با پسوند `_v` به‌طور عمومی برای همه Type Traits ارائه نشدند؛ نسخه‌های استاندارد کتابخانه‌ای مانند `std::is_integral_v` در ++C17 اضافه شدند. با این حال، در ++C14 می‌توان چنین متغیرهایی را خودمان تعریف کرد:

```cpp
#include <type_traits>

template <typename T>
constexpr bool is_integral_v = std::is_integral<T>::value;
```

سپس می‌توان نوشت:

```cpp
static_assert(is_integral_v<int>, "int must be integral");
static_assert(!is_integral_v<double>, "double is not integral");
```

در ++C17 همین کاربرد با `std::is_integral_v<T>` به‌صورت استاندارد در دسترس است. اگر پروژه باید با ++C14 کامپایل شود، تعریف سفارشی یا الگوی مبتنی بر `::value` همچنان کاربرد دارد.

## پارامترهای غیرنوعی

قالب متغیر می‌تواند از پارامترهای غیرنوعی نیز استفاده کند. در ++C14، این پارامترها باید از انواع مجاز آن استاندارد باشند؛ محدودیت‌های آن با امکانات جدیدتر مانند ++C20 یکسان نیست.

```cpp
template <unsigned N>
constexpr unsigned buffer_size = N * 2;

static_assert(buffer_size<8> == 16, "unexpected size");
```

در این مثال، `N` مقدار زمان کامپایل است و نمونه‌سازی `buffer_size<8>` مقدار ثابت ۱۶ را ارائه می‌دهد.

ترکیب پارامتر نوع و پارامتر غیرنوعی نیز ممکن است:

```cpp
template <typename T, unsigned N>
constexpr T scale = T(N) * T(1.5);

constexpr double x = scale<double, 4>;
```

مقداردهی باید برای نوع انتخاب‌شده معتبر باشد. برای نمونه، تبدیل‌های عددی ممکن است دقت را از دست بدهند یا برای برخی انواع اصلاً معتبر نباشند.

## تخصصی‌سازی قالب متغیر

همانند قالب‌های دیگر، قالب متغیر می‌تواند Full Specialization و Partial Specialization داشته باشد. تخصصی‌سازی جزئی معمولاً برای خانواده‌ای از انواع، مانند اشاره‌گرها یا آرایه‌ها، مفید است.

```cpp
template <typename T>
constexpr int category_v = 0;

template <typename T>
constexpr int category_v<T*> = 1;

template <typename T>
constexpr int category_v<const T> = 2;
```

در این مثال، تخصصی‌سازی‌ها برای الگوهای نوعی مشخص اعمال می‌شوند. ترتیب و قابلیت انطباق تخصصی‌سازی‌ها باید بدون ابهام باشد؛ قواعد انتخاب تخصصی‌سازی مشابه قواعد قالب‌های کلاس و تابع است.

تخصصی‌سازی کامل برای یک نوع مشخص نیز امکان‌پذیر است:

```cpp
template <typename T>
constexpr int rank_v = 0;

template <>
constexpr int rank_v<bool> = 1;
```

توجه کنید که تخصصی‌سازی کامل باید با اعلان اصلی سازگار باشد و در پروژه‌های چندواحدی باید قواعد تعریف و ODR رعایت شوند.

## مقدارهای constexpr و زمان کامپایل

قالب‌های متغیر اغلب با `constexpr` ترکیب می‌شوند تا مقدارشان در زمان کامپایل قابل استفاده باشد. البته `constexpr` بودن تعریف به‌تنهایی تضمین نمی‌کند که هر عبارت وابسته به آن در هر زمینه‌ای معتبر باشد؛ مقداردهی و نوع باید شرایط ثابت‌بودن را برآورده کنند.

```cpp
template <typename T>
constexpr T zero_v = T{};

static_assert(zero_v<int> == 0, "zero value");
```

اگر متغیر برای نوعی نمونه‌سازی شود که مقداردهی `T{}` برای آن معتبر نیست، همان نمونه‌سازی نامعتبر خواهد بود. قالب‌ها معمولاً تا زمانی که نمونه‌سازی لازم نشود، چنین خطاهایی را آشکار نمی‌کنند.

## استفاده از decltype و نوع دقیق متغیر

نوع متغیر قالبی می‌تواند به پارامترها وابسته باشد. برای فهمیدن نوع دقیق یک عبارت، می‌توان از `decltype` استفاده کرد:

```cpp
template <typename T>
constexpr auto identity_v = T{};

static_assert(std::is_same<decltype(identity_v<int>), const int>::value,
              "decltype of constexpr variable is const-qualified");
```

متغیر تعریف‌شده با `constexpr` دارای `const` است؛ به همین دلیل `decltype(identity_v<int>)` نوع `const int` را برمی‌گرداند. در عین حال، `auto` در مقداردهی اولیه نوع را استنتاج می‌کند و در این مثال به نوع `T` می‌رسد، سپس `constexpr` آن را ثابت و const-qualified می‌کند.

## الگوهای رایج و پسوند _v

در کدهای ++C، پسوند `_v` یک قرارداد نام‌گذاری رایج برای متغیرهای قالبی است که نتیجه یک trait یا ویژگی را نشان می‌دهند. این پسوند الزام زبان نیست، اما در کتابخانه استاندارد و کتابخانه‌های عمومی متداول است.

```cpp
#include <type_traits>

template <typename T>
constexpr bool is_signed_v = std::is_signed<T>::value;

template <typename T>
constexpr bool is_arithmetic_v = std::is_arithmetic<T>::value;
```

این نام‌گذاری استفاده را نسبت به `std::is_signed<T>::value` کوتاه‌تر می‌کند. بهتر است پسوند `_v` برای مقادیری به‌کار رود که نقش trait یا ویژگی منطقی/عددی دارند و از آن برای متغیرهای عادی پروژه بدون الگوی نام‌گذاری روشن استفاده نشود.

## پیوند با constexpr if

قابلیت `if constexpr` در ++C17 معرفی شده است و بخشی از ++C14 نیست. با وجود این، قالب‌های متغیر می‌توانند در کدهای ++C17 و جدیدتر شرط‌های خواناتری ایجاد کنند:

```cpp
#include <type_traits>

template <typename T>
constexpr bool is_integral_v = std::is_integral<T>::value;

template <typename T>
void process(T value) {
    if constexpr (is_integral_v<T>) {
        // Handle integral types
    } else {
        // Handle other types
    }
}
```

در پروژه‌ای که دقیقاً با ++C14 کامپایل می‌شود، باید از سازوکارهای موجود در آن نسخه، مانند overload، specialization یا `std::enable_if` استفاده کرد. تعریف قالب متغیر با `constexpr` در ++C14 معتبر است، اما `if constexpr` نیست.

## قواعد ODR و استفاده در فایل‌های سرآیند

قالب‌های متغیر معمولاً در فایل‌های سرآیند تعریف می‌شوند تا هنگام نمونه‌سازی در دسترس باشند. در ++C14، تعریف متغیر قالبی با `constexpr` به‌طور خودکار همان قاعده `inline variable` استاندارد ++C17 را ندارد؛ نباید `inline` را به کد ++C14 افزود و انتظار داشت که استاندارد باشد.

در تعریف‌های قالبی، قواعد One Definition Rule همچنان اهمیت دارند. تعریف یک قالب متغیر معمولاً در چند واحد ترجمه دیده می‌شود، اما باید از تعریف‌های ناسازگار و تخصصی‌سازی‌های متناقض جلوگیری کرد. برای متغیرهای سراسری غیرقالبی که در سرآیند تعریف می‌شوند، راهکارهای ++C14 متفاوت‌اند؛ برای مثال می‌توان اعلان `extern` را در سرآیند و یک تعریف را در فایل منبع قرار داد.

## محدودیت‌ها و خطاهای رایج

- قابلیت `Variable Templates` از ++C14 آغاز می‌شود؛ کامپایلر باید با استاندارد مناسب تنظیم شده باشد.
- کلیدواژه `inline` برای متغیرها از ++C17 است و نباید آن را به‌عنوان بخشی از راهکار استاندارد ++C14 به کار برد.
- نام‌های استاندارد `std::is_integral_v` و بسیاری از traitهای `_v` از ++C17 هستند؛ در ++C14 می‌توان معادل محلی تعریف کرد.
- نوع یا مقدار نامعتبر ممکن است فقط هنگام نمونه‌سازی یک specialization آشکار شود.
- مقدار `constexpr` باید واقعاً با قواعد عبارت ثابت سازگار باشد؛ صرف قرار دادن `constexpr` همه عبارت‌ها را معتبر نمی‌کند.
- تخصصی‌سازی‌ها باید از نظر الگوی تطبیق و تعریف در واحدهای ترجمه سازگار باشند.
- قالب متغیر برای نگهداری مقدار وابسته به پارامتر مناسب است، اما جایگزین کامل قالب تابع یا کلاس نیست؛ اگر به overload، رفتار اجرایی یا نوع مرکب نیاز دارید، آن قالب‌ها مناسب‌ترند.

## مقایسه با روش‌های قدیمی‌تر

پیش از ++C14، برای نمایش ویژگی وابسته به نوع معمولاً از اعضای `static constexpr` یک کلاس قالبی استفاده می‌شد:

```cpp
template <typename T>
struct is_pointer : std::false_type {};

template <typename T>
struct is_pointer<T*> : std::true_type {};

static_assert(is_pointer<int*>::value, "pointer type");
```

این روش همچنان معتبر است و در ++C11 نیز قابل استفاده بود. مزیت `Variable Templates` ارائه رابط مستقیم‌تر است:

```cpp
template <typename T>
constexpr bool is_pointer_v = is_pointer<T>::value;
```

روش کلاس‌محور زمانی همچنان مفید است که به نوعی با اعضای متعدد، تخصصی‌سازی کلاس، یا سازگاری با APIهای قدیمی نیاز باشد. قالب متغیر اغلب به‌عنوان لایه رابط راحت‌تر روی چنین traitهایی قرار می‌گیرد.

## راهنمای انتخاب در پروژه واقعی

- برای ثابت‌ها یا ویژگی‌های ساده وابسته به نوع، `Variable Templates` انتخاب خوانا و مستقیمی است.
- برای traitهای کتابخانه‌ای در ++C14، می‌توان متغیر قالبی محلی را به‌عنوان رابط روی `Trait<T>::value` تعریف کرد.
- برای پشتیبانی از ++C17 و جدیدتر، ابتدا بررسی کنید که آیا کتابخانه استاندارد نسخه `_v` موردنیاز را ارائه می‌دهد.
- برای منطق نوعی پیچیده، رفتار اجرایی، یا overload، از قالب تابع یا کلاس استفاده کنید؛ متغیر قالبی صرفاً یک متغیر تعریف می‌کند.
- در کتابخانه‌های عمومی، استاندارد هدف، قواعد ODR، نام‌گذاری و نیاز به سازگاری با نسخه‌های قدیمی را از ابتدا مشخص کنید.

## جمع‌بندی

قابلیت `Variable Templates` در ++C14 روشی مستقیم برای تعریف متغیرها و ثابت‌های وابسته به پارامترهای قالب فراهم می‌کند. این ویژگی به‌ویژه برای ثابت‌های نوع‌محور و رابط‌های ساده‌تر برای Type Traits سودمند است. در عین حال، باید تفاوت آن با امکانات ++C17 مانند `inline variables` و traitهای استاندارد دارای پسوند `_v` را در نظر داشت. انتخاب درست این قابلیت به استاندارد هدف پروژه، نیاز به تخصصی‌سازی، و پیچیدگی نوع یا رفتار موردنظر بستگی دارد.
