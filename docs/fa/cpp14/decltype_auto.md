# آموزش جامع `decltype(auto)` در ++C14

## مقدمه و هدف طراحی

قابلیت `decltype(auto)` یکی از امکانات زبان ++C14 است که کنترل دقیق‌تری بر استنتاج نوع (Type Deduction) فراهم می‌کند. این قابلیت به‌ویژه هنگام نوشتن توابع Generic، توابع واسط (Wrapper Functions)، توابعی با نوع بازگشتی وابسته به عبارت (Expression-Dependent Return Type) و کدهایی که باید Reference بودن مقادیر را حفظ کنند، اهمیت زیادی دارد.

در بسیاری از مواقع، برنامه‌نویس می‌خواهد نوع یک متغیر یا مقدار بازگشتی تابع به‌صورت خودکار تعیین شود؛ اما استنتاج معمولی با `auto` همیشه نوع دقیق موردنظر را حفظ نمی‌کند. برای مثال، ممکن است یک عبارت از نوع `int&` باشد، ولی استفاده از `auto` برای استنتاج نوع متغیر حاصل، به `int` منجر شود. در چنین شرایطی، اگر حفظ Reference ضروری باشد، `decltype(auto)` می‌تواند راه‌حل مناسبی باشد.

برای استفاده صحیح از این قابلیت، باید تفاوت میان `auto`، `decltype`، `decltype(auto)`، مقادیر Lvalue و Rvalue، و قواعد مربوط به Referenceها را به‌خوبی شناخت.

## مفهوم اصلی و دلیل معرفی

قابلیت `decltype(auto)` در استاندارد ++C14 معرفی شد. این قابلیت ترکیبی از دو سازوکار موجود در زبان است:

- سازوکار `decltype` که نوع دقیق یک نام یا عبارت را طبق قواعد مشخص زبان تعیین می‌کند.
- سازوکار `auto` که امکان استنتاج خودکار نوع را فراهم می‌کند.

تفاوت اصلی در این است که `decltype(auto)` از قواعد استنتاج `auto` برای تعیین نوع استفاده نمی‌کند؛ بلکه نوع را با قواعد `decltype` استنتاج می‌کند.

### تفاوت اولیه میان `auto` و `decltype(auto)`

کد زیر را در نظر بگیرید:

```
int value = 42;
int& reference = value;

auto first = reference;
decltype(auto) second = reference;
```

در این مثال:

- نوع `first` برابر `int` است.
- نوع `second` برابر `int&` است.

علت این تفاوت آن است که `auto` در این اعلان، Reference بودن نوع مقداردهی اولیه را حذف می‌کند؛ اما `decltype(auto)` قواعد `decltype` را روی عبارت مقداردهی اولیه اعمال می‌کند.

بنابراین، با استفاده از `decltype(auto)` می‌توان در موارد لازم، ویژگی‌هایی مانند Reference بودن و `const` بودن نوع را حفظ کرد.

### چرا این قابلیت اهمیت دارد؟

فرض کنید تابعی Generic می‌نویسید که نتیجه فراخوانی تابع دیگری را برمی‌گرداند. اگر تابع اصلی Reference برگرداند، ممکن است بخواهید تابع واسط نیز همان Reference را حفظ کند. استفاده از `auto` برای نوع بازگشتی می‌تواند این ویژگی را از بین ببرد، در حالی که `decltype(auto)` امکان حفظ دقیق‌تر نوع بازگشتی را فراهم می‌کند.

البته حفظ نوع دقیق همیشه به معنای بهتر بودن کد نیست. گاهی حذف Reference و بازگرداندن یک مقدار مستقل، رفتاری مطلوب‌تر و ایمن‌تر است. انتخاب میان این دو باید بر اساس قرارداد تابع و طول عمر شیء موردنظر انجام شود.

## قواعد استنتاج نوع با `decltype`

برای درک کامل رفتار `decltype(auto)`، ابتدا باید قواعد `decltype` را بررسی کنیم.

### استنتاج نوع از نام یک متغیر

اگر آرگومان `decltype` نام بدون پرانتز یک متغیر باشد، نتیجه نوع اعلام‌شده همان متغیر است.

```
int value = 10;
const int constantValue = 20;
int& reference = value;

decltype(value) a = 1;
decltype(constantValue) b = 2;
decltype(reference) c = value;
```

نوع متغیرها به این صورت خواهد بود:

| متغیر | نوع استنتاج‌شده |
| ----- | --------------- |
| `a`   | `int`           |
| `b`   | `const int`     |
| `c`   | `int&`          |

در این قاعده، `decltype(reference)` برابر `int&` است؛ زیرا نوع اعلام‌شده `reference` از ابتدا `int&` بوده است.

### تأثیر پرانتز بر نتیجه `decltype`

یکی از مهم‌ترین نکات در استفاده از `decltype(auto)` این است که پرانتزگذاری یک عبارت می‌تواند نوع استنتاج‌شده را تغییر دهد.

برای عبارتی که نام بدون پرانتز یک متغیر نیست، قاعده عمومی به دسته‌بندی مقدار (Value Category) عبارت وابسته است:

- اگر عبارت از نوع Lvalue باشد، نتیجه `decltype` برابر `T&` خواهد بود.
- اگر عبارت از نوع Xvalue باشد، نتیجه برابر `T&&` خواهد بود.
- اگر عبارت از نوع Prvalue باشد، نتیجه برابر `T` خواهد بود.

در این قواعد، `T` نوع شیء یا نوع نتیجه عبارت، با در نظر گرفتن قواعد مربوط به نوع و Qualifierها، است.

به مثال زیر توجه کنید:

```
int value = 42;

decltype(value) first = value;
decltype((value)) second = value;
```

نوع متغیرها متفاوت است:

- نوع `first` برابر `int` است.
- نوع `second` برابر `int&` است.

در عبارت `decltype(value)`، چون `value` نام بدون پرانتز متغیر است، نوع اعلام‌شده آن استفاده می‌شود. اما در `decltype((value))`، عبارت داخل `decltype` دیگر نام بدون پرانتز متغیر محسوب نمی‌شود. از آنجا که `(value)` یک عبارت Lvalue است، نوع نتیجه `int&` خواهد بود.

این تفاوت ظریف یکی از رایج‌ترین منابع خطا در کدهایی است که از `decltype(auto)` استفاده می‌کنند.

### تأثیر `const` و Referenceها

قواعد `decltype` می‌توانند `const`، `volatile` و Referenceها را حفظ کنند. برای نمونه:

```
const int value = 42;

decltype(value) first = 10;
decltype((value)) second = value;
```

در این مثال:

- نوع `first` برابر `const int` است.
- نوع `second` برابر `const int&` است.

از آنجا که `value` یک Lvalue از نوع `const int` است، عبارت پرانتزدار `(value)` نیز به `const int&` منجر می‌شود.

این ویژگی برای نوشتن کد Generic که باید نوع و دسته‌بندی مقدار را دقیقاً حفظ کند، ضروری است.

## نحوه استفاده از `decltype(auto)` برای اعلان متغیر

در استاندارد ++C14، می‌توان از `decltype(auto)` برای استنتاج نوع متغیر از عبارت مقداردهی اولیه استفاده کرد.

```
int value = 42;
const int constantValue = 100;
int& reference = value;

decltype(auto) a = value;
decltype(auto) b = (value);
decltype(auto) c = constantValue;
decltype(auto) d = reference;
```

نوع هر متغیر به شرح زیر است:

| متغیر | عبارت مقداردهی اولیه | نوع نهایی   |
| ----- | -------------------- | ----------- |
| `a`   | `value`              | `int`       |
| `b`   | `(value)`            | `int&`      |
| `c`   | `constantValue`      | `const int` |
| `d`   | `reference`          | `int&`      |

در این مثال، پرانتزگذاری عبارت `value` باعث می‌شود که نوع متغیر `b` به Reference تبدیل شود. در مقابل، نام بدون پرانتز `reference` همچنان نوع اعلام‌شده آن، یعنی `int&`، را حفظ می‌کند.

### محدودیت‌های نحوی در اعلان متغیر

در استفاده از `decltype(auto)` باید توجه داشت که این قابلیت برای استنتاج نوع از یک عبارت منفرد طراحی شده است. برخلاف برخی کاربردهای `auto`، نمی‌توان چند متغیر با نوع‌های استنتاج‌شده مستقل را در یک اعلان مشترک با `decltype(auto)` تعریف کرد.

برای مثال، اعلان زیر معتبر نیست:

```
int x = 1;
int y = 2;

// Invalid declaration
// decltype(auto) a = x, b = y;
```

برای هر متغیر باید یک اعلان جداگانه نوشته شود.

همچنین، مانند `auto`، نوع متغیر باید از یک مقداردهی اولیه قابل استنتاج باشد؛ بنابراین اعلان بدون مقداردهی اولیه مجاز نیست:

```
// Invalid declaration
// decltype(auto) value;
```

### تفاوت مقداردهی اولیه مستقیم و پرانتزدار

برای درک بهتر رفتار این قابلیت، مثال زیر را در نظر بگیرید:

```
int value = 10;

decltype(auto) first = value;
decltype(auto) second(value);
decltype(auto) third{value};
```

در هر سه اعلان بالا، نوع استنتاج‌شده `int` است؛ زیرا عبارت یا مقداردهی اولیه، در هر سه مورد، به‌گونه‌ای است که قواعد `decltype` نوع `int` را نتیجه می‌دهند.

با این حال، نباید این نتیجه را به اعلان‌هایی تعمیم داد که در آن‌ها یک عبارت صریحاً داخل پرانتز قرار می‌گیرد. عبارت زیر به Reference منجر می‌شود:

```
decltype(auto) reference = (value);
```

نوع `reference` برابر `int&` خواهد بود.

نکته مهم این است که `decltype(auto)` برای اعلان‌های متغیر از قواعد `decltype` روی عبارت مقداردهی اولیه استفاده می‌کند؛ بنابراین، شکل دقیق عبارت بخشی از معنای برنامه است.

## کاربرد `decltype(auto)` در نوع بازگشتی تابع

یکی از مهم‌ترین کاربردهای این قابلیت، تعیین نوع بازگشتی تابع است.

در استاندارد ++C14، امکان استنتاج نوع بازگشتی با `auto` وجود دارد. با این حال، `auto` معمولاً Reference بودن نوع حاصل را حذف می‌کند؛ در حالی که `decltype(auto)` می‌تواند Reference را حفظ کند.

### مقایسه نوع بازگشتی `auto` و `decltype(auto)`

```
int globalValue = 42;

auto getValue() {
    return globalValue;
}

decltype(auto) getReference() {
    return (globalValue);
}
```

در این مثال:

- تابع `getValue` یک `int` برمی‌گرداند.
- تابع `getReference` یک `int&` برمی‌گرداند.

در تابع اول، نوع بازگشتی با قواعد `auto` استنتاج می‌شود و Reference بودن عبارت بازگشتی حفظ نمی‌شود. در تابع دوم، عبارت `(globalValue)` طبق قواعد `decltype` یک Lvalue است؛ بنابراین، نوع بازگشتی `int&` خواهد بود.

این تفاوت از نظر رفتار برنامه مهم است:

```
getValue() = 10;      // Invalid: the result is not a modifiable lvalue
getReference() = 10; // Valid: modifies globalValue
```

عبارت اول معتبر نیست، زیرا نتیجه `getValue()` یک Prvalue از نوع `int` است و نمی‌توان آن را به‌عنوان Lvalue قابل‌تغییر استفاده کرد. عبارت دوم معتبر است و مقدار `globalValue` را تغییر می‌دهد.

### اهمیت پرانتز در عبارت `return`

در توابعی که نوع بازگشتی آن‌ها `decltype(auto)` است، پرانتزگذاری عبارت `return` می‌تواند تفاوت اساسی ایجاد کند.

```
int value = 42;

decltype(auto) first() {
    return value;
}

decltype(auto) second() {
    return (value);
}
```

در این مثال، نوع بازگشتی تابع `first` برابر `int` و نوع بازگشتی تابع `second` برابر `int&` است.

علت این تفاوت دقیقاً همان قاعده ویژه `decltype` برای نام بدون پرانتز متغیر است. در تابع `first`، عبارت `return value;` نوع اعلام‌شده متغیر را نتیجه می‌دهد؛ اما در تابع `second`، عبارت `(value)` یک Lvalue است و نوع بازگشتی به `int&` تبدیل می‌شود.

بنابراین، افزودن یا حذف یک جفت پرانتز در چنین تابعی صرفاً یک تغییر ظاهری نیست؛ بلکه ممکن است قرارداد تابع و رفتار فراخواننده را تغییر دهد.

### شرایط استنتاج نوع بازگشتی

در تابعی که نوع بازگشتی آن با `decltype(auto)` مشخص شده است، نوع بازگشتی از عبارت‌های `return` و قواعد `decltype` تعیین می‌شود. در نتیجه، اگر چند مسیر بازگشت وجود داشته باشد، باید نوع‌های استنتاج‌شده با یکدیگر سازگار باشند.

برای مثال:

```
int value = 42;

decltype(auto) getValue(bool condition) {
    if (condition) {
        return value;
    }

    return 0;
}
```

این تابع معتبر است، زیرا هر دو مسیر نوع بازگشتی `int` را نتیجه می‌دهند.

اما در مثال زیر، یک مسیر نوع `int` و مسیر دیگر نوع `int&` را نتیجه می‌دهد:

```
int value = 42;

decltype(auto) invalidFunction(bool condition) {
    if (condition) {
        return value;
    }

    return (value);
}
```

این تابع معتبر نیست، زیرا نوع‌های بازگشتی استنتاج‌شده یکسان نیستند. هنگام استفاده از `decltype(auto)` باید تمام مسیرهای بازگشت را بررسی کرد، نه فقط مسیر معمول اجرای تابع را.

## کاربرد در توابع Generic و Wrapperها

یکی از کاربردهای حرفه‌ای `decltype(auto)`، نوشتن Wrapperهایی است که رفتار تابع اصلی را تا حد امکان حفظ می‌کنند.

فرض کنید تابعی دارید که نتیجه آن ممکن است مقدار مستقل یا Reference باشد. اگر یک تابع واسط بخواهد نتیجه را برگرداند، باید تصمیم بگیرد که آیا نوع دقیق نتیجه را حفظ کند یا همواره یک مقدار مستقل برگرداند.

### حفظ نوع بازگشتی تابع اصلی

در مثال زیر، یک Wrapper ساده با قابلیت حفظ نوع بازگشتی نشان داده شده است:

```
#include <utility>

template <typename F, typename... Args>
decltype(auto) invokeWrapper(F&& function, Args&&... args) {
    return std::forward<F>(function)(
        std::forward<Args>(args)...
    );
}
```

این تابع از `decltype(auto)` برای استنتاج نوع بازگشتی و از `std::forward` برای حفظ دسته‌بندی مقدار آرگومان‌ها استفاده می‌کند.

در این مثال، اگر تابع اصلی یک Lvalue از نوع `T` برگرداند، Wrapper نیز می‌تواند `T&` را حفظ کند. اگر نتیجه تابع اصلی یک مقدار مستقل باشد، نوع بازگشتی Wrapper نیز بر اساس همان عبارت استنتاج خواهد شد.

البته این کد یک Wrapper عمومی ساده است و جایگزین کامل `std::invoke` یا `std::invoke_result` در تمام شرایط نیست. در ++C17، امکانات استانداردی مانند `std::invoke` برای فراخوانی یکپارچه توابع، اشاره‌گرهای عضو و اشیای قابل‌فراخوانی معرفی شدند.

### حفظ Reference در دسترسی به اعضای یک شیء

فرض کنید می‌خواهید تابعی بنویسید که یک عضو از شیء را برگرداند و Reference بودن نتیجه را حفظ کند:

```
struct Data {
    int value = 42;
};

Data object;

decltype(auto) getMember() {
    return (object.value);
}
```

نوع بازگشتی تابع `getMember` برابر `int&` است. بنابراین، فراخواننده می‌تواند مقدار عضو را مستقیماً تغییر دهد:

```
getMember() = 100;
```

در مقابل، اگر عبارت بازگشتی بدون پرانتز نوشته شود، نتیجه متفاوت خواهد بود:

```
decltype(auto) getMemberCopy() {
    return object.value;
}
```

در این حالت، نوع بازگشتی `int` است و تغییر نتیجه تابع، عضو اصلی شیء را تغییر نمی‌دهد.

### کاربرد در توابع واسط برای کتابخانه‌ها

در کتابخانه‌های Generic، گاهی لازم است یک تابع واسط بدون تحمیل سیاست جدیدی برای تبدیل نوع، نتیجه تابع دیگری را منتقل کند. استفاده از `decltype(auto)` در این شرایط می‌تواند از کپی‌های غیرضروری جلوگیری کند و امکان حفظ Referenceها را فراهم سازد.

با این حال، این قابلیت نباید به‌صورت خودکار در تمام توابع واسط استفاده شود. اگر قرارداد کتابخانه برگرداندن یک مقدار مستقل است، استفاده از `auto` ممکن است انتخاب ساده‌تر و ایمن‌تری باشد.

## کاربرد در Lambda Expressionها

در استاندارد ++C14، امکان استفاده از `auto` برای نوع بازگشتی Lambda Expressionها به‌صورت استنتاجی فراهم است. همچنین می‌توان برای حفظ دقیق نوع نتیجه از `decltype(auto)` در trailing return type استفاده کرد.

### استنتاج نوع بازگشتی در Lambda

کد زیر یک Lambda را نشان می‌دهد که مقدار یک متغیر را برمی‌گرداند:

```
int value = 42;

auto getValue = [&]() {
    return value;
};

auto getReference = [&]() -> decltype(auto) {
    return (value);
};
```

در این مثال:

- نوع بازگشتی `getValue` برابر `int` است.
- نوع بازگشتی `getReference` برابر `int&` است.

استفاده از `decltype(auto)` در trailing return type باعث می‌شود نوع عبارت بازگشتی طبق قواعد `decltype` تعیین شود.

### انتخاب نوع بازگشتی مناسب برای Lambda

هنگام طراحی Lambda باید مشخص شود که آیا نتیجه باید یک کپی مستقل باشد یا Reference به داده اصلی را ارائه دهد.

```
int values[] = {10, 20, 30};

auto getCopy = [&]() {
    return values[0];
};

auto getReference = [&]() -> decltype(auto) {
    return (values[0]);
};
```

در تابع اول، نتیجه یک مقدار مستقل از نوع `int` است. در تابع دوم، نتیجه `int&` است و تغییر آن مقدار آرایه را تغییر می‌دهد.

این تفاوت برای Lambdaهایی که به‌عنوان Callback، Accessor یا بخشی از یک API عمومی استفاده می‌شوند، اهمیت ویژه‌ای دارد.

## تفاوت `decltype(auto)` با `auto` و `decltype`

برای انتخاب درست این قابلیت، باید تفاوت آن با دو سازوکار مرتبط را به‌صورت دقیق شناخت.

| ویژگی                  | `auto`                                         | `decltype`                               | `decltype(auto)`                |
| ---------------------- | ---------------------------------------------- | ---------------------------------------- | ------------------------------- |
| هدف اصلی               | استنتاج نوع با قواعد `auto`                    | تعیین نوع بر اساس قواعد `decltype`       | استنتاج نوع با قواعد `decltype` |
| اعلان متغیر            | بله                                            | بله                                      | بله                             |
| نوع بازگشتی تابع       | بله                                            | بله، با نوع صریح یا trailing return type | بله                             |
| حفظ Reference          | معمولاً حذف می‌شود، مگر با `auto&` یا `auto&&` | مطابق قواعد `decltype`                   | مطابق قواعد `decltype`          |
| حساسیت به پرانتز عبارت | در استنتاج معمولی خیر                          | بله                                      | بله                             |
| معرفی در استاندارد     | ++C11                                          | ++C11                                    | ++C14                           |

### تفاوت با `auto&` و `auto&&`

قابلیت `auto&` زمانی مناسب است که هدف، نگهداری Reference به یک Lvalue باشد. همچنین `auto&&` در بسیاری از زمینه‌های Generic Programming برای دریافت انواع مختلف دسته‌بندی مقدار به کار می‌رود.

```
int value = 42;

auto copy = value;
auto& lvalueReference = value;
auto&& forwardingReference = value;
decltype(auto) exactType = (value);
```

نوع متغیرها به این صورت است:

- `copy` از نوع `int` است.
- `lvalueReference` از نوع `int&` است.
- `forwardingReference` در این مثال از نوع `int&` است.
- `exactType` از نوع `int&` است.

در این مثال، `auto&&` به دلیل مقداردهی اولیه با یک Lvalue، به `int&` تبدیل می‌شود. این رفتار نتیجه قواعد Reference Collapsing است.

تفاوت اصلی آن است که `auto&` و `auto&&` نوع Reference را بر اساس نوع و دسته‌بندی مقداردهی اولیه و قواعد مربوط به `auto` تعیین می‌کنند؛ اما `decltype(auto)` از قواعد `decltype` استفاده می‌کند.

### تفاوت با `std::decay` و `std::remove_reference`

در برنامه‌نویسی Generic، گاهی هدف دقیقاً برعکس حفظ نوع است: ممکن است بخواهید Reference یا برخی Qualifierها را حذف کنید.

برای این منظور، ابزارهای Type Traits مانند `std::remove_reference` و `std::decay` کاربرد دارند. این ابزارها بخشی از Standard Library هستند، در حالی که `decltype(auto)` یک قابلیت زبانی است.

```
#include <type_traits>

int value = 42;
int& reference = value;

using ExactType = decltype(reference);
using ValueType = std::remove_reference_t<ExactType>;
using DecayedType = std::decay_t<decltype(reference)>;
```

در این مثال:

- `ExactType` برابر `int&` است.
- `ValueType` برابر `int` است.
- `DecayedType` نیز برابر `int` است.

نوع‌های `std::remove_reference_t` و `std::decay_t` در ++C14 معرفی شدند. استفاده از آن‌ها زمانی مناسب است که تبدیل نوع بخشی از طراحی باشد، نه اینکه صرفاً بخواهیم نوع عبارت را بدون تغییر حفظ کنیم.

## ارتباط با Value Category و Reference Collapsing

درک کامل `decltype(auto)` بدون شناخت Value Categoryها دشوار است؛ زیرا نتیجه `decltype` برای عبارت‌های معمولی به دسته‌بندی مقدار وابسته است.

### شناخت Lvalue، Xvalue و Prvalue

در ++C، عبارت‌ها بر اساس Value Category به دسته‌هایی تقسیم می‌شوند که برای مدیریت Referenceها و استنتاج نوع اهمیت دارند.

- Lvalue: عبارتی که یک هویت قابل‌شناسایی دارد و به‌طور معمول می‌توان به آن از طریق Lvalue Reference اشاره کرد؛ مانند یک متغیر نام‌گذاری‌شده.
- Prvalue: عبارتی که معمولاً برای محاسبه یک مقدار جدید استفاده می‌شود؛ مانند یک عدد صحیح ثابت.
- Xvalue: عبارتی که به یک شیء قابل‌شناسایی اشاره می‌کند، اما نشان‌دهنده قابلیت انتقال منابع آن است؛ مانند عبارتی که با `std::move` تولید می‌شود.

در این دسته‌بندی، Xvalue و Lvalue هر دو جزو دسته کلی Glvalue هستند؛ در حالی که Xvalue و Prvalue هر دو جزو دسته کلی Rvalue محسوب می‌شوند.

### تأثیر Value Category بر نوع حاصل

```
#include <utility>

int value = 42;

decltype(value) a = value;
decltype((value)) b = value;
decltype(std::move(value)) c = std::move(value);
```

نوع متغیرها به این صورت است:

- نوع `a` برابر `int` است.
- نوع `b` برابر `int&` است.
- نوع `c` برابر `int&&` است.

علت آن است که `value` بدون پرانتز از قاعده ویژه نام متغیر پیروی می‌کند؛ `(value)` یک Lvalue است؛ و `std::move(value)` یک Xvalue تولید می‌کند.

نکته مهم این است که `std::move` خودش شیء را جابه‌جا نمی‌کند؛ بلکه عبارت را به‌گونه‌ای تبدیل می‌کند که عملیات مناسب Move Semantics در صورت وجود و انتخاب شدن توسط قواعد زبان، امکان‌پذیر باشد.

### مفهوم Reference Collapsing

در Templateها و اعلان‌های Generic، ممکن است ترکیب Referenceها به نوع‌هایی مانند `T& &` یا `T&& &` منجر شود. قواعد زبان این ترکیب‌ها را به نوع‌های معتبر نهایی تبدیل می‌کنند که به آن Reference Collapsing گفته می‌شود.

قاعده کلی این است که اگر در ترکیب Referenceها حداقل یک Lvalue Reference وجود داشته باشد، نوع نهایی Lvalue Reference خواهد بود. تنها ترکیب `T&& &&` به `T&&` منجر می‌شود.

این قواعد در فهم رفتار `auto&&`، Forwarding Referenceها و توابع Generic اهمیت زیادی دارند؛ هرچند استنتاج `decltype(auto)` مستقیماً از همین قواعد ساده برای تعیین نوع اولیه استفاده نمی‌کند، نوع‌های Reference حاصل می‌توانند در اعلان‌های بعدی با این قواعد ترکیب شوند.

## محدودیت‌ها و خطرهای کاربردی

قابلیت `decltype(auto)` امکان کنترل دقیق نوع را فراهم می‌کند، اما استفاده نادرست از آن می‌تواند به خطاهای کامپایل یا مشکلات طول عمر اشیا منجر شود.

### خطر بازگرداندن Reference به متغیر محلی

یکی از مهم‌ترین خطاها، بازگرداندن Reference به متغیر محلی تابع است.

```
decltype(auto) dangerousFunction() {
    int localValue = 42;
    return (localValue);
}
```

نوع بازگشتی این تابع `int&` است؛ اما `localValue` پس از پایان اجرای تابع از بین می‌رود. بنابراین، Reference بازگشتی آویزان (Dangling Reference) خواهد بود و استفاده از آن رفتار تعریف‌نشده (Undefined Behavior) ایجاد می‌کند.

راه‌حل این است که در صورت نیاز به بازگرداندن مقدار، نوع بازگشتی را به‌صورت `auto` یا `int` انتخاب کنید:

```
auto safeFunction() {
    int localValue = 42;
    return localValue;
}
```

در این مثال، مقدار به‌صورت مستقل برگردانده می‌شود.

### خطر بازگرداندن Reference از یک Temporary

گاهی تابعی Reference به داده‌ای برمی‌گرداند که از یک Temporary به دست آمده است. برای مثال:

```
#include <string>

decltype(auto) dangerousString() {
    return std::string{"temporary"};
}
```

در این مثال، نوع بازگشتی `std::string` است، نه Reference؛ زیرا عبارت بازگشتی یک Prvalue است. بنابراین، این تابع به‌خودی‌خود مشکلی از نظر Dangling Reference ندارد.

اما اگر Reference به زیرشیء یک Temporary بازگردانده شود، وضعیت متفاوت خواهد بود:

```
#include <string>

decltype(auto) dangerousCharacter() {
    return (std::string{"temporary"}[0]);
}
```

در این مثال، عبارت داخل پرانتز یک Lvalue از نوع `char` است؛ بنابراین نوع بازگشتی `char&` خواهد بود. با پایان اجرای تابع، رشته موقت از بین می‌رود و Reference بازگشتی آویزان می‌شود.

این نمونه نشان می‌دهد که بررسی نوع بازگشتی به‌تنهایی کافی نیست؛ طول عمر شیئی که Reference به آن اشاره می‌کند نیز باید بررسی شود.

### خطر تغییر ناخواسته قرارداد تابع

فرض کنید تابعی قبلاً یک مقدار مستقل برمی‌گردانده است و برای کوتاه‌تر شدن کد، نوع بازگشتی آن به `decltype(auto)` تغییر داده می‌شود. اگر عبارت بازگشتی پرانتزگذاری شود، ممکن است نوع بازگشتی از `T` به `T&` تغییر کند.

این تغییر می‌تواند پیامدهای مهمی داشته باشد:

- فراخواننده ممکن است بتواند شیء داخلی را تغییر دهد.
- طول عمر شیء مورد اشاره به قرارداد تابع وابسته می‌شود.
- استفاده از نتیجه تابع در عبارت‌های دیگر ممکن است رفتار متفاوتی پیدا کند.
- تغییر نوع بازگشتی در API عمومی می‌تواند سازگاری کدهای وابسته را مختل کند.

به همین دلیل، `decltype(auto)` باید با هدف روشن حفظ نوع دقیق استفاده شود، نه صرفاً به‌عنوان جایگزینی عمومی برای `auto`.

## نکات پیشرفته و حالت‌های مرزی

### محدودیت در استنتاج از Initializer List

قابلیت `decltype(auto)` برای استنتاج نوع از یک Initializer List مستقل با آکولادهای مستقیم، مانند `auto` عمل نمی‌کند و نمی‌توان آن را به‌صورت عمومی برای استنتاج نوع `std::initializer_list` به کار برد.

برای مثال:

```
// Invalid: decltype(auto) cannot deduce from a braced-init-list
// decltype(auto) values = {1, 2, 3};
```

در این حالت، عبارت داخل آکولادها نوع مستقلی ندارد که بتوان قواعد `decltype` را مستقیماً روی آن اعمال کرد.

اگر هدف ایجاد یک مجموعه از اعداد صحیح است، می‌توان نوع را صریحاً مشخص کرد:

```
#include <initializer_list>

std::initializer_list<int> values = {1, 2, 3};
```

همچنین، اگر هدف استنتاج نوع از یک مقدار منفرد باشد، می‌توان از مقداردهی اولیه معمولی استفاده کرد:

```
decltype(auto) value = 42;
```

### محدودیت در بازگرداندن Bit-field

در ++C، اعضای Bit-field رفتار خاصی دارند. اگر یک عبارت به Bit-field اشاره کند، نمی‌توان آن را مانند یک شیء معمولی به Reference متصل کرد.

برای مثال:

```
struct Flags {
    unsigned int enabled : 1;
};

Flags flags{};

decltype(auto) getFlag() {
    return (flags.enabled);
}
```

این تابع معتبر نیست؛ زیرا عبارت `(flags.enabled)` یک Lvalue از نوع Bit-field است و قواعد `decltype` نوع بازگشتی را به `unsigned int&` تبدیل می‌کنند. اما ایجاد Reference به Bit-field مجاز نیست.

در چنین مواردی، اگر هدف صرفاً خواندن مقدار عضو باشد، بهتر است مقدار را به‌صورت مستقل برگردانید:

```
unsigned int getFlagValue() {
    return flags.enabled;
}
```

این محدودیت نشان می‌دهد که حتی اگر نوع استنتاج‌شده از نظر ظاهری مناسب به نظر برسد، محدودیت‌های زبان در زمینه Referenceها همچنان اعمال می‌شوند.

### کاربرد همراه با `constexpr`

قابلیت `decltype(auto)` می‌تواند در توابع `constexpr` نیز استفاده شود؛ زیرا استنتاج نوع بازگشتی و ارزیابی ثابت دو مفهوم مستقل هستند.

```
constexpr int calculate() {
    return 42;
}

constexpr decltype(auto) getResult() {
    return calculate();
}
```

در این مثال، نوع بازگشتی `getResult` برابر `int` است و تابع می‌تواند در زمینه‌های نیازمند Constant Expression استفاده شود.

با این حال، `constexpr` بودن تابع به‌تنهایی تضمین نمی‌کند که تمام فراخوانی‌های آن در زمان کامپایل ارزیابی شوند. این موضوع به شرایط فراخوانی و قواعد Constant Expression وابسته است.

### استفاده در Templateها و محدودیت‌های تشخیص خطا

در Templateها، نوع بازگشتی `decltype(auto)` ممکن است به نوع آرگومان‌های Template، نوع نتیجه یک تابع دیگر یا Value Category یک عبارت وابسته باشد.

```
template <typename T>
decltype(auto) getValue(T& value) {
    return (value);
}
```

در این مثال، نوع بازگشتی تابع برای `T = int` برابر `int&` و برای `T = const int` برابر `const int&` خواهد بود.

این رفتار باعث می‌شود تابع بتواند Reference بودن و `const` بودن آرگومان را حفظ کند.

اما باید توجه داشت که اگر نوع بازگشتی به یک عبارت نامعتبر وابسته باشد، ممکن است نمونه‌سازی Template با خطای کامپایل مواجه شود. استنتاج نوع بازگشتی، به‌خودی‌خود، یک سازوکار عمومی برای تبدیل تمام خطاهای نوع به SFINAE نیست؛ به‌خصوص در مواردی که بدنه تابع برای تعیین نوع بازگشتی باید نمونه‌سازی شود.

در طراحی Templateهای عمومی، بهتر است محدودیت‌های نوعی و شرایط معتبر بودن عملیات به‌صورت روشن تعریف شوند. در ++C20، امکاناتی مانند Concepts و Constraints می‌توانند بیان این محدودیت‌ها را ساده‌تر کنند.

## راهنمای انتخاب در طراحی API

هنگام انتخاب میان `auto` و `decltype(auto)`، بهتر است ابتدا مشخص شود که تابع یا متغیر چه قراردادی باید داشته باشد.

| نیاز طراحی                               | انتخاب پیشنهادی                                   |
| ---------------------------------------- | ------------------------------------------------- |
| تولید یک مقدار مستقل                     | `auto` یا نوع صریح                                |
| حفظ نوع دقیق عبارت بازگشتی               | `decltype(auto)`                                  |
| دریافت Lvalue به‌صورت Reference          | `auto&`                                           |
| دریافت عمومی مقادیر با قابلیت Forwarding | `auto&&` یا پارامتر Template مناسب                |
| حفظ Reference در Wrapper عمومی           | معمولاً `decltype(auto)` همراه با Forwarding صحیح |
| حذف Reference از یک نوع در Template      | `std::remove_reference_t`                         |
| جلوگیری از افشای Reference به داده داخلی | معمولاً بازگرداندن مقدار مستقل                    |

این جدول یک راهنمای طراحی است، نه مجموعه‌ای از قواعد مطلق. برای مثال، بازگرداندن Reference از یک Container ممکن است در یک API کارآمد و مناسب باشد، اما تنها زمانی که طول عمر Container و قرارداد دسترسی به آن به‌درستی مدیریت شده باشد.

### ملاحظات مربوط به کارایی

استفاده از `decltype(auto)` لزوماً باعث افزایش کارایی نمی‌شود. مزیت اصلی آن حفظ نوع دقیق و جلوگیری از تغییر ناخواسته رفتار عبارت است.

اگر نتیجه تابع یک مقدار مستقل باشد، استفاده از `auto` معمولاً همان نتیجه معنایی را فراهم می‌کند. همچنین، در ++C11 و استانداردهای بعدی، قواعد Move Semantics و Return Value Optimization می‌توانند هزینه بازگرداندن مقادیر را کاهش دهند؛ بنابراین، نباید صرفاً برای جلوگیری از یک کپی فرضی، Reference بازگرداند.

در طراحی حرفه‌ای، ابتدا باید مالکیت داده، طول عمر اشیا و قرارداد API مشخص شوند و سپس درباره حفظ Reference تصمیم‌گیری شود.

## بررسی چند مثال کاربردی

### مثال حفظ Reference در یک Accessor

در این مثال، یک تابع Generic برای دسترسی به عضو یک شیء تعریف می‌شود:

```
struct User {
    int age = 30;
};

template <typename T>
decltype(auto) getAge(T& user) {
    return (user.age);
}
```

این تابع برای یک شیء قابل‌تغییر، Reference قابل‌تغییر برمی‌گرداند و برای یک شیء `const`، Reference از نوع `const int&` تولید می‌کند.

```
User user;
getAge(user) = 40;

const User readOnlyUser{};
int age = getAge(readOnlyUser);
```

در این مثال، تغییر نتیجه فراخوانی اول، عضو `age` را تغییر می‌دهد؛ در حالی که فراخوانی دوم فقط مقدار را می‌خواند.

نکته طراحی این است که این تابع صرفاً برای نوع‌هایی مناسب است که عضو `age` معتبر و قابل‌دسترسی دارند. در یک کتابخانه عمومی، باید محدودیت‌های مربوط به نوع ورودی نیز به‌روشنی مشخص شوند.

### مثال ساخت Wrapper برای حفظ دسته‌بندی نتیجه

در مثال زیر، Wrapper نتیجه یک تابع را بدون تحمیل تبدیل نوع جدید برمی‌گرداند:

```
#include <utility>

template <typename F, typename... Args>
decltype(auto) call(F&& function, Args&&... args) {
    return std::forward<F>(function)(
        std::forward<Args>(args)...
    );
}

int value = 42;

int& getReference() {
    return value;
}

int main() {
    call(getReference) = 100;
}
```

در این کد، تابع `call` یک Lvalue Reference از نوع `int&` برمی‌گرداند؛ بنابراین، انتساب به نتیجه فراخوانی معتبر است و مقدار `value` تغییر می‌کند.

این مثال کاربرد مهمی از ترکیب `decltype(auto)` و Perfect Forwarding را نشان می‌دهد. هرچند برای پیاده‌سازی یک Wrapper واقعی در کتابخانه عمومی، باید مواردی مانند فراخوانی توابع عضو، Overloadها، محدودیت‌های قابل‌فراخوانی بودن و سازگاری با قواعد `std::invoke` نیز بررسی شوند.

## جمع‌بندی نهایی

قابلیت `decltype(auto)` در استاندارد ++C14 ابزاری دقیق برای استنتاج نوع بر اساس قواعد `decltype` است. این قابلیت به‌ویژه زمانی ارزشمند است که حفظ Referenceها، Qualifierها و رفتار دقیق عبارت بازگشتی اهمیت داشته باشد.

مهم‌ترین نکات کاربردی عبارت‌اند از:

- استفاده از `decltype(auto)` به معنای استنتاج نوع با قواعد `decltype` است، نه قواعد معمول `auto`.
- پرانتزگذاری عبارت می‌تواند نوع بازگشتی را از `T` به `T&` تغییر دهد.
- این قابلیت در توابع Generic، Wrapperها، Lambda Expressionها و Accessorها کاربرد دارد.
- استفاده نادرست از آن ممکن است به بازگرداندن Dangling Reference یا تغییر ناخواسته قرارداد API منجر شود.
- برای بازگرداندن یک مقدار مستقل، `auto` اغلب ساده‌تر و مناسب‌تر است.
- انتخاب صحیح باید بر اساس مالکیت، طول عمر شیء، Value Category و نیاز واقعی به حفظ Reference انجام شود.

در نهایت، `decltype(auto)` زمانی بهترین انتخاب است که حفظ دقیق نوع عبارت بخشی از طراحی باشد. اگر این ویژگی ضروری نیست، استفاده از نوع بازگشتی ساده‌تر معمولاً خوانایی و قابلیت نگهداری کد را افزایش می‌دهد.
