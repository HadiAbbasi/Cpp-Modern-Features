# معرفی Binary Literals در ++C14

## مقدمه

نمایش اعداد در مبنای دودویی (Binary) یکی از مفاهیم پایه‌ای در برنامه‌نویسی سیستم‌محور، پردازش بیت‌ها، طراحی الگوریتم‌ها و کار با داده‌های سطح پایین است. با وجود اینکه کامپیوترها اطلاعات را در سطح سخت‌افزار به‌صورت بیت‌ها پردازش می‌کنند، برنامه‌نویسان معمولاً اعداد صحیح را در کدهای خود با نمایش ده‌دهی (Decimal) می‌نویسند.

برای مثال، عدد ده‌دهی ۱۰ در مبنای دودویی به‌شکل `1010` نمایش داده می‌شود. پیش از استاندارد ++C14، زبان ++C از Literalهای عددی با مبنای ده‌دهی، هشت‌هشتی (Octal) و شانزده‌شانزدهی (Hexadecimal) پشتیبانی می‌کرد، اما نوشتن مستقیم یک عدد صحیح با مبنای دودویی به‌صورت استاندارد امکان‌پذیر نبود.

استاندارد ++C14 این محدودیت را برطرف کرد و امکان تعریف Binary Literal را با پیشوند `0b` یا `0B` فراهم ساخت. این قابلیت باعث می‌شود مقادیر دودویی مستقیماً در کد نوشته شوند و درک عملیات بیت‌به‌بیت ساده‌تر شود.

## مفهوم Binary Literal

یک Literal در ++C مقداری است که مستقیماً در کد منبع نوشته می‌شود؛ برای مثال، `42`، `0x2A` و `3.14` همگی Literal هستند.

قابلیت Binary Literal اجازه می‌دهد یک عدد صحیح را با استفاده از ارقام دودویی `0` و `1` تعریف کنیم. در این روش، پیشوند `0b` یا `0B` مشخص می‌کند که عدد پس از آن در مبنای دو نوشته شده است.

```cpp
#include <iostream>

int main()
{
    int decimal = 10;
    int binary = 0b1010;
    int hexadecimal = 0xA;
    int octal = 012;

    std::cout << decimal << '\n';
    std::cout << binary << '\n';
    std::cout << hexadecimal << '\n';
    std::cout << octal << '\n';
}
```

خروجی برنامه به این صورت است:

```text
10
10
10
10
```

در این مثال، هر چهار Literal به یک مقدار عددی اشاره می‌کنند، اما مبنای نوشتاری آن‌ها متفاوت است.

نکته مهم این است که مبنای نوشتاری Literal، نوع داده یا مقدار ذخیره‌شده را به‌تنهایی تعیین نمی‌کند. برای مثال، `0b1010` یک Literal عدد صحیح است که مقدار عددی ده‌دهی آن برابر با ۱۰ است؛ این Literal به معنای ذخیره‌سازی یک رشته شامل کاراکترهای `1`، `0`، `1` و `0` نیست.

## نحوه نوشتن Binary Literal

### استفاده از پیشوندهای دودویی

در ++C14 می‌توان از دو پیشوند زیر استفاده کرد:

```cpp
int a = 0b1010;
int b = 0B1010;
```

هر دو عبارت معتبر هستند و مقدار عددی ۱۰ را تولید می‌کنند.

پیشوند باید مستقیماً در ابتدای نمایش عدد قرار بگیرد. استفاده از حروف کوچک یا بزرگ تفاوتی در معنا ایجاد نمی‌کند.

### قواعد ارقام مجاز

در بخش دودویی Literal فقط ارقام `0` و `1` مجاز هستند.

```cpp
int a = 0b0;
int b = 0b1;
int c = 0b101;
int d = 0b11111111;
```

اما نمونه‌های زیر معتبر نیستند:

```cpp
// Invalid binary literals
// int a = 0b102;
// int b = 0b1202;
// int c = 0b2;
```

در این نمونه‌ها، وجود رقم `2` باعث می‌شود عبارت یک Binary Literal معتبر نباشد.

همچنین پیشوند دودویی باید حداقل با یک رقم معتبر همراه باشد؛ بنابراین `0b` به‌تنهایی یک عدد کامل نیست.

### استفاده از جداکننده ارقام

استاندارد ++C14 قابلیت دیگری به نام Digit Separator را نیز معرفی کرد. با استفاده از علامت `'` می‌توان ارقام یک Literal را به گروه‌های خواناتر تقسیم کرد.

```cpp
int flags = 0b1101'0010;
int mask = 0b1111'0000;
int value = 0b1010'1010'0101'0101;
```

این جداکننده‌ها صرفاً برای خوانایی هستند و هیچ تأثیری بر مقدار عددی ندارند.

برای مثال، دو عبارت زیر مقدار یکسانی دارند:

```cpp
int a = 0b11010010;
int b = 0b1101'0010;
```

این قابلیت به‌خصوص هنگام نوشتن Maskها، الگوهای بیتی و مقادیر دودویی طولانی مفید است.

توجه کنید که جداکننده باید بین ارقام قرار بگیرد و نمی‌توان آن را به‌جای پیشوند یا به‌عنوان بخشی مستقل از عدد به کار برد.

## تبدیل Binary Literal به مقدار عددی

### محاسبه مقدار دودویی

هر رقم در مبنای دو بر اساس توان متناظر با جایگاه خود وزن دارد. از سمت راست، وزن‌ها به‌ترتیب \(2^0\)، \(2^1\)، \(2^2\) و به همین ترتیب افزایش می‌یابند.

برای مثال، مقدار `0b101101` از محاسبه زیر به دست می‌آید:

\[
1 \times 2^5 +
0 \times 2^4 +
1 \times 2^3 +
1 \times 2^2 +
0 \times 2^1 +
1 \times 2^0
= 45
\]

بنابراین مقدار این Literal برابر با ۴۵ در مبنای ده‌دهی است.

### تفاوت نمایش عدد با نوع داده

پیشوند `0b` صرفاً مبنای نوشتاری عدد را مشخص می‌کند. نوع عددی حاصل همچنان بر اساس قواعد تعیین نوع Integer Literal در زبان ++C مشخص می‌شود.

برای مثال:

```cpp
auto value = 0b1010;
```

نوع `value` برابر با `int` است، زیرا این مقدار در نخستین نوع مناسب از فهرست انواع نامزد برای یک Integer Literal دودویی قرار می‌گیرد که بتواند مقدار آن را نمایش دهد.

در نتیجه، نوشتن یک عدد با مبنای دودویی به معنای انتخاب خودکار `unsigned int` یا یک نوع مخصوص بیت‌ها نیست.

## قواعد تعیین نوع Binary Literal

یکی از نکات مهم در کار حرفه‌ای با Binary Literal، شناخت قواعد تعیین نوع Integer Literal است.

در ++C، نوع Literalهای عدد صحیح بدون پسوند به مقدار عددی و فهرست انواع نامزد وابسته است. برای Literalهای دودویی، این فهرست از انواع صحیح استاندارد زیر تشکیل می‌شود:

- `int`
- `unsigned int`
- `long int`
- `unsigned long int`
- `long long int`
- `unsigned long long int`

کامپایلر این فهرست را به‌ترتیب بررسی می‌کند و نخستین نوعی را انتخاب می‌کند که بتواند مقدار Literal را نمایش دهد.

برای مثال:

```cpp
auto a = 0b1010;
auto b = 0b11111111;
```

هر دو مقدار به‌راحتی در `int` جا می‌شوند؛ بنابراین نوع استنباط‌شده برای هر دو متغیر `int` است.

اما اگر مقدار Literal از محدوده `int` فراتر برود، نوع مناسب بعدی از فهرست بررسی می‌شود. این رفتار به پیاده‌سازی و محدوده انواع صحیح پشتیبانی‌شده وابسته است.

### استفاده از پسوندهای عددی

مانند سایر Integer Literalها، برای Binary Literal نیز می‌توان از پسوندهایی مانند `U`، `L` و `LL` استفاده کرد.

```cpp
auto a = 0b1010U;
auto b = 0b1010L;
auto c = 0b1010LL;
auto d = 0b1010ULL;
```

نوع این متغیرها به‌ترتیب از قواعد مربوط به پسوندهای `U`، `L`، `LL` و ترکیب `ULL` پیروی می‌کند.

| پسوند | مفهوم |
|---|---|
| `U` | انتخاب نوع بدون علامت |
| `L` | انتخاب نوع با پسوند `long` |
| `LL` | انتخاب نوع با پسوند `long long` |
| `ULL` | انتخاب نوع بدون علامت با پسوند `long long` |

پسوندها می‌توانند به انتخاب نوع مناسب کمک کنند، اما استفاده از آن‌ها به‌تنهایی تضمین نمی‌کند که هر مقدار دلخواه در نوع انتخاب‌شده جا شود.

برای مثال، اگر مقدار Literal در محدوده نوع موردنیاز نباشد، ممکن است برنامه با خطای ترجمه مواجه شود.

## کاربرد Binary Literal در عملیات بیت‌به‌بیت

یکی از مهم‌ترین کاربردهای Binary Literal، ساده‌تر کردن کار با عملگرهای Bitwise است. این عملگرها روی نمایش بیتی مقادیر صحیح کار می‌کنند و در بسیاری از بخش‌های برنامه‌نویسی سطح پایین کاربرد دارند.

### عملگر AND برای استخراج بیت‌ها

عملگر `&` زمانی نتیجه یک را در هر جایگاه تولید می‌کند که هر دو بیت متناظر یک باشند.

```cpp
#include <iostream>

int main()
{
    unsigned int value = 0b11010110;
    unsigned int mask = 0b00001111;

    unsigned int result = value & mask;

    std::cout << result << '\n';
}
```

خروجی برنامه برابر با ۶ است، زیرا Mask چهار بیت کم‌ارزش را حفظ می‌کند و بقیه بیت‌ها را صفر می‌کند.

```text
6
```

استفاده از Binary Literal در چنین مثال‌هایی باعث می‌شود ساختار Mask به‌صورت مستقیم قابل مشاهده باشد.

### عملگر OR برای فعال‌کردن بیت‌ها

عملگر `|` زمانی بیت نتیجه را یک می‌کند که حداقل یکی از دو بیت متناظر یک باشد.

```cpp
unsigned int flags = 0b00000001;
unsigned int readPermission = 0b00000100;

flags |= readPermission;
```

پس از اجرای این عملیات، بیت متناظر با مجوز موردنظر فعال می‌شود، بدون آنکه سایر بیت‌های یک در `flags` تغییر کنند.

### عملگر XOR برای تغییر وضعیت بیت‌ها

عملگر `^` زمانی بیت نتیجه را یک می‌کند که دو بیت متناظر متفاوت باشند.

```cpp
unsigned int flags = 0b00000101;
unsigned int mask = 0b00000100;

flags ^= mask;
```

در این مثال، بیت سوم از سمت راست تغییر وضعیت می‌دهد؛ یعنی اگر صفر باشد یک می‌شود و اگر یک باشد صفر می‌شود.

### عملگر NOT برای معکوس‌کردن بیت‌ها

عملگر `~` تمام بیت‌های مقدار صحیح را معکوس می‌کند.

```cpp
unsigned int value = 0b00001111;
unsigned int result = ~value;
```

نکته مهم این است که نتیجه این عمل الزاماً همان تعداد بیت‌هایی را ندارد که در Literal نوشته شده‌اند. عملگر `~` روی مقدار با نوع صحیح واقعی آن عمل می‌کند و قواعد Integer Promotion نیز ممکن است دخالت داشته باشند.

به همین دلیل، نباید فرض کرد که معکوس‌کردن `0b00001111` همیشه به `0b11110000` منجر می‌شود. این نتیجه فقط در صورتی قابل انتظار است که عرض موردنظر و نوع داده به‌طور مشخص محدود شده باشند.

## تعریف و استفاده از Bit Mask

یک Bit Mask الگویی از بیت‌ها است که برای بررسی، فعال‌کردن، غیرفعال‌کردن یا تغییر وضعیت بیت‌های خاص استفاده می‌شود.

Binary Literal نوشتن این الگوها را خواناتر می‌کند.

```cpp
#include <iostream>

int main()
{
    constexpr unsigned int Read  = 0b0001;
    constexpr unsigned int Write = 0b0010;
    constexpr unsigned int Exec  = 0b0100;

    unsigned int permissions = Read | Exec;

    bool canRead = (permissions & Read) != 0;
    bool canWrite = (permissions & Write) != 0;
    bool canExecute = (permissions & Exec) != 0;

    std::cout << canRead << '\n';
    std::cout << canWrite << '\n';
    std::cout << canExecute << '\n';
}
```

خروجی برنامه به صورت زیر است:

```text
1
0
1
```

در این مثال، هر مجوز به یک بیت مستقل اختصاص داده شده است. با ترکیب مجوزها از طریق `|` می‌توان چند قابلیت را در یک متغیر ذخیره کرد.

این روش در موارد زیر مفید است:

- مدیریت مجوزها و ویژگی‌ها
- نگهداری مجموعه‌ای از گزینه‌های مستقل
- پیاده‌سازی پروتکل‌های ارتباطی
- پردازش داده‌های باینری
- مدیریت وضعیت‌های متعدد در یک مقدار صحیح

برای طراحی حرفه‌ای، باید اطمینان حاصل کرد که هر Flag از بیت مستقل خود استفاده می‌کند و نوع داده انتخاب‌شده ظرفیت کافی برای تعداد Flagها را دارد.

## کاربرد Binary Literal در بررسی و تغییر بیت‌های مشخص

در بسیاری از الگوریتم‌ها، لازم است وضعیت یک بیت مشخص بررسی یا تغییر داده شود. برای این منظور می‌توان از Shift Operatorها و Binary Literalها استفاده کرد.

### بررسی وضعیت یک بیت

```cpp
bool isBitSet(unsigned int value, unsigned int position)
{
    return (value & (1u << position)) != 0;
}
```

این تابع بررسی می‌کند که آیا بیت مشخص‌شده در مقدار ورودی برابر با یک است یا خیر.

نکته مهم این است که مقدار `position` باید در محدوده معتبر نوع مورد استفاده قرار داشته باشد. در غیر این صورت، رفتار Shift می‌تواند تعریف‌نشده باشد.

### فعال‌کردن یک بیت

```cpp
unsigned int setBit(unsigned int value, unsigned int position)
{
    return value | (1u << position);
}
```

در این تابع، عملگر `|` بیت موردنظر را فعال می‌کند و سایر بیت‌ها را بدون تغییر نگه می‌دارد.

### غیرفعال‌کردن یک بیت

```cpp
unsigned int clearBit(unsigned int value, unsigned int position)
{
    return value & ~(1u << position);
}
```

در این روش، ابتدا Mask معکوس می‌شود و سپس با مقدار ورودی AND می‌شود تا بیت موردنظر صفر شود.

### تغییر وضعیت یک بیت

```cpp
unsigned int toggleBit(unsigned int value, unsigned int position)
{
    return value ^ (1u << position);
}
```

استفاده از Shift برای ساخت Mask زمانی مناسب است که موقعیت بیت در زمان اجرا مشخص شود. در مقابل، اگر الگوی بیت ثابت و از قبل مشخص باشد، نوشتن مستقیم Binary Literal ممکن است خواناتر باشد.

## مقایسه Binary Literal با Hexadecimal Literal

در ++C، علاوه بر نمایش دودویی، امکان نوشتن Literalهای شانزده‌شانزدهی نیز وجود دارد. این دو روش از نظر مقدار عددی معادل هستند، اما در خوانایی و کاربرد تفاوت دارند.

| ویژگی | Binary Literal | Hexadecimal Literal |
|---|---|---|
| پیشوند | `0b` یا `0B` | `0x` یا `0X` |
| ارقام | `0` و `1` | `0` تا `9` و `A` تا `F` |
| خوانایی بیت‌ها | هر بیت مستقیماً قابل مشاهده است | هر رقم معادل چهار بیت است |
| مناسب برای | Maskهای کوچک و الگوهای بیت‌محور | مقادیر بزرگ، آدرس‌ها و داده‌های باینری |
| طول نمایش | معمولاً طولانی‌تر | معمولاً کوتاه‌تر |

برای مثال، دو Literal زیر مقدار یکسانی دارند:

```cpp
unsigned int binary = 0b1111111111111111;
unsigned int hexadecimal = 0xFFFF;
```

مقدار هر دو برابر با ۶۵۵۳۵ است.

برای الگویی که باید بیت‌های مشخصی را به‌وضوح نشان دهد، نمایش دودویی معمولاً مناسب‌تر است. اما برای مقادیر بزرگ‌تر، نمایش شانزده‌شانزدهی می‌تواند فشرده‌تر و خواناتر باشد.

در نهایت، انتخاب مبنا باید براساس هدف کد و خوانایی آن انجام شود، نه صرفاً براساس کوتاه‌تر بودن Literal.

## محدودیت‌های Binary Literal

### محدودیت در نوع داده

Binary Literal نوع داده‌ای مستقل ایجاد نمی‌کند. برای ذخیره مقدار همچنان باید از انواع صحیح استاندارد یا انواع مناسب دیگر استفاده کرد.

برای مثال، اگر هدف نگهداری یک مقدار ۸ بیتی باشد، استفاده از `std::uint8_t` در صورت وجود این نوع در پیاده‌سازی می‌تواند انتخاب مناسبی باشد.

```cpp
#include <cstdint>

std::uint8_t value = 0b11111111;
```

البته وجود `std::uint8_t` در همه پیاده‌سازی‌ها تضمین نشده است؛ زیرا این نوع تنها زمانی تعریف می‌شود که پیاده‌سازی یک نوع صحیح بدون علامت با دقیقاً هشت بیت و بدون بیت Padding داشته باشد.

همچنین اگر هدف نگهداری یک الگوی بیتی با عرض ثابت باشد، باید تبدیل‌ها و عملیات عددی را با توجه به قواعد ارتقای انواع صحیح و محدوده نوع مقصد بررسی کرد.

### محدودیت در نمایش رشته‌ای

نوشتن `0b1010` به معنای ساخت یک رشته از کاراکترهای دودویی نیست. این عبارت یک مقدار عددی است.

اگر هدف تولید نمایش متنی یک عدد در مبنای دو باشد، باید از الگوریتم یا ابزار مناسبی برای تبدیل مقدار عددی به رشته استفاده کرد. قابلیت Binary Literal تنها برای نوشتن مقدار ثابت در کد منبع است و جایگزین عملیات تبدیل در زمان اجرا نمی‌شود.

### محدودیت در طول Literal

طولانی‌بودن یک Binary Literal به‌خودی‌خود مشکل نحوی ایجاد نمی‌کند، اما مقدار آن باید در یکی از انواع صحیح نامزد قابل نمایش باشد. در غیر این صورت، Literal معتبر نخواهد بود.

بنابراین، هنگام تعریف Maskهای بزرگ یا الگوهای بیتی طولانی، باید نوع عددی مناسب و محدوده قابل نمایش آن را در نظر گرفت.

## تفاوت پشتیبانی استاندارد و قابلیت‌های کامپایلر

پیش از استاندارد ++C14، بعضی کامپایلرها از Binary Literal به‌عنوان یک Extension پشتیبانی می‌کردند. با این حال، چنین پشتیبانی‌ای به معنای استانداردبودن قابلیت در نسخه‌های قدیمی زبان نبود.

از ++C14 به بعد، استفاده از پیشوندهای `0b` و `0B` بخشی از استاندارد زبان است.

برای استفاده از این قابلیت در پروژه‌ها، باید نسخه زبان انتخاب‌شده در تنظیمات کامپایلر را بررسی کرد.

برای مثال، در GCC و Clang می‌توان استاندارد موردنظر را به این شکل مشخص کرد:

```bash
g++ -std=c++14 main.cpp -o main
```

یا:

```bash
clang++ -std=c++14 main.cpp -o main
```

در MSVC نیز باید از گزینه مناسب برای تعیین استاندارد زبان استفاده کرد. انتخاب استاندارد مناسب به ابزار ساخت و نسخه کامپایلر وابسته است.

توجه داشته باشید که فعال‌کردن استاندارد ++C14 به‌تنهایی تضمین نمی‌کند که تمام ویژگی‌های استاندارد در هر نسخه قدیمی کامپایلر بدون محدودیت پیاده‌سازی شده باشند.

## اشتباهات رایج در استفاده از Binary Literal

### اشتباه در تشخیص مبنای عدد

یکی از خطاهای رایج، تصور این است که نوشتن `1010` و `0b1010` یک مقدار تولید می‌کند.

```cpp
int decimal = 1010;
int binary = 0b1010;
```

در این مثال، مقدار متغیر اول برابر با ۱۰۱۰ و مقدار متغیر دوم برابر با ۱۰ است.

### تصور وجود نوع داده مخصوص Binary

پیشوند `0b` نوع خاصی به عدد نمی‌دهد. نوع آن همچنان از قواعد تعیین نوع Integer Literal به دست می‌آید.

بنابراین، اگر نیاز به یک نوع صحیح با عرض مشخص وجود داشته باشد، باید نوع داده مناسب به‌طور صریح انتخاب شود.

### فرض‌کردن عرض ثابت برای عملگر NOT

عملگر `~` تمام بیت‌های نوع عددی واقعی را معکوس می‌کند، نه فقط بیت‌هایی را که در Literal نوشته شده‌اند.

برای محدودکردن نتیجه به یک عرض مشخص، باید از نوع مناسب و Mask متناسب با آن عرض استفاده کرد.

### استفاده نادرست از Shift

عملیات Shift زمانی مشکل‌ساز می‌شوند که مقدار شیفت منفی باشد یا از عرض بیت نوع ارتقایافته سمت چپ کوچک‌تر نباشد.

برای مثال، عبارت `1u << position` زمانی معتبر است که `position` در محدوده مجاز برای نوع `unsigned int` قرار داشته باشد.

در کدهای عمومی و قابل استفاده مجدد، بهتر است اعتبار موقعیت بیت بررسی شود.

### استفاده از Binary Literal برای داده‌های متغیر

Binary Literal برای مقادیر ثابت در کد منبع مناسب است. اگر مقدار دودویی از ورودی کاربر، فایل، شبکه یا محاسبات زمان اجرا به دست می‌آید، باید آن را با روش مناسب پردازش کرد.

نوشتن Literal دودویی جایگزین الگوریتم‌های تبدیل رشته به عدد یا پردازش داده‌های باینری نیست.

## راهنمای انتخاب روش مناسب

برای انتخاب روش مناسب نمایش اعداد صحیح، می‌توان از معیارهای زیر استفاده کرد:

- زمانی که خوانایی الگوی بیت‌ها اهمیت دارد، Binary Literal انتخاب مناسبی است.
- زمانی که فشردگی نمایش و خوانایی داده‌های باینری بزرگ اهمیت دارد، Hexadecimal Literal معمولاً گزینه بهتری است.
- زمانی که مقدار در زمان اجرا محاسبه می‌شود، باید از عملیات عددی، Shift، Mask یا الگوریتم تبدیل مناسب استفاده کرد.
- زمانی که عرض بیت مشخصی لازم است، باید نوع داده و محدودیت‌های آن را به‌طور صریح در نظر گرفت.
- زمانی که کد باید با استانداردهای قدیمی‌تر از ++C14 سازگار باشد، استفاده از Binary Literal استاندارد ممکن نیست؛ مگر آنکه به Extension خاص کامپایلر وابسته شوید یا مقدار را با روش دیگری بنویسید.

## جمع‌بندی

قابلیت Binary Literal که در استاندارد ++C14 معرفی شد، راهی ساده و خوانا برای نوشتن مقادیر صحیح در مبنای دودویی فراهم می‌کند. با استفاده از پیشوندهای `0b` و `0B` می‌توان الگوهای بیتی را مستقیماً در کد تعریف کرد و درک Bit Maskها و عملیات Bitwise را آسان‌تر ساخت.

این قابلیت به‌ویژه در برنامه‌نویسی سیستم‌محور، مدیریت Flagها، پردازش داده‌های باینری و پیاده‌سازی الگوریتم‌های بیت‌محور مفید است.

با این حال، Binary Literal یک روش نوشتاری برای مقادیر ثابت است و نه یک نوع داده مستقل یا ابزاری برای تبدیل رشته در زمان اجرا. برای استفاده حرفه‌ای از آن، باید قواعد تعیین نوع Integer Literal، محدوده انواع صحیح، رفتار عملگرهای Bitwise و محدودیت‌های Shift را نیز در نظر گرفت.
