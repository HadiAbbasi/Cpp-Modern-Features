# آموزش جامع std::quoted در ++C14

## معرفی قابلیت std::quoted

قابلیت `std::quoted` از ++C14 یکی از ابزارهای کتابخانه استاندارد ++C برای قالب‌بندی رشته‌ها در عملیات ورودی و خروجی است. این قابلیت به برنامه‌نویس اجازه می‌دهد رشته‌ای را با قرار دادن یک نویسه مشخص در ابتدا و انتهای آن نمایش دهد و در صورت وجود نویسه‌های خاص، آن‌ها را با استفاده از یک `escape character` مشخص کند.

هدف اصلی این قابلیت، ساده‌تر کردن خواندن و نوشتن رشته‌هایی است که ممکن است شامل فاصله، علامت نقل‌قول یا نویسه‌های دیگری باشند که در قالب خروجی نیاز به مدیریت ویژه دارند.

برای مثال، اگر رشته‌ای شامل چند کلمه باشد، استفاده معمولی از `operator<<` آن را بدون علامت نقل‌قول چاپ می‌کند؛ اما با `std::quoted` می‌توان آن را به شکلی نمایش داد که مرز رشته به‌وضوح مشخص باشد.

```
#include <iomanip>
#include <iostream>
#include <string>

int main() {
    std::string text = "Hello World";

    std::cout << text << '\n';
    std::cout << std::quoted(text) << '\n';
}
```

خروجی برنامه به صورت زیر است:

```
Hello World
"Hello World"
```

در این مثال، تابع `std::quoted` رشته را به یک شیء واسط تبدیل می‌کند که رفتار ویژه‌ای هنگام استفاده با streamهای ورودی و خروجی دارد.

نکته مهم این است که `std::quoted` از قابلیت‌های **Standard Library** در ++C14 است، نه یک keyword زبان و نه یک compiler extension.

## دلیل طراحی std::quoted

در بسیاری از برنامه‌ها، رشته‌ها باید در قالبی ذخیره یا منتقل شوند که بتوان آن‌ها را بعداً به‌درستی بازیابی کرد. برای مثال، ممکن است بخواهیم رشته‌ای را در فایل متنی ذخیره کنیم یا آن را در یک گزارش تشخیصی نمایش دهیم.

روش معمول چاپ رشته با `operator<<` چنین است:

```
#include <iostream>
#include <string>

int main() {
    std::string text = "Alice Smith";

    std::cout << text << '\n';
}
```

خروجی:

```
Alice Smith
```

این خروجی برای نمایش به کاربر مناسب است، اما اگر چند رشته در یک خط ذخیره شوند، تشخیص مرز آن‌ها همیشه ساده نیست. در قالب‌هایی که فاصله به‌عنوان جداکننده استفاده می‌شود، چنین خروجی‌ای ممکن است مبهم باشد.

برای نمونه، دو مقدار زیر را در نظر بگیرید:

```
Alice Smith
Bob Jones
```

بدون یک قرارداد مشخص، مشخص نیست هر خط شامل یک رشته است یا چند مقدار جداگانه.

با استفاده از `std::quoted` می‌توان مرز رشته‌ها را صریح‌تر نمایش داد:

```
#include <iomanip>
#include <iostream>
#include <string>

int main() {
    std::string first = "Alice Smith";
    std::string second = "Bob Jones";

    std::cout << std::quoted(first) << '\n';
    std::cout << std::quoted(second) << '\n';
}
```

خروجی:

```
"Alice Smith"
"Bob Jones"
```

این روش برای قالب‌های متنی ساده، فایل‌های پیکربندی ابتدایی و ابزارهای تشخیصی کاربردی است؛ البته استفاده از `std::quoted` به‌تنهایی به معنی پیاده‌سازی یک قالب داده استاندارد مانند JSON نیست.

## معرفی سرآیند موردنیاز

برای استفاده از `std::quoted` باید سرآیند `<iomanip>` را اضافه کنید.

```
#include <iomanip>
```

سرآیند `<iomanip>` امکاناتی برای تنظیم قالب‌بندی عملیات ورودی و خروجی ارائه می‌دهد. قابلیت `std::quoted` نیز در همین سرآیند تعریف شده است.

نمونه‌ای از یک برنامه کامل:

```
#include <iomanip>
#include <iostream>
#include <string>

int main() {
    const std::string message = "C++ streams";

    std::cout << std::quoted(message) << '\n';
}
```

در این برنامه، سرآیند `<string>` برای استفاده از `std::string` و سرآیند `<iostream>` برای دسترسی به `std::cout` به کار می‌روند.

## بررسی امضای تابع و پارامترها

تابع `std::quoted` در ++C14 به‌صورت overloadهای مختلفی ارائه شده است. دو دسته کاربرد اصلی آن عبارت‌اند از قالب‌بندی رشته برای خروجی و استخراج رشته از ورودی.

شکل مفهومی overloadهای اصلی چنین است:

```
std::quoted(const charT* s, charT delim = charT('"'),
            charT escape = charT('\\'));

std::quoted(const basic_string<charT, traits, Allocator>& s,
            charT delim = charT('"'),
            charT escape = charT('\\'));

std::quoted(basic_string<charT, traits, Allocator>& s,
            charT delim = charT('"'),
            charT escape = charT('\\'));
```

این امضاها برای درک رفتار کلی API هستند؛ اعلان دقیق استاندارد از نوع بازگشتی واسطی و جزئیات template استفاده می‌کند و نباید آن‌ها را به‌عنوان امضای کامل و لفظ‌به‌لفظ اعلان استاندارد در نظر گرفت.

پارامترهای مهم عبارت‌اند از:

- `s`: رشته‌ای که قرار است قالب‌بندی یا استخراج شود.
- `delim`: نویسه جداکننده‌ای که در دو طرف رشته قرار می‌گیرد؛ مقدار پیش‌فرض آن `"` است.
- `escape`: نویسه‌ای که برای escape کردن `delim` و خود `escape` استفاده می‌شود؛ مقدار پیش‌فرض آن `\` است.

برای مثال، می‌توان جداکننده را به یک نویسه دیگر تغییر داد:

```
#include <iomanip>
#include <iostream>
#include <string>

int main() {
    std::string text = "Hello";

    std::cout << std::quoted(text, '\'') << '\n';
}
```

خروجی:

```
'Hello'
```

در این مثال، علامت نقل‌قول تکی به‌عنوان جداکننده استفاده شده است.

## مفهوم شیء واسط و رفتار آن

تابع `std::quoted` معمولاً خود رشته را تغییر نمی‌دهد. در عوض، یک شیء واسط برمی‌گرداند که اطلاعات لازم برای قالب‌بندی رشته را نگه می‌دارد.

این شیء واسط هنگام استفاده با streamهای ورودی و خروجی، رفتار متفاوتی دارد:

- هنگام استفاده با `operator<<`، رشته را با جداکننده‌ها و escapeهای لازم می‌نویسد.
- هنگام استفاده با `operator>>`، رشته را با قواعد مخصوص `std::quoted` استخراج می‌کند.

برای مثال:

```
#include <iomanip>
#include <iostream>
#include <string>

int main() {
    std::string text = "She said \"Hello\"";

    std::cout << std::quoted(text) << '\n';
}
```

خروجی:

```
"She said \"Hello\""
```

در اینجا، علامت نقل‌قول داخلی با نویسه `\` escape شده است.

نکته مهم این است که این رفتار به overloadهای ورودی و خروجی وابسته است. شیء واسط به‌خودی‌خود رشته را به یک نوع داده مستقل برای ذخیره‌سازی تبدیل نمی‌کند.

## بررسی رفتار خروجی با operator<<

مهم‌ترین کاربرد `std::quoted`، قالب‌بندی رشته هنگام نوشتن در stream است.

در حالت عادی، عملیات خروجی رشته فقط محتوای آن را می‌نویسد:

```
#include <iostream>
#include <string>

int main() {
    std::string text = "one two";

    std::cout << text << '\n';
}
```

خروجی:

```
one two
```

در مقابل، `std::quoted` جداکننده را در ابتدا و انتهای رشته می‌نویسد و نویسه‌های خاص موردنظر را escape می‌کند:

```
#include <iomanip>
#include <iostream>
#include <string>

int main() {
    std::string text = "one \"two\" three";

    std::cout << std::quoted(text) << '\n';
}
```

خروجی:

```
"one \"two\" three"
```

رفتار خروجی را می‌توان به این صورت خلاصه کرد:

- نویسه `delim` درون رشته با `escape` پیشوندگذاری می‌شود.
- خود نویسه `escape` نیز با `escape` پیشوندگذاری می‌شود.
- در ابتدا و انتهای خروجی، نویسه `delim` نوشته می‌شود.

نکته مهم این است که `std::quoted` تمام نویسه‌های کنترلی را به نمایش متنی قابل‌حمل تبدیل نمی‌کند. برای مثال، نباید انتظار داشت که newline یا tab به‌طور خودکار به توالی‌های متنی `\n` و `\t` تبدیل شوند.

## بررسی رفتار ورودی با operator>>

قابلیت `std::quoted` برای خواندن رشته‌هایی که داخل جداکننده قرار گرفته‌اند نیز کاربرد دارد.

هنگام استخراج از stream، اگر نویسه بعدی با `delim` برابر باشد، عملیات ورودی وارد حالت خواندن رشته نقل‌قول‌شده می‌شود. در این حالت، جداکننده ابتدایی مصرف می‌شود و رشته تا جداکننده پایانی خوانده خواهد شد.

اگر نویسه‌ای برابر با `escape` دیده شود، نویسه بعدی به‌عنوان بخشی از رشته در نظر گرفته می‌شود، مشروط بر اینکه در stream موجود باشد.

مثال:

```
#include <iomanip>
#include <iostream>
#include <sstream>
#include <string>

int main() {
    std::istringstream input("\"Hello World\"");

    std::string text;
    input >> std::quoted(text);

    std::cout << text << '\n';
}
```

خروجی:

```
Hello World
```

برخلاف استخراج معمولی رشته با `operator>>`، در این حالت فاصله‌های داخل جداکننده حفظ می‌شوند.

در استخراج معمولی، فاصله معمولاً پایان رشته را مشخص می‌کند:

```
#include <iostream>
#include <sstream>
#include <string>

int main() {
    std::istringstream input("Hello World");

    std::string text;
    input >> text;

    std::cout << text << '\n';
}
```

خروجی:

```
Hello
```

در مقابل، استفاده از `std::quoted` به برنامه اجازه می‌دهد رشته‌ای شامل چند کلمه را در یک عملیات استخراج دریافت کند.

## رفتار ورودی برای رشته‌های بدون نقل‌قول

اگر نخستین نویسه ورودی با `delim` برابر نباشد، `std::quoted` به‌صورت ویژه رشته نقل‌قول‌شده را پردازش نمی‌کند. در این حالت، استخراج تا رسیدن به نویسه‌ای که توسط `std::isspace` در locale مربوطه به‌عنوان فاصله شناخته می‌شود ادامه پیدا می‌کند.

برای مثال:

```
#include <iomanip>
#include <iostream>
#include <sstream>
#include <string>

int main() {
    std::istringstream input("Hello World");

    std::string text;
    input >> std::quoted(text);

    std::cout << text << '\n';
}
```

خروجی:

```
Hello
```

بنابراین، استفاده از `std::quoted` تضمین نمی‌کند که هر رشته‌ای بدون جداکننده به‌صورت کامل استخراج شود.

برای ورودی‌ای که ممکن است شامل فاصله باشد، باید قرارداد قالب داده مشخص باشد و فرستنده و گیرنده درباره نحوه استفاده از جداکننده توافق داشته باشند.

## بررسی نویسه‌های escape

رفتار escape یکی از مهم‌ترین جزئیات `std::quoted` است.

در حالت پیش‌فرض، جداکننده `"` و نویسه escape برابر با `\` است. بنابراین، دو حالت مهم در رشته خروجی باید مدیریت شوند:

- علامت نقل‌قول داخلی باید escape شود.
- خود نویسه backslash نیز باید escape شود.

مثال:

```
#include <iomanip>
#include <iostream>
#include <string>

int main() {
    std::string text = "Path: C:\\temp\\file.txt";

    std::cout << std::quoted(text) << '\n';
}
```

خروجی:

```
"Path: C:\\temp\\file.txt"
```

در این مثال، رشته در حافظه شامل یک backslash در هر محل موردنظر است؛ اما هنگام قالب‌بندی، هر backslash به‌صورت دو backslash نمایش داده می‌شود.

این تفاوت میان محتوای واقعی رشته و نمایش متنی آن اهمیت زیادی دارد. توالی‌های escape در کد منبع نیز با توالی‌های escape تولیدشده توسط `std::quoted` یکسان نیستند؛ اولی بخشی از قواعد literalهای رشته‌ای زبان است و دومی بخشی از قالب‌بندی stream.

## استفاده از جداکننده و escape سفارشی

یکی از امکانات کاربردی `std::quoted`، تعیین جداکننده و نویسه escape به‌صورت دلخواه است.

```
#include <iomanip>
#include <iostream>
#include <string>

int main() {
    std::string text = "It's a 'quoted' value";

    std::cout << std::quoted(text, '\'', '\\') << '\n';
}
```

خروجی:

```
'It\'s a \'quoted\' value'
```

در این مثال، علامت نقل‌قول تکی جداکننده است و backslash برای escape کردن آن استفاده می‌شود.

در انتخاب جداکننده باید به محتوای رشته توجه کرد. اگر جداکننده در متن زیاد ظاهر شود، خروجی ممکن است پر از escape شود؛ این رفتار از نظر صحت قالب‌بندی مشکلی ایجاد نمی‌کند، اما خوانایی را کاهش می‌دهد.

همچنین، قرارداد ورودی و خروجی باید یکسان باشد. اگر داده با جداکننده سفارشی نوشته شود، هنگام خواندن نیز باید همان جداکننده و همان نویسه escape به `std::quoted` داده شوند.

## خواندن و نوشتن با قرارداد مشترک

برای ذخیره و بازیابی رشته‌ها، مهم است که قالب خروجی با قالب ورودی سازگار باشد.

نمونه زیر یک رشته را در یک `std::stringstream` می‌نویسد و سپس آن را استخراج می‌کند:

```
#include <iomanip>
#include <iostream>
#include <sstream>
#include <string>

int main() {
    std::stringstream stream;

    std::string original = "A string with spaces and \"quotes\"";
    stream << std::quoted(original);

    std::string restored;
    stream >> std::quoted(restored);

    std::cout << std::boolalpha
              << (original == restored) << '\n';
}
```

خروجی:

```
true
```

این مثال نشان می‌دهد که قالب‌بندی و استخراج `std::quoted` برای چنین رشته‌ای با یکدیگر سازگار هستند.

بااین‌حال، این قابلیت به‌تنهایی یک پروتکل کامل برای ذخیره‌سازی داده نیست. برای مثال، اگر چند فیلد مختلف پشت سر هم نوشته شوند، باید جداکننده میان فیلدها و سیاست برخورد با ورودی نامعتبر نیز مشخص شود.

## مدیریت چند رشته در یک stream

قابلیت `std::quoted` می‌تواند در کنار سایر عملیات ورودی و خروجی استفاده شود.

```
#include <iomanip>
#include <iostream>
#include <sstream>
#include <string>

int main() {
    std::stringstream stream;

    stream << std::quoted(std::string("Alice Smith"))
           << ' '
           << std::quoted(std::string("Developer"));

    std::string name;
    std::string role;

    stream >> std::quoted(name) >> std::quoted(role);

    std::cout << name << '\n';
    std::cout << role << '\n';
}
```

خروجی:

```
Alice Smith
Developer
```

در این مثال، فاصله میان دو مقدار بخشی از قالب داده است و هر رشته با قواعد مخصوص خود استخراج می‌شود.

نکته مهم این است که جداکننده میان فیلدها همچنان باید مدیریت شود. `std::quoted` تنها مسئول قالب‌بندی یک رشته است و ساختار کل رکورد را تعریف نمی‌کند.

## تفاوت std::quoted با std::string و operator<<

نوع `std::string` رشته را نگه می‌دارد و `operator<<` معمولاً محتوای آن را در stream می‌نویسد. در مقابل، `std::quoted` نحوه نمایش یا استخراج رشته را برای یک عملیات stream تغییر می‌دهد.

| ویژگی                | `std::string`        | `operator<<` معمولی | `std::quoted`           |
| -------------------- | -------------------- | ------------------- | ----------------------- |
| نگهداری داده         | بله                  | خیر                 | خیر                     |
| نوشتن رشته           | با استفاده از stream | بله                 | با قالب نقل‌قول‌شده     |
| حفظ فاصله در استخراج | به‌تنهایی خیر        | مربوط نیست          | در حالت نقل‌قول‌شده بله |
| escape کردن جداکننده | خیر                  | خیر                 | بله                     |
| تغییر رشته اصلی      | خیر                  | خیر                 | خیر                     |

انتخاب میان این روش‌ها به هدف برنامه بستگی دارد. برای نمایش عادی متن، `operator<<` کافی است؛ اما برای ساخت یک قالب متنی ساده که مرز رشته‌ها در آن اهمیت دارد، `std::quoted` انتخاب مناسبی است.

## تفاوت std::quoted با JSON و سایر قالب‌های داده

قابلیت `std::quoted` نباید با serializerهای قالب‌های داده استاندارد اشتباه گرفته شود.

برای مثال، JSON قواعد خاصی برای نمایش رشته‌ها، escape کردن نویسه‌های کنترلی و ساختاردهی داده‌ها دارد. `std::quoted` تنها قواعد محدود خود را برای یک رشته در stream پیاده‌سازی می‌کند.

محدودیت‌های مهم آن عبارت‌اند از:

- همه نویسه‌های کنترلی را به توالی‌های escape متنی تبدیل نمی‌کند.
- اعتبارسنجی UTF-8 انجام نمی‌دهد.
- ساختار object یا array تعریف نمی‌کند.
- قواعد کامل JSON را اجرا نمی‌کند.
- اعتبارسنجی ورودی در سطح یک پروتکل کامل را بر عهده ندارد.

بنابراین، برای تولید یا پردازش JSON باید از یک کتابخانه مناسب JSON استفاده شود. استفاده از `std::quoted` به‌عنوان جایگزین یک serializer استاندارد ممکن است داده‌ای تولید کند که با قالب موردنظر سازگار نباشد.

## تفاوت std::quoted با std::format

قابلیت `std::format` از ++C20 برای قالب‌بندی عمومی مقادیر معرفی شده است. این قابلیت هدف گسترده‌تری نسبت به `std::quoted` دارد و برای ساخت رشته‌های قالب‌بندی‌شده با قالب مشخص به کار می‌رود.

در مقابل، `std::quoted` از ++C14 در درجه نخست برای نمایش رشته با جداکننده و escapeهای مربوط به آن طراحی شده است.

اگر هدف، قالب‌بندی عمومی اعداد و رشته‌ها باشد، `std::format` می‌تواند گزینه مناسبی باشد؛ اما اگر لازم است رشته‌ای با قواعد مشخص `std::quoted` از طریق stream نوشته یا خوانده شود، همین ابزار مستقیماً با این هدف سازگار است.

این دو ابزار جایگزین کامل یکدیگر نیستند و انتخاب آن‌ها باید بر اساس قرارداد قالب داده و نیاز برنامه انجام شود.

## محدودیت‌های مهم در استخراج رشته

اگر ورودی نقل‌قول‌شده باشد اما جداکننده پایانی آن وجود نداشته باشد، استخراج کامل نمی‌شود و stream وضعیت خطا می‌گیرد.

برای مثال:

```
#include <iomanip>
#include <iostream>
#include <sstream>
#include <string>

int main() {
    std::istringstream input("\"unfinished string");

    std::string text;
    input >> std::quoted(text);

    if (!input) {
        std::cout << "Input error\n";
    }
}
```

خروجی:

```
Input error
```

در برنامه‌های واقعی، بررسی وضعیت stream پس از استخراج مهم است. نباید فرض کرد که هر ورودی با استفاده از `std::quoted` به‌صورت موفق پردازش می‌شود.

نکته دیگر این است که اگر نویسه escape در انتهای ورودی قرار بگیرد و نویسه‌ای پس از آن وجود نداشته باشد، استخراج کامل نخواهد بود؛ زیرا escape برای مصرف نویسه بعدی استفاده می‌شود.

## مدیریت وضعیت stream و ورودی نامعتبر

قابلیت `std::quoted` از قواعد معمول وضعیت stream پیروی می‌کند. بنابراین، پس از استخراج باید وضعیت stream بررسی شود.

```
#include <iomanip>
#include <iostream>
#include <sstream>
#include <string>

int main() {
    std::istringstream input("\"valid value\"");

    std::string value;

    if (input >> std::quoted(value)) {
        std::cout << "Parsed: " << value << '\n';
    } else {
        std::cout << "Failed to parse input\n";
    }
}
```

این الگو در برنامه‌هایی که ورودی از فایل، شبکه یا کاربر دریافت می‌شود، مناسب است.

برای ورودی‌های غیرقابل‌اعتماد، بررسی موفقیت عملیات کافی نیست؛ برنامه باید در صورت نیاز محدودیت اندازه رشته، سیاست مدیریت خطا و قواعد اعتبارسنجی سطح بالاتر را نیز پیاده‌سازی کند.

## نکات مربوط به overloadها و نوع رشته

قابلیت `std::quoted` فقط برای `std::string` محدود نشده است. overloadهای آن برای رشته‌های مبتنی بر `basic_string` و همچنین رشته‌های مبتنی بر اشاره‌گر به نویسه نیز در نظر گرفته شده‌اند.

در خانواده `basic_string`، نوع نویسه می‌تواند انواعی مانند `char` یا `wchar_t` باشد؛ البته نوع stream مورد استفاده نیز باید با نوع نویسه سازگار باشد.

برای مثال، در برنامه‌ای که از wide characterها استفاده می‌کند، باید از نوع رشته و stream مناسب استفاده شود. نمی‌توان یک شیء مبتنی بر `wchar_t` را بدون توجه به نوع stream با `std::cout` ترکیب کرد و انتظار رفتار درست داشت.

همچنین، در overload مبتنی بر اشاره‌گر به نویسه، داده باید یک رشته با پایان‌دهنده null معتبر باشد. اگر اشاره‌گر نامعتبر باشد یا رشته به‌درستی خاتمه نیافته باشد، رفتار برنامه می‌تواند تعریف‌نشده باشد.

در مقابل، overloadهای مبتنی بر `std::string` اندازه رشته را از خود شیء دریافت می‌کنند و برای رشته‌هایی که شامل null داخلی هستند، محدود به اولین null نیستند؛ هرچند نمایش چنین رشته‌هایی در قالب‌های متنی ممکن است به قراردادهای اضافی نیاز داشته باشد.

## نکات مهم درباره موقت‌ها و طول عمر اشیا

از آنجا که `std::quoted` یک شیء واسط برمی‌گرداند، استفاده مستقیم از آن در یک عبارت stream معمولاً ساده و ایمن است.

```
#include <iomanip>
#include <iostream>
#include <string>

int main() {
    std::cout << std::quoted(std::string("temporary string")) << '\n';
}
```

در این عبارت، رشته موقت تا پایان عبارت کامل زنده می‌ماند و عملیات خروجی روی آن انجام می‌شود.

بااین‌حال، نگهداری یک شیء واسط برای استفاده در زمانی دیرتر، به‌ویژه اگر به رشته‌ای اشاره کند که طول عمر آن پایان یافته است، می‌تواند مشکل‌ساز باشد. برای استفاده‌های ساده، بهتر است `std::quoted` مستقیماً در عملیات ورودی یا خروجی قرار بگیرد.

## نکات مربوط به رشته‌های Unicode

قابلیت `std::quoted` یک ابزار عمومی برای serialization متن Unicode نیست. این تابع قواعد escape محدودی را بر اساس نوع نویسه و مقادیر `delim` و `escape` اجرا می‌کند.

برای رشته‌های UTF-8 که با `std::string` ذخیره شده‌اند، عملیات قالب‌بندی روی واحدهای بایتی انجام می‌شود. این قابلیت نه اعتبار UTF-8 را بررسی می‌کند و نه نویسه‌های Unicode را بر اساس معنا یا تعداد code pointها پردازش می‌کند.

در نتیجه، اگر برنامه با داده‌های چندزبانه سروکار دارد، باید اعتبار encoding و سیاست تبدیل داده را جداگانه مدیریت کند. استفاده از `std::quoted` به‌تنهایی تضمین‌کننده صحت encoding نیست.

## اشتباهات رایج در استفاده از std::quoted

چند اشتباه رایج می‌تواند باعث ایجاد خروجی نامطلوب یا پردازش نادرست ورودی شود.

### فراموش کردن سرآیند مناسب

برای دسترسی به `std::quoted` باید `<iomanip>` را اضافه کنید. وارد کردن `<iostream>` به‌تنهایی برای تضمین دسترسی به این قابلیت کافی نیست.

### انتظار escape شدن همه نویسه‌های ویژه

قابلیت `std::quoted` نویسه جداکننده و نویسه escape را مدیریت می‌کند، اما یک سیستم عمومی برای تبدیل تمام نویسه‌های کنترلی به نمایش متنی نیست.

### استفاده از قراردادهای متفاوت در ورودی و خروجی

اگر هنگام نوشتن از جداکننده سفارشی استفاده شود اما هنگام خواندن جداکننده پیش‌فرض انتخاب شود، ممکن است داده مطابق انتظار بازیابی نشود.

### نادیده گرفتن خطاهای استخراج

در صورت ناقص بودن جداکننده‌ها یا وجود escape ناقص، عملیات استخراج ممکن است شکست بخورد. بررسی وضعیت stream باید بخشی از کد پردازش ورودی باشد.

### استفاده از std::quoted برای تولید JSON

قواعد `std::quoted` با قواعد کامل JSON یکسان نیستند. برای تولید JSON معتبر باید از ابزار مناسب همان قالب استفاده شود.

### فرض اینکه فاصله‌ها همیشه حفظ می‌شوند

فاصله‌ها در حالت رشته نقل‌قول‌شده حفظ می‌شوند؛ اما اگر ورودی با جداکننده آغاز نشود، استخراج مانند یک رشته معمولی و تا اولین فاصله ادامه پیدا می‌کند.

## توصیه‌های کاربردی برای طراحی نرم‌افزار

در پروژه‌های حرفه‌ای، بهتر است استفاده از `std::quoted` بر اساس قرارداد مشخصی انجام شود.

- برای نمایش رشته‌ها در گزارش‌ها و خروجی‌های تشخیصی، این قابلیت می‌تواند خوانایی را افزایش دهد.
- برای ذخیره رشته‌ها در قالب متنی ساده، ابتدا باید قواعد جداکننده‌ها و نحوه مدیریت ورودی نامعتبر تعریف شوند.
- برای تبادل داده میان برنامه‌های مستقل، باید از قالبی استفاده شود که قواعد آن به‌صورت دقیق مستند شده باشد.
- برای داده‌های غیرقابل‌اعتماد، محدودیت اندازه و مدیریت خطا باید در سطح برنامه اعمال شود.
- برای رشته‌های Unicode، صحت encoding باید جدا از قالب‌بندی stream بررسی شود.
- برای serialization ساختاریافته، استفاده از کتابخانه تخصصی قالب موردنظر معمولاً انتخاب مطمئن‌تری است.

## جمع‌بندی

قابلیت `std::quoted` که در ++C14 معرفی شده است، راهکاری استاندارد و ساده برای نوشتن و خواندن رشته‌های نقل‌قول‌شده در streamها ارائه می‌دهد. این قابلیت از جداکننده و نویسه escape پشتیبانی می‌کند و امکان حفظ فاصله‌های داخل رشته را هنگام استخراج رشته نقل‌قول‌شده فراهم می‌سازد.

مهم‌ترین کاربردهای آن شامل قالب‌بندی خروجی، پردازش فایل‌های متنی ساده و ساخت قراردادهای ابتدایی برای ذخیره و بازیابی رشته‌ها است.

بااین‌حال، `std::quoted` یک serializer عمومی نیست و جایگزین قالب‌هایی مانند JSON یا ابزارهای تخصصی serialization نمی‌شود. در استفاده حرفه‌ای، توجه به قرارداد ورودی و خروجی، وضعیت stream، نویسه‌های escape، طول عمر داده و محدودیت‌های encoding اهمیت زیادی دارد.
