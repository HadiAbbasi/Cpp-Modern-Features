# استنتاج نوع بازگشتی در ++C14

## مقدمه

در طراحی توابع ++C، نوع بازگشتی بخشی از رابط تابع است و بر نحوه استفاده از نتیجه، انتخاب overloadها، انتقال مقدار و حتی خوانایی کد اثر می‌گذارد. در بسیاری از موارد، نوشتن نوع بازگشتی به‌صورت صریح ضروری و مفید است؛ اما گاهی نوع نتیجه از عبارت `return` یا از بدنه تابع قابل تعیین است. قابلیت **Return Type Deduction** در ++C14 امکان می‌دهد کامپایلر در شرایط مشخص نوع بازگشتی تابع را استنتاج کند.

این قابلیت با استنتاج نوع متغیرها به کمک `auto` مرتبط است، اما دقیقاً همان سازوکار نیست. به‌ویژه، قواعد تابع معمولی با قواعد `auto` در نوع بازگشتی trailing و با قواعد `decltype(auto)` تفاوت دارند. شناخت این تفاوت‌ها برای جلوگیری از کپی ناخواسته، از دست رفتن reference و خطاهای کامپایل ضروری است.

## مبانی استنتاج نوع بازگشتی

### معرفی قابلیت در ++C14

استاندارد ++C11، `auto` را برای استنتاج نوع متغیرها و نیز برای نوع بازگشتی trailing با `->` معرفی کرد. برای نمونه، در ++C11 می‌شد نوع نتیجه را در انتهای اعلان تابع مشخص کرد:

```cpp
auto add(int a, int b) -> int {
    return a + b;
}
```

در ++C14، امکان حذف نوع صریح بازگشتی و استفاده از `auto` به‌عنوان نوع بازگشتی معمولی اضافه شد:

```cpp
auto add(int a, int b) {
    return a + b;
}
```

در این مثال، کامپایلر نوع عبارت بازگشتی `a + b` را استنتاج می‌کند. از آنجا که نتیجه جمع دو `int` از نوع `int` است، نوع بازگشتی تابع نیز `int` خواهد بود.

### چرا این قابلیت اضافه شد؟

این قابلیت چند مسئله رایج را ساده می‌کند:

- در توابعی که نوع نتیجه از عبارت بازگشتی به‌روشنی مشخص است، از تکرار نوع جلوگیری می‌شود.
- نوشتن wrapperها و توابع کمکی generic ساده‌تر می‌شود؛ زیرا نوع نتیجه ممکن است به نوع آرگومان‌ها وابسته باشد.
- در کدهای template، نیازی نیست نویسنده نوعی پیچیده را دستی بازسازی کند.
- هنگام تغییر نوع عبارت محاسباتی، احتمال ناسازگاری بین نوع اعلام‌شده و نتیجه واقعی کاهش می‌یابد.

با این حال، استنتاج خودکار همیشه خوانایی را بهتر نمی‌کند. اگر نوع بازگشتی بخش مهمی از قرارداد API باشد، مشخص‌کردن صریح آن می‌تواند مستندتر و پایدارتر باشد.

## قواعد پایه استنتاج با `auto`

### استنتاج بر اساس عبارت `return`

برای تابعی که نوع بازگشتی آن `auto` است، نوع از عبارت‌های `return` دارای مقدار استنتاج می‌شود:

```cpp
auto getValue() {
    return 42;
}
```

نوع بازگشتی این تابع `int` است. در این حالت، قواعد استنتاج نوع مشابه استنتاج نوع متغیر با `auto` هستند: cv-qualifierها و referenceهای سطح بالای عبارت معمولاً بخشی از نوع استنتاج‌شده باقی نمی‌مانند.

```cpp
int globalValue = 10;

auto byValue() {
    return globalValue;
}

auto byReference() {
    return (globalValue);
}
```

هر دو تابع بالا `int` برمی‌گردانند، نه `int&`. وجود پرانتز در عبارت دوم، به‌تنهایی باعث حفظ reference نمی‌شود؛ زیرا نوع بازگشتی `auto` از قواعد استنتاج `auto` پیروی می‌کند.

اگر هدف بازگرداندن reference باشد، باید آن را صریح اعلام کرد یا از `decltype(auto)` با آگاهی از قواعد آن استفاده کرد:

```cpp
int globalValue = 10;

auto& referenceToValue() {
    return globalValue;
}
```

در این نمونه نوع بازگشتی `int&` است.

### تفاوت `auto` در متغیر و تابع

در متغیر محلی، نوع `auto` از مقدار initializer استنتاج می‌شود:

```cpp
int value = 10;
auto copy = value;
```

در تابع، نوع `auto` از عبارت‌های `return` استنتاج می‌شود:

```cpp
auto makeValue() {
    return 10;
}
```

در هر دو حالت، استنتاج `auto` معمولاً reference و cv-qualifier سطح بالا را حذف می‌کند. بااین‌حال، تابع محدودیت‌های اضافی دارد؛ از جمله اینکه عبارت‌های `return` باید به نوع واحدی قابل استنتاج منتهی شوند.

## چند عبارت `return` و سازگاری نوع‌ها

### یکسان بودن نوع‌های استنتاج‌شده

در تابعی با `auto`، عبارت‌های `return` باید نوع بازگشتی سازگاری داشته باشند. برای مثال:

```cpp
auto absoluteLike(int value) {
    if (value < 0) {
        return -value;
    }

    return value;
}
```

هر دو عبارت از نوع `int` هستند، بنابراین استنتاج معتبر است.

اما مثال زیر معتبر نیست:

```cpp
auto choose(bool condition) {
    if (condition) {
        return 1;
    }

    return 2.0;
}
```

یکی از عبارت‌ها `int` و دیگری `double` است. کامپایلر برای این تابع یک نوع مشترک دلخواه انتخاب نمی‌کند؛ استنتاج نوع بازگشتی با شکست مواجه می‌شود. اگر نتیجه باید نوع مشخصی داشته باشد، نوع را صریح بنویسید یا همه مسیرها را به یک نوع برسانید:

```cpp
double choose(bool condition) {
    if (condition) {
        return 1;
    }

    return 2.0;
}
```

### تبدیل‌های ضمنی را مفروض نگیرید

وجود تبدیل ضمنی از یک نوع به نوع دیگر به این معنا نیست که استنتاج `auto` همان تبدیل را برای یکسان‌سازی تمام عبارت‌های `return` اعمال می‌کند. استنتاج، نوع عبارت‌ها را طبق قواعد زبان بررسی می‌کند؛ بنابراین در طراحی تابع، به نوع دقیق هر عبارت توجه کنید.

### مسیر بدون `return` دارای مقدار

تابعی که نوع بازگشتی آن `auto` است، نمی‌تواند از یک مسیر دارای مقدار و مسیر دیگری با نوع ناسازگار استفاده کند. اگر هیچ عبارت `return` دارای مقدار وجود نداشته باشد، استنتاج نوع بازگشتی `auto` به نوع `void` منتهی نمی‌شود؛ تابع باید در نهایت نوع را از عبارت بازگشتی مناسب به دست آورد. برای تابعی که عمداً مقداری برنمی‌گرداند، `void` را صریح بنویسید:

```cpp
void logMessage() {
    // Perform logging.
}
```

نکته: تابعی که `return;` دارد و هیچ مقدار بازگشتی ندارد، با تابعی که `return expression;` دارد یکسان نیست. در طراحی API، برای تابع بدون نتیجه از `void` استفاده کنید.

## استنتاج در توابع بازگشتی

### محدودیت تعیین نوع در بازگشت مستقیم

در تابع بازگشتی که نوع بازگشتی آن `auto` است، کامپایلر باید بتواند نوع را هنگام تحلیل عبارت‌های `return` تعیین کند. اگر تابع برای استنتاج نوع به فراخوانی بازگشتی خودش وابسته باشد، ممکن است نوع هنوز مشخص نشده باشد:

```cpp
auto factorial(int n) {
    if (n <= 1) {
        return 1;
    }

    return n * factorial(n - 1);
}
```

این الگو در ++C14 مشکل دارد، زیرا نوع بازگشتی باید از عبارت‌های `return` استنتاج شود، اما یکی از این عبارت‌ها به فراخوانی تابعی وابسته است که نوعش هنوز در حال استنتاج است. راه معمول، تعیین نوع بازگشتی به‌صورت صریح است:

```cpp
int factorial(int n) {
    if (n <= 1) {
        return 1;
    }

    return n * factorial(n - 1);
}
```

این محدودیت را نباید با تمام شکل‌های بازگشت یکسان دانست. اگر نوع از عبارتی مستقل از فراخوانی بازگشتی قابل تعیین باشد، جزئیات اعلان و ترتیب تعریف همچنان اهمیت دارد؛ بااین‌حال، برای توابع بازگشتی، نوع صریح اغلب ساده‌ترین و خواناترین انتخاب است.

### بازگشت متقابل

در بازگشت متقابل، دو تابع مستقیماً یا غیرمستقیم یکدیگر را فراخوانی می‌کنند. اگر نوع بازگشتی هر دو به استنتاج وابسته باشد، تعیین نوع‌ها دشوار یا ناممکن می‌شود. اعلام نوع بازگشتی صریح برای دست‌کم اعلان‌های لازم، وابستگی را برطرف می‌کند:

```cpp
bool isEven(int n);
bool isOdd(int n);

bool isEven(int n) {
    return n == 0 ? true : isOdd(n - 1);
}

bool isOdd(int n) {
    return n == 0 ? false : isEven(n - 1);
}
```

## تفاوت `auto` و `decltype(auto)`

### استنتاج با `auto`

نوع بازگشتی `auto` از قواعد استنتاج `auto` استفاده می‌کند و معمولاً نتیجه را به‌صورت value برمی‌گرداند:

```cpp
int value = 7;

auto getCopy() {
    return value;
}
```

نوع نتیجه `int` است. این رفتار برای بیشتر توابع محاسباتی و factoryهایی که مالکیت مقدار را تحویل می‌دهند مناسب است.

### استنتاج با `decltype(auto)`

قابلیت `decltype(auto)` از ++C14 در دسترس است و نوع را بر اساس قواعد `decltype` استنتاج می‌کند. بنابراین، بسته به شکل عبارت، می‌تواند reference را حفظ کند:

```cpp
int value = 7;

decltype(auto) getReference() {
    return (value);
}
```

در این نمونه، عبارت `(value)` یک lvalue است و `decltype((value))` برابر `int&` خواهد بود؛ پس تابع reference برمی‌گرداند.

در مقابل:

```cpp
int value = 7;

decltype(auto) getValue() {
    return value;
}
```

در این مثال، چون operand در `decltype` نام بدون پرانتز یک متغیر است، نوع `decltype(value)` برابر نوع اعلام‌شده متغیر، یعنی `int` خواهد بود. بنابراین این تابع مقدار برمی‌گرداند، نه reference.

### چرا پرانتزها اهمیت دارند؟

قاعده ویژه `decltype` برای نام بدون پرانتز متغیر با قواعد عبارت‌های دیگر متفاوت است. برای یک عبارت lvalue مانند `(value)`، `decltype` نتیجه‌ای از نوع lvalue reference می‌دهد. در نتیجه، افزودن یا حذف پرانتز در کد دارای `decltype(auto)` ممکن است نوع بازگشتی را تغییر دهد:

```cpp
int value = 7;

decltype(auto) byValue() {
    return value;
}

decltype(auto) byReference() {
    return (value);
}
```

تابع نخست `int` و تابع دوم `int&` برمی‌گرداند. این تفاوت از مهم‌ترین منابع خطا در استفاده از `decltype(auto)` است.

### انتخاب بین این دو

- از `auto` استفاده کنید وقتی هدف، بازگرداندن مقدار مستقل است.
- از `decltype(auto)` استفاده کنید وقتی لازم است نوع دقیق عبارت، از جمله reference بودن آن، حفظ شود.
- برای API عمومی، اگر نوع یا مالکیت نتیجه باید واضح باشد، نوع بازگشتی صریح معمولاً خواناتر است.
- از `decltype(auto)` صرفاً برای کوتاه‌کردن اعلان استفاده نکنید؛ زیرا تغییر ظاهراً کوچک در عبارت `return` می‌تواند قرارداد تابع را تغییر دهد.

## استنتاج نوع بازگشتی در توابع lambda

### قابلیت در ++C14

در ++C11، تابع lambda می‌توانست نوع بازگشتی trailing داشته باشد یا در موارد ساده از قواعد استنتاج محدود استفاده کند. در ++C14، استنتاج نوع بازگشتی برای lambdaها گسترده‌تر شد و معمولاً می‌توان نوع را حذف کرد:

```cpp
auto square = [](int value) {
    return value * value;
};
```

نوع بازگشتی این lambda از عبارت `value * value` استنتاج می‌شود.

### سازگاری مسیرهای مختلف

همانند توابع معمولی، عبارت‌های `return` در lambda باید نوع سازگاری داشته باشند:

```cpp
auto selectValue = [](bool condition) {
    if (condition) {
        return 10;
    }

    return 20;
};
```

این نمونه معتبر است؛ هر دو مسیر `int` برمی‌گردانند. اما اگر یک مسیر `int` و مسیر دیگر `std::string` برگرداند، استنتاج معمول `auto` موفق نخواهد بود.

### استفاده در الگوریتم‌ها

استنتاج بازگشتی در lambdaها هنگام استفاده از الگوریتم‌های Standard Library کد را ساده می‌کند:

```cpp
#include <algorithm>
#include <vector>

int main() {
    std::vector<int> values{1, 2, 3, 4};

    std::transform(
        values.begin(),
        values.end(),
        values.begin(),
        [](int value) {
            return value * value;
        }
    );
}
```

در این مثال، lambda برای هر ورودی یک `int` تولید می‌کند و نیازی به نوشتن نوع بازگشتی جداگانه نیست.

## کاربرد در توابع قالبی و generic

### ساده‌سازی توابع وابسته به نوع آرگومان

در توابع template، نوع نتیجه ممکن است از عملیات روی آرگومان‌ها به دست آید. استفاده از `auto` می‌تواند از تکرار نوع عبارت جلوگیری کند:

```cpp
template <typename T, typename U>
auto addValues(const T& left, const U& right) {
    return left + right;
}
```

نوع بازگشتی با نوع عبارت `left + right` تعیین می‌شود. برای نمونه، ترکیب `int` و `double` معمولاً نتیجه‌ای از نوع `double` دارد. البته نوع واقعی به overload عملگر و نوع‌های ورودی وابسته است.

### تفاوت با trailing return type

در ++C11 می‌شد نوع نتیجه تابع template را با `decltype` و trailing return type بیان کرد:

```cpp
template <typename T, typename U>
auto addValues(const T& left, const U& right)
    -> decltype(left + right) {
    return left + right;
}
```

در ++C14، شکل مبتنی بر `auto` کوتاه‌تر است. با این حال، trailing return type هنوز در مواردی مفید است که نوع بازگشتی باید صریحاً مشخص شود، یا اعلان تابع پیش از بدنه به نوع وابسته‌ای نیاز دارد.

### محدودیت در اعلان بدون بدنه

برای تابعی که تنها اعلان شده و بدنه‌اش در دسترس نیست، کامپایلر نمی‌تواند نوع بازگشتی `auto` را از عبارت‌های `return` استنتاج کند. برای مثال، رابطی مانند زیر برای استفاده‌ای که به نوع نتیجه نیاز دارد کافی نیست:

```cpp
auto calculate(int value);
```

تا زمانی که تعریف تابع در دسترس نباشد، نوع بازگشتی معلوم نیست و استفاده‌ای که مستلزم دانستن آن باشد قابل کامپایل نیست. برای APIهای جداشده به فایل header و source، معمولاً نوع بازگشتی را صریح اعلام کنید یا تعریف را در همان جایی قرار دهید که استنتاج لازم است.

## تفاوت استنتاج نوع بازگشتی با `decltype`

### رفتار `decltype(expression)`

عبارت `decltype(expression)` نوع دقیق عبارت را طبق قواعد خاص خود تعیین می‌کند. به‌طور خلاصه:

- اگر `expression` نام بدون پرانتز یک متغیر یا عضو باشد، `decltype` نوع اعلام‌شده آن را می‌دهد.
- اگر عبارت lvalue باشد، نتیجه معمولاً lvalue reference است.
- اگر عبارت xvalue باشد، نتیجه معمولاً rvalue reference است.
- اگر عبارت prvalue باشد، نتیجه نوع خود آن عبارت است.

این قواعد در templateها و در طراحی wrapperهایی که باید category و reference بودن عبارت را حفظ کنند، اهمیت دارند.

### مقایسه عملی

```cpp
int value = 5;

auto a() {
    return (value);
}

decltype(auto) b() {
    return (value);
}

auto c() -> decltype((value)) {
    return (value);
}
```

در این مثال، `a` مقدار `int` را برمی‌گرداند، درحالی‌که `b` و `c` نوع بازگشتی `int&` دارند. این تفاوت نشان می‌دهد که `auto`، `decltype(auto)` و `decltype` سازوکارهای مرتبط اما غیرقابل‌جایگزین هستند.

## بازگرداندن reference و طول عمر شیء

### خطر reference به متغیر محلی

استنتاج صحیح نوع به‌تنهایی ایمنی را تضمین نمی‌کند. بازگرداندن reference به متغیر محلی که با پایان تابع نابود می‌شود، رفتار نامعتبر ایجاد می‌کند:

```cpp
auto& invalidReference() {
    int localValue = 42;
    return localValue;
}
```

این تابع reference به شیئی محلی برمی‌گرداند که پس از خروج از تابع طول عمرش تمام می‌شود. استفاده از reference حاصل، رفتار تعریف‌نشده دارد. کامپایلرها ممکن است هشدار دهند، اما نباید به هشدار وابسته بود.

### خطر `decltype(auto)` در wrapperها

در wrapperها، `decltype(auto)` می‌تواند reference نتیجه تابع فراخوانی‌شده را حفظ کند؛ این کار در بعضی موارد مطلوب است، اما اگر نتیجه به یک شیء موقت یا شیء محلی وابسته باشد، می‌تواند خطرناک باشد. قرارداد طول عمر باید جدا از استنتاج نوع بررسی شود.

```cpp
decltype(auto) identity(int& value) {
    return (value);
}
```

این تابع reference به آرگومان موجود را برمی‌گرداند و در صورت معتبر ماندن طول عمر شیء اصلی می‌تواند مناسب باشد. اما نسخه‌ای که آرگومان را به‌صورت value دریافت کند و سپس به آن reference بدهد، ایمن نیست:

```cpp
decltype(auto) invalidIdentity(int value) {
    return (value);
}
```

در این نسخه، نتیجه `int&` است که به پارامتر محلی اشاره می‌کند؛ این reference پس از بازگشت تابع dangling خواهد بود.

### انتخاب آگاهانه مالکیت

هنگام طراحی تابع، مشخص کنید نتیجه باید مقدار مستقل باشد، reference به شیء موجود باشد یا reference به یک شیء موقت. `auto` اغلب انتخاب ساده و ایمن‌تری برای تحویل مقدار است؛ `auto&`، `auto&&` و `decltype(auto)` را زمانی انتخاب کنید که حفظ reference بخشی از قرارداد روشن تابع باشد.

## تفاوت نوع بازگشتی با `auto` در پارامترها

### پارامترهای تابع در ++C14

قابلیت استنتاج نوع بازگشتی `auto` نباید با پارامترهای `auto` اشتباه گرفته شود. پارامترهای عادی تابع در ++C14 نمی‌توانند صرفاً با `auto` به شکل تابع عادی اعلام شوند. برای نمونه، شکل زیر تابع عادی معتبری در ++C14 نیست:

```cpp
auto add(auto left, auto right) {
    return left + right;
}
```

استنتاج نوع پارامتر به این شکل به **generic lambda**ها در ++C14 مربوط است، نه تابع عادی. برای تابع عادی generic باید از `template` استفاده شود:

```cpp
template <typename T, typename U>
auto add(T left, U right) {
    return left + right;
}
```

قابلیت abbreviated function templates با پارامترهای `auto` در استاندارد ++C20 معرفی شد؛ بنابراین نباید آن را به ++C14 نسبت داد.

## محدودیت‌ها و خطاهای رایج

### استفاده از نوع‌های ناسازگار در `return`

اگر مسیرهای مختلف تابع نوع‌های متفاوتی تولید کنند، استنتاج معمول `auto` شکست می‌خورد. نوع خروجی را صریح کنید یا عبارت‌ها را به نوعی مشخص تبدیل کنید.

### فرض حفظ reference در `auto`

نوع بازگشتی `auto` به‌طور خودکار reference را حفظ نمی‌کند. اگر API باید reference بدهد، این موضوع را صریح بیان کنید یا از `decltype(auto)` با درک کامل قواعد `decltype` استفاده کنید.

### اتکا به استنتاج در اعلان‌های عمومی

در اعلان تابعی که فقط prototype آن در header قرار دارد، `auto` معمولاً انتخاب مناسبی نیست؛ زیرا مصرف‌کننده برای استفاده از نتیجه به تعریف قابل مشاهده نیاز دارد تا نوع را استنتاج کند.

### فراموش کردن طول عمر

حتی اگر نوع بازگشتی دقیقاً همان نوع موردنظر باشد، reference به شیء نابودشده همچنان نامعتبر است. بررسی lifetime از بررسی نوع جداست.

### اشتباه گرفتن `auto` با `decltype(auto)`

این دو همیشه نوع یکسانی تولید نمی‌کنند. تفاوت میان `value` و `(value)` در تابع دارای `decltype(auto)` ممکن است نوع را از `int` به `int&` تغییر دهد.

### استفاده بی‌دلیل از استنتاج

استنتاج برای کاهش تکرار و حفظ سازگاری نوعی مفید است، اما در APIهای عمومی، رابط‌های ABI-sensitive یا کدی که نوع نتیجه بخشی از قرارداد مستند است، نوع صریح می‌تواند انتخاب بهتری باشد. همچنین تغییر بدنه تابعی که نوع بازگشتی آن استنتاج می‌شود ممکن است ناخواسته نوع API را تغییر دهد.

## مقایسه روش‌های اعلام نوع بازگشتی

| روش | استاندارد | رفتار اصلی | کاربرد مناسب |
|---|---|---|---|
| نوع صریح، مانند `int` | پیش از ++C11 | نوع قرارداد را مستقیماً مشخص می‌کند | API عمومی و قرارداد پایدار |
| `auto` در نوع بازگشتی | ++C14 | نوع از عبارت‌های `return` و قواعد استنتاج `auto` به دست می‌آید | توابع محاسباتی و templateها |
| trailing return type، مانند `auto f() -> T` | ++C11 | نوع بعد از فهرست پارامترها نوشته می‌شود | نوع‌های وابسته و اعلان‌های صریح |
| `decltype(auto)` | ++C14 | نوع طبق قواعد `decltype` استنتاج می‌شود | wrapperها و حفظ reference در صورت نیاز |

## راهنمای انتخاب در پروژه‌های واقعی

### زمان استفاده از `auto`

از `auto` استفاده کنید اگر نوع نتیجه به‌وضوح از عبارت بازگشتی به دست می‌آید، چند نوع ورودی مختلف در یک template می‌توانند خروجی‌های متفاوتی تولید کنند، یا تکرار نوع در اعلان خطاپذیر است. این روش به‌خصوص در توابع کمکی داخلی و lambdaها مفید است.

### زمان انتخاب نوع صریح

نوع صریح را ترجیح دهید اگر نوع خروجی بخشی از قرارداد عمومی است، تعریف از اعلان جداست، ثبات API اهمیت دارد، یا نوع بازگشتی با نگاه به امضای تابع باید فوراً مشخص باشد. نوع صریح همچنین در توابع بازگشتی و بازگشت متقابل اغلب ابهام استنتاج را از بین می‌برد.

### زمان استفاده از `decltype(auto)`

از `decltype(auto)` زمانی استفاده کنید که لازم است نوع دقیق عبارت حفظ شود؛ به‌ویژه در forwarding wrapperها یا توابعی که باید نتیجه فراخوانی دیگری را بدون تغییر category آن برگردانند. این قابلیت باید با دقت به lifetime و value category همراه باشد.

## جمع‌بندی

قابلیت Return Type Deduction در ++C14 امکان می‌دهد نوع بازگشتی تابع از عبارت‌های `return` استنتاج شود و در نتیجه نوشتن توابع generic، lambdaها و توابع کمکی ساده‌تر شود. بااین‌حال، `auto` به معنی حفظ خودکار reference نیست و چند عبارت `return` باید نوع سازگاری داشته باشند. همچنین، اعلان تابع بدون تعریف قابل مشاهده نمی‌تواند نوع استنتاج‌شده را به مصرف‌کننده ارائه کند.

برای انتخاب درست، میان سه هدف تمایز بگذارید: **سادگی اعلان**، **شفافیت قرارداد** و **حفظ دقیق نوع عبارت**. در بسیاری از توابع معمولی `auto` کافی است؛ برای رابط‌های پایدار، نوع صریح اغلب خواناتر است؛ و برای wrapperهایی که به حفظ reference نیاز دارند، `decltype(auto)` می‌تواند مناسب باشد، به شرط آنکه طول عمر شیء و قواعد `decltype` به‌دقت بررسی شوند.
