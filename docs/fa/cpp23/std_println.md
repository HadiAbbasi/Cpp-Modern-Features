# معرفی std::println در ++C23

## مقدمه

قابلیت `std::println` یکی از امکانات کتابخانه استاندارد در ++C23 است که چاپ متن قالب‌بندی‌شده را همراه با پایان خط ساده می‌کند. این تابع از خانواده توابع جدید `std::print` و `std::println` است و از زیرساخت قالب‌بندی معرفی‌شده در ++C20، یعنی `std::format`، استفاده می‌کند.

در روش‌های قدیمی‌تر، برای چاپ خروجی معمولاً از `std::cout` و عملگر درج `<<` یا از توابعی مانند `printf` استفاده می‌شد. این روش‌ها همچنان معتبرند، اما هرکدام محدودیت‌هایی در خوانایی، قالب‌بندی، نوع‌پذیری یا مدیریت رشته‌های قالب دارند. خانواده `print` راهی استاندارد و مستقیم برای ترکیب قالب و آرگومان‌ها فراهم می‌کند؛ `println` نیز در پایان خروجی یک نویسه خط جدید اضافه می‌کند.

این قابلیت بخشی از **Standard Library** است، نه یک قابلیت نحوی زبان. بنابراین فعال‌بودن حالت زبانی ++C23 به‌تنهایی تضمین نمی‌کند که کتابخانه استاندارد مورد استفاده، `<print>` و `std::println` را پیاده‌سازی کرده باشد.

## مسئله‌ای که std::println حل می‌کند

### دشواری‌های روش‌های قدیمی چاپ

روش مبتنی بر `std::cout` برای بسیاری از کاربردها مناسب است، اما قالب‌بندی مقادیر مختلف ممکن است به زنجیره‌ای از عملگرها، دست‌کاری وضعیت stream و استفاده از manipulatorها نیاز داشته باشد. برای نمونه، تنظیم تعداد رقم اعشار یا نمایش مبنای شانزده‌تایی روی وضعیت stream اثر می‌گذارد و این وضعیت می‌تواند بر چاپ‌های بعدی نیز تأثیر بگذارد.

روش `printf` قالب‌بندی فشرده‌ای دارد، اما مشخص‌کننده‌های قالب آن در زمان کامپایل به شکل نوع‌امن با آرگومان‌ها تطبیق داده نمی‌شوند. ناهماهنگی میان `%d` و نوع آرگومان، برای مثال، می‌تواند به رفتار تعریف‌نشده منجر شود.

قابلیت `std::println` این مشکلات را با استفاده از format string نوع‌امن و سازوکار formatterهای کتابخانه استاندارد کاهش می‌دهد. همچنین نیاز به افزودن دستی `'\n'` را از بین می‌برد.

### مزیت‌های اصلی

- **قالب‌بندی نوع‌امن:** در format stringهای ثابت، نوع و تعداد آرگومان‌ها در زمان کامپایل بررسی می‌شوند.
- **خوانایی:** قالب خروجی و مقادیر در یک فراخوانی مشخص هستند.
- **سادگی پایان خط:** تابع به‌صورت خودکار `'\n'` را به خروجی اضافه می‌کند.
- **هماهنگی با `std::format`:** قواعد قالب‌بندی با قابلیت معرفی‌شده در ++C20 یکسان‌اند.
- **پشتیبانی از انواع سفارشی:** انواع کاربر می‌توانند با تخصصی‌سازی `std::formatter` قابل قالب‌بندی شوند.

## معرفی و سربرگ موردنیاز

برای استفاده از overloadهای اصلی `std::println` باید سربرگ `<print>` را وارد کرد:

```cpp
#include <print>

int main() {
    std::println("Hello, world!");
}
```

این برنامه متن `Hello, world!` را چاپ می‌کند و سپس یک خط جدید می‌نویسد.

نکته مهم این است که نام تابع `println` به معنای چاپ و سپس رفتن به خط بعدی است. این رفتار با `std::print` تفاوت دارد؛ `std::print` به‌خودی‌خود خط جدید اضافه نمی‌کند.

## امضای تابع و overloadها

در ++C23 دو overload اصلی در سربرگ `<print>` معرفی شده‌اند:

```cpp
template<class... Args>
void println(std::format_string<Args...> fmt, Args&&... args);

template<class... Args>
void println(
    std::FILE* stream,
    std::format_string<Args...> fmt,
    Args&&... args
);
```

overload نخست خروجی را به `stdout` می‌فرستد. overload دوم مقصد را با یک اشاره‌گر `std::FILE` مشخص می‌کند؛ بنابراین می‌توان خروجی را به فایل بازشده یا streamهای استاندارد C هدایت کرد.

هر دو overload، آرگومان‌ها را مطابق `fmt` قالب‌بندی می‌کنند و در پایان یک `'\n'` اضافه می‌کنند. مقدار بازگشتی تابع `void` است.

### چاپ در خروجی استاندارد

```cpp
#include <print>

int main() {
    std::println("Application started");
    std::println("User: {}", "Alice");
    std::println("Retry count: {}", 3);
}
```

### چاپ در فایل با std::FILE

```cpp
#include <cstdio>
#include <print>

int main() {
    if (std::FILE* file = std::fopen("application.log", "w")) {
        std::println(file, "Application started");
        std::println(file, "Exit code: {}", 0);
        std::fclose(file);
    }
}
```

در مثال بالا، بازشدن فایل بررسی شده است. تابع `std::println` مالکیت فایل را به دست نمی‌گیرد و آن را نمی‌بندد؛ مدیریت طول عمر `std::FILE` همچنان بر عهده فراخواننده است.

## تفاوت std::print و std::println

هر دو تابع در ++C23 و در سربرگ `<print>` ارائه شده‌اند. تفاوت اصلی آن‌ها در افزودن خط جدید است.

```cpp
#include <print>

int main() {
    std::print("Loading");
    std::print("...");
    std::println(" done");
    std::println("Ready");
}
```

خروجی:

```text
Loading... done
Ready
```

برای ساخت خروجی چندبخشی در یک خط، `std::print` مناسب است. برای خروجی‌هایی که هر رکورد یا پیام باید خط مستقلی داشته باشد، `std::println` انتخاب طبیعی‌تری است.

استفاده از `std::println` برای رشته‌ای که خودش با `'\n'` تمام می‌شود، معمولاً دو خط جدید متوالی ایجاد می‌کند. بنابراین باید مشخص باشد که پایان خط در داده وجود دارد یا قرار است تابع آن را اضافه کند.

## قالب‌بندی آرگومان‌ها

قواعد format string در `std::println` از خانواده `std::format` پیروی می‌کنند. جای‌نگهدارهای `{}` با آرگومان‌ها پر می‌شوند و می‌توان مشخصات قالب‌بندی را پس از دونقطه نوشت.

### جای‌نگهدارهای ساده

```cpp
#include <print>
#include <string>

int main() {
    std::string name = "Ada";
    int age = 36;

    std::println("Name: {}, age: {}", name, age);
}
```

جای‌نگهدارها به ترتیب با آرگومان‌های متناظر پر می‌شوند. در format stringهای معمولی، تعداد جای‌نگهدارها و آرگومان‌ها باید با یکدیگر سازگار باشد.

### قالب‌بندی عددها

```cpp
#include <print>

int main() {
    int value = 255;

    std::println("Decimal: {}", value);
    std::println("Hexadecimal: {:x}", value);
    std::println("Uppercase hexadecimal: {:X}", value);
    std::println("Binary: {:b}", value);
    std::println("Padded: {:08}", value);

    double pi = 3.1415926535;
    std::println("Pi: {:.2f}", pi);
}
```

مشخص‌کننده‌های قالب‌بندی امکان کنترل مبنای نمایش، عرض فیلد، دقت اعشار و موارد مشابه را فراهم می‌کنند. قواعد دقیق هر نوع به formatter مربوط به همان نوع وابسته است.

### تعیین ترتیب آرگومان‌ها

در format string می‌توان از index برای تعیین صریح آرگومان استفاده کرد:

```cpp
#include <print>

int main() {
    std::println("{1} is learning {0}", "C++", "Nina");
}
```

در این نمونه، `{1}` به آرگومان دوم و `{0}` به آرگومان اول اشاره می‌کند. در یک format string نباید شیوه‌های شماره‌گذاری دستی و خودکار را به‌صورت ناسازگار با هم ترکیب کرد.

### قالب‌بندی متن و تراز

```cpp
#include <print>

int main() {
    std::println("|{:<12}|", "left");
    std::println("|{:^12}|", "center");
    std::println("|{:>12}|", "right");
}
```

این مشخص‌کننده‌ها متن را در یک میدان با عرض معین چپ‌چین، وسط‌چین یا راست‌چین می‌کنند. عرض میدان حداقل فضای اختصاص‌یافته است؛ اگر متن از آن بلندتر باشد، معمولاً بریده نمی‌شود.

## نوع‌امن بودن format string

پارامتر قالب از نوع `std::format_string<Args...>` است. این نوع برای format stringهای ثابت، امکان بررسی سازگاری قالب و آرگومان‌ها در زمان کامپایل را فراهم می‌کند.

```cpp
#include <print>

int main() {
    int count = 42;

    std::println("Count: {}", count);

    // This format string is invalid for the supplied argument.
    // std::println("Count: {:s}", count);
}
```

در نمونه بالا، مشخص‌کننده `s` برای مقدار صحیح مناسب نیست و پیاده‌سازی استاندارد باید خطا را در زمان کامپایل تشخیص دهد. خط نامعتبر در مثال کامنت شده است تا برنامه قابل کامپایل بماند.

نوع‌امن بودن به معنای حذف همه خطاهای زمان اجرا نیست. formatter سفارشی می‌تواند هنگام اجرا exception پرتاب کند و نوشتن روی مقصد خروجی نیز ممکن است با خطا مواجه شود.

## قالب‌بندی انواع سفارشی

برای چاپ یک نوع کاربرساخته، باید formatter سازگار با چارچوب `std::format` ارائه شود. این کار معمولاً با تخصصی‌سازی `std::formatter` انجام می‌شود.

```cpp
#include <format>
#include <print>
#include <string>

struct User {
    std::string name;
    int id;
};

template<>
struct std::formatter<User> : std::formatter<std::string> {
    auto format(const User& user, std::format_context& ctx) const {
        return std::formatter<std::string>::format(
            user.name + " (#" + std::to_string(user.id) + ")",
            ctx
        );
    }
};

int main() {
    User user{"Ada", 7};
    std::println("User: {}", user);
}
```

این formatter از formatter رشته استفاده می‌کند و نمایش متنی شیء را به آن می‌سپارد. در پروژه واقعی بهتر است formatter تا حد امکان ساده، قابل پیش‌بینی و مستقل از وضعیت خارجی باشد.

نکته طراحی این است که formatter مسئول تبدیل مقدار به نمایش متنی است، نه انجام عملیات جانبی مانند نوشتن مستقیم در فایل، تغییر وضعیت برنامه یا ثبت log. چنین جداسازی‌ای استفاده مجدد از نوع در `std::format` و دیگر توابع قالب‌بندی را آسان‌تر می‌کند.

## خروجی Unicode و رفتار وابسته به محیط

خانواده توابع چاپ در `<print>` با درنظرگرفتن خروجی متن Unicode طراحی شده است. در محیط‌هایی که مقصد خروجی به‌عنوان terminal با قابلیت Unicode شناخته می‌شود، کتابخانه می‌تواند برای جلوگیری از خروجی ناقص یا خراب، مسیر مناسب چاپ Unicode را به کار بگیرد.

بااین‌حال، نمایش صحیح متن به عوامل بیرون از خود تابع نیز وابسته است؛ از جمله encoding محیط، تنظیمات terminal، locale سیستم‌عامل، فونت و پیکربندی کنسول. بنابراین صرف استفاده از `std::println` تضمین نمی‌کند که همه محیط‌ها متن فارسی یا سایر نویسه‌های غیر ASCII را یکسان نمایش دهند.

برای خروجی فایل نیز باید encoding مورد انتظار مصرف‌کننده فایل را در نظر گرفت. تابع، سیاست عمومی و قابل‌حملی برای تبدیل محتوای دلخواه به encoding اختصاصی برنامه شما ارائه نمی‌کند.

## هم‌زمانی و چندرشته‌ای

توابع چاپ استاندارد برای جلوگیری از درهم‌تنیدگی خروجی در سناریوهای متداول، از سازوکارهای داخلی کتابخانه استفاده می‌کنند؛ اما نباید از این موضوع نتیجه گرفت که چند فراخوانی مستقل `std::println` یک تراکنش واحد یا یک ترتیب قطعی میان threadها ایجاد می‌کنند.

اگر چند thread هم‌زمان پیام چاپ کنند، ترتیب پیام‌ها به زمان‌بندی و پیاده‌سازی وابسته است. برای ثبت یک رکورد چندبخشی که باید به‌صورت یک واحد منطقی دیده شود، بهتر است متن کامل ابتدا با `std::format` ساخته شود و سپس با سازوکار synchronization مناسب نوشته شود؛ یا دسترسی به خروجی در سطح برنامه با mutex هماهنگ شود.

```cpp
#include <format>
#include <mutex>
#include <print>
#include <string>

std::mutex output_mutex;

void log_message(int thread_id, int event_id) {
    std::string message =
        std::format("thread={}, event={}", thread_id, event_id);

    std::lock_guard<std::mutex> lock(output_mutex);
    std::println("{}", message);
}
```

در این مثال، قفل‌گذاری در سطح برنامه ترتیب دسترسی بخش محافظت‌شده به خروجی را کنترل می‌کند. اگر تمام بخش‌های برنامه از همین سیاست پیروی نکنند، همچنان امکان درهم‌آمیختگی با خروجی سایر بخش‌ها وجود دارد.

## خطاها و exceptionها

فراخوانی `std::println` ممکن است در شرایط مختلف exception پرتاب کند:

- در صورت شکست تخصیص حافظه، `std::bad_alloc` ممکن است پرتاب شود.
- در صورت شکست عملیات نوشتن روی stream، `std::system_error` ممکن است پرتاب شود.
- اگر formatter استفاده‌شده exception پرتاب کند، آن exception به فراخواننده منتقل می‌شود؛ برای مثال `std::format_error` در موارد مرتبط با قالب‌بندی.

بنابراین اگر خروجی بخشی حیاتی از یک عملیات است، باید سیاست مدیریت خطا مشخص باشد. در کدهای ساده CLI ممکن است انتشار exception به لایه بالاتر کافی باشد، اما در سیستم‌های حساس یا سرویس‌های بلندمدت باید شکست نوشتن خروجی به‌صورت آگاهانه مدیریت شود.

همچنین `std::println` مقدار موفقیت یا تعداد بایت‌های نوشته‌شده را برنمی‌گرداند. اگر APIای با قرارداد دقیق‌تر برای مدیریت وضعیت نوشتن لازم است، باید گزینه‌های دیگر I/O و سیاست خطای متناسب با برنامه بررسی شوند.

## تفاوت با std::cout و printf

### مقایسه با std::cout

`std::cout` مبتنی بر stream و زنجیره `operator<<` است. این روش برای اتصال انواع مختلف به stream، کار با streamهای سفارشی و ترکیب با قابلیت‌های قدیمی iostream مناسب است.

در مقابل، `std::println` قالب و آرگومان‌ها را به‌شکل یک واحد مشخص دریافت می‌کند. این سبک اغلب برای پیام‌های وضعیت، خروجی CLI و logهای ساده خواناتر است. اما جایگزین کامل iostream نیست؛ برای ورودی، streamهای سفارشی یا کدهایی که عمیقاً بر رفتار stream تکیه دارند، `std::cout` همچنان کاربرد دارد.

### مقایسه با printf

`printf` از format stringهای C و آرگومان‌های variadic استفاده می‌کند. این API در پروژه‌های C و مرزهای ABI با C همچنان رایج است، اما تطبیق نوع آرگومان و مشخص‌کننده قالب به شکل `std::format_string` نوع‌امن نیست.

`std::println` از قواعد قالب‌بندی مدرن کتابخانه ++C استفاده می‌کند و با formatterهای سفارشی قابل توسعه است. در پروژه ++C جدید، معمولاً برای خروجی قالب‌بندی‌شده انتخاب مناسب‌تری است؛ مگر اینکه سازگاری با APIهای C، محدودیت محیط یا الزام یک کتابخانه خاص استفاده از `printf` را ضروری کند.

| ویژگی | `std::println` | `std::cout` | `printf` |
|---|---|---|---|
| قالب‌بندی | مبتنی بر `std::format` | مبتنی بر `operator<<` و manipulatorها | مبتنی بر format specifierهای C |
| بررسی نوع قالب ثابت | بله، برای format stringهای معتبر در زمان کامپایل | وابسته به overloadهای عملگر | خیر، به شکل نوع‌امن |
| افزودن خودکار خط جدید | بله | خیر | خیر |
| formatter سفارشی | با `std::formatter` | با overload یا inserter مناسب | محدود به قراردادهای C |
| مقصد خروجی | `stdout` یا `std::FILE*` در overloadهای `<print>` | شیء stream | `stdout` یا `FILE*` |
| استاندارد | ++C23 | نسخه‌های اولیه ++C | C و قابل استفاده در ++C |

## تفاوت overloadهای سربرگ <ostream>

در کتابخانه استاندارد ++C23، قابلیت‌های چاپ قالب‌بندی‌شده برای `std::ostream` نیز ارائه شده‌اند. این APIها با overloadهای سربرگ `<print>` که مقصدشان `stdout` یا `std::FILE*` است، یکسان نیستند.

برای نمونه، نسخه `std::println` مربوط به `std::ostream` در سربرگ `<ostream>` در دسترس است:

```cpp
#include <ostream>
#include <sstream>
#include <string>

int main() {
    std::ostringstream output;
    std::println(output, "Value: {}", 42);

    std::string result = output.str();
}
```

این overload برای نوشتن در streamهای ++C مفید است. در نتیجه، هنگام بررسی مستندات یا خطای کامپایل باید به سربرگ و نوع مقصد توجه کرد: `<print>` برای خانواده چاپ مبتنی بر `stdout` و `std::FILE` است و `<ostream>` overloadهای streamمحور را فراهم می‌کند.

## نسخه استاندارد و پشتیبانی کامپایلر

`std::println` در ++C23 استاندارد شده است، اما پشتیبانی عملی آن به نسخه کامپایلر و مهم‌تر از آن به نسخه Standard Library وابسته است. کامپایلر ممکن است حالت ++C23 را بشناسد، درحالی‌که کتابخانه همراه آن هنوز سربرگ `<print>` را به‌طور کامل ارائه نکرده باشد.

برای نمونه، فعال‌سازی استاندارد در GCC معمولاً با `-std=c++23` و در Clang نیز با `-std=c++23` انجام می‌شود. در MSVC می‌توان از گزینه `/std:c++latest` یا گزینه استاندارد متناظر با نسخه ابزار استفاده کرد؛ جزئیات دقیق به نسخه ابزار وابسته است.

نمونه فرمان‌ها:

```bash
g++ -std=c++23 -Wall -Wextra -pedantic main.cpp -o app
clang++ -std=c++23 -Wall -Wextra -pedantic main.cpp -o app
```

در MSVC:

```bat
cl /std:c++latest /EHsc main.cpp
```

وجود گزینه استاندارد کافی نیست. در صورت خطا در پیدا کردن `<print>` یا نبودن `std::println`، نسخه کتابخانه استاندارد و جدول پشتیبانی همان toolchain را بررسی کنید.

### بررسی feature-test macro

برای تشخیص پشتیبانی کتابخانه‌ای می‌توان از macro زیر استفاده کرد:

```cpp
#include <version>

#if defined(__cpp_lib_print) && __cpp_lib_print >= 202207L
    #define HAS_STD_PRINT 1
#else
    #define HAS_STD_PRINT 0
#endif
```

مقدار `202207L` نشان‌دهنده قابلیت formatted output استانداردشده برای ++C23 است. macroهای feature-test مربوط به کتابخانه، راهی دقیق‌تر از اتکا به شماره نسخه کامپایلر برای تشخیص وجود یک قابلیت مشخص هستند.

در کدی که قرار است روی toolchainهای متنوع ساخته شود، بهتر است بررسی feature-test macro در کنار تنظیم استاندارد build system و آزمون واقعی compile قرار گیرد.

## محدودیت‌ها و نکات طراحی

### این تابع ابزار logging کامل نیست

`std::println` صرفاً متن قالب‌بندی‌شده را به مقصد می‌نویسد. این تابع امکاناتی مانند سطح‌بندی log، چرخش فایل، timestamp خودکار، ساختاردهی رویدادها، فیلتر پیام یا ارسال غیرهم‌زمان را فراهم نمی‌کند.

برای برنامه کوچک، ابزار خط فرمان یا پیام‌های تشخیصی ساده، استفاده مستقیم از آن مناسب است. برای سرویس بزرگ یا برنامه چندرشته‌ای با نیازهای عملیاتی جدی، یک logging library اختصاصی انتخاب مناسب‌تری خواهد بود.

### مقصد خروجی را با نوع مناسب انتخاب کنید

overload بدون stream به `stdout` می‌نویسد. اگر مقصد باید فایل یا stream مشخصی باشد، overload دارای `std::FILE*` یا API مربوط به `std::ostream` را متناسب با نوع مقصد انتخاب کنید. نباید `std::ostream*` را به‌جای `std::FILE*` به overload سربرگ `<print>` ارسال کرد؛ این دو نوع و دو خانواده API متفاوت‌اند.

### خط جدید را دوباره اضافه نکنید

از آنجا که `std::println` خودش یک `'\n'` اضافه می‌کند، افزودن خط جدید به انتهای format string می‌تواند یک خط خالی ناخواسته ایجاد کند. اگر کنترل دقیق‌تر محل پایان خط لازم است، `std::print` گزینه مناسب‌تری است.

### format string باید با آرگومان‌ها سازگار باشد

در format string ثابت، جای‌نگهدار نامعتبر یا تعداد ناسازگار آرگومان‌ها معمولاً خطای کامپایل ایجاد می‌کند. این ویژگی مزیت مهمی است، اما در مهاجرت از `printf` باید مشخص‌کننده‌های قالب قدیمی بازبینی شوند؛ قواعد `%d` و `{}` یکسان نیستند.

### خروجی تابع الزاماً بلافاصله روی رسانه پایدار نمی‌شود

افزودن `'\n'` به معنی تضمین flush شدن دیسک یا حتی تضمین پایداری فوری داده روی رسانه ذخیره‌سازی نیست. اگر دوام داده یا ترتیب flush اهمیت دارد، باید از API و سیاست buffering مناسب استفاده شود. خط جدید و flush دو مفهوم جدا هستند.

## نمونه کاربردی

نمونه زیر چند قابلیت متداول را در یک برنامه خط فرمان ترکیب می‌کند:

```cpp
#include <print>
#include <string>
#include <vector>

struct Task {
    int id;
    std::string title;
    bool completed;
};

int main() {
    const std::vector<Task> tasks{
        {1, "Review pull request", true},
        {2, "Update documentation", false},
        {3, "Run test suite", true}
    };

    std::println("Task report");
    std::println("{:-<48}", "");

    for (const Task& task : tasks) {
        const char* status = task.completed ? "done" : "pending";
        std::println("#{:<3} {:<28} [{}]", task.id, task.title, status);
    }

    std::println("{:-<48}", "");
    std::println("Total tasks: {}", tasks.size());
}
```

در این برنامه، قالب‌بندی عرض ستون‌ها را کنترل می‌کند و هر فراخوانی `std::println` یک خط مستقل تولید می‌کند. چنین الگویی برای گزارش‌های متنی ساده در ابزارهای CLI مفید است.

## خطاهای رایج

- **فراموش‌کردن سربرگ:** برای overloadهای اصلی باید `<print>` وارد شود.
- **فرض پشتیبانی صرفاً بر اساس `-std=c++23`:** حالت زبان و پیاده‌سازی کتابخانه استاندارد دو موضوع جدا هستند.
- **استفاده از قواعد `printf`:** مشخص‌کننده‌هایی مانند `%d` در format string مربوط به `std::println` معنا ندارند.
- **افزودن `'\n'` غیرضروری:** این کار می‌تواند فاصله خالی ناخواسته بین پیام‌ها ایجاد کند.
- **اشتباه گرفتن `std::FILE*` و `std::ostream`:** برای هرکدام باید overload و سربرگ مربوط انتخاب شود.
- **فرض ترتیب قطعی بین threadها:** هم‌زمانی فراخوانی‌ها، ترتیب کلی پیام‌ها را به‌صورت قراردادی برای برنامه تضمین نمی‌کند.
- **فرض flush شدن با پایان خط:** `'\n'` معادل flush یا تضمین ذخیره پایدار نیست.
- **نادیده‌گرفتن exceptionها:** خطای formatter یا شکست نوشتن ممکن است به‌صورت exception به فراخواننده منتقل شود.

## جمع‌بندی

`std::println` در ++C23 راهی استاندارد، خوانا و نوع‌امن برای چاپ متن قالب‌بندی‌شده همراه با خط جدید فراهم می‌کند. این تابع بر پایه چارچوب `std::format` ساخته شده است و برای خروجی CLI، پیام‌های وضعیت، گزارش‌های متنی و موارد مشابه انتخاب مناسبی محسوب می‌شود.

برای استفاده درست از آن باید به سه نکته توجه کرد: سربرگ و overload متناسب با مقصد خروجی را انتخاب کنید، پشتیبانی واقعی Standard Library را جدا از حالت زبان بررسی کنید و در کاربردهای چندرشته‌ای یا حساس به خطا، سیاست synchronization و مدیریت exception را در سطح برنامه تعریف کنید. `std::println` جایگزین همه ابزارهای I/O یا logging نیست، اما برای بسیاری از نیازهای چاپ قالب‌بندی‌شده در برنامه‌های مدرن ++C انتخابی ساده و مؤثر است.
