# آشنایی با `std::views::pairwise` در ++C23

## مقدمه

در بسیاری از الگوریتم‌ها لازم است هر عنصر یک بازه را همراه با عنصر بعدی آن بررسی کنیم؛ برای نمونه، محاسبه اختلاف دو مقدار متوالی، تشخیص تغییرات در یک دنباله، بررسی یال‌های متوالی یک مسیر یا ساختن بازه‌های دو‌تایی از داده‌ها. پیاده‌سازی سنتی این مسئله معمولاً به iterator، شرط پایان و افزایش دستی iterator نیاز دارد.

قابلیت `std::views::pairwise` در کتابخانه استاندارد ++C23 این الگو را به‌شکل یک `view` بیان می‌کند. این ابزار از هر موقعیت، یک زوج شامل عنصر جاری و عنصر بعدی می‌سازد و بدون کپی‌کردن عناصر، آن‌ها را در اختیار مصرف‌کننده قرار می‌دهد.

## معرفی قابلیت و جایگاه استانداردی

نام `std::views::pairwise` در فضای نام `std::views` و در هدر `<ranges>` تعریف شده و از ++C23 در دسترس است. این قابلیت در واقع نام مستعارِ مفهومی برای `std::views::adjacent<2>` است؛ بنابراین رفتار و محدودیت‌های آن از `adjacent_view` می‌آیند.

```cpp
#include <ranges>
#include <vector>

int main() {
    std::vector values{10, 20, 30, 40};

    for (auto [current, next] : values | std::views::pairwise) {
        // Use current and next
    }
}
```

در مثال بالا، زوج‌های `(10, 20)`، `(20, 30)` و `(30, 40)` تولید می‌شوند. تعداد زوج‌ها برای بازه‌ای با `n` عنصر، در صورت `n >= 2` برابر `n - 1` است؛ در غیر این صورت خروجی خالی خواهد بود.

## مفهوم پنجره مجاور

قابلیت `pairwise` نمونه‌ای از مفهوم sliding window با اندازه ثابت دو است. اگر عناصر بازه ورودی را با `x[0]` تا `x[n-1]` نشان دهیم، خروجی از زوج‌های زیر تشکیل می‌شود:

```text
(x[0], x[1])
(x[1], x[2])
(x[2], x[3])
...
(x[n-2], x[n-1])
```

هر زوج با زوج قبلی یک عنصر مشترک دارد. در نتیجه، این view نه زوج‌های مستقل و غیرهم‌پوشان، بلکه پنجره‌های متوالی و هم‌پوشان تولید می‌کند.

نوع عنصر خروجی یک `std::tuple` دو‌عضوی است که اجزای آن به عناصر بازه اصلی ارجاع می‌دهند. به همین دلیل، در حالت معمول ساختن زوج‌ها به معنی کپی‌شدن مقدار عناصر نیست. نوع دقیق reference و رفتار `const` تابع نوع بازه ورودی است.

## نحوه استفاده از قابلیت

### استفاده مستقیم

ساده‌ترین شکل استفاده، اعمال adaptor روی یک range است:

```cpp
#include <iostream>
#include <ranges>
#include <vector>

int main() {
    std::vector values{3, 8, 12, 19};

    for (auto pair : values | std::views::pairwise) {
        std::cout << std::get<0>(pair)
                  << " -> "
                  << std::get<1>(pair)
                  << '\n';
    }
}
```

در این نمونه، عملگر pipe خروجی range سمت چپ را به adaptor سمت راست می‌دهد. همچنین می‌توان از شکل فراخوانی مستقیم `std::views::pairwise(values)` استفاده کرد.

### استفاده با structured binding

از آنجا که هر عنصر خروجی tuple-like است، می‌توان از structured binding برای نام‌گذاری دو عضو استفاده کرد:

```cpp
#include <iostream>
#include <ranges>
#include <vector>

int main() {
    std::vector values{2, 5, 9, 14};

    for (auto [left, right] : values | std::views::pairwise) {
        std::cout << left << ", " << right << '\n';
    }
}
```

در این مثال، متغیرهای `left` و `right` از اعضای tuple مقدار می‌گیرند. چون اعضای tuple ارجاع به عناصر اصلی هستند، کپی‌شدن خود عناصر به‌وسیله view انجام نمی‌شود؛ بااین‌حال نوع متغیرهای structured binding و نحوه استفاده از `auto` یا `auto&` در حلقه بر کپی یا ارجاع در سطح متغیرهای محلی اثر می‌گذارد. اگر قصد تغییر عناصر اصلی را دارید، رفتار ارجاعی را آگاهانه انتخاب کنید.

### استفاده با فراخوانی مستقیم

شکل فراخوانی مستقیم برای ترکیب با متغیرهای میانی یا APIهایی که pipe در آن‌ها مناسب نیست، مفید است:

```cpp
auto adjacent_pairs = std::views::pairwise(values);

for (auto [a, b] : adjacent_pairs) {
    // Process the adjacent elements
}
```

این عبارت یک view می‌سازد؛ به‌خودی‌خود عناصر را پیمایش یا در container جدید ذخیره نمی‌کند.

## الزامات بازه ورودی

یکی از محدودیت‌های مهم `std::views::pairwise` این است که range ورودی باید مفهوم `std::ranges::forward_range` را مدل کند. بنابراین یک `input_range` صرف، مانند برخی streamها یا rangeهایی که فقط یک‌بار قابل پیمایش‌اند، کافی نیست.

این شرط از ماهیت الگوریتم ناشی می‌شود: برای تشکیل پنجره‌های هم‌پوشان، پیاده‌سازی باید بتواند iteratorهای لازم را نگه دارد و به عناصر مجاور دسترسی پایدار داشته باشد. `forward_range` حداقل قابلیت مورد نیاز را فراهم می‌کند.

ورودی همچنین باید یک `viewable_range` باشد تا adaptor بتواند آن را به view مناسب تبدیل کند. این الزام به معنی آن نیست که کاربر همیشه باید از قبل یک view ساخته باشد؛ containerهایی مانند `std::vector` نیز مستقیماً قابل استفاده‌اند.

## رفتار ارجاعی و تغییر عناصر

اعضای tuple خروجی به عناصر اصلی range اشاره می‌کنند. بنابراین اگر range قابل‌تغییر باشد، می‌توان از زوج‌ها برای تغییر عناصر اصلی استفاده کرد:

```cpp
#include <ranges>
#include <vector>

int main() {
    std::vector values{1, 2, 3, 4};

    for (auto pair : values | std::views::pairwise) {
        std::get<0>(pair) *= 10;
    }
}
```

در این مثال، عنصرهای اول زوج‌ها تغییر می‌کنند؛ در نتیجه عناصر متناظر در `values` نیز تغییر خواهند کرد. توجه کنید که عنصرهای میانی ممکن است در دو زوج متوالی ظاهر شوند؛ پس تغییر یک عنصر می‌تواند در تکرار بعدی نیز دیده شود.

برای خواندن صرف، استفاده از متغیرهای محلی معمولی کافی است. برای تغییر عناصر، بهتر است قصد خود را با نوع‌های ارجاعی و structured binding روشن کنید و از فرض‌کردن اینکه هر زوج یک کپی مستقل از داده‌هاست، بپرهیزید.

## ترکیب با سایر range adaptorها

قدرت اصلی `pairwise` زمانی آشکار می‌شود که با adaptorهای دیگر ترکیب شود. برای نمونه، می‌توان ابتدا داده‌ها را فیلتر کرد و سپس زوج‌های مجاور را ساخت:

```cpp
#include <iostream>
#include <ranges>
#include <vector>

int main() {
    std::vector values{1, 2, 3, 4, 5, 6, 7, 8};

    auto even_values = values
        | std::views::filter([](int value) {
              return value % 2 == 0;
          });

    for (auto [a, b] : even_values | std::views::pairwise) {
        std::cout << a << " - " << b << '\n';
    }
}
```

در این نمونه، مجاورت بر اساس دنباله خروجی `filter` تعریف می‌شود، نه بر اساس اندیس‌های متوالی در container اصلی. بنابراین زوج‌های حاصل `(2, 4)`، `(4, 6)` و `(6, 8)` هستند.

همچنین می‌توان از `transform` برای تبدیل نتیجه هر زوج استفاده کرد:

```cpp
#include <iostream>
#include <ranges>
#include <vector>

int main() {
    std::vector values{4, 9, 15, 22};

    auto differences = values
        | std::views::pairwise
        | std::views::transform([](auto pair) {
              return std::get<1>(pair) - std::get<0>(pair);
          });

    for (int difference : differences) {
        std::cout << difference << '\n';
    }
}
```

خروجی این مثال اختلاف عناصر متوالی، یعنی `5`، `6` و `7` است. این زنجیره همچنان lazy است؛ محاسبه هر اختلاف هنگام پیمایش انجام می‌شود.

## کاربردهای عملی

### محاسبه اختلاف عناصر متوالی

یکی از کاربردهای رایج، محاسبه تغییرات بین دو نمونه متوالی است. این الگو در تحلیل سری‌های زمانی، اندازه‌گیری‌ها و داده‌های عددی کاربرد دارد:

```cpp
#include <iostream>
#include <ranges>
#include <vector>

int main() {
    std::vector temperatures{18, 20, 19, 23, 25};

    auto changes = temperatures
        | std::views::pairwise
        | std::views::transform([](auto values) {
              return std::get<1>(values) - std::get<0>(values);
          });

    for (int change : changes) {
        std::cout << change << ' ';
    }
}
```

### بررسی مرتب‌بودن صعودی

با بررسی تمام زوج‌های مجاور می‌توان صعودی‌بودن یک دنباله را ارزیابی کرد:

```cpp
#include <ranges>
#include <vector>

bool is_strictly_increasing(const std::vector<int>& values) {
    for (auto [a, b] : values | std::views::pairwise) {
        if (a >= b) {
            return false;
        }
    }

    return true;
}
```

برای بازه‌ای با صفر یا یک عنصر، حلقه اجرا نمی‌شود و تابع `true` برمی‌گرداند؛ این نتیجه با تعریف معمولِ صعودی‌بودن اکید برای چنین دنباله‌ای سازگار است.

### پیمایش یال‌های متوالی یک مسیر

اگر نقاط یک مسیر به‌ترتیب ذخیره شده باشند، هر زوج متوالی نماینده یک یال است. این روش برای محاسبه طول قطعه‌های مسیر یا بررسی اتصال نقاط کاربرد دارد:

```cpp
#include <cmath>
#include <iostream>
#include <ranges>
#include <utility>
#include <vector>

int main() {
    using Point = std::pair<double, double>;

    std::vector<Point> path{
        {0.0, 0.0},
        {3.0, 4.0},
        {6.0, 4.0}
    };

    for (auto [from, to] : path | std::views::pairwise) {
        const double dx = to.first - from.first;
        const double dy = to.second - from.second;
        const double length = std::hypot(dx, dy);

        std::cout << length << '\n';
    }
}
```

## تفاوت با راهکارهای نزدیک

### مقایسه با حلقه مبتنی بر iterator

در روش دستی معمولاً دو iterator نگهداری می‌شوند؛ یکی برای عنصر جاری و دیگری برای عنصر بعدی. سپس هر دو تا رسیدن iterator دوم به پایان جلو می‌روند. این روش همچنان معتبر است و در شرایطی که کنترل دقیق‌تری بر پیمایش لازم است، می‌تواند مناسب باشد.

مزیت `pairwise` بیان مستقیم قصد برنامه‌نویس و کاهش خطاهای مربوط به شرط پایان و افزایش iteratorهاست. در مقابل، حلقه دستی برای ورودی‌های تک‌گذر یا الگوریتم‌هایی با منطق پیمایش غیرمعمول ممکن است انتخاب مناسب‌تری باشد.

### مقایسه با `std::views::adjacent`

آداپتور `std::views::adjacent<N>` تعمیم‌یافته همین ایده است و پنجره‌هایی با اندازه ثابت `N` تولید می‌کند. نام `std::views::pairwise` دقیقاً معادل `std::views::adjacent<2>` است.

```cpp
auto pairs = values | std::views::adjacent<2>;
auto triples = values | std::views::adjacent<3>;
```

در هر دو حالت، خروجی شامل tupleهایی از ارجاع به عناصر مجاور است. اندازه پنجره در زمان کامپایل و از طریق پارامتر قالب تعیین می‌شود.

### مقایسه با `std::views::slide`

آداپتور `std::views::slide` نیز پنجره‌های لغزان می‌سازد، اما هر عنصر خروجی آن یک range است، نه یک tuple از ارجاع‌ها. اندازه پنجره در فراخوانی `slide` به‌صورت آرگومان داده می‌شود.

بنابراین اگر به یک پنجره عمومی از عناصر برای پیمایش داخلی نیاز دارید، `slide` معمولاً طبیعی‌تر است؛ اما اگر دقیقاً به چند عنصر مجاور با ساختار tuple-like نیاز دارید، `adjacent` یا `pairwise` انتخاب مناسب‌تری است.

### مقایسه با `std::views::zip`

آداپتور `std::views::zip` عناصر هم‌مکان چند range مستقل را با هم ترکیب می‌کند. در مقابل، `pairwise` دو عنصر مجاور از یک range واحد را کنار هم قرار می‌دهد. پس این دو ابزار از نظر مسئله‌ای که حل می‌کنند متفاوت‌اند.

## ویژگی‌های پیمایش و کارایی

خروجی `adjacent_view` همواره یک `forward_range` است. اگر view پایه قابلیت‌های قوی‌تری داشته باشد، view حاصل نیز می‌تواند آن‌ها را حفظ کند؛ از جمله `bidirectional_range`، `random_access_range` و `sized_range`.

در یک range اندازه‌پذیر با `n` عنصر، اندازه خروجی برای `n >= 2` برابر `n - 1` است و برای ورودی کوچک‌تر از دو، صفر خواهد بود. این view داده‌های زوج‌ها را در یک container جداگانه ذخیره نمی‌کند؛ در نتیجه هزینه ساخت آن معمولاً ناچیز است و هزینه اصلی در زمان پیمایش و عملیاتی است که مصرف‌کننده روی هر زوج انجام می‌دهد.

بااین‌حال، نباید از این موضوع نتیجه گرفت که هر ترکیب adaptor الزاماً هزینه ثابت یا دسترسی تصادفی دارد. قابلیت‌های نهایی به range پایه و adaptorهای زنجیره‌شده وابسته‌اند. همچنین اگر در `transform` عملیات پرهزینه‌ای انجام دهید، آن عملیات هنگام dereference و مصرف عناصر اجرا می‌شود.

## طول عمر داده و ملاحظات ایمنی

از آنجا که عناصر خروجی به range پایه ارجاع می‌دهند، طول عمر داده اصلی باید از طول عمر استفاده از view و iteratorهای آن بیشتر باشد. نگهداری view به‌تنهایی تضمین نمی‌کند که حافظه متعلق به یک container خارجی همچنان معتبر است.

همچنین عملیات‌هایی که iteratorهای container پایه را نامعتبر می‌کنند، می‌توانند استفاده بعدی از view را نیز نامعتبر کنند. برای نمونه، تغییر ساختار `std::vector` از طریق عملیاتی که باعث reallocation می‌شود، ممکن است ارجاع‌ها و iteratorهای مورد استفاده view را بی‌اعتبار کند.

قابلیت `borrowed_range` برای `adjacent_view` از view پایه تبعیت می‌کند. این ویژگی به معنای مالکیت داده‌ها نیست؛ تنها درباره اعتبار iteratorهای باقی‌مانده پس از نابودی شیء view و با توجه به ویژگی range پایه صحبت می‌کند. بنابراین نباید آن را جایگزین مدیریت صحیح طول عمر container دانست.

## محدودیت‌ها و خطاهای رایج

- ورودی باید `forward_range` باشد؛ بنابراین نمی‌توان هر stream یا `input_range` تک‌گذر را مستقیماً به `pairwise` داد.
- برای range خالی یا تک‌عضوی، هیچ زوجی تولید نمی‌شود. کدی که بدون بررسی اندازه فرض کند حداقل یک زوج وجود دارد، ممکن است منطق نادرستی داشته باشد.
- زوج‌ها هم‌پوشانی دارند؛ عنصر میانی در دو زوج متوالی ظاهر می‌شود. تغییر آن در یک مرحله می‌تواند در مرحله بعد قابل مشاهده باشد.
- زوج خروجی یک کپی مستقل از دو مقدار نیست؛ اجزای آن به عناصر اصلی ارجاع دارند.
- مجاورت پس از اعمال adaptorهای قبلی تعریف می‌شود. برای نمونه، `filter | pairwise` زوج‌های مجاور در خروجی فیلتر را تولید می‌کند.
- view تنبل است؛ تا زمانی که پیمایش انجام نشود، transformهای زنجیره‌شده لزوماً اجرا نمی‌شوند.
- نباید view را پس از نابودی range پایه یا پس از نامعتبرشدن iteratorهای آن استفاده کرد.

## بررسی پشتیبانی کتابخانه و تشخیص قابلیت

برای تشخیص پشتیبانی کتابخانه استاندارد، می‌توان از feature-test macro مربوط به خانواده قابلیت‌های zip و adjacent استفاده کرد. مقدار `202110L` برای `__cpp_lib_ranges_zip` نشان‌دهنده پشتیبانی از `adjacent_view` و قابلیت‌های مرتبط در ++C23 است.

```cpp
#include <ranges>

#ifndef __cpp_lib_ranges_zip
#error "The standard library does not provide C++23 ranges zip/adjacent support"
#elif __cpp_lib_ranges_zip < 202110L
#error "Insufficient ranges zip/adjacent support"
#endif

int main() {
    // Use std::views::pairwise
}
```

صرف انتخاب حالت کامپایل ++C23 تضمین نمی‌کند که نسخه نصب‌شده کتابخانه استاندارد تمام قابلیت‌های این بخش را پیاده‌سازی کرده باشد. پشتیبانی کامپایلر و پشتیبانی کتابخانه استاندارد دو موضوع مرتبط اما جداگانه‌اند؛ نسخه‌های مختلف ابزارهای توسعه ممکن است در میزان تکمیل پیاده‌سازی تفاوت داشته باشند.

## نکات طراحی برای کد حرفه‌ای

هنگام استفاده از `pairwise` ابتدا مشخص کنید مجاورت باید نسبت به کدام دنباله سنجیده شود. ترتیب adaptorها اهمیت معنایی دارد: فیلترکردن قبل از `pairwise` با فیلترکردن پس از ساخت زوج‌ها یکسان نیست.

اگر فقط به یک محاسبه روی هر زوج نیاز دارید، ترکیب `pairwise` و `transform` معمولاً کد بیانی و مناسبی ایجاد می‌کند. اگر هدف صرفاً یافتن وجود یک زوج با ویژگی خاص است، الگوریتم‌های استاندارد یا یک حلقه زودبازگشت ممکن است از ساخت زنجیره‌ای طولانی روشن‌تر باشند.

در APIهایی که view را از تابع بازمی‌گردانند، طول عمر range پایه را با دقت بررسی کنید. بازگرداندن view ارجاعی به یک container محلی، نمونه‌ای از خطای dangling است. در چنین شرایطی باید مالکیت داده، نوع view و مدت استفاده از نتیجه را به‌درستی طراحی کنید.

## جمع‌بندی

قابلیت `std::views::pairwise` در ++C23 راهی استاندارد، lazy و خوانا برای پیمایش زوج‌های هم‌پوشان از عناصر مجاور یک range فراهم می‌کند. این قابلیت برای محاسبه اختلاف‌های متوالی، بررسی ترتیب، تحلیل تغییرات و پردازش یال‌های مسیر بسیار مفید است.

مهم‌ترین نکته‌های استفاده از آن عبارت‌اند از الزام `forward_range`، ارجاعی‌بودن عناصر tuple خروجی، هم‌پوشانی زوج‌ها و وابستگی طول عمر view به داده پایه. برای پنجره‌های بزرگ‌تر از دو عضو باید `std::views::adjacent<N>` را بررسی کرد و برای پنجره‌هایی با خروجی range-like، `std::views::slide` گزینه مرتبط‌تری است.
