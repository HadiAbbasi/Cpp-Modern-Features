# `std::ref` در ++C

`std::ref` یکی از ابزارهای کاربردی کتابخانهٔ استاندارد ++C است که اجازه می‌دهد در موقعیت‌هایی که معمولاً انتظار می‌رود آرگومان‌ها کپی شوند، یک **ارجاع به شیء** ارسال کنیم؛ برای مثال، هنگام استفاده از بعضی الگوریتم‌ها و ابزارهای کتابخانهٔ استاندارد.

## چه مشکلی را حل می‌کند؟

`std::ref` زمانی مفید است که بخواهیم تابعی را فراخوانی کنیم که پارامتر مرجعی می‌گیرد، اما سازوکار فراخوانی یا نگه‌داری آرگومان‌ها (مانند `std::thread`، `std::bind` یا برخی توابع قالبی) به‌طور پیش‌فرض آن‌ها را با مقدار دریافت یا ذخیره می‌کند.

بسیاری از ابزارهای قالبی ++C، مانند `std::thread` و `std::bind`، آرگومان‌های خود را در قالب اشیایی با مالکیت مستقل نگه می‌دارند؛ در نتیجه ممکن است از آرگومان‌ها کپی ساخته شود. حتی اگر تابع مقصد پارامتری از نوع مرجع (`T&`) داشته باشد، لایهٔ میانی می‌تواند باعث کپی‌شدن آرگومان شود.

این وضعیت چند مشکل ایجاد می‌کند:

- **خطای کامپایل:** اگر شیء قابل کپی نباشد، مانند `std::unique_ptr` یا `std::mutex`، ساخت کپی می‌تواند باعث خطای کامپایل شود.
- **تغییر کپی به‌جای شیء اصلی:** اگر تابع نسخهٔ کپی‌شده را تغییر دهد، شیء اصلی تغییر نمی‌کند.
- **اشتباه گرفتن اشاره‌گر با مرجع:** عملگر گرفتن آدرس (`&`) یک اشاره‌گر خام تولید می‌کند، نه یک مرجع واقعی.

اینجا `std::ref` به کار می‌آید. این تابع شیء را در یک wrapper کوچک و قابل کپی به نام `std::reference_wrapper` قرار می‌دهد. این wrapper مانند مرجع رفتار می‌کند و کمک می‌کند آرگومان به‌جای کپی‌شدن، به شیء اصلی ارجاع دهد.

## کاربردهای `std::ref`

### ۱. ارسال مرجع به `std::thread` (رایج‌ترین کاربرد)

سازندهٔ `std::thread` آرگومان‌ها را برای استفاده در رشتهٔ اجرایی جدید ذخیره می‌کند. اگر بخواهیم تابعِ اجراشده در رشته، متغیر اصلی را تغییر دهد، می‌توانیم از `std::ref` استفاده کنیم.

```cpp
#include <iostream>
#include <thread>
#include <functional> // برای std::ref

void increment(int& n) {
    n++;
}

int main() {
    int x = 10;

    std::thread t(increment, std::ref(x));
    t.join();

    std::cout << x << '\n'; // خروجی: 11
}
```

در این مثال، `std::ref(x)` باعث می‌شود تابع `increment` به متغیر اصلی `x` دسترسی داشته باشد. فراخوانی `join()` نیز منتظر می‌ماند تا رشتهٔ اجرایی پایان یابد.

### ۲. استفاده در `std::bind`

به‌طور پیش‌فرض، `std::bind` آرگومان‌هایی را که به آن متصل می‌کنیم ذخیره می‌کند. با استفاده از `std::ref` می‌توانیم مشخص کنیم که تابع به متغیر اصلی دسترسی داشته باشد.

```cpp
#include <iostream>
#include <functional>

void update(int& n) {
    n += 5;
}

int main() {
    int val = 20;

    // با std::ref، تابع متغیر اصلی را تغییر می‌دهد.
    auto bound_fn = std::bind(update, std::ref(val));
    bound_fn();

    std::cout << val << '\n'; // خروجی: 25
}
```

اگر به‌جای `std::ref(val)` خود `val` را به `std::bind` بدهیم، آرگومان معمولاً در شیء حاصل از `bind` ذخیره می‌شود و تغییر روی همان مقدار ذخیره‌شده اعمال خواهد شد، نه روی متغیر اصلی.

### ۳. نگه‌داری ارجاع‌ها در کانتینرهای STL، مانند `std::vector`

در ++C نمی‌توان مستقیماً کانتینری از مرجع‌ها ساخت؛ برای نمونه، `std::vector<int&>` معتبر نیست، چون مرجع‌ها شیء مستقلی نیستند و نمی‌توان آن‌ها را مانند عناصر معمول کانتینر مدیریت کرد.

در عوض، می‌توان از `std::reference_wrapper` استفاده کرد:

```cpp
#include <iostream>
#include <vector>
#include <functional>

int main() {
    int a = 1, b = 2, c = 3;

    std::vector<std::reference_wrapper<int>> vec = {
        std::ref(a), std::ref(b), std::ref(c)
    };

    for (int& item : vec) {
        item *= 10;
    }

    std::cout << a << ", " << b << ", " << c << '\n';
    // خروجی: 10, 20, 30
}
```

عناصر `vec` کپیِ مقادیر `a`، `b` و `c` نیستند؛ هر عنصر به یکی از متغیرهای اصلی ارجاع می‌دهد. بنابراین تغییر از طریق عناصر کانتینر روی همان متغیرها اعمال می‌شود.

## تفاوت `std::ref` و `std::cref`

- `std::ref(x)` یک wrapper برای مرجع قابل تغییر می‌سازد؛ معمولاً از نوع `std::reference_wrapper<T>` است.
- `std::cref(x)` یک wrapper برای مرجع فقط‌خواندنی می‌سازد؛ از نوع `std::reference_wrapper<const T>` است.

`std::cref` زمانی مفید است که تابع فقط باید داده را بخواند و نمی‌خواهیم آن را از طریق این مرجع تغییر دهد. این روش همچنین برای جلوگیری از کپی‌کردن اشیای بزرگ مفید است.

## نکته‌های مهم

- برای استفاده از `std::ref` و `std::cref`، هدر `<functional>` را وارد کنید.
- `std::ref` خودِ شیء را کپی نمی‌کند؛ wrapper حاصل به شیء اصلی ارجاع می‌دهد.
- **طول عمر شیء اصلی اهمیت دارد.** ارجاعی که با `std::ref` ساخته شده، مالک شیء نیست. اگر شیء اصلی پیش از پایان استفاده از wrapper از بین برود، ارجاع نامعتبر می‌شود.
- در برنامه‌های چندرشته‌ای، اگر چند رشته هم‌زمان یک متغیر را تغییر دهند، همچنان باید مسائل هم‌زمانی و احتمال رقابت داده‌ای را مدیریت کنید. `std::ref` به‌تنهایی هیچ همگام‌سازی‌ای انجام نمی‌دهد.

## خلاصه

`std::ref` راهی برای انتقال یا نگه‌داری ارجاع به یک شیء در ابزارهایی است که معمولاً آرگومان‌ها را با مقدار ذخیره می‌کنند. این قابلیت به‌ویژه در `std::thread`، `std::bind` و کانتینرهایی از `std::reference_wrapper` کاربرد دارد. برای ارجاع فقط‌خواندنی نیز می‌توان از `std::cref` استفاده کرد.
