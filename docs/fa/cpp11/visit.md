# آشنایی با `std::variant` و `std::visit`

تصور کنید در حال برنامه‌نویسی هستید و برنامه شما باید انواع مختلفی از داده‌ها را مدیریت کند؛ گاهی یک عدد صحیح، گاهی یک رشته و شاید هم یک شیء سفارشی. در نسخه‌های قدیمی‌تر ++C، نوع `union` یکی از گزینه‌های موجود بود. می‌توان `union` را مانند جعبه‌ای در نظر گرفت که در هر لحظه می‌تواند یکی از انواع ازپیش‌تعریف‌شده را نگه دارد.

اما یک مشکل وجود دارد: `union` به‌طور معمول نوع داده‌ای را که در حال حاضر داخل آن قرار دارد، به‌صورت خودکار مدیریت نمی‌کند. بنابراین اگر به عضوی دسترسی پیدا کنید که آخرین عضو فعال آن نیست، ممکن است با رفتار نامعتبر یا مشکلاتی در برنامه روبه‌رو شوید.

در ++C مدرن، ابزار امن‌تری به نام `std::variant` داریم.

## ۱. `std::variant`

`std::variant` شبیه `union` است، اما ایمن‌تر عمل می‌کند. آن را مانند جعبه‌ای با چند محفظه برچسب‌گذاری‌شده تصور کنید که هر محفظه برای نوع مشخصی از داده در نظر گرفته شده است.

ویژگی مهم `std::variant` این است که نوع مقداری را که در حال حاضر نگه می‌دارد، می‌شناسد. در نتیجه، گزینه‌ای امن‌تر و قابل‌اعتمادتر برای مدیریت داده‌هایی است که می‌توانند از چند نوع متفاوت باشند.

```cpp
#include <iostream>
#include <variant>
#include <string>

int main() {
    std::variant<int, std::string> data;

    data = 42;
    std::cout << std::get<int>(data) << std::endl; // خروجی: 42

    data = "Hello, world!";

    return 0;
}
```

در این مثال، متغیر `data` می‌تواند یک `int` یا یک `std::string` را نگه دارد. ابتدا مقدار `42` در آن قرار می‌گیرد و سپس مقدار آن با یک رشته جایگزین می‌شود.

### ایمنی نوع در عمل

یکی از مزیت‌های مهم `std::variant`، ایمنی نوع (Type Safety) است. اگر با استفاده از `std::get` بخواهید نوعی را دریافت کنید که در حال حاضر در `variant` قرار ندارد، با یکی از این حالت‌ها روبه‌رو می‌شوید:

- اگر نوع درخواستی اصلاً یکی از انواع تعریف‌شده در `variant` نباشد، برنامه معمولاً در زمان کامپایل با خطا مواجه می‌شود.
- اگر نوع درخواستی جزو انواع مجاز باشد، اما نوع فعال فعلی با آن مطابقت نداشته باشد، `std::get` در زمان اجرا استثنای `std::bad_variant_access` را پرتاب می‌کند.

برای بررسی نوع فعال بدون پرتاب استثنا نیز می‌توانید از `std::get_if` استفاده کنید.

این سازوکارها کمک می‌کنند کد در مواجهه با داده‌هایی که نوعشان تغییر می‌کند، قابل‌اعتمادتر و قابل‌پیش‌بینی‌تر باشد.

## ۲. `std::visit`

اکنون یک `std::variant` داریم که می‌تواند داده‌هایی با انواع مختلف را نگه دارد. اما اگر بخواهیم بر اساس نوع فعلی داده، عملیات متفاوتی انجام دهیم، چه باید بکنیم؟

اینجاست که `std::visit` وارد عمل می‌شود. می‌توان آن را ابزاری دانست که یک تابع یا شیء بازدیدکننده (Visitor) را روی مقدار فعلی `variant` اجرا می‌کند.

```cpp
#include <iostream>
#include <variant>
#include <string>
#include <type_traits>
#include <utility>

int main() {
    std::variant<int, std::string> data = 42;

    auto visitor = [](auto&& arg) -> std::string {
        using T = std::decay_t<decltype(arg)>;

        if constexpr (std::is_same_v<T, int>) {
            return "It's an int: " + std::to_string(arg);
        }
        else if constexpr (std::is_same_v<T, std::string>) {
            return "It's a string: " + arg;
        }
        else {
            return "Unknown type";
        }
    };

    std::string result = std::visit(visitor, data);
    std::cout << result << std::endl; // خروجی: It's an int: 42

    return 0;
}
```

در این مثال، `std::visit` دو آرگومان دریافت می‌کند:

1. تابع بازدیدکننده یا `visitor` که رفتار موردنظر را تعریف می‌کند.
2. متغیر `data` از نوع `std::variant`.

سپس بازدیدکننده روی مقدار فعال داخل `variant` اجرا می‌شود. به کمک این روش می‌توانیم برای هر نوع، رفتار مخصوصی تعریف کنیم.

در مثال بالا، اگر مقدار فعال یک عدد صحیح باشد، پیام مربوط به عدد چاپ می‌شود؛ اگر مقدار فعال یک رشته باشد، پیام مربوط به رشته برگردانده می‌شود.

نکته: استفاده از `if constexpr` باعث می‌شود شاخه‌های نامرتبط در زمان نمونه‌سازی قالب حذف شوند. در این مثال، نوع `T` با استفاده از `std::decay_t` تعیین می‌شود تا ویژگی‌هایی مانند ارجاع بودن از نوع استنتاج‌شده حذف شوند.

### مقدار بازگشتی `std::visit`

نوع بازگشتی `std::visit` به نوع بازگشتی بازدیدکننده بستگی دارد. در مثال بالا، هر دو شاخه مقدار `std::string` برمی‌گردانند؛ بنابراین نوع نتیجه نیز `std::string` است.

برخلاف این تصور که `std::visit` همیشه یک نوع مشترک را به‌صورت خودکار انتخاب می‌کند، در حالت معمول C++17، فراخوانی بازدیدکننده برای تمام ترکیب‌های ممکن باید معتبر باشد و نوع بازگشتی آن‌ها باید با الزامات `std::visit` سازگار باشد. برای مثال ساده بالا، همه شاخه‌های معتبر باید نوع بازگشتی یکسانی داشته باشند.

## ۳. کاربردهای `std::visit`

### ۱. پیاده‌سازی الگوی Visitor و چندریختی ایستا

به‌جای تکیه بر وراثت، کلاس‌های پایه دارای توابع مجازی و اشاره‌گرهای خام، می‌توان انواع مختلف داده را درون `std::variant` نگه داشت و رفتار هر نوع را با `std::visit` تعریف کرد.

این روش در بسیاری از موارد از سربار فراخوانی توابع مجازی و جست‌وجوی جدول مجازی (vtable) اجتناب می‌کند. به این رویکرد گاهی «چندریختی ایستا» (Static Polymorphism) گفته می‌شود؛ هرچند انتخاب شاخه در زمان اجرا بر اساس نوع فعال `variant` انجام می‌شود و کامپایلر معمولاً می‌تواند بخش زیادی از منطق فراخوانی را بهینه کند.

### ۲. مدیریت رویدادها و ماشین‌های حالت

`std::visit` برای پردازش رویدادها یا تغییر وضعیت در یک ماشین حالت بسیار مناسب است.

برای نمونه، می‌توانید رویدادهایی مانند موارد زیر را به‌عنوان اعضای یک `variant` تعریف کنید:

- `MouseClick`
- `KeyPress`
- `WindowResize`

سپس با استفاده از `std::visit` هر رویداد را به پردازشگر مربوط به خودش هدایت کنید. این کار منطق حلقه رویداد را خواناتر و نوع‌امن‌تر می‌کند.

### ۳. مفسرها، کامپایلرها و درخت‌های نحوی انتزاعی (AST)

یکی از کاربردهای مهم `std::variant` و `std::visit` در طراحی درخت‌های نحوی انتزاعی (Abstract Syntax Trees یا AST) است.

گره‌های یک AST ممکن است انواع مختلفی داشته باشند؛ برای مثال:

- `NumberNode`
- `BinaryOpNode`
- `VariableNode`

با قرار دادن این انواع در یک `std::variant`، می‌توان با استفاده از `std::visit` درخت را پیمایش کرد، عبارت‌ها را ارزیابی کرد یا ساختار آن را بهینه‌سازی کرد. این روش کمک می‌کند رفتار مربوط به انواع مختلف گره‌ها به شکلی روشن و قابل‌بررسی تعریف شود.

## ۴. مثال‌ها

### مثال اول: استفاده از Generic Lambda

اگر عملیاتی که می‌خواهید انجام دهید برای همه انواع داخل `variant` یکسان است، مثلاً فقط چاپ مقدار، می‌توانید از یک لامبدای عمومی (Generic Lambda) استفاده کنید.

```cpp
#include <iostream>
#include <variant>
#include <string>

int main() {
    std::variant<int, double, std::string> data = "Hello C++";

    // این لامبدا با تمام انواع موجود در variant سازگار است
    std::visit([](const auto& val) {
        std::cout << "Value: " << val << '\n';
    }, data);

    data = 42;

    std::visit([](const auto& val) {
        std::cout << "Value: " << val << '\n';
    }, data);
}
```

خروجی:

```text
Value: Hello C++
Value: 42
```

در اینجا، پارامتر `const auto&` به لامبدا اجازه می‌دهد مقدار را بدون کپی‌کردن دریافت کند و با انواع مختلف موجود در `variant` سازگار باشد.

### مثال دوم: الگوی `overloaded` برای مدیریت متفاوت انواع

الگوی پرکاربردی به نام `overloaded` وجود دارد که چند لامبدا را در یک شیء ترکیب می‌کند. به این ترتیب می‌توان برای هر نوع، یک لامبدای جداگانه نوشت.

```cpp
#include <iostream>
#include <variant>
#include <string>

// ساختاری کمکی برای ترکیب چند لامبدا در یک شیء
template<class... Ts>
struct overloaded : Ts... {
    using Ts::operator()...;
};

template<class... Ts>
overloaded(Ts...) -> overloaded<Ts...>; // راهنمای استنتاج نوع در C++17

int main() {
    std::variant<int, double, std::string> data = 3.14;

    std::visit(overloaded{
        [](int arg) {
            std::cout << "Integer: " << arg << '\n';
        },
        [](double arg) {
            std::cout << "Double: " << arg << '\n';
        },
        [](const std::string& arg) {
            std::cout << "String: " << arg << '\n';
        }
    }, data);
}
```

خروجی:

```text
Double: 3.14
```

مزیت مهم این روش این است که اگر نوع جدیدی به `variant` اضافه کنید و هیچ لامبدای سازگاری برای آن تعریف نکنید، معمولاً برنامه در زمان کامپایل خطا می‌دهد؛ زیرا `std::visit` باید برای تمام انواع ممکن قابل فراخوانی باشد. این موضوع احتمال فراموش‌شدن یک حالت را کاهش می‌دهد.

### مثال سوم: اجرای `std::visit` روی چند `variant`

می‌توانید دو یا چند `variant` را هم‌زمان به `std::visit` بدهید. این قابلیت برای انجام عملیات ترکیبی بین چند مقدار مفید است.

```cpp
#include <iostream>
#include <variant>

int main() {
    std::variant<int, double> a = 10;
    std::variant<int, double> b = 2.5;

    // انجام عملیات روی دو variant به‌صورت هم‌زمان
    std::visit([](auto x, auto y) {
        std::cout << "Sum: " << (x + y) << '\n';
    }, a, b);
}
```

خروجی:

```text
Sum: 12.5
```

در این مثال، `std::visit` بازدیدکننده را با مقادیر فعال هر دو `variant` فراخوانی می‌کند. چون هر دو متغیر می‌توانند `int` یا `double` باشند، عبارت `x + y` باید برای تمام ترکیب‌های ممکن معتبر باشد.

## ۵. خلاصه مزایای `std::variant` و `std::visit`

- **ایمنی نوع (Type Safety):** نوع فعال داده مشخص است و دسترسی اشتباه با ابزارهایی مانند `std::get` قابل‌شناسایی است.
- **کارایی بالا:** در بسیاری از پیاده‌سازی‌ها، این ابزارها امکان dispatch کارآمد و بهینه‌سازی در زمان کامپایل را فراهم می‌کنند. با این حال، کارایی دقیق به پیاده‌سازی و کاربرد بستگی دارد.
- **کد خواناتر:** می‌توان به‌جای زنجیره‌های پیچیده `if-else` یا `switch`، رفتار مربوط به هر نوع را به شکلی روشن تعریف کرد.
- **پوشش حالت‌ها:** با استفاده از `std::visit` و الگوی `overloaded` می‌توان اطمینان حاصل کرد که تمام انواع تعریف‌شده در `variant` پردازش می‌شوند.

**خلاصه:** از `std::variant` برای نگهداری یکی از چند نوع مشخص به‌شکلی نوع‌امن استفاده می‌کنیم و از `std::visit` برای اجرای رفتار مناسب بر اساس نوع مقداری که در حال حاضر داخل آن قرار دارد.
