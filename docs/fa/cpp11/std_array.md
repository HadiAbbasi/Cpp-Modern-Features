# راهنمای جامع استفاده از `std::array` در ++C11

## مقدمه

در ++C11، کتابخانه استاندارد ++C نوع `std::array` را معرفی کرد تا امکان استفاده از آرایه‌های با اندازه ثابت را در قالب یک Container استاندارد فراهم کند. این نوع، برخلاف آرایه‌های بومی زبان، رابطی سازگار با بسیاری از امکانات کتابخانه استاندارد ارائه می‌دهد و در عین حال سربار مدیریتی قابل‌توجهی به داده‌ها اضافه نمی‌کند.

آرایه‌های بومی مانند `int values[5]` از دیرباز برای نگهداری تعداد ثابتی از عناصر استفاده می‌شدند؛ اما این آرایه‌ها محدودیت‌هایی در زمینه تعامل با الگوریتم‌های استاندارد، انتقال اندازه به توابع و یکپارچگی با سایر Containerها دارند.

نوع `std::array` این مشکلات را تا حد زیادی برطرف می‌کند، بدون آنکه اندازه آرایه را در زمان اجرا تغییر دهد یا حافظه را به‌صورت پویا تخصیص دهد.

```cpp
#include <array>
#include <iostream>

int main() {
    std::array<int, 5> values = {10, 20, 30, 40, 50};

    for (const int value : values) {
        std::cout << value << ' ';
    }

    std::cout << '\n';
}
```

خروجی برنامه به شکل زیر است:

```text
10 20 30 40 50
```

در این مثال، آرایه‌ای شامل پنج عنصر از نوع `int` ساخته شده است. تعداد عناصر بخشی از نوع داده محسوب می‌شود و پس از تعریف آرایه نمی‌توان آن را تغییر داد.

## معرفی ساختار و ویژگی‌های اصلی

### مفهوم std::array چیست؟

نوع `std::array` یک Class Template است که در Header استاندارد `<array>` تعریف شده است.

ساختار کلی آن به شکل زیر است:

```cpp
std::array<T, N>
```

در این ساختار:

- پارامتر `T` نوع داده عناصر آرایه را مشخص می‌کند.
- پارامتر `N` تعداد عناصر آرایه را در زمان کامپایل تعیین می‌کند.
- اندازه آرایه پس از ساخت تغییر نمی‌کند.
- عناصر به‌صورت پیوسته در حافظه قرار می‌گیرند.
- نوع آرایه از رابط استاندارد Containerها پشتیبانی می‌کند.

برای نمونه، نوع `std::array<double, 10>` آرایه‌ای از ده مقدار `double` را مشخص می‌کند.

```cpp
#include <array>

int main() {
    std::array<int, 3> integers = {1, 2, 3};
    std::array<double, 4> measurements = {1.2, 2.4, 3.6, 4.8};
    std::array<char, 5> letters = {'H', 'e', 'l', 'l', 'o'};
}
```

### تفاوت آرایه ثابت و اندازه ثابت

یکی از نکات مهم این است که ثابت بودن اندازه به معنی ثابت بودن مقادیر عناصر نیست.

```cpp
#include <array>

int main() {
    std::array<int, 3> values = {10, 20, 30};

    values[0] = 100;
    values[1] = 200;
}
```

در این مثال، تعداد عناصر همواره سه عدد باقی می‌ماند، اما مقادیر آن‌ها قابل تغییر است.

برای جلوگیری از تغییر عناصر می‌توان از `const` استفاده کرد:

```cpp
#include <array>

int main() {
    const std::array<int, 3> values = {10, 20, 30};

    // values[0] = 100; // Compilation error
}
```

همچنین ثابت بودن اندازه آرایه به این معنا نیست که هر نمونه از `std::array` الزاماً دارای اندازه حافظه غیرصفر است؛ آرایه‌ای با تعداد عناصر صفر نیز مجاز است.

### نقش پارامتر اندازه در نوع داده

در `std::array`، مقدار `N` بخشی از نوع داده است. به همین دلیل، دو آرایه با اندازه‌های متفاوت، دو نوع متفاوت محسوب می‌شوند.

```cpp
#include <array>
#include <type_traits>

int main() {
    using Array3 = std::array<int, 3>;
    using Array5 = std::array<int, 5>;

    static_assert(!std::is_same<Array3, Array5>::value,
                  "The array types must be different");
}
```

این ویژگی امکان بررسی اندازه آرایه در زمان کامپایل را فراهم می‌کند؛ اما در عین حال، هنگام طراحی API باید به تفاوت نوع آرایه‌هایی با اندازه‌های متفاوت توجه داشت.

## نحوه تعریف و مقداردهی اولیه

### روش‌های مقداردهی اولیه

برای تعریف `std::array` چند روش متداول وجود دارد.

```cpp
#include <array>

int main() {
    std::array<int, 4> first = {1, 2, 3, 4};

    std::array<int, 4> second{{1, 2, 3, 4}};

    std::array<int, 4> third = {};

    std::array<int, 4> fourth{};

    std::array<int, 4> fifth = {1, 2};
}
```

در این مثال:

- متغیر `first` با چهار مقدار مشخص مقداردهی می‌شود.
- متغیر `second` از شکل قدیمی‌تر مقداردهی تو‌در‌تو استفاده می‌کند که در برخی الگوهای ++C11 دیده می‌شود.
- متغیرهای `third` و `fourth` با مقداردهی اولیه مقداری، تمام عناصر را به مقدار صفر برای نوع `int` تبدیل می‌کنند.
- متغیر `fifth` دارای چهار عنصر است؛ دو عنصر نخست به‌ترتیب `1` و `2` هستند و عناصر باقی‌مانده صفر خواهند بود.

در کدهای جدید، معمولاً استفاده از `{}` یا فهرست مقادیر صریح خوانایی مناسبی دارد.

### تفاوت مقداردهی اولیه با مقداردهی نکردن

یکی از خطاهای رایج، فرض کردن این موضوع است که تمام عناصر `std::array` به‌صورت خودکار صفر می‌شوند.

```cpp
#include <array>

int main() {
    std::array<int, 3> initialized{};
    std::array<int, 3> uninitialized;
}
```

آرایه `initialized` با مقداردهی اولیه مقداری ساخته می‌شود و تمام عناصر آن صفر هستند.

در مقابل، آرایه `uninitialized` که یک متغیر محلی با طول غیرصفر است، بدون مقداردهی اولیه صریح تعریف شده است. در این حالت، عناصر از نوع `int` مقدار اولیه قابل اتکایی ندارند و خواندن آن‌ها پیش از مقداردهی معتبر نیست.

برای نوع‌های کلاس نیز رفتار دقیق به سازوکار مقداردهی اولیه و Constructorهای آن نوع بستگی دارد.

بنابراین، در کدهای کاربردی معمولاً بهتر است آرایه با `{}` یا با مقادیر مشخص مقداردهی اولیه شود.

### مقداردهی اولیه با مقادیر کمتر

در صورتی که تعداد مقادیر اولیه از ظرفیت آرایه کمتر باشد، عناصر باقی‌مانده به‌صورت مقداری مقداردهی اولیه می‌شوند.

```cpp
#include <array>
#include <iostream>

int main() {
    std::array<int, 5> values = {7, 8};

    for (int value : values) {
        std::cout << value << ' ';
    }
}
```

خروجی:

```text
7 8 0 0 0
```

این رفتار برای نوع‌های عددی و بسیاری از کاربردهای معمول مفید است. با این حال، در صورت استفاده از نوع‌های کلاس، باید هزینه و معنای مقداردهی اولیه هر عنصر را نیز در نظر گرفت.

### آرایه با اندازه صفر

در ++C11 تعریف آرایه‌ای با اندازه صفر مجاز است:

```cpp
#include <array>

int main() {
    std::array<int, 0> values{};

    return static_cast<int>(values.size());
}
```

اندازه این آرایه صفر است و هیچ عنصری برای دسترسی وجود ندارد.

در چنین شرایطی، توابعی مانند `begin()` و `end()` همچنان رابط معتبر Container را فراهم می‌کنند و بازه حاصل برای پیمایش خالی است.

با این حال، نباید به `front()`، `back()` یا دسترسی اندیسی به عناصر چنین آرایه‌ای متوسل شد؛ زیرا عنصری وجود ندارد که دسترسی به آن معتبر باشد.

## دسترسی به عناصر آرایه

### دسترسی با عملگر اندیس

عملگر `operator[]` یکی از ساده‌ترین روش‌ها برای دسترسی به عناصر است.

```cpp
#include <array>
#include <iostream>

int main() {
    std::array<int, 4> values = {10, 20, 30, 40};

    std::cout << values[0] << '\n';
    std::cout << values[2] << '\n';

    values[1] = 99;

    std::cout << values[1] << '\n';
}
```

اندیس عناصر از صفر آغاز می‌شود؛ بنابراین، برای آرایه‌ای با اندازه `N`، اندیس معتبر در بازه صفر تا `N - 1` قرار دارد.

دسترسی با `operator[]` بررسی محدوده را تضمین نمی‌کند. استفاده از اندیس نامعتبر، رفتار تعریف‌نشده ایجاد می‌کند.

به همین دلیل، اگر معتبر بودن اندیس تضمین نشده باشد، باید از روش مناسبی برای کنترل آن استفاده کرد.

### دسترسی کنترل‌شده با at

تابع `at()` عنصر موردنظر را با بررسی محدوده برمی‌گرداند.

```cpp
#include <array>
#include <iostream>
#include <stdexcept>

int main() {
    std::array<int, 3> values = {10, 20, 30};

    try {
        std::cout << values.at(1) << '\n';
        std::cout << values.at(5) << '\n';
    } catch (const std::out_of_range& error) {
        std::cout << "Index is out of range\n";
    }
}
```

در این مثال، دسترسی به اندیس `5` باعث پرتاب استثنای `std::out_of_range` می‌شود.

تفاوت اصلی این دو روش عبارت است از:

- `operator[]` برای زمانی مناسب است که معتبر بودن اندیس از قبل تضمین شده باشد.
- `at()` زمانی مفید است که اندیس از ورودی خارجی یا محاسباتی با اعتبار نامشخص به دست آمده باشد.

در مسیرهای حساس به کارایی، `operator[]` انتخاب رایجی است؛ اما حذف بررسی محدوده باید مبتنی بر یک تضمین واقعی باشد، نه صرفاً فرض برنامه‌نویس.

### دسترسی به اولین و آخرین عنصر

توابع `front()` و `back()` به‌ترتیب برای دسترسی به اولین و آخرین عنصر استفاده می‌شوند.

```cpp
#include <array>
#include <iostream>

int main() {
    std::array<int, 4> values = {10, 20, 30, 40};

    std::cout << values.front() << '\n';
    std::cout << values.back() << '\n';

    values.front() = 100;
    values.back() = 400;
}
```

این توابع زمانی خوانایی بیشتری دارند که منظور برنامه دسترسی به اولین یا آخرین عنصر باشد، نه یک موقعیت عددی خاص.

نکته مهم آن است که استفاده از این توابع روی آرایه خالی معتبر نیست.

### دسترسی به حافظه زیرین با data

تابع `data()` یک Pointer به اولین عنصر آرایه برمی‌گرداند.

```cpp
#include <array>
#include <iostream>

int main() {
    std::array<int, 3> values = {10, 20, 30};

    int* pointer = values.data();

    std::cout << pointer[0] << '\n';
    std::cout << pointer[1] << '\n';
    std::cout << pointer[2] << '\n';
}
```

این قابلیت برای تعامل با APIهای قدیمی C یا کتابخانه‌هایی که Pointer و تعداد عناصر را دریافت می‌کنند، مفید است.

برای نمونه، اگر یک API به `int*` و طول آرایه نیاز داشته باشد، می‌توان از `data()` و `size()` استفاده کرد.

با این حال، Pointer بازگشتی مالکیت مستقلی از آرایه ندارد. همچنین نباید فرض کرد که برای آرایه با اندازه صفر، استفاده از Pointer بازگشتی برای دسترسی به یک عنصر معتبر است.

## مدیریت اندازه و ظرفیت

### بررسی اندازه با size

تابع `size()` تعداد عناصر آرایه را برمی‌گرداند.

```cpp
#include <array>
#include <iostream>

int main() {
    std::array<int, 5> values{};

    std::cout << values.size() << '\n';
}
```

خروجی:

```text
5
```

نوع مقدار بازگشتی `size()` برابر `std::size_t` است.

از آنجا که اندازه `std::array` هنگام کامپایل مشخص می‌شود، مقدار بازگشتی این تابع نیز در هر نمونه تغییر نمی‌کند.

### بررسی خالی بودن با empty

تابع `empty()` مشخص می‌کند که آرایه هیچ عنصری دارد یا خیر.

```cpp
#include <array>
#include <iostream>

int main() {
    std::array<int, 0> emptyArray{};
    std::array<int, 3> nonEmptyArray{};

    std::cout << std::boolalpha;
    std::cout << emptyArray.empty() << '\n';
    std::cout << nonEmptyArray.empty() << '\n';
}
```

خروجی:

```text
true
false
```

این تابع برای نوشتن کدهای عمومی و جلوگیری از فرض وجود عناصر، خوانایی مناسبی دارد.

### مفهوم max_size

تابع `max_size()` بیشترین تعداد عناصری را که نمونه می‌تواند در خود نگه دارد، گزارش می‌کند.

برای `std::array`، اندازه نوع از قبل مشخص است؛ بنابراین، در پیاده‌سازی‌های استاندارد معمول، مقدار `max_size()` با `size()` برابر است.

این تابع بیشتر در کدهای عمومی که با انواع مختلف Container کار می‌کنند، کاربرد دارد.

## پیمایش عناصر با Iteratorها

### استفاده از begin و end

نوع `std::array` از Iteratorهای استاندارد پشتیبانی می‌کند و به همین دلیل با الگوریتم‌های کتابخانه استاندارد قابل استفاده است.

```cpp
#include <array>
#include <iostream>

int main() {
    std::array<int, 5> values = {1, 2, 3, 4, 5};

    for (auto iterator = values.begin();
         iterator != values.end();
         ++iterator) {
        std::cout << *iterator << ' ';
    }
}
```

توابع `begin()` و `end()` به‌ترتیب Iterator ابتدای بازه و Iterator موقعیت یک واحد پس از آخرین عنصر را برمی‌گردانند.

Iterator بازگشتی از `end()` برای dereference کردن نیست؛ بلکه برای مشخص کردن پایان بازه استفاده می‌شود.

### پیمایش از انتها با reverse_iterator

توابع `rbegin()` و `rend()` امکان پیمایش معکوس را فراهم می‌کنند.

```cpp
#include <array>
#include <iostream>

int main() {
    std::array<int, 4> values = {10, 20, 30, 40};

    for (auto iterator = values.rbegin();
         iterator != values.rend();
         ++iterator) {
        std::cout << *iterator << ' ';
    }
}
```

خروجی:

```text
40 30 20 10
```

این روش بدون نیاز به محاسبه دستی اندیس‌ها، امکان پیمایش معکوس را فراهم می‌کند.

### پیمایش مبتنی بر range-based for

در بسیاری از کاربردها، حلقه مبتنی بر بازه خواناترین انتخاب است.

```cpp
#include <array>
#include <iostream>

int main() {
    std::array<int, 4> values = {10, 20, 30, 40};

    for (const int value : values) {
        std::cout << value << ' ';
    }
}
```

اگر لازم باشد عناصر تغییر کنند، می‌توان از Reference استفاده کرد:

```cpp
#include <array>

int main() {
    std::array<int, 4> values = {1, 2, 3, 4};

    for (int& value : values) {
        value *= 2;
    }
}
```

در مقابل، استفاده از متغیر محلی بدون Reference باعث کپی شدن هر عنصر می‌شود. این موضوع برای نوع‌های ساده معمولاً هزینه ناچیزی دارد، اما برای نوع‌های کلاس بزرگ یا غیرقابل‌کپی ممکن است نامناسب باشد.

## استفاده از الگوریتم‌های استاندارد

### مرتب‌سازی عناصر با sort

از آنجا که `std::array` از Iteratorهای دسترسی تصادفی پشتیبانی می‌کند، می‌توان آن را با الگوریتم `std::sort` استفاده کرد.

```cpp
#include <algorithm>
#include <array>
#include <iostream>

int main() {
    std::array<int, 5> values = {50, 10, 40, 20, 30};

    std::sort(values.begin(), values.end());

    for (int value : values) {
        std::cout << value << ' ';
    }
}
```

خروجی:

```text
10 20 30 40 50
```

الگوریتم `std::sort` از ++C98 در کتابخانه استاندارد وجود داشته است و اختصاصی `std::array` نیست.

### جست‌وجو با find

الگوریتم `std::find` برای پیدا کردن یک مقدار در بازه استفاده می‌شود.

```cpp
#include <algorithm>
#include <array>
#include <iostream>

int main() {
    std::array<int, 5> values = {10, 20, 30, 40, 50};

    auto iterator = std::find(
        values.begin(),
        values.end(),
        30
    );

    if (iterator != values.end()) {
        std::cout << "Value found: " << *iterator << '\n';
    }
}
```

اگر مقدار پیدا نشود، Iterator بازگشتی برابر `end()` خواهد بود.

### محاسبه مجموع با accumulate

برای محاسبه مجموع عناصر، می‌توان از `std::accumulate` استفاده کرد.

```cpp
#include <array>
#include <iostream>
#include <numeric>

int main() {
    std::array<int, 4> values = {10, 20, 30, 40};

    const int total = std::accumulate(
        values.begin(),
        values.end(),
        0
    );

    std::cout << total << '\n';
}
```

خروجی:

```text
100
```

نکته مهم این است که نوع مقدار اولیه در `std::accumulate` بر نوع متغیر انباشته‌شونده تأثیر می‌گذارد. برای مثال، اگر عناصر از نوع `int` باشند و مقدار اولیه نیز `0` باشد، جمع در نوع `int` انجام می‌شود و ممکن است در صورت سرریز عدد صحیح، رفتار تعریف‌نشده رخ دهد.

در محاسباتی که مجموع می‌تواند از محدوده `int` فراتر برود، بهتر است نوع مناسب‌تری برای مقدار اولیه انتخاب شود.

## مقایسه std::array با آرایه بومی

### تفاوت‌های ساختاری

آرایه بومی و `std::array` هر دو برای نگهداری تعداد ثابتی از عناصر مناسب هستند، اما از نظر رابط برنامه‌نویسی تفاوت‌های مهمی دارند.

| ویژگی | آرایه بومی | `std::array` |
|---|---|---|
| تعیین اندازه در زمان کامپایل | بله | بله |
| امکان تغییر اندازه | خیر | خیر |
| قرارگیری پیوسته عناصر | بله | بله |
| تابع `size()` | ندارد | دارد |
| تابع `at()` | ندارد | دارد |
| پشتیبانی مستقیم از Iteratorهای استاندارد | از طریق توابع کمکی یا Pointer | بله |
| انتساب کل آرایه با عملگر `=` | به‌طور مستقیم امکان‌پذیر نیست | امکان‌پذیر است |
| سازگاری با الگوریتم‌های استاندارد | با Pointer و بازه مناسب | با Iteratorهای استاندارد |
| نوع استاندارد Container | خیر | بله |

### تفاوت در انتساب و کپی

یکی از مزیت‌های مهم `std::array`، پشتیبانی از انتساب کل آرایه است.

```cpp
#include <array>

int main() {
    std::array<int, 3> source = {1, 2, 3};
    std::array<int, 3> destination{};

    destination = source;
}
```

در این مثال، عناصر `source` به `destination` کپی می‌شوند.

در مقابل، آرایه‌های بومی به‌صورت مستقیم از انتساب کل آرایه پشتیبانی نمی‌کنند و برای کپی عناصر باید از روش‌هایی مانند حلقه یا `std::copy` استفاده کرد.

### تفاوت در تبدیل به Pointer

آرایه بومی در بسیاری از عبارت‌ها به Pointer به اولین عنصر تبدیل می‌شود. این رفتار که به Array-to-pointer decay معروف است، ممکن است باعث از دست رفتن اطلاعات اندازه در برخی APIها شود.

اما `std::array` به‌طور خودکار به Pointer تبدیل نمی‌شود.

```cpp
#include <array>

void process(int* data, std::size_t count);

int main() {
    std::array<int, 3> values = {1, 2, 3};

    process(values.data(), values.size());
}
```

در این مثال، تبدیل به Pointer صریح است و اندازه آرایه نیز جداگانه ارسال می‌شود.

## مقایسه با std::vector

### تفاوت در اندازه و تخصیص حافظه

نوع `std::vector` برای نگهداری دنباله‌ای از عناصر با اندازه قابل تغییر طراحی شده است، در حالی که `std::array` اندازه ثابت دارد.

| ویژگی | `std::array` | `std::vector` |
|---|---|---|
| اندازه | ثابت | قابل تغییر |
| تعیین تعداد عناصر | در زمان کامپایل | معمولاً در زمان اجرا |
| مدیریت حافظه | ذخیره‌سازی درون شیء | مدیریت فضای ذخیره‌سازی پویا برای عناصر |
| پشتیبانی از `push_back` | خیر | بله |
| امکان افزایش اندازه | خیر | بله |
| مناسب برای تعداد ثابت عناصر | بسیار مناسب | مناسب، اما معمولاً غیرضروری |
| دسترسی تصادفی | بله | بله |

در `std::array`، عناصر در فضای ذخیره‌سازی متعلق به خود شیء قرار دارند. در `std::vector`، خود شیء Vector معمولاً اطلاعات مدیریتی را نگه می‌دارد و فضای عناصر را به‌صورت پویا مدیریت می‌کند.

البته استاندارد تضمین نمی‌کند که یک Container مشخص حتماً روی Stack یا Heap قرار بگیرد؛ محل ذخیره‌سازی به محل تعریف شیء، نحوه تخصیص و جزئیات پیاده‌سازی وابسته است.

### انتخاب مناسب برای کاربردهای مختلف

استفاده از `std::array` زمانی منطقی است که تعداد عناصر از نظر طراحی برنامه ثابت باشد؛ برای مثال، یک ماتریس سه‌درسه، مجموعه‌ای از ضرایب ثابت یا یک بسته داده با تعداد فیلدهای مشخص.

در مقابل، اگر تعداد عناصر بر اساس ورودی کاربر، فایل، شبکه یا نتایج محاسبات در زمان اجرا تغییر می‌کند، معمولاً `std::vector` انتخاب مناسب‌تری است.

توجه کنید که ثابت بودن اندازه به‌تنهایی دلیل کافی برای انتخاب `std::array` نیست؛ اندازه آرایه باید در زمان کامپایل قابل تعیین باشد و مدل مالکیت و عمر داده نیز با این انتخاب سازگار باشد.

## ارسال std::array به توابع

### ارسال آرایه با Reference

از آنجا که اندازه بخشی از نوع `std::array` است، می‌توان تابعی تعریف کرد که اندازه مشخصی را به‌عنوان بخشی از پارامتر نوع دریافت کند.

```cpp
#include <array>
#include <iostream>

void printValues(const std::array<int, 3>& values) {
    for (int value : values) {
        std::cout << value << ' ';
    }

    std::cout << '\n';
}

int main() {
    std::array<int, 3> values = {10, 20, 30};

    printValues(values);
}
```

استفاده از Reference ثابت باعث می‌شود آرایه کپی نشود و تابع نیز نتواند عناصر آن را تغییر دهد.

محدودیت این روش آن است که تابع فقط آرایه‌ای با نوع دقیق `std::array<int, 3>` را می‌پذیرد.

### دریافت اندازه‌های مختلف با Function Template

اگر تابع باید آرایه‌هایی با اندازه‌های متفاوت را دریافت کند، می‌توان اندازه را به پارامتر Template تبدیل کرد.

```cpp
#include <array>
#include <iostream>

template <typename T, std::size_t N>
void printArray(const std::array<T, N>& values) {
    for (const T& value : values) {
        std::cout << value << ' ';
    }

    std::cout << '\n';
}

int main() {
    std::array<int, 3> integers = {1, 2, 3};
    std::array<double, 2> decimals = {1.5, 2.5};

    printArray(integers);
    printArray(decimals);
}
```

در این روش، کامپایلر نوع عنصر و اندازه آرایه را از آرگومان تابع استخراج می‌کند.

این الگو برای نوشتن توابع عمومی که با انواع مختلف `std::array` کار می‌کنند، بسیار کاربردی است.

### دریافت آرایه با اندازه نامشخص در زمان کامپایل

گاهی تابع باید صرف‌نظر از اندازه آرایه، روی یک بازه از عناصر کار کند. در چنین شرایطی، وابسته کردن امضای تابع به یک اندازه خاص ممکن است مناسب نباشد.

در ++C20، نوع `std::span` برای نمایش یک بازه غیرمالک از عناصر پیوسته معرفی شد.

```cpp
#include <array>
#include <span>
#include <iostream>

void printValues(std::span<const int> values) {
    for (int value : values) {
        std::cout << value << ' ';
    }

    std::cout << '\n';
}

int main() {
    std::array<int, 3> first = {1, 2, 3};
    std::array<int, 5> second = {4, 5, 6, 7, 8};

    printValues(first);
    printValues(second);
}
```

این مثال به ++C20 یا نسخه جدیدتری نیاز دارد و بخشی از قابلیت‌های ++C11 نیست.

برای پروژه‌هایی که باید روی ++C11 باقی بمانند، می‌توان از Function Template، Pointer همراه با طول، یا یک رابط عمومی مناسب دیگر استفاده کرد.

## کاربردهای عملی std::array

### نگهداری ضرایب و مقادیر ثابت

برای مجموعه‌ای از مقادیر که تعدادشان در طراحی برنامه مشخص است، `std::array` انتخابی ساده و قابل پیش‌بینی محسوب می‌شود.

```cpp
#include <array>
#include <iostream>

int main() {
    const std::array<double, 4> weights = {
        0.1, 0.2, 0.3, 0.4
    };

    double result = 0.0;

    for (std::size_t i = 0; i < weights.size(); ++i) {
        result += weights[i] * static_cast<double>(i + 1);
    }

    std::cout << result << '\n';
}
```

در این مثال، تعداد ضرایب مشخص است و نیازی به تغییر اندازه در زمان اجرا وجود ندارد.

### نمایش بردار سه‌بعدی

برای نمایش یک بردار سه‌بعدی، می‌توان از آرایه‌ای شامل سه مقدار استفاده کرد.

```cpp
#include <array>
#include <iostream>

using Vector3 = std::array<double, 3>;

Vector3 add(const Vector3& first, const Vector3& second) {
    Vector3 result{};

    for (std::size_t i = 0; i < result.size(); ++i) {
        result[i] = first[i] + second[i];
    }

    return result;
}

int main() {
    const Vector3 first = {1.0, 2.0, 3.0};
    const Vector3 second = {4.0, 5.0, 6.0};

    const Vector3 result = add(first, second);

    std::cout << result[0] << ' '
              << result[1] << ' '
              << result[2] << '\n';
}
```

در این کاربرد، `std::array` مالکیت داده را به‌سادگی مدیریت می‌کند و بازگرداندن نتیجه از تابع نیز امکان‌پذیر است.

با این حال، اگر عملیات برداری پیچیده، قواعد ریاضی تخصصی یا نیازهای بهینه‌سازی خاص وجود داشته باشد، استفاده از یک نوع اختصاصی یا کتابخانه ریاضی ممکن است طراحی بهتری ارائه دهد.

### نمایش ماتریس با ابعاد ثابت

برای یک ماتریس کوچک با ابعاد مشخص، می‌توان از آرایه تو‌در‌تو استفاده کرد.

```cpp
#include <array>
#include <iostream>

int main() {
    std::array<std::array<int, 3>, 2> matrix = {{
        {{1, 2, 3}},
        {{4, 5, 6}}
    }};

    for (const auto& row : matrix) {
        for (const int value : row) {
            std::cout << value << ' ';
        }

        std::cout << '\n';
    }
}
```

این ساختار یک ماتریس با دو سطر و سه ستون را نشان می‌دهد.

در چنین ساختاری، هر سطر یک `std::array<int, 3>` مستقل از نظر نوع است و کل ماتریس شامل دو سطر از این نوع خواهد بود.

### استفاده در پروتکل‌ها و بسته‌های داده

در برنامه‌های شبکه، فایل‌های باینری و پروتکل‌های دارای طول مشخص، `std::array` می‌تواند برای نگهداری بافرهایی با اندازه ثابت مناسب باشد.

```cpp
#include <array>
#include <cstdint>

int main() {
    std::array<std::uint8_t, 16> identifier{};

    identifier[0] = 0x10;
    identifier[1] = 0x20;
}
```

این ساختار برای نگهداری شانزده بایت داده مناسب است، اما به‌تنهایی تضمین نمی‌کند که چیدمان حافظه آن با قالب یک پروتکل خارجی یا یک ساختار باینری مشخص یکسان باشد.

در طراحی پروتکل‌های باینری، باید ترتیب بایت‌ها، قالب Serialization، اعتبارسنجی ورودی و قواعد دقیق نمایش داده به‌صورت جداگانه مدیریت شوند.

## ملاحظات حافظه و کارایی

### ذخیره‌سازی پیوسته عناصر

یکی از ویژگی‌های اصلی `std::array`، قرارگیری پیوسته عناصر آن در حافظه است.

این ویژگی باعث می‌شود بتوان از Pointer به اولین عنصر برای پیمایش متوالی استفاده کرد و بسیاری از الگوریتم‌ها نیز دسترسی کارآمدی به عناصر داشته باشند.

با این حال، کارایی واقعی به نوع عناصر، الگوی دسترسی، اندازه داده، رفتار Cache و کد تولیدشده توسط کامپایلر بستگی دارد.

بنابراین، صرف استفاده از `std::array` تضمین نمی‌کند که هر عملیات از معادل آن با `std::vector` سریع‌تر باشد.

### هزینه کپی آرایه

کپی کردن یک `std::array` شامل کپی شدن عناصر آن است.

```cpp
#include <array>

int main() {
    std::array<int, 100> source{};

    std::array<int, 100> destination = source;
}
```

در این مثال، آرایه مقصد دارای نسخه‌ای مستقل از مقادیر آرایه مبدأ است.

اگر عناصر از نوع‌های کلاس باشند، هزینه کپی به رفتار Copy Constructor یا عملگر انتساب آن نوع بستگی خواهد داشت.

برای آرایه‌های بزرگ، ارسال با Reference ثابت معمولاً مانع از کپی غیرضروری می‌شود.

### اندازه بزرگ و فضای Stack

اگر یک آرایه بزرگ به‌صورت متغیر محلی تعریف شود، ممکن است فضای زیادی از حافظه پشته مصرف کند.

```cpp
#include <array>

int main() {
    std::array<int, 1000000> values{};
}
```

این مثال تقریباً به چهار میلیون بایت برای عناصر نیاز دارد، با فرض اینکه اندازه هر `int` برابر چهار بایت باشد. اندازه دقیق به پیاده‌سازی وابسته است.

اگر چنین آرایه‌ای در محیطی با محدودیت Stack تعریف شود، ممکن است اجرای برنامه با مشکل مواجه شود.

برای مجموعه‌های بزرگ که اندازه آن‌ها در زمان اجرا مشخص می‌شود یا به تخصیص پویا نیاز دارند، `std::vector` معمولاً انتخاب مناسب‌تری است. در موارد خاص می‌توان `std::array` را در فضای ایستا یا درون یک شیء دارای طول عمر مناسب نیز نگهداری کرد.

### عدم تخصیص پویا به‌وسیله خود آرایه

نوع `std::array` برای ذخیره عناصر خود از تخصیص پویای جداگانه مانند سازوکار معمول `std::vector` استفاده نمی‌کند.

این موضوع به معنای آن نیست که عناصر آن نمی‌توانند منابع پویا داشته باشند. برای مثال، اگر عنصرها از نوع `std::string` یا `std::unique_ptr` باشند، هر عنصر ممکن است منابعی را مدیریت کند.

بنابراین، باید بین محل ذخیره‌سازی خود عناصر آرایه و منابعی که اشیای داخل آن مدیریت می‌کنند، تفاوت قائل شد.

## مدیریت Swap و انتساب

### جابه‌جایی محتویات با swap

تابع `swap()` برای جابه‌جایی محتویات دو آرایه با نوع یکسان استفاده می‌شود.

```cpp
#include <array>
#include <iostream>

int main() {
    std::array<int, 3> first = {1, 2, 3};
    std::array<int, 3> second = {4, 5, 6};

    first.swap(second);

    for (int value : first) {
        std::cout << value << ' ';
    }

    std::cout << '\n';
}
```

پس از اجرای این عملیات، عناصر دو آرایه با یکدیگر جابه‌جا می‌شوند.

از آنجا که اندازه بخشی از نوع آرایه است، آرایه‌هایی با اندازه متفاوت را نمی‌توان با این تابع عضو به‌صورت مستقیم جابه‌جا کرد.

### تفاوت Swap با تعویض Pointer

در `std::array`، جابه‌جایی محتویات به معنی تعویض Pointerهای مالک داده نیست؛ زیرا خود آرایه عناصر را در فضای ذخیره‌سازی متعلق به شیء نگهداری می‌کند.

به همین دلیل، نباید رفتار `swap()` در `std::array` را با تعویض ساده Pointerها یا تغییر مالکیت فضای ذخیره‌سازی در برخی Containerهای پویا یکسان دانست.

## استفاده از مقایسه و عملگرهای رابطه‌ای

در ++C11، `std::array` از مقایسه با عملگرهای رابطه‌ای پشتیبانی می‌کند، مشروط بر آنکه نوع عناصر الزامات لازم برای مقایسه را داشته باشد.

```cpp
#include <array>
#include <iostream>

int main() {
    std::array<int, 3> first = {1, 2, 3};
    std::array<int, 3> second = {1, 2, 4};

    std::cout << std::boolalpha;
    std::cout << (first == second) << '\n';
    std::cout << (first < second) << '\n';
}
```

خروجی:

```text
false
true
```

عملگر `==` عناصر متناظر را مقایسه می‌کند و تنها زمانی نتیجه درست است که تمام عناصر متناظر برابر باشند.

مقایسه ترتیب‌دار نیز به‌صورت واژه‌نامه‌ای انجام می‌شود؛ یعنی عناصر از ابتدا مقایسه می‌شوند و نخستین عنصری که متفاوت باشد، نتیجه مقایسه را تعیین می‌کند.

این قابلیت برای کلیدهای ثابت و برخی کاربردهای مرتب‌سازی مفید است. با این حال، برای نوع‌های سفارشی باید مطمئن بود که معنای مقایسه عناصر با معنای مورد انتظار برنامه سازگار است.

## استفاده از std::get و Tuple Interface

### دسترسی به عنصر با std::get

نوع `std::array` از رابط Tuple استاندارد پشتیبانی می‌کند. در نتیجه، در ++C11 می‌توان از `std::get` برای دسترسی به عنصر با اندیس ثابت استفاده کرد.

```cpp
#include <array>
#include <iostream>
#include <tuple>

int main() {
    std::array<int, 3> values = {10, 20, 30};

    std::cout << std::get<0>(values) << '\n';
    std::cout << std::get<1>(values) << '\n';
    std::cout << std::get<2>(values) << '\n';
}
```

اندیس `std::get` یک پارامتر Template است و باید در زمان کامپایل مشخص باشد.

استفاده از این تابع در کدهای Generic و الگوریتم‌هایی که به اطلاعات نوع در زمان کامپایل نیاز دارند، مفید است.

اگر اندیس موردنظر خارج از محدوده باشد، برنامه با خطای کامپایل مواجه می‌شود.

### استفاده از tuple_size و tuple_element

در ++C11، Traitهای استاندارد `std::tuple_size` و `std::tuple_element` برای استخراج اطلاعات ساختاری آرایه در زمان کامپایل قابل استفاده هستند.

```cpp
#include <array>
#include <tuple>
#include <type_traits>

int main() {
    using ArrayType = std::array<double, 4>;

    static_assert(
        std::tuple_size<ArrayType>::value == 4,
        "Unexpected array size"
    );

    static_assert(
        std::is_same<
            std::tuple_element<0, ArrayType>::type,
            double
        >::value,
        "Unexpected element type"
    );
}
```

این قابلیت‌ها در طراحی Templateهای عمومی و کتابخانه‌هایی که به اندازه و نوع عناصر در زمان کامپایل نیاز دارند، کاربرد دارند.

## استفاده از std::to_array در نسخه‌های جدیدتر

### ساخت آرایه با std::to_array

تابع `std::to_array` در ++C20 معرفی شد و بخشی از قابلیت‌های استاندارد ++C11 نیست.

این تابع می‌تواند از یک آرایه بومی، یک `std::array` با اندازه مناسب بسازد و نوع عنصر و تعداد عناصر را استخراج کند.

```cpp
#include <array>
#include <iostream>

int main() {
    auto values = std::to_array({1, 2, 3, 4});

    std::cout << values.size() << '\n';
}
```

این قابلیت برای زمانی مفید است که نمی‌خواهیم تعداد عناصر را در اعلان نوع به‌صورت دستی تکرار کنیم.

با این حال، اگر پروژه باید با کامپایلر و کتابخانه استاندارد سازگار با ++C11 ساخته شود، باید از روش‌های مقداردهی اولیه معمول `std::array` استفاده کرد.

## محدودیت‌ها و خطاهای رایج

### فرض کردن مقدار اولیه صفر برای عناصر

تعریف آرایه بدون مقداردهی اولیه در همه شرایط به معنی صفر شدن عناصر نیست. برای جلوگیری از خواندن مقدار نامعتبر، در متغیرهای محلی بهتر است مقداردهی اولیه صریح انجام شود.

### دسترسی به اندیس خارج از محدوده

استفاده از `operator[]` برای اندیس نامعتبر رفتار تعریف‌نشده ایجاد می‌کند. در مواردی که محدوده ورودی مشخص نیست، استفاده از `at()` یا بررسی دستی محدوده انتخاب مطمئن‌تری است.

### استفاده از تابع روی آرایه خالی

توابع `front()` و `back()` برای آرایه‌ای با اندازه صفر قابل استفاده نیستند. پیش از دسترسی به این عناصر باید وجود عنصر تضمین شود.

### اشتباه گرفتن اندازه ثابت با ثبات مقادیر

ثابت بودن اندازه آرایه، تغییرناپذیری عناصر را تضمین نمی‌کند. اگر تغییر عناصر نباید مجاز باشد، باید از `const` یا یک رابط مناسب برای محدود کردن دسترسی استفاده کرد.

### ارسال آرایه بزرگ با مقدار

ارسال آرایه بزرگ با مقدار می‌تواند باعث کپی شدن تعداد زیادی عنصر شود. در توابعی که نیازی به تغییر آرایه ندارند، ارسال با Reference ثابت معمولاً انتخاب بهتری است.

### تصور امکان تغییر اندازه

نوع `std::array` از عملیات `push_back`، `resize` یا `clear` پشتیبانی نمی‌کند. اگر اندازه دنباله باید تغییر کند، بهتر است از Container مناسب مانند `std::vector` استفاده شود.

### فرض یکسان بودن نوع آرایه‌های هم‌عنصر

دو آرایه مانند `std::array<int, 3>` و `std::array<int, 4>` با وجود یکسان بودن نوع عناصر، دو نوع داده متفاوت هستند. این تفاوت هنگام تعریف پارامترهای تابع و Templateها اهمیت دارد.

### تصور تضمین‌شده بودن چیدمان باینری خاص

پیوسته بودن عناصر `std::array` به معنی تضمین یک قالب Serialization یا چیدمان باینری قابل‌انتقال نیست. برای تبادل داده با سیستم‌های دیگر باید قالب داده و قواعد تبدیل آن به‌صورت صریح تعریف شوند.

## ملاحظات طراحی و انتخاب Container

### زمان مناسب برای انتخاب std::array

استفاده از `std::array` معمولاً زمانی مناسب است که:

- تعداد عناصر در زمان کامپایل مشخص باشد.
- اندازه آرایه در طول عمر شیء تغییر نکند.
- دسترسی تصادفی و حافظه پیوسته اهمیت داشته باشد.
- نیاز به سازگاری با الگوریتم‌های استاندارد وجود داشته باشد.
- مالکیت داده باید ساده و قابل پیش‌بینی باشد.

### زمان نامناسب برای انتخاب std::array

در مقابل، اگر اندازه دنباله باید در زمان اجرا تعیین شود، تعداد عناصر مرتب تغییر کند یا داده بسیار بزرگی در اختیار برنامه باشد، معمولاً Container دیگری مناسب‌تر است.

همچنین برای مدل‌سازی مفاهیمی که عناصر آن‌ها نقش معنایی متفاوت دارند، استفاده از یک `struct` یا کلاس اختصاصی ممکن است خواناتر و ایمن‌تر باشد.

برای مثال، اگر یک شیء شامل نام، سن و وضعیت فعال بودن باشد، تعریف یک نوع اختصاصی معمولاً بهتر از نگهداری سه مقدار با اندیس‌های عددی در یک آرایه است.

## جمع‌بندی

نوع `std::array` در ++C11 راهکاری استاندارد برای نگهداری مجموعه‌ای با اندازه ثابت از عناصر هم‌نوع ارائه می‌دهد. این نوع، مزایای آرایه‌های بومی مانند حافظه پیوسته و اندازه ثابت را حفظ می‌کند و در عین حال، امکاناتی مانند `size()`، `at()`، Iteratorها، انتساب مستقیم و سازگاری با الگوریتم‌های استاندارد را در اختیار برنامه‌نویس قرار می‌دهد.

در توسعه نرم‌افزار حرفه‌ای، انتخاب این نوع باید بر اساس نیاز واقعی برنامه انجام شود. اگر اندازه داده از پیش مشخص است و قرار نیست تغییر کند، `std::array` اغلب انتخابی ساده، قابل‌پیش‌بینی و مناسب است. اگر اندازه باید تغییر کند، `std::vector` معمولاً گزینه بهتری خواهد بود.

رعایت مقداردهی اولیه صحیح، کنترل محدوده اندیس‌ها، پرهیز از کپی‌های غیرضروری و توجه به تفاوت میان اندازه ثابت و تغییرناپذیری عناصر، به استفاده ایمن‌تر و مؤثرتر از این Container کمک می‌کند.
