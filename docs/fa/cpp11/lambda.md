# عبارت Lambda

یکی از جذاب‌ترین قابلیت‌های معرفی‌شده در C++11، امکان ایجاد **توابع Lambda** است که گاهی به آن‌ها **Closure** نیز گفته می‌شود.

اما این یعنی چه؟

یک تابع Lambda تابعی است که می‌توانید آن را مستقیماً در محل استفاده، داخل کد خود بنویسید؛ معمولاً برای ارسال به یک تابع دیگر. این مفهوم شباهت زیادی به **Functor** یا **Function Pointer** دارد.

با Lambda، ساختن توابع کوچک و سریع بسیار ساده‌تر شده است. این موضوع نه‌تنها باعث می‌شود بتوانیم در جاهایی که قبلاً مجبور بودیم یک تابع نام‌گذاری‌شده‌ی جداگانه بنویسیم از Lambda استفاده کنیم، بلکه امکان نوشتن کدهایی را فراهم می‌کند که به‌شکل گسترده‌تری از توابع کوتاه و سریع استفاده می‌کنند.

> - **برای اختصاص منطق سفارشی به الگوریتم‌هایی مانند `sort`، `for_each` و `find_if` در STL استفاده می‌شود.**
> - **برای Callbackها و مدیریت رویدادها در کارهای غیرهمزمان و Eventها استفاده می‌شود.**

## چرا Lambda؟

فرض کنید یک کلاس `AddressBook` دارید و می‌خواهید قابلیتی برای جست‌وجو در آن فراهم کنید.

ممکن است یک تابع جست‌وجوی ساده ایجاد کنید که یک رشته دریافت کند و تمام آدرس‌هایی را که با آن رشته مطابقت دارند برگرداند. گاهی کاربران کلاس دقیقاً همین قابلیت را می‌خواهند.

اما اگر بخواهند فقط در **نام دامنه (Domain Name)** جست‌وجو کنند چه؟

یا شاید بخواهند فقط در **نام کاربری (Username)** جست‌وجو کنند و نتایج مربوط به Domain را نادیده بگیرند؟

یا حتی ممکن است بخواهند تمام آدرس‌های ایمیلی را پیدا کنند که در یک لیست دیگر نیز وجود دارند.

حالت‌های مختلف و جالب زیادی برای جست‌وجو وجود دارد.

به‌جای اینکه تمام این حالت‌ها را داخل کلاس پیاده‌سازی کنیم، بهتر نیست یک تابع عمومی به نام `findMatchingAddresses` داشته باشیم که یک **تابع یا شیء شبیه تابع** دریافت کند و تصمیم‌گیری درباره اینکه آیا یک آدرس موردنظر است یا نه را به آن واگذار کند؟

```cpp
#include <string>
#include <vector>

class AddressBook
{
public:
    // استفاده از template باعث می‌شود تفاوت بین Functor،
    // Function Pointer و Lambda برای ما اهمیتی نداشته باشد.
    template<typename Func>
    std::vector<std::string> findMatchingAddresses(Func func)
    {
        std::vector<std::string> results;

        for (auto itr = _addresses.begin(),
                  end = _addresses.end();
             itr != end;
             ++itr)
        {
            // تابعی را که به findMatchingAddresses ارسال شده
            // اجرا می‌کنیم و بررسی می‌کنیم که آیا مطابقت دارد یا نه.
            if (func(*itr))
            {
                results.push_back(*itr);
            }
        }

        return results;
    }

private:
    std::vector<std::string> _addresses;
};
```

هر کسی می‌تواند تابعی را به `findMatchingAddresses` ارسال کند که منطق موردنظر برای پیدا کردن یک آدرس خاص را در خود داشته باشد.

اگر تابع برای یک آدرس مشخص مقدار `true` برگرداند، آن آدرس در نتایج قرار خواهد گرفت.

این روش در نسخه‌های قدیمی‌تر C++ نیز امکان‌پذیر بود، اما یک مشکل اساسی داشت:

**ایجاد توابع کوچک برای استفاده‌های یک‌باره چندان راحت نبود.**

برای این کار مجبور بودیم ابتدا تابع را در جای دیگری تعریف کنیم و سپس آن را به تابع موردنظر ارسال کنیم؛ حتی اگر آن تابع فقط برای یک استفاده‌ی بسیار ساده نوشته شده باشد.

اینجاست که **Lambda** وارد می‌شود.

## ساختار Lambda

ساختار کلی یک Lambda به شکل زیر است:

```cpp
auto func = [capture](parameters) -> return_type {
    cout << "Hello world";
};

func();
```

آیا Lambda را که با `[]` شروع می‌شود مشاهده کردید؟

این بخش که **Capture Specification** یا به‌طور معمول **Capture List** نامیده می‌شود، به کامپایلر اعلام می‌کند که در حال ایجاد یک تابع Lambda هستیم.

این قسمت یا یکی از حالت‌های آن را تقریباً در ابتدای هر Lambda خواهید دید.

بعد از آن، مانند هر تابع دیگری، می‌توانیم لیست پارامترها را قرار دهیم:

```cpp
(parameters)
```

اما مقدار بازگشتی کجاست؟

در واقع لازم نیست همیشه آن را مشخص کنیم.

در C++11، اگر کامپایلر بتواند نوع مقدار بازگشتی Lambda را تشخیص دهد، خودش آن را **Deduce** می‌کند و نیازی نیست نوع را به‌صورت صریح بنویسیم.

در مثال بالا، کامپایلر می‌داند که Lambda چیزی برنمی‌گرداند و نوع آن `void` است.

در نهایت بدنه‌ی تابع را داریم:

```cpp
{
    cout << "Hello world";
}
```

البته صرفاً تعریف Lambda باعث اجرای آن نمی‌شود؛ در این مرحله فقط تابع را ایجاد کرده‌ایم.

این تقریباً شبیه تعریف یک تابع معمولی است، با این تفاوت که Lambda می‌تواند مستقیماً در همان محل موردنیاز نوشته شود.

### بخش‌های Lambda

```text
[]          Capture List
()          Parameters
->          Return Type
{ ... }     Function Body
```

> `[]` **Capture List:** برای وارد کردن متغیرهای محیط بیرونی به Lambda  
> `()` **Parameters:** پارامترهای Lambda  
> `->` **Return Type:** نوع مقدار بازگشتی  
> `{...}` **Function Body:** بدنه‌ی تابع

## Capture کردن متغیرها در Lambda

استفاده‌های ساده از Lambda بسیار کاربردی هستند، اما قابلیت **Variable Capture** است که Lambda را واقعاً قدرتمند می‌کند.

فرض کنید می‌خواهید تابع کوچکی ایجاد کنید که آدرس‌هایی را پیدا کند که شامل یک نام مشخص هستند.

خوب نیست اگر بتوانیم چیزی شبیه کد زیر بنویسیم؟

```cpp
// نامی را از کاربر دریافت می‌کنیم که می‌خواهیم جست‌وجو کنیم.
string name;
cin >> name;

return global_address_book.findMatchingAddresses(
    // Lambda از متغیر name استفاده می‌کند.
    [&] (const string& addr)
    {
        return addr.find(name) != string::npos;
    }
);
```

ما توانستیم متغیری را که **خارج از Lambda** تعریف شده است (`name`) داخل Lambda استفاده کنیم.

وقتی `findMatchingAddresses` Lambda ما را اجرا می‌کند، تمام کد داخل Lambda اجرا می‌شود و هنگام فراخوانی `addr.find`، Lambda به متغیر `name` که کاربر وارد کرده است دسترسی دارد.

تنها کاری که برای این منظور لازم بود انجام دهیم، این بود که به کامپایلر اعلام کنیم می‌خواهیم متغیرهای بیرونی را Capture کنیم.

این کار را با استفاده از:

```cpp
[&]
```

انجام دادیم.

در مقابل، `[]` خالی به کامپایلر می‌گوید که **هیچ متغیری را Capture نکن**.

بنابراین:

```cpp
[]
```

یعنی هیچ متغیر بیرونی Capture نشود.

و:

```cpp
[&]
```

یعنی متغیرهای مورد استفاده از محیط بیرونی به‌صورت **Reference** Capture شوند.

با این قابلیت می‌توانیم یک تابع کوچک برای ارسال به تابع جست‌وجو ایجاد کنیم، متغیر `name` را Capture کنیم و همه‌ی این کارها را تنها در چند خط انجام دهیم.

برای دستیابی به رفتاری مشابه در نسخه‌های قبل از C++11، احتمالاً مجبور بودیم یک **Functor Class** کامل ایجاد کنیم یا یک تابع اختصاصی برای `AddressBook` بنویسیم.

اما در C++11 می‌توانیم یک Interface ساده و عمومی برای `AddressBook` داشته باشیم که به‌راحتی از انواع مختلف Filterها پشتیبانی کند.

## Lambda و STL

یکی از بزرگ‌ترین استفاده‌کنندگان Lambda بدون شک کاربران حرفه‌ای **الگوریتم‌های Standard Template Library (STL)** هستند.

در گذشته، استفاده از الگوریتم‌هایی مانند `for_each` چندان راحت نبود.

اما اکنون می‌توانیم از `for_each` و سایر الگوریتم‌های STL تقریباً مانند یک حلقه‌ی معمولی استفاده کنیم.

### روش معمول

```cpp
vector<int> v;

v.push_back(1);
v.push_back(2);
// ...

for (auto itr = v.begin(), end = v.end();
     itr != end;
     itr++)
{
    cout << *itr;
}
```

### استفاده از Lambda

```cpp
vector<int> v;

v.push_back(1);
v.push_back(2);
// ...

for_each(v.begin(), v.end(), [] (int val)
{
    cout << val;
});
```

**نکته‌ی جالب اینجاست:**

الگوریتم `for_each` تقریباً عملکردی مشابه یک حلقه‌ی `for` معمولی دارد و در بعضی شرایط حتی می‌تواند سریع‌تر نیز باشد.

## توضیح بیشتر درباره Syntax جدید Lambda

به‌طور کلی، **لیست پارامترها** نیز مانند نوع مقدار بازگشتی اختیاری است.

اگر بخواهید Lambdaای داشته باشید که هیچ آرگومانی دریافت نمی‌کند، حتی می‌توانید پارامترها را حذف کنید.

برای مثال:

```cpp
int main()
{
    [] {
        cout << "Hello, my Greek friends";
    }();
}
```

در این مثال Lambda بلافاصله پس از تعریف، با استفاده از `()` اجرا می‌شود.

## مقدار بازگشتی

اگر Lambda شما دستور `return` نداشته باشد، به‌صورت پیش‌فرض نوع بازگشتی آن `void` خواهد بود.

اگر یک عبارت بازگشتی ساده داشته باشید، کامپایلر می‌تواند نوع مقدار بازگشتی را تشخیص دهد:

```cpp
[] () {
    return 1;
}
```

کامپایلر می‌داند که این Lambda مقدار `int` برمی‌گرداند.

اگر Lambda پیچیده‌تری داشته باشید که بیش از یک `return` دارد، ممکن است لازم باشد نوع بازگشتی را به‌صورت صریح مشخص کنید.

برای مثال:

```cpp
[] () -> int {
    return 1;
}
```

در اینجا به‌صورت صریح به کامپایلر اعلام کرده‌ایم که نوع مقدار بازگشتی `int` است.

در Lambda، اگر بخواهیم نوع Return را به‌صورت صریح مشخص کنیم، باید از Syntax زیر استفاده کنیم:

```cpp
[capture] (parameters) -> return_type
{
    // body
}
```

یعنی نوع بازگشتی **بعد از لیست پارامترها و با استفاده از `->`** قرار می‌گیرد.

## Lambda Closureها چگونه پیاده‌سازی می‌شوند؟

C++ به دلیل اهمیت بسیار زیاد Performance، انعطاف زیادی در مورد اینکه چه متغیرهایی Capture شوند و چگونه Capture شوند در اختیار برنامه‌نویس قرار می‌دهد.

تمام این رفتارها از طریق **Capture Specification** یا همان `[]` کنترل می‌شوند.

تا اینجا دو حالت را دیده‌ایم:

- `[]` هیچ متغیری را Capture نمی‌کند.
- `[&]` متغیرها را به‌صورت Reference Capture می‌کند.

اگر Lambda دارای Capture List خالی باشد:

```cpp
[]
```

در واقع هیچ متغیر محلی از محیط بیرون وارد Lambda نمی‌شود.

حالت‌های مختلف Capture عبارت‌اند از:

| Capture | توضیح |
|---|---|
| `[]` | هیچ متغیری Capture نمی‌شود. |
| `[&]` | هر متغیری که مورد استفاده قرار بگیرد، به‌صورت Reference Capture می‌شود. |
| `[=]` | هر متغیری که مورد استفاده قرار بگیرد، با ایجاد یک Copy Capture می‌شود. |
| `[=, &foo]` | متغیرهای مورد استفاده به‌صورت Copy Capture می‌شوند، اما `foo` به‌صورت Reference Capture می‌شود. |
| `[bar]` | فقط `bar` به‌صورت Copy Capture می‌شود و سایر متغیرها Capture نمی‌شوند. |
| `[this]` | اشاره‌گر `this` از کلاس دربرگیرنده Capture می‌شود. |

### مثال استفاده از `[this]`

```cpp
class Foo
{
public:
    Foo() : _x(3) {}

    void func()
    {
        // یک روش ساده برای چاپ مقدار _x
        [this]() {
            cout << _x;
        }();
    }

private:
    int _x;
};

int main()
{
    Foo f;
    f.func();
}
```

در این مثال، Lambda به `this` مربوط به شیء `Foo` دسترسی دارد و بنابراین می‌تواند به عضو `_x` دسترسی پیدا کند.

## خطرات و مزایای Capture به‌صورت Reference

وقتی متغیری را به‌صورت Reference Capture می‌کنید، Lambda می‌تواند متغیر محلی خارج از Lambda را تغییر دهد؛ زیرا در واقع به همان متغیر اصلی Reference دارد.

برای مثال:

```cpp
int value = 10;

[&value]() {
    value = 20;
}();
```

پس از اجرای Lambda، مقدار `value` برابر `20` خواهد بود.

اما این قابلیت یک خطر مهم نیز دارد.

اگر یک Lambda را از داخل یک تابع برگردانید، نباید از **Capture به‌صورت Reference** برای متغیرهای محلی آن تابع استفاده کنید.

زیرا پس از پایان اجرای تابع، متغیر محلی از بین می‌رود و Reference موجود در Lambda دیگر معتبر نخواهد بود.

برای مثال، چنین کدی خطرناک است:

```cpp
auto createLambda()
{
    int value = 10;

    return [&value]() {
        return value;
    };
}
```

پس از پایان `createLambda`، متغیر `value` دیگر وجود ندارد و Lambda یک Reference نامعتبر در اختیار خواهد داشت.

در چنین شرایطی معمولاً باید از **Capture by Value** استفاده کرد:

```cpp
auto createLambda()
{
    int value = 10;

    return [value]() {
        return value;
    };
}
```

در این حالت Lambda یک Copy از `value` را در خود نگه می‌دارد.

## جمع‌بندی

با معرفی Lambdaها در C++11، امکان تعریف **توابع ناشناس (Anonymous Functions)** و **توابع Inline** فراهم شد.

این قابلیت در بسیاری از موارد باعث:

- کاهش حجم کد
- افزایش خوانایی
- ساده‌تر شدن Unit Testها
- کاهش نیاز به ایجاد توابع و کلاس‌های کمکی
- و جایگزینی ایمن‌تر برای برخی استفاده‌های Macroها

می‌شود.

به همین دلیل، استفاده از Lambdaها در کدهای C++ به‌طور قابل‌توجهی افزایش پیدا کرده است.

Lambdaها یکی از قابلیت‌های مهم C++11 هستند و امروزه بخش جدایی‌ناپذیری از کدنویسی مدرن C++ به شمار می‌روند.
