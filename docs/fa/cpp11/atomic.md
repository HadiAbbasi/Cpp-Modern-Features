# Atomic

هدر `<atomic>` که در **C++11** معرفی شد، نوع‌ها و عملیات اتمیک را برای
دسترسی ایمن به داده‌های مشترک در برنامه‌های چندنخی فراهم می‌کند. این هدر با
اطمینان از اینکه عملیات روی متغیرهای مشترک به‌صورت **اتمیک (Atomic)**
انجام می‌شوند، به جلوگیری از **Data Race** کمک می‌کند.

-   برای بسیاری از انواع داده‌های اولیه، امکان همگام‌سازی بدون استفاده از
    قفل (**Lock-Free**) را فراهم می‌کند.
-   امکان ارتباط ایمن بین چندین نخ (**Thread**) را بدون نیاز به استفاده
    مستقیم از `mutex` فراهم می‌کند.

``` cpp
std::atomic<type> variable_name;
```

## پارامترها

-   `data_type`: نوع داده، مانند `int`، `bool`، `char` و غیره.
-   `variable_name`: نام متغیر اتمیک.

## عملیات رایج Atomic

هدر `<atomic>` عملیات مختلفی برای خواندن، تغییر دادن و همگام‌سازی
متغیرهای اتمیک فراهم می‌کند.

  -----------------------------------------------------------------------
  تابع                                توضیح
  ----------------------------------- -----------------------------------
  `load()`                            مقدار فعلی متغیر اتمیک را می‌خواند.

  `store()`                           مقدار جدیدی را در متغیر اتمیک ذخیره
                                      می‌کند.

  `exchange()`                        مقدار فعلی را با مقدار جدید جایگزین
                                      کرده و مقدار قبلی را برمی‌گرداند.

  `fetch_add()`                       به‌صورت اتمیک مقداری را اضافه کرده و
                                      مقدار قبلی را برمی‌گرداند.

  `fetch_sub()`                       به‌صورت اتمیک مقداری را کم کرده و
                                      مقدار قبلی را برمی‌گرداند.

  `fetch_and()`                       عملیات AND بیتی را به‌صورت اتمیک
                                      انجام می‌دهد.

  `fetch_or()`                        عملیات OR بیتی را به‌صورت اتمیک
                                      انجام می‌دهد.

  `fetch_xor()`                       عملیات XOR بیتی را به‌صورت اتمیک
                                      انجام می‌دهد.

  `wait()`                            تا زمانی که مقدار متغیر اتمیک تغییر
                                      کند، منتظر می‌ماند. **(C++20)**

  `notify_one()`                      یکی از Threadهای منتظر را بیدار
                                      می‌کند. **(C++20)**

  `notify_all()`                      تمام Threadهای منتظر را بیدار
                                      می‌کند. **(C++20)**
  -----------------------------------------------------------------------

## مثال

در این مثال:

-   دو Thread یک شمارنده اتمیک مشترک را افزایش می‌دهند.
-   تابع `fetch_add()` هر افزایش را به‌صورت اتمیک انجام می‌دهد.
-   نتیجه نهایی صحیح خواهد بود، زیرا **Data Race** اتفاق نمی‌افتد.

``` cpp
#include <atomic>
#include <iostream>
#include <thread>
using namespace std;

atomic<int> counter(0); // شمارنده اتمیک

void increment_counter(int id)
{
    for (int i = 0; i < 100000; ++i) {
        // افزایش اتمیک شمارنده
        counter.fetch_add(1);
    }
}

int main()
{
    thread t1(increment_counter, 1);
    thread t2(increment_counter, 2);

    t1.join();
    t2.join();

    cout << "Counter: " << counter.load() << std::endl;

    return 0;
}
```

در این برنامه هر Thread تعداد **100000 بار** شمارنده را افزایش می‌دهد.
بنابراین مقدار نهایی `counter` برابر با:

``` text
200000
```

خواهد بود.

## `std::atomic_flag`

`std::atomic_flag` ساده‌ترین نوع اتمیک موجود در هدر `<atomic>` است.

این نوع یک **فلگ (Flag) بولی اتمیک** است و معمولاً برای پیاده‌سازی روش‌های
سبک همگام‌سازی مانند **Spinlock** استفاده می‌شود.

عملیات اصلی آن عبارت‌اند از:

  -----------------------------------------------------------------------
  تابع                                توضیح
  ----------------------------------- -----------------------------------
  `test()`                            مقدار فعلی Flag را می‌خواند.
                                      **(C++20)**

  `test_and_set()`                    Flag را تنظیم (`set`) کرده و مقدار
                                      قبلی آن را برمی‌گرداند.

  `clear()`                           Flag را پاک کرده و به حالت `false`
                                      برمی‌گرداند.
  -----------------------------------------------------------------------

### مثال

در مثال زیر:

-   `test_and_set()` به‌صورت اتمیک Flag را در اختیار یک Thread قرار
    می‌دهد.
-   در هر لحظه فقط یک Thread می‌تواند وارد بخش حساس (**Critical
    Section**) شود.
-   `clear()` Flag را آزاد می‌کند تا Thread دیگری بتواند از آن استفاده
    کند.

``` cpp
#include <atomic>
#include <iostream>
#include <thread>

using namespace std;

atomic_flag flag = ATOMIC_FLAG_INIT;

void work(int id)
{
    while (flag.test_and_set(memory_order_acquire))
        ;

    cout << "Thread " << id << " is running\n";

    flag.clear(memory_order_release);
}

int main()
{
    thread t1(work, 1);
    thread t2(work, 2);

    t1.join();
    t2.join();

    return 0;
}
```

در این مثال، `atomic_flag` مانند یک **قفل بسیار ساده** عمل می‌کند. اگر
Flag آزاد باشد، یک Thread آن را می‌گیرد و وارد بخش حساس می‌شود. پس از
اتمام کار، با `clear()` آن را آزاد می‌کند.

## مزایای Atomic

هدر `<atomic>` مزایای مختلفی دارد:

-   از **Data Race** در برنامه‌های چندنخی جلوگیری می‌کند.
-   در بسیاری از سیستم‌ها از برنامه‌نویسی **Lock-Free** پشتیبانی می‌کند.
-   برای دسترسی‌های سبک به داده‌های مشترک می‌تواند عملکرد مناسبی داشته
    باشد.
-   برای عملیات ساده روی متغیرهای مشترک، در بسیاری از موارد نسبت به
    استفاده از `mutex` سبک‌تر است.

## محدودیت‌های Atomic

با وجود مزایای `atomic`، این روش محدودیت‌هایی نیز دارد:

-   بیشتر برای کار با **متغیرهای منفرد** مناسب است و برای عملیات پیچیده
    روی چند متغیر کافی نیست.
-   انتخاب نادرست **Memory Ordering** همچنان می‌تواند باعث ایجاد خطاهای
    همگام‌سازی شود.
-   برای مدیریت منابع مشترک و عملیات پیچیده، معمولاً همچنان به `mutex` و
    سایر ابزارهای همگام‌سازی نیاز است.

## نکته مهم

**Atomic بودن یک متغیر به این معنی نیست که کل برنامه به‌صورت خودکار
Thread-Safe می‌شود.**

`atomic` فقط عملیات مشخصی را روی همان متغیر به‌صورت اتمیک انجام می‌دهد.
اگر یک عملیات شامل چند مرحله یا چند متغیر باشد، ممکن است همچنان به
`mutex` یا روش‌های دیگر برای همگام‌سازی نیاز داشته باشید.
