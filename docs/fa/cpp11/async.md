# async

> `std::async` یکی از آن ابزارهای C++ است که در ابتدا کوچک و ساده به نظر می‌رسد، اما وقتی شروع به استفاده از آن می‌کنید، کد شما تمیزتر و به‌صورت طبیعی غیرهمزمان می‌شود. چه در حال بارگذاری منابع در پس‌زمینه باشید، چه محاسبات سنگین را به پس‌زمینه منتقل کنید یا صرفاً بخواهید رابط کاربری خود را پاسخ‌گو نگه دارید، `std::async` روشی سطح‌بالا و تمیز برای اجرای کارها بدون مسدود کردن جریان اصلی برنامه ارائه می‌دهد.

> برنامه‌نویسی غیرهمزمان (Asynchronous Programming) به بخش مهمی از توسعهٔ برنامه‌های مدرن تبدیل شده است؛ به‌خصوص زمانی که نیاز داریم وظایف طولانی‌مدت را بدون مسدود کردن رابط کاربری یا متوقف کردن برنامه اجرا کنیم. در زبان‌هایی مانند JavaScript، الگوی Async/Await برای ساده‌تر کردن نوشتن کدهای غیرهمزمان استفاده می‌شود و باعث می‌شود کد ظاهری شبیه به کدهای همزمان داشته باشد. اما چگونه می‌توان مفهومی مشابه را در زبانی مانند C++ پیاده‌سازی کرد؟ در این مقاله بررسی می‌کنیم که چگونه می‌توان برنامه‌نویسی غیرهمزمان را در C++ با استفاده از ابزارهای استانداردی مانند `std::async` پیاده‌سازی کرد و این رویکرد در چه سناریوهایی می‌تواند مفید باشد.

## چرا async؟

هر مسئلهٔ مربوط به همزمانی به این معنا نیست که باید یک Thread ایجاد کنیم و آن را برای همیشه مدیریت کنیم.

بسیاری از وظایف بیشتر شبیه این هستند:

- اجرای یک کار سنگین
- ادامه دادن کار دیگری در همین حین
- دریافت نتیجه در زمان مناسب
- مدیریت صحیح خطاها

این دقیقاً همان جایی است که **Futureها** کاربرد دارند.

### مثال‌ها

- پردازش یک فایل تنظیمات بزرگ در حالی که رابط کاربری همچنان به کار خود ادامه می‌دهد
- بارگذاری منابع در پس‌زمینه
- اجرای محاسبات مستقل در یک ابزار Build
- اجرای چند مرحلهٔ مستقل Benchmark و جمع‌آوری نتایج در ادامه

## هستهٔ Async در C++ مدرن

C++ مدرن مجموعه‌ای از Typeها و ابزارها را برای مدیریت نتایج غیرهمزمان در اختیار ما قرار می‌دهد:

- `std::async`: اجرای یک کار را به‌صورت غیرهمزمان آغاز می‌کند و یک `std::future` برمی‌گرداند.
- `std::future<T>`: نمایندهٔ نتیجه‌ای است که در آینده در دسترس قرار خواهد گرفت. [یادگیری future](./future.md)
- `std::promise<T>`: به یک Thread اجازه می‌دهد نتیجه‌ای را برای Thread دیگری تولید کند.
- `std::shared_future<T>`: به چند مصرف‌کننده اجازه می‌دهد یک نتیجهٔ مشترک را مشاهده کنند.

ایدهٔ اصلی ساده است:

**یک طرف نتیجه را تولید می‌کند و طرف دیگر در صورت نیاز منتظر آن می‌ماند یا نتیجه را دریافت می‌کند.**

## std::async

ساده‌ترین نقطهٔ شروع برای اجرای یک کار غیرهمزمان، `std::async` است.

```cpp
#include <future>
#include <iostream>

int compute()
{
    return 42;
}

int main()
{
    std::future<int> result =
        std::async(std::launch::async, compute);

    std::cout << result.get() << '\n';

    return 0;
}
```

یک نکتهٔ مهم این است که `std::async` می‌تواند با **Launch Policy**های مختلفی استفاده شود.

### std::launch::async

با استفاده از `std::launch::async`، تابع برای اجرای غیرهمزمان انتخاب می‌شود.

```cpp
auto future_value = std::async(std::launch::async, [] {
    return 10 * 20;
});
```

### std::launch::deferred

در این حالت اجرای تابع تا زمانی که روی Future عملیات انتظار انجام شود، به تعویق می‌افتد.

```cpp
auto future_value = std::async(std::launch::deferred, [] {
    return 10 * 20;
});
```

اجرای تابع زمانی انجام می‌شود که مثلاً `get()` یا `wait()` روی Future فراخوانی شود.

### Launch Policy پیش‌فرض

اگر Policy را مشخص نکنیم:

```cpp
auto future_value = std::async([] {
    return 10 * 20;
});
```

پیاده‌سازی استاندارد می‌تواند بین اجرای `async` و `deferred` تصمیم بگیرد.

بنابراین اگر رفتار قابل پیش‌بینی برای شما مهم است، بهتر است Launch Policy را به‌صورت صریح مشخص کنید.

## یک مثال واقعی

فرض کنید برنامه‌ای داریم که اطلاعات آب‌وهوا را از یک API دریافت می‌کند:

```cpp
#include <chrono>
#include <iostream>
#include <string>
#include <thread>

#include "httplib.h"

std::string getWeatherData()
{
    httplib::Client cli("http://api.open-meteo.com");

    std::string apiBody;

    if (auto res = cli.Get(
            "/v1/forecast?latitude=52.52&longitude=13.41"
            "&current=temperature_2m"))
    {
        apiBody = res->body;
    }

    std::this_thread::sleep_for(std::chrono::seconds(4));

    return apiBody;
}

int main()
{
    while (true)
    {
        std::cout << "Fetching weather data....\n";

        std::string currentWeather = getWeatherData();

        std::cout << "Loading UI ...\n";

        std::cout << "\nCurrent weather is: "
                  << currentWeather << '\n';

        std::this_thread::sleep_for(
            std::chrono::seconds(1)
        );
    }

    return 0;
}
```

در این مثال به‌وضوح می‌توان دید که برنامه در هر چرخه حدود **۴ ثانیه** منتظر می‌ماند و در این مدت نمی‌تواند کار دیگری انجام دهد.

در برنامه‌های واقعی نیز درخواست‌های API ممکن است بسته به سرعت شبکه و وضعیت سرور حتی بیشتر از این زمان طول بکشند.

حالا می‌توانیم به‌جای اجرای مستقیم تابع `getWeatherData()`، آن را با `std::async` اجرا کنیم:

```cpp
auto weatherFuture =
    std::async(std::launch::async, getWeatherData);
```

در این حالت، اجرای `getWeatherData()` به‌صورت غیرهمزمان انجام می‌شود و برنامهٔ اصلی می‌تواند در همین حین به کار خود ادامه دهد.

هر زمان که به نتیجه نیاز داشتیم، می‌توانیم با استفاده از `get()` آن را دریافت کنیم:

```cpp
std::string currentWeather = weatherFuture.get();
```

اگر نتیجه هنوز آماده نشده باشد، `get()` منتظر می‌ماند تا عملیات کامل شود و سپس نتیجه را برمی‌گرداند.

به این ترتیب، به‌جای مدیریت مستقیم Threadها، می‌توانیم تمرکز خود را روی **کاری که باید انجام شود** و **نتیجه‌ای که در آینده دریافت خواهیم کرد** قرار دهیم.

## Conclusion

`std::async` یک ابزار سطح‌بالا در کتابخانهٔ استاندارد C++ برای اجرای عملیات غیرهمزمان است که می‌تواند پیچیدگی مدیریت مستقیم Threadها را کاهش دهد و کد را خواناتر و کوتاه‌تر کند.

با این حال، باید توجه داشت که رفتار `std::async` به Launch Policy انتخاب‌شده وابسته است. همچنین در استفاده‌های همزمانی، باید به نحوهٔ دسترسی به داده‌های مشترک، طول عمر متغیرها و نحوهٔ مدیریت `std::future` توجه ویژه‌ای داشته باشیم.

به‌طور خاص، در کدهای همزمان باید مراقب متغیرهای `thread_local` و همچنین رفتار Future بازگشتی از `std::async` باشیم.

در نهایت، اگر فقط به اجرای یک کار در پس‌زمینه و دریافت نتیجهٔ آن در آینده نیاز دارید، `std::async` می‌تواند یکی از ساده‌ترین گزینه‌های موجود در C++ مدرن باشد.
