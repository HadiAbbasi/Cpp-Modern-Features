# راهنمای جامع تولید اعداد تصادفی در ++C با استفاده از `std::random`، `std::random_device`، `std::mt19937` و `distributions`

در ++C مدرن، تولید اعداد تصادفی بر اساس همکاری دو مؤلفه اصلی انجام می‌شود: موتورهای تولید اعداد تصادفی (Random Number Engines) و توزیع‌های آماری (Random Number Distributions). این معماری امکان تولید اعداد شبه‌تصادفی با کیفیت مناسب، کنترل‌پذیری بالا و رفتار قابل بازتولید را فراهم می‌کند.

کتابخانه استاندارد `<random>` از ++C11 معرفی شد تا جایگزینی قدرتمندتر و قابل‌اعتمادتر برای روش‌های قدیمی مانند `std::rand` و `std::srand` باشد.

در این راهنما، نحوه کار این اجزا، تفاوت‌های مهم آن‌ها، کاربردهای عملی، محدودیت‌ها و اشتباهات رایج را بررسی می‌کنیم.

## آشنایی با کتابخانه `<random>`

کتابخانه استاندارد `<random>` مجموعه‌ای از ابزارها برای تولید اعداد تصادفی و نمونه‌گیری از توزیع‌های آماری ارائه می‌دهد.

این کتابخانه به‌طور کلی از سه مفهوم تشکیل شده است:

- منبع اولیه آنتروپی (Entropy Source): برای مثال، `std::random_device` که ممکن است به منبع تصادفی سیستم‌عامل یا یک پیاده‌سازی جایگزین متکی باشد.
- موتور تولید اعداد تصادفی (Random Number Engine): مانند `std::mt19937` که دنباله‌ای از اعداد شبه‌تصادفی تولید می‌کند.
- توزیع آماری (Distribution): مانند `std::uniform_int_distribution` که خروجی موتور را به نمونه‌هایی با توزیع آماری مشخص تبدیل می‌کند.

### مفهوم تفاوت موتور و توزیع

موتور و توزیع دو وظیفه متفاوت دارند. موتور، اعداد خام را از یک دنباله شبه‌تصادفی تولید می‌کند؛ توزیع تعیین می‌کند که این اعداد چگونه به مقادیر موردنیاز برنامه تبدیل شوند.

برای مثال، اگر بخواهیم عددی صحیح بین ۱ و ۶ برای شبیه‌سازی تاس تولید کنیم، استفاده از یک موتور به‌تنهایی کافی نیست. بهتر است خروجی آن را به کمک یک توزیع یکنواخت صحیح به بازه موردنظر نگاشت کنیم.

```
#include <iostream>
#include <random>

int main() {
    std::mt19937 engine{std::random_device{}()};
    std::uniform_int_distribution<int> distribution{1, 6};

    for (int i = 0; i < 10; ++i) {
        std::cout << distribution(engine) << '\n';
    }
}
```

در این مثال، موتور `std::mt19937` دنباله شبه‌تصادفی را تولید می‌کند و توزیع `std::uniform_int_distribution` اعداد صحیح بین ۱ و ۶ را برمی‌گرداند.

## معرفی `std::random_device`

کلاس `std::random_device` یک منبع تولید اعداد شبه‌تصادفی یا تصادفی را در اختیار برنامه قرار می‌دهد که معمولاً برای مقداردهی اولیه موتورهای تصادفی استفاده می‌شود.

این کلاس از ++C11 در کتابخانه استاندارد وجود دارد.

### کاربرد اصلی `std::random_device`

یکی از کاربردهای رایج این کلاس، فراهم کردن seed برای موتوری مانند `std::mt19937` است. هدف این است که اجرای برنامه در شرایط معمول با اجرای دیگر دنباله متفاوتی تولید کند.

```
#include <iostream>
#include <random>

int main() {
    std::random_device rd;

    std::cout << rd() << '\n';
    std::cout << rd() << '\n';
    std::cout << rd() << '\n';
}
```

در این برنامه، هر بار فراخوانی `rd()` مقداری از نوع `std::random_device::result_type` برمی‌گرداند.

### محدودیت‌های مهم `std::random_device`

نباید فرض کرد که این کلاس در تمام سیستم‌ها الزاماً از سخت‌افزار یا منبع تصادفی رمزنگاری‌شده استفاده می‌کند.

- در بعضی پیاده‌سازی‌ها، خروجی از یک منبع تصادفی سیستم‌عامل تأمین می‌شود.
- در برخی شرایط، پیاده‌سازی ممکن است از یک مولد شبه‌تصادفی استفاده کند.
- هزینه فراخوانی آن ممکن است نسبت به یک موتور معمولی بیشتر باشد.
- رفتار دقیق آن به پیاده‌سازی کتابخانه استاندارد و محیط اجرا وابسته است.

بنابراین، استفاده از `std::random_device` برای مقداردهی اولیه موتور مناسب است، اما نباید بدون بررسی مستندات پلتفرم آن را تضمینی برای امنیت رمزنگاری در نظر گرفت.

### بررسی `entropy()`

تابع عضو `entropy()` مقدار تقریبی آنتروپی منبع را برمی‌گرداند. این مقدار می‌تواند درباره ویژگی‌های منبع اطلاعات بدهد، اما به‌تنهایی تضمین نمی‌کند که خروجی برای اهداف رمزنگاری امن باشد.

```
#include <iostream>
#include <random>

int main() {
    std::random_device rd;

    std::cout << "Entropy estimate: "
              << rd.entropy()
              << '\n';
}
```

در این مثال، مقدار نمایش‌داده‌شده باید مطابق مستندات پیاده‌سازی تفسیر شود. مقدار صفر نیز لزوماً به این معنا نیست که خروجی در تمام شرایط فاقد هرگونه تصادفی‌بودن است.

## معرفی `std::mt19937`

موتور `std::mt19937` یکی از شناخته‌شده‌ترین موتورهای شبه‌تصادفی در کتابخانه استاندارد ++C است. این موتور بر اساس الگوریتم Mersenne Twister طراحی شده و از ++C11 در دسترس است.

نام آن به پارامتر دوره الگوریتم اشاره دارد: دوره این موتور برابر با \\(2^{19937}-1\\) است.

### ویژگی‌های اصلی `std::mt19937`

- دوره بسیار طولانی دارد.
- برای شبیه‌سازی، بازی‌سازی، آزمون نرم‌افزار و نمونه‌گیری آماری کاربرد دارد.
- نسبت به بسیاری از منابع تصادفی سیستم‌عامل، برای تولید تعداد زیادی عدد معمولاً کارآمد است.
- امکان بازتولید دنباله با seed یکسان را فراهم می‌کند.
- برای استفاده مستقیم در رمزنگاری طراحی نشده است.

### مقداردهی اولیه موتور

برای مقداردهی اولیه موتور می‌توان از یک seed ثابت استفاده کرد:

```
#include <iostream>
#include <random>

int main() {
    std::mt19937 engine{12345};

    for (int i = 0; i < 5; ++i) {
        std::cout << engine() << '\n';
    }
}
```

با یکسان بودن پیاده‌سازی و seed، دنباله تولیدشده توسط این موتور قابل بازتولید است. این ویژگی در آزمون نرم‌افزار و اشکال‌زدایی اهمیت زیادی دارد.

### مقداردهی اولیه با `std::random_device`

در کاربردهایی که بازتولید دقیق دنباله از پیش تعیین نشده است، می‌توان موتور را با خروجی `std::random_device` مقداردهی اولیه کرد:

```
#include <random>

int main() {
    std::random_device rd;
    std::mt19937 engine{rd()};

    return static_cast<int>(engine() & 1U);
}
```

این روش ساده است، اما تنها یک مقدار seed فراهم می‌کند. اگر به مقداردهی اولیه با تعداد بیشتری از داده‌های seed نیاز باشد، می‌توان از `std::seed_seq` استفاده کرد.

### مفهوم `std::seed_seq`

کلاس `std::seed_seq` برای تبدیل مجموعه‌ای از مقادیر اولیه به داده‌هایی مناسب برای مقداردهی اولیه موتور طراحی شده است.

```
#include <iostream>
#include <random>
#include <array>

int main() {
    std::random_device rd;

    std::array<std::random_device::result_type, 8> seed_data{};

    for (auto& value : seed_data) {
        value = rd();
    }

    std::seed_seq seed_sequence(seed_data.begin(), seed_data.end());
    std::mt19937 engine(seed_sequence);

    std::cout << engine() << '\n';
}
```

این روش برای ساختن وضعیت اولیه موتور از چند مقدار seed مفید است. با این حال، تعداد مقادیر seed به‌تنهایی تضمین نمی‌کند که منبع اولیه آنتروپی کافی یا امنیت رمزنگاری فراهم کرده باشد.

## آشنایی با توزیع‌های آماری

توزیع‌ها تعیین می‌کنند که خروجی موتور تصادفی چگونه به مقادیر موردنیاز برنامه تبدیل شود. کتابخانه استاندارد توزیع‌های مختلفی برای داده‌های صحیح، اعشاری و برخی توزیع‌های آماری متداول ارائه می‌دهد.

### توزیع یکنواخت صحیح

توزیع `std::uniform_int_distribution` اعداد صحیح را در یک بازه بسته تولید می‌کند؛ یعنی هر دو کران ابتدا و انتها جزو بازه هستند.

```
#include <iostream>
#include <random>

int main() {
    std::mt19937 engine{42};
    std::uniform_int_distribution<int> distribution{10, 20};

    for (int i = 0; i < 10; ++i) {
        std::cout << distribution(engine) << '\n';
    }
}
```

در این مثال، خروجی همواره بین ۱۰ و ۲۰ خواهد بود.

استفاده از این توزیع برای انتخاب تصادفی یک اندیس، شبیه‌سازی تاس یا تولید مقادیر صحیح در یک محدوده مناسب است.

### توزیع یکنواخت اعشاری

توزیع `std::uniform_real_distribution` برای تولید مقادیر اعشاری با توزیع یکنواخت استفاده می‌شود.

```
#include <iostream>
#include <random>

int main() {
    std::mt19937 engine{42};
    std::uniform_real_distribution<double> distribution{0.0, 1.0};

    for (int i = 0; i < 5; ++i) {
        std::cout << distribution(engine) << '\n';
    }
}
```

در این توزیع، بازه معمول به‌صورت \\([a,b)\\) تعریف می‌شود؛ کران پایین شامل و کران بالا خارج از بازه است.

این توزیع برای محاسبات شبیه‌سازی، انتخاب احتمالاتی و تولید مقادیر اعشاری مناسب است.

### توزیع نرمال

توزیع `std::normal_distribution` مقادیر را مطابق توزیع نرمال با میانگین و انحراف معیار مشخص تولید می‌کند.

```
#include <iostream>
#include <random>

int main() {
    std::mt19937 engine{42};
    std::normal_distribution<double> distribution{100.0, 15.0};

    for (int i = 0; i < 5; ++i) {
        std::cout << distribution(engine) << '\n';
    }
}
```

در این مثال، میانگین توزیع برابر با ۱۰۰ و انحراف معیار برابر با ۱۵ است.

مقادیر تولیدشده محدود به یک بازه مشخص نیستند و ممکن است از میانگین فاصله زیادی داشته باشند. در صورت نیاز به محدودیت بازه، باید راهکار آماری مناسبی انتخاب شود؛ صرفاً محدود کردن مقادیر با `std::clamp` لزوماً توزیع نرمال موردنظر را حفظ نمی‌کند.

### توزیع برنولی

توزیع `std::bernoulli_distribution` برای رویدادهایی با دو نتیجه، مانند موفقیت و شکست، مناسب است.

```
#include <iostream>
#include <random>

int main() {
    std::mt19937 engine{42};
    std::bernoulli_distribution distribution{0.7};

    for (int i = 0; i < 10; ++i) {
        std::cout << (distribution(engine) ? "Success" : "Failure")
                  << '\n';
    }
}
```

در این مثال، احتمال نتیجه `true` برابر با ۰٫۷ است.

### توزیع پواسون

توزیع `std::poisson_distribution` برای مدل‌سازی تعداد رخدادها در یک بازه، با فرض‌های مناسب مدل پواسون، استفاده می‌شود.

```
#include <iostream>
#include <random>

int main() {
    std::mt19937 engine{42};
    std::poisson_distribution<int> distribution{4.0};

    for (int i = 0; i < 10; ++i) {
        std::cout << distribution(engine) << '\n';
    }
}
```

پارامتر این توزیع، نرخ موردانتظار رخدادها است و باید مقدار معتبر و غیرمنفی داشته باشد.

### توزیع نمایی

توزیع `std::exponential_distribution` برای مدل‌سازی فاصله زمانی میان رخدادها در فرایندهای مناسب کاربرد دارد.

```
#include <iostream>
#include <random>

int main() {
    std::mt19937 engine{42};
    std::exponential_distribution<double> distribution{2.0};

    for (int i = 0; i < 5; ++i) {
        std::cout << distribution(engine) << '\n';
    }
}
```

پارامتر این توزیع نرخ \\(\lambda\\) است و میانگین خروجی آن برابر با \\(1/\lambda\\) خواهد بود.

## مدیریت وضعیت موتور و بازتولیدپذیری

یکی از مهم‌ترین ویژگی‌های موتورهای شبه‌تصادفی، داشتن وضعیت داخلی است. هر بار فراخوانی موتور، وضعیت آن را تغییر می‌دهد و مقدار بعدی دنباله را تولید می‌کند.

### تفاوت seed ثابت و seed متغیر

استفاده از seed ثابت برای آزمون‌ها و شبیه‌سازی‌های تکرارپذیر مفید است. در مقابل، استفاده از یک منبع اولیه متغیر می‌تواند دنباله‌های متفاوتی در اجراهای مختلف ایجاد کند.

```
#include <iostream>
#include <random>

int main() {
    std::mt19937 engine{2026};
    std::uniform_int_distribution<int> distribution{1, 100};

    for (int i = 0; i < 5; ++i) {
        std::cout << distribution(engine) << '\n';
    }
}
```

برای آزمون‌های خودکار، استفاده از seed ثابت معمولاً انتخاب مناسبی است؛ زیرا نتایج را می‌توان بازتولید کرد.

### ذخیره و بازیابی وضعیت

موتورهای استاندارد مانند `std::mt19937` از عملگرهای جریان برای ذخیره و بازیابی وضعیت پشتیبانی می‌کنند.

```
#include <iostream>
#include <random>
#include <sstream>

int main() {
    std::mt19937 engine{42};

    engine();

    std::stringstream state;
    state << engine;

    const auto expected = engine();

    std::mt19937 restored;
    state >> restored;

    std::cout << (restored() == expected) << '\n';
}
```

در این مثال، وضعیت موتور پس از یک فراخوانی ذخیره می‌شود. سپس موتور اصلی یک مقدار دیگر تولید می‌کند و موتور بازیابی‌شده همان مقدار بعدی را تولید خواهد کرد.

این قابلیت برای بازتولید خطاها و ادامه شبیه‌سازی مفید است. برای بازتولید کامل یک فرایند، باید وضعیت توزیع‌هایی را که وضعیت داخلی دارند و سایر عوامل مؤثر بر محاسبه نیز در نظر گرفته شوند.

## کاربرد عملی در انتخاب تصادفی از یک مجموعه

برای انتخاب یک عنصر تصادفی از یک مجموعه، می‌توان از `std::uniform_int_distribution` استفاده کرد؛ اما کتابخانه استاندارد الگوریتم `std::sample` را نیز از ++C17 ارائه می‌دهد.

```
#include <algorithm>
#include <iostream>
#include <random>
#include <vector>

int main() {
    std::vector<int> values{10, 20, 30, 40, 50};
    std::mt19937 engine{42};

    auto selected = values.begin();

    std::advance(
        selected,
        std::uniform_int_distribution<std::size_t>{
            0, values.size() - 1
        }(engine)
    );

    std::cout << *selected << '\n';
}
```

در این مثال، مجموعه خالی نیست؛ بنابراین بازه اندیس‌ها معتبر است. اگر امکان خالی بودن مجموعه وجود داشته باشد، باید پیش از ساخت توزیع یا انتخاب اندیس، خالی بودن آن بررسی شود.

## نکات مهم برای برنامه‌های چندریسمانی

موتورهای تصادفی دارای وضعیت قابل‌تغییر هستند. دسترسی هم‌زمان و بدون هماهنگی به یک موتور مشترک می‌تواند به رقابت داده‌ای منجر شود.

در برنامه‌های چندریسمانی، معمولاً بهتر است هر thread موتور مستقل خود را داشته باشد یا دسترسی به موتور مشترک با سازوکار همگام‌سازی مناسب مدیریت شود.

همچنین، استفاده از seed یکسان برای چند موتور مستقل می‌تواند دنباله‌های یکسانی ایجاد کند. برای شبیه‌سازی‌های موازی، طراحی راهبرد مقداردهی اولیه باید با توجه به نیازهای بازتولیدپذیری و استقلال دنباله‌ها انجام شود.

## اشتباهات رایج در تولید اعداد تصادفی

### استفاده از `%` برای محدود کردن خروجی

استفاده از عملگر باقیمانده برای تبدیل خروجی موتور به بازه دلخواه می‌تواند توزیع غیریکنواخت ایجاد کند، به‌خصوص هنگامی که تعداد خروجی‌های ممکن موتور مضرب تعداد مقادیر بازه نیست.

روش پیشنهادی، استفاده از توزیع استاندارد متناسب با نیاز است.

### مقداردهی اولیه در هر تکرار

ساختن یک موتور جدید در هر تکرار حلقه، به‌ویژه با استفاده از منبعی مانند `std::random_device`، معمولاً هزینه اضافی ایجاد می‌کند و مدیریت بازتولیدپذیری را دشوارتر می‌سازد.

بهتر است موتور را یک‌بار در محل مناسب ایجاد و سپس در فراخوانی‌های متعدد استفاده کنید.

### تصور امنیت رمزنگاری

موتور `std::mt19937` برای کاربردهای معمول آماری طراحی شده است، نه برای تولید کلیدهای رمزنگاری، توکن‌های امنیتی یا اعداد محرمانه. دوره طولانی آن به معنای امنیت رمزنگاری نیست.

برای کاربردهای حساس، باید از APIهای تصادفی امن سیستم‌عامل یا کتابخانه‌های رمزنگاری معتبر استفاده شود.

### فرض یکنواخت بودن خروجی موتور خام

خروجی خام موتور، لزوماً مستقیماً با بازه موردنیاز برنامه سازگار نیست. توزیع‌ها برای تبدیل خروجی موتور به مقادیر دارای ویژگی‌های آماری موردنیاز طراحی شده‌اند.

## جمع‌بندی

کتابخانه `<random>` در ++C چارچوبی انعطاف‌پذیر برای تولید و استفاده از اعداد تصادفی فراهم می‌کند. انتخاب صحیح اجزای آن به هدف برنامه بستگی دارد:

- برای مقداردهی اولیه در کاربردهای معمول، `std::random_device` گزینه‌ای رایج است، اما ویژگی‌های دقیق آن به پیاده‌سازی بستگی دارد.
- برای تولید سریع و بازتولیدپذیر دنباله‌های شبه‌تصادفی، `std::mt19937` انتخاب متداولی است.
- برای تبدیل خروجی موتور به مقادیر با ویژگی آماری مشخص، باید از توزیع مناسب استفاده کرد.
- برای آزمون و اشکال‌زدایی، seed ثابت معمولاً مفید است.
- برای امنیت رمزنگاری، نباید به `std::mt19937` تکیه کرد.

در نهایت، طراحی درست یک راهکار تصادفی تنها به انتخاب موتور وابسته نیست؛ نحوه مقداردهی اولیه، انتخاب توزیع، مدیریت وضعیت، نیازهای آماری و الزامات امنیتی همگی باید در نظر گرفته شوند.
