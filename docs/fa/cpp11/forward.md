# آشنایی با `std::forward` در ++C

در زبان ++C11، نحو جدیدی برای ارجاع‌ها معرفی شد: `&&`. احتمالاً آن را با نام **ارجاع به مقدار راست (Rvalue Reference)** می‌شناسید. اما در برخی شرایط خاص، عبارت `T&&` می‌تواند نقش متفاوتی داشته باشد و به‌عنوان **ارجاع انتقالی (Forwarding Reference)** شناخته شود که به آن ارجاع یونیورسال (Universal Reference) نیز می‌گویند.

ارجاع انتقالی الگویی از ارجاع است که می‌تواند هم به مقادیر چپ (Lvalue) و هم به مقادیر راست (Rvalue) متصل شود و نوع ارجاع آن با توجه به آرگومانی که به تابع ارسال می‌کنیم، تعیین می‌شود.

پیش از آنکه درباره ارجاع‌های یونیورسال صحبت کنیم، بهتر است با یک مفهوم آشنا شروع کنیم: ارسال اشیا به توابع. در ادامه چند الگوی رایج را بررسی می‌کنیم که در ابتدا مناسب به نظر می‌رسند، اما در کدهای واقعی به مشکلاتی برخورد می‌کنند. همین مشکلات ما را به مفهوم ارجاع یونیورسال و دلیل معرفی آن در ++C11 می‌رسانند.

## ۱. ارسال شیء به تابع با ارجاع Lvalue

فرض کنید تابعی به نام `upload` داریم که یک شیء از نوع `Photo` را به‌عنوان پارامتر دریافت می‌کند و عملیات موردنظر را روی آن انجام می‌دهد. این عملیات می‌تواند صرفاً بارگذاری عکس، ویرایش عکس و سپس بارگذاری آن، یا هر عملیات دیگری باشد.

```cpp
void upload(Photo& p) {
    std::cout << "upload(Photo&) called\n";
    // انجام عملیات موردنظر
}

int main() {
    Photo selfie = Photo{1, 2};
    upload(selfie);
}
```

در این مثال، شیء `selfie` یک متغیر نام‌دار است؛ بنابراین یک مقدار چپ یا Lvalue محسوب می‌شود. از آنجا که پارامتر تابع از نوع `Photo&` است، این فراخوانی کاملاً معتبر است.

## ۲. مشکل هنگام ارسال اشیای موقت

حالا فرض کنید در تابع `main` بخواهیم شیء `Photo` را مستقیماً ایجاد کنیم و بدون ذخیره‌کردن آن در یک متغیر نام‌دار، به تابع ارسال کنیم:

```cpp
void upload(Photo& p) {
    std::cout << "upload(Photo&) called\n";
    // انجام عملیات موردنظر
}

int main() {
    Photo selfie = Photo{1, 2};

    upload(selfie);
    upload(Photo{1, 2});
}
```

**خطا: کامپایلر نمی‌تواند این برنامه را کامپایل کند.**

دلیل این خطا آن است که عبارت `Photo{1, 2}` یک شیء موقت و در نتیجه یک Rvalue است؛ اما پارامتر `Photo&` یک ارجاع غیرثابت به Lvalue است و نمی‌تواند مستقیماً به این شیء موقت متصل شود.

### راه‌حل اول: استفاده از Overload

می‌توانیم نسخه دیگری از تابع `upload` تعریف کنیم که به‌جای Lvalue، یک Rvalue Reference دریافت کند:

```cpp
void upload(Photo& p) {
    std::cout << "upload(Photo&) called\n";
}

void upload(Photo&& p) {
    std::cout << "upload(Photo&&) called\n";
}

int main() {
    Photo selfie = Photo{1, 2};

    upload(selfie);       // فراخوانی upload(Photo&)
    upload(Photo{1, 2}); // فراخوانی upload(Photo&&)
}
```

اکنون برنامه به‌درستی کار می‌کند:

- هنگام ارسال `selfie`، نسخه دارای پارامتر `Photo&` فراخوانی می‌شود.
- هنگام ارسال شیء موقت `Photo{1, 2}`، نسخه دارای پارامتر `Photo&&` فراخوانی می‌شود.

اما این راه‌حل با بزرگ‌ترشدن برنامه مشکلاتی ایجاد می‌کند.

برای مثال:

- اگر بخواهیم از اشیای `const Photo` نیز پشتیبانی کنیم، به سربارهای بیشتری نیاز خواهیم داشت.
- اگر بخواهیم همین الگو را برای انواع مختلف داده‌ها استفاده کنیم، تعداد توابع افزایش پیدا می‌کند.
- اگر بخواهیم آرگومان‌ها را بدون تغییر ویژگی‌هایشان به تابع دیگری منتقل کنیم، مسئله پیچیده‌تر خواهد شد.

در حالت ایده‌آل، به یک تابع نیاز داریم که:

- هم Lvalue و هم Rvalue را بپذیرد.
- دسته‌بندی مقدار (Value Category) آرگومان را حفظ کند.
- ویژگی `const` بودن یا نبودن شیء را حفظ کند.
- برای انواع مختلف داده‌ها قابل استفاده باشد.

برای حل این مسئله، قابلیت **Forwarding Reference** و ابزار `std::forward` در ++C11 به کار گرفته می‌شوند.

---

## ۳. ارجاع یونیورسال یا Forwarding Reference

اگر عبارت `T&&` را مشاهده کردید، لزوماً به این معنا نیست که با یک Rvalue Reference معمولی روبه‌رو هستید. در صورتی که `T` یک نوع وابسته به استنتاج نوع (Type Deduction) باشد، این عبارت می‌تواند یک Forwarding Reference باشد.

### قوانین تشخیص Forwarding Reference

**حالت اول: پارامتر تابع قالبی با استنتاج نوع**

```cpp
template <typename T>
void f(T&& x);  // Forwarding Reference
```

در اینجا، کامپایلر نوع `T` را با توجه به آرگومانی که به تابع ارسال می‌شود، استنتاج می‌کند. همین استنتاج باعث می‌شود `T&&` بتواند هم Lvalue و هم Rvalue را بپذیرد.

**حالت دوم: استفاده از `auto&&`**

```cpp
auto&& x = expr;
```

در این حالت نیز نوع `auto` از عبارت سمت راست استنتاج می‌شود و `auto&&` می‌تواند یک Forwarding Reference باشد؛ البته با رعایت قواعد استنتاج نوع و اتصال ارجاع‌ها در ++C.

**حالت سوم: پارامترهای قالبی متغیر (Variadic Templates)**

```cpp
template <typename... Args>
void f(Args&&... args);
```

در این مثال، هر پارامتر در بسته `args` می‌تواند با توجه به آرگومان متناظر خود، Lvalue یا Rvalue را حفظ کند.

### چه زمانی `&&` ارجاع انتقالی نیست؟

در شرایط زیر، `&&` به‌خودی‌خود یک Rvalue Reference معمولی است، نه Forwarding Reference:

```cpp
void f(int&& x);  // Rvalue Reference

template <typename T>
void f(std::vector<T>&& x); // Rvalue Reference

template <typename T>
void f(const T&& x); // Rvalue Reference
```

نکته مهم این است که صرف وجود `&&` کافی نیست. برای Forwarding Reference بودن، باید شرایط لازم برای استنتاج نوع و الگوی پارامتر برقرار باشد.

---

## ۴. `std::forward` چیست؟

اصطلاح **Perfect Forwarding** یا «انتقال کامل آرگومان‌ها» به این معناست که آرگومان‌ها را از یک تابع به تابع دیگر به شکلی منتقل کنیم که ویژگی‌های مهم آن‌ها حفظ شود.

این ویژگی‌ها عبارت‌اند از:

۱. **حفظ دسته‌بندی مقدار (Value Category)**

- Lvalue به‌صورت Lvalue باقی بماند.
- Rvalue به‌صورت Rvalue باقی بماند.

۲. **حفظ ویژگی `const`**

- شیء `const` همچنان `const` باقی بماند.
- شیء غیر `const` همچنان غیر `const` باقی بماند.

۳. **حفظ نوع استنتاج‌شده**

- نوع آرگومان مطابق قواعد استنتاج قالب‌ها حفظ شود؛ از جمله اطلاعات `const` و در صورت لزوم `volatile`.

در ++C11، تابع قالبی `std::forward` در هدر `<utility>` معرفی شد تا این کار را امکان‌پذیر کند.

شکل کلی استفاده از آن به این صورت است:

```cpp
std::forward<T>(arg)
```

در اینجا، `T` معمولاً همان نوعی است که در تابع قالبی از آرگومان اولیه استنتاج شده است.

### مثال: استفاده از `std::forward`

```cpp
#include <iostream>
#include <utility>

using namespace std;

// تابعی که Lvalue Reference دریافت می‌کند
void UtilityFun(int& i) {
    cout << "Process lvalue: " << i << endl;
}

// تابعی که Rvalue Reference دریافت می‌کند
void UtilityFun(int&& i) {
    cout << "Process rvalue: " << i << endl;
}

// تابع قالبی برای انتقال آرگومان
template <typename T>
void Fun(T&& arg) {
    UtilityFun(std::forward<T>(arg));
}

int main() {
    int x = 10;

    // ارسال Lvalue
    Fun(x);

    // ارسال Rvalue
    Fun(std::move(x));
}
```

خروجی برنامه:

```text
Process lvalue: 10
Process rvalue: 10
```

### این برنامه چگونه کار می‌کند؟

**حالت اول: ارسال Lvalue**

```cpp
int x = 10;
Fun(x);
```

چون `x` یک Lvalue است، کامپایلر در این فراخوانی نوع `T` را به شکل `int&` استنتاج می‌کند.

در نتیجه، با اعمال قواعد فروپاشی ارجاع‌ها (Reference Collapsing)، پارامتر `T&&` به `int&` تبدیل می‌شود.

سپس عبارت زیر:

```cpp
std::forward<T>(arg)
```

در این حالت یک Lvalue تولید می‌کند؛ بنابراین نسخه زیر فراخوانی می‌شود:

```cpp
void UtilityFun(int& i);
```

**حالت دوم: ارسال Rvalue**

```cpp
Fun(std::move(x));
```

تابع `std::move(x)` یک عبارت Rvalue تولید می‌کند. بنابراین، نوع `T` برابر با `int` است و پارامتر `T&&` از نوع `int&&` خواهد بود.

در این حالت، `std::forward<T>(arg)` یک Rvalue تولید می‌کند؛ بنابراین نسخه زیر فراخوانی می‌شود:

```cpp
void UtilityFun(int&& i);
```

نکته مهم این است که `std::forward` خودش تصمیم‌گیری مستقلی درباره آرگومان انجام نمی‌دهد؛ بلکه بر اساس نوع قالبی `T` که به آن داده شده است، دسته‌بندی مقدار مناسب را حفظ می‌کند.

## ۵. اگر از `std::forward` استفاده نکنیم چه اتفاقی می‌افتد؟

ممکن است تصور کنیم چون `arg` از نوع `T&&` است، در بدنه تابع نیز به‌عنوان یک Rvalue شناخته خواهد شد. اما این تصور اشتباه است.

در ++C، **هر متغیری که نام دارد، هنگام استفاده در یک عبارت، Lvalue محسوب می‌شود**؛ حتی اگر نوع آن Rvalue Reference باشد.

بنابراین، اگر `arg` را مستقیماً به تابع دیگری ارسال کنیم، رفتار مورد انتظار ما اتفاق نمی‌افتد.

```cpp
#include <iostream>
#include <utility>

using namespace std;

void UtilityFun(int& i) {
    cout << "Process lvalue: " << i << endl;
}

void UtilityFun(int&& i) {
    cout << "Process rvalue: " << i << endl;
}

template <typename T>
void Fun(T&& arg) {
    UtilityFun(arg); // بدون std::forward
}

int main() {
    int x = 10;

    Fun(x);
    Fun(std::move(x));
}
```

خروجی برنامه:

```text
Process lvalue: 10
Process lvalue: 10
```

چرا هر دو بار نسخه Lvalue فراخوانی می‌شود؟

زیرا عبارت `arg`، صرف‌نظر از نوع ارجاعی آن، یک Lvalue است. در نتیجه، فراخوانی زیر:

```cpp
UtilityFun(arg);
```

به نسخه‌ای متصل می‌شود که پارامتر `int&` دارد.

برای حفظ دسته‌بندی مقدار اصلی آرگومان، باید از `std::forward<T>(arg)` استفاده کنیم.

## ۶. تفاوت `std::move` و `std::forward`

هر دو ابزار به دسته‌بندی مقدار و ارجاع‌ها مربوط هستند، اما هدف آن‌ها متفاوت است.

| ویژگی | `std::move` | `std::forward` |
|---|---|---|
| هدف اصلی | تبدیل عبارت به Rvalue مناسب برای انتقال | حفظ دسته‌بندی مقدار اصلی آرگومان |
| رفتار با Lvalue | آن را به یک Rvalue تبدیل می‌کند | با `T` مناسب، آن را Lvalue نگه می‌دارد |
| رفتار با Rvalue | آن را به Rvalue تبدیل می‌کند | در الگوی Perfect Forwarding، آن را Rvalue نگه می‌دارد |
| کاربرد رایج | فعال‌کردن امکان استفاده از عملیات انتقال (Move) | انتقال آرگومان‌ها در توابع قالبی |

### نکته مهم درباره `std::move`

`std::move` خودش هیچ شیئی را جابه‌جا نمی‌کند. این تابع در اصل یک تبدیل نوع انجام می‌دهد که امکان انتخاب سازنده یا عملگر انتساب انتقالی را فراهم می‌کند؛ البته اگر چنین عملیاتی در دسترس باشد.

برای مثال:

```cpp
std::move(x);
```

به‌تنهایی تضمین نمی‌کند که منابع شیء `x` منتقل شوند. انتقال واقعی به عملیاتی بستگی دارد که با عبارت حاصل انتخاب می‌شود.

### نکته مهم درباره `std::forward`

`std::forward` نیز خودش عملیات انتقال منابع انجام نمی‌دهد. این تابع نوع ارجاع مناسب را بر اساس پارامتر قالبی `T` ایجاد می‌کند.

برای مثال:

```cpp
template <typename T>
void Fun(T&& arg) {
    UtilityFun(std::forward<T>(arg));
}
```

- اگر آرگومان اولیه Lvalue باشد، `std::forward<T>(arg)` نیز Lvalue خواهد بود.
- اگر آرگومان اولیه Rvalue باشد، `std::forward<T>(arg)` نیز Rvalue خواهد بود.

این رفتار زمانی حاصل می‌شود که `T` مطابق الگوی Forwarding Reference از آرگومان اولیه استنتاج شده باشد.

---

## ۷. نکاتی که باید به خاطر بسپارید

- `T&&` فقط در شرایط مشخصی یک Forwarding Reference است؛ هر `&&` به این معنا نیست.
- نام یک متغیر، حتی اگر از نوع Rvalue Reference باشد، هنگام استفاده در یک عبارت Lvalue محسوب می‌شود.
- `std::forward<T>(arg)` برای حفظ دسته‌بندی مقدار آرگومان در توابع قالبی استفاده می‌شود.
- `std::move` عبارت را به یک Rvalue تبدیل می‌کند، اما به‌تنهایی منابع شیء را جابه‌جا نمی‌کند.
- `std::forward` و `std::move` ابزارهایی برای تبدیل دسته‌بندی مقدار هستند و به‌خودی‌خود عملیات انتقال منابع انجام نمی‌دهند.
- برای استفاده از هر دو ابزار باید هدر `<utility>` را وارد کنید.

**خلاصه:** اگر می‌خواهید در یک تابع قالبی، آرگومان را به تابع دیگری منتقل کنید و Lvalue یا Rvalue بودن آن را حفظ کنید، معمولاً باید از الگوی `T&&` همراه با `std::forward<T>(arg)` استفاده کنید. این همان ایده اصلی Perfect Forwarding در ++C است.
