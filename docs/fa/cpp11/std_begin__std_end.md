# بررسی std::begin و std::end در ++C11

## مقدمه

قابلیت‌های `std::begin` و `std::end` از ابزارهای مهم Standard Library در ++C11 هستند که دسترسی یکپارچه به ابتدا و انتهای محدوده‌های داده را فراهم می‌کنند. این دو تابع به توسعه‌دهندگان اجازه می‌دهند تا بدون نیاز به دانستن جزئیات پیاده‌سازی یک Container، عملیات پیمایش، جست‌وجو، مرتب‌سازی و پردازش عناصر را به شکل عمومی‌تری انجام دهند.

اهمیت این قابلیت زمانی مشخص می‌شود که بخواهیم یک الگوریتم را برای انواع مختلفی از داده‌ها، مانند آرایه‌های داخلی زبان، `std::vector`، `std::array` و سایر Containerهای استاندارد، قابل استفاده کنیم.

برای مثال، کد زیر در ++C11 معتبر است:

```
#include <algorithm>
#include <iostream>
#include <iterator>
#include <vector>

int main() {
    std::vector<int> values = {10, 20, 30, 40};

    auto first = std::begin(values);
    auto last = std::end(values);

    std::for_each(first, last, [](int value) {
        std::cout << value << ' ';
    });

    std::cout << '\n';
}
```

خروجی برنامه به صورت زیر است:

```
10 20 30 40
```

در این مثال، تابع `std::begin` یک Iterator به اولین عنصر و تابع `std::end` یک Iterator به موقعیت بلافاصله پس از آخرین عنصر برمی‌گرداند.

نکته مهم این است که `std::end` به آخرین عنصر اشاره نمی‌کند؛ بلکه موقعیتی را نشان می‌دهد که پیمایش باید در آن متوقف شود.

## مفهوم Iterator و محدوده داده‌ها

### مفهوم Iterator

مفهوم Iterator در ++C روشی استاندارد برای دسترسی به عناصر یک مجموعه از داده‌ها است. یک Iterator بسته به نوع خود می‌تواند امکان خواندن، تغییر، پیمایش یا دسترسی به عناصر را فراهم کند.

برای نمونه، Container زیر را در نظر بگیرید:

```
#include <iostream>
#include <vector>

int main() {
    std::vector<int> numbers = {10, 20, 30};

    auto it = numbers.begin();

    std::cout << *it << '\n';

    ++it;

    std::cout << *it << '\n';
}
```

خروجی برنامه:

```
10
20
```

در این برنامه، متد `begin()` متعلق به `std::vector` یک Iterator به اولین عنصر برمی‌گرداند. عملگر `*` مقدار عنصر مورد اشاره را در اختیار قرار می‌دهد و عملگر `++` Iterator را به موقعیت بعدی منتقل می‌کند.

### مفهوم محدوده نیمه‌باز

در الگوریتم‌های استاندارد ++C، محدوده‌ها معمولاً به صورت نیمه‌باز تعریف می‌شوند:

```
[first, last)
```

این نماد به این معناست که محدوده شامل عنصر مورد اشاره توسط `first` است، اما موقعیت `last` را شامل نمی‌شود.

برای مثال، اگر یک `std::vector` شامل چهار عنصر باشد، محدوده حاصل از `begin()` و `end()` تمام چهار عنصر را در بر می‌گیرد.

این طراحی چند مزیت دارد:

- تعداد عناصر یک محدوده تصادفی با Iteratorهای سازگار را می‌توان از تفاضل آن‌ها به دست آورد.
- محدوده خالی با برابر بودن دو Iterator مشخص می‌شود.
- اتصال محدوده‌های مجاور ساده‌تر است؛ انتهای یک محدوده می‌تواند با ابتدای محدوده بعدی برابر باشد.
- الگوریتم‌ها بدون نیاز به بررسی ویژه برای آخرین عنصر می‌توانند از شرط توقف یکسان استفاده کنند.

برای یک آرایه یا Container معتبر، الگوی معمول پیمایش به شکل زیر است:

```
for (auto it = first; it != last; ++it) {
    // Process the current element
}
```

شرط `it != last` پیش از دسترسی به عنصر بررسی می‌شود. بنابراین، Iterator به موقعیت انتهایی هرگز در این حلقه dereference نمی‌شود.

## معرفی تابع std::begin

### کاربرد و رفتار تابع

تابع `std::begin` از Header استاندارد `<iterator>` در ++C11 معرفی شده است. این تابع یک Iterator به ابتدای محدوده برمی‌گرداند.

شکل کلی استفاده از آن به صورت زیر است:

```
auto first = std::begin(container);
```

در این عبارت، نوع واقعی `first` از نوع بازگشتی تابع تعیین می‌شود. استفاده از `auto` باعث می‌شود نیازی به نوشتن صریح نوع Iterator نباشد.

تابع `std::begin` برای Containerهای استاندارد، آرایه‌های داخلی زبان و انواعی که با Overloadهای مناسب سازگار هستند، قابل استفاده است.

### تفاوت std::begin با begin()

تفاوت این دو روش در محل تعریف تابع و نحوه فراخوانی آن‌ها است.

روش عضو Container:

```
auto first = values.begin();
```

روش تابع آزاد استاندارد:

```
auto first = std::begin(values);
```

روش اول مستقیماً متد عضو Container را فراخوانی می‌کند. روش دوم از تابع آزاد استاندارد استفاده می‌کند که برای چندین نوع داده مختلف Overload شده است.

این تفاوت در آرایه‌های داخلی اهمیت زیادی دارد؛ زیرا آرایه‌های داخلی متد `begin()` ندارند، اما `std::begin` می‌تواند ابتدای آن‌ها را مشخص کند.

### بررسی رفتار با std::vector

```
#include <iostream>
#include <iterator>
#include <vector>

int main() {
    std::vector<int> values = {5, 10, 15};

    auto first = std::begin(values);

    std::cout << *first << '\n';
}
```

خروجی:

```
5
```

در این مورد، `std::begin(values)` به متد `values.begin()` ارجاع می‌دهد و Iterator متناظر با اولین عنصر را برمی‌گرداند.

### بررسی رفتار با آرایه داخلی

```
#include <iostream>
#include <iterator>

int main() {
    int values[] = {100, 200, 300};

    auto first = std::begin(values);

    std::cout << *first << '\n';
}
```

خروجی:

```
100
```

در این مثال، آرایه داخلی دارای متد عضو نیست. با این حال، `std::begin` یک اشاره‌گر به اولین عنصر آرایه برمی‌گرداند.

برای آرایه داخلی، نوع بازگشتی تابع معمولاً به شکل `T*` است که در آن `T` نوع عنصر آرایه است.

## معرفی تابع std::end

### کاربرد و رفتار تابع

تابع `std::end` نیز از Header استاندارد `<iterator>` در ++C11 معرفی شده است. این تابع Iterator مربوط به موقعیت بلافاصله پس از آخرین عنصر را برمی‌گرداند.

شکل کلی استفاده از آن چنین است:

```
auto last = std::end(container);
```

این Iterator برای تعیین پایان محدوده در حلقه‌ها و الگوریتم‌های استاندارد استفاده می‌شود.

### بررسی موقعیت انتهایی

```
#include <iostream>
#include <iterator>

int main() {
    int values[] = {10, 20, 30};

    auto first = std::begin(values);
    auto last = std::end(values);

    while (first != last) {
        std::cout << *first << ' ';
        ++first;
    }

    std::cout << '\n';
}
```

خروجی:

```
10 20 30
```

در این مثال، `last` به موقعیتی پس از عنصر `30` اشاره می‌کند. به همین دلیل، شرط حلقه مانع از dereference شدن Iterator انتهایی می‌شود.

### دلیل استفاده از موقعیت پس از آخرین عنصر

در طراحی Iteratorهای استاندارد، موقعیت انتهایی یک مرز است، نه یک عنصر قابل خواندن.

برای آرایه‌ای با سه عنصر، اگر `first` به اولین عنصر اشاره کند، سه بار افزایش Iterator آن را به `last` می‌رساند.

در مقابل، تلاش برای خواندن مقدار `*last` در این حالت رفتار تعریف‌نشده (Undefined Behavior) ایجاد می‌کند.

این قاعده فقط مختص آرایه‌ها نیست؛ در مورد Iteratorهای Containerهای استاندارد نیز نباید فرض کرد که Iterator انتهایی قابل dereference است.

## بررسی نحوه پیاده‌سازی استاندارد

### رفتار با Containerهای استاندارد

برای انواع Containerهای استاندارد، Overloadهای مربوط به `std::begin` و `std::end` از متدهای عضو متناظر استفاده می‌کنند.

مفهوم کلی این رفتار را می‌توان به شکل زیر نمایش داد:

```
template <class Container>
auto begin(Container& container) -> decltype(container.begin());

template <class Container>
auto end(Container& container) -> decltype(container.end());
```

این قطعه کد صرفاً نمایشی از ایده کلی است و پیاده‌سازی واقعی Standard Library نیست. پیاده‌سازی استاندارد می‌تواند جزئیات دیگری داشته باشد و تابع‌های آزاد استاندارد نیز در Namespace مربوط به `std` قرار دارند.

نکته مهم این است که نوع Iterator از نوع متد عضو Container حاصل می‌شود. بنابراین، اگر Container از نوعی با Iterator سفارشی استفاده کند، توابع استاندارد می‌توانند همان نوع را حفظ کنند.

### رفتار با آرایه‌های داخلی

آرایه‌های داخلی از متدهای عضو برخوردار نیستند. برای پشتیبانی از آن‌ها، Overloadهای ویژه‌ای برای آرایه‌ها وجود دارند.

برای نمونه، در ++C11 می‌توان ایده بازگرداندن اشاره‌گر ابتدای آرایه را به شکل زیر نمایش داد:

```
template <class T, std::size_t N>
T* begin(T (&array)[N]) noexcept;
```

این کد نیز فقط نمایش مفهومی امضای تابع است، نه تعریفی که باید جایگزین تابع استاندارد شود.

در چنین Overloadی، پارامتر به صورت Reference به آرایه تعریف شده است. این موضوع اجازه می‌دهد اندازه آرایه در قالب پارامتر `N` حفظ شود.

در نتیجه، `std::begin` می‌تواند اندازه آرایه را در زمان کامپایل تشخیص دهد، بدون اینکه آرایه به اشاره‌گر تبدیل شود.

### رفتار با آرایه خالی

آرایه داخلی با اندازه صفر در ++C11 یک آرایه استاندارد معتبر نیست. با این حال، Containerهایی مانند `std::vector` می‌توانند خالی باشند.

در یک Container خالی، `begin()` و `end()` برابر هستند و حلقه پیمایش معمولاً هیچ بار اجرا نمی‌شود.

```
#include <iostream>
#include <iterator>
#include <vector>

int main() {
    std::vector<int> values;

    auto first = std::begin(values);
    auto last = std::end(values);

    if (first == last) {
        std::cout << "The range is empty\n";
    }
}
```

خروجی:

```
The range is empty
```

این رفتار باعث می‌شود الگوریتم‌هایی که از محدوده‌های استاندارد استفاده می‌کنند، بتوانند بدون شرط‌های اضافی برای بسیاری از ورودی‌های خالی کار کنند.

## استفاده از const و Iteratorهای قابل تغییر

### رفتار با اشیای غیر const

هنگامی که یک Container غیر `const` به `std::begin` داده می‌شود، معمولاً Iterator قابل تغییر آن Container برگردانده می‌شود.

```
#include <iterator>
#include <vector>

int main() {
    std::vector<int> values = {1, 2, 3};

    auto first = std::begin(values);

    *first = 100;
}
```

در این مثال، مقدار اولین عنصر از `1` به `100` تغییر می‌کند.

### رفتار با اشیای const

اگر Container از نوع `const` باشد، تابع متناظر باید Iterator ثابت را برگرداند.

```
#include <iostream>
#include <iterator>
#include <vector>

int main() {
    const std::vector<int> values = {1, 2, 3};

    auto first = std::begin(values);

    std::cout << *first << '\n';
}
```

خروجی:

```
1
```

در این وضعیت، Iterator حاصل اجازه تغییر عنصر را نمی‌دهد. تلاش برای تغییر مقدار از طریق این Iterator، در یک برنامه استاندارد معتبر نخواهد بود.

### مقایسه با cbegin و cend

از ++C11، توابع `std::cbegin` و `std::cend` نیز در دسترس هستند. این توابع برای دستیابی به محدوده از طریق Iteratorهای ثابت کاربرد دارند.

```
#include <iterator>
#include <vector>

int main() {
    std::vector<int> values = {10, 20, 30};

    auto first = std::cbegin(values);
    auto last = std::cend(values);

    for (auto it = first; it != last; ++it) {
        // Read-only access
        int value = *it;
        (void)value;
    }
}
```

در این مثال، حتی با وجود غیر `const` بودن `values`، نوع Iterator به گونه‌ای انتخاب می‌شود که تغییر عناصر از طریق آن امکان‌پذیر نباشد.

استفاده از `cbegin` و `cend` زمانی مفید است که قصد داریم محدودیت عدم تغییر را صریح بیان کنیم.

البته `const` بودن Iterator لزوماً به معنای تغییرناپذیری مطلق داده‌های پشت آن نیست؛ این تضمین تنها به دسترسی‌ای مربوط است که از طریق همان Iterator فراهم می‌شود.

## استفاده از std::begin و std::end در الگوریتم‌های استاندارد

### جست‌وجو با std::find

یکی از کاربردهای رایج این دو تابع، ارسال محدوده به الگوریتم‌های Standard Library است.

```
#include <algorithm>
#include <iostream>
#include <iterator>
#include <vector>

int main() {
    std::vector<int> values = {4, 8, 12, 16};

    auto it = std::find(
        std::begin(values),
        std::end(values),
        12
    );

    if (it != std::end(values)) {
        std::cout << "Value found: " << *it << '\n';
    }
}
```

خروجی:

```
Value found: 12
```

تابع `std::find` از ابتدای محدوده تا موقعیت انتهایی جست‌وجو می‌کند. اگر عنصر مورد نظر پیدا نشود، Iterator انتهایی برگردانده می‌شود.

در این مثال، از `std::end(values)` برای تشخیص موفقیت جست‌وجو استفاده شده است.

### مرتب‌سازی با std::sort

برای Containerهایی مانند `std::vector` که Iteratorهای مناسب برای مرتب‌سازی تصادفی دارند، می‌توان از `std::sort` استفاده کرد.

```
#include <algorithm>
#include <iostream>
#include <iterator>
#include <vector>

int main() {
    std::vector<int> values = {9, 2, 7, 1, 5};

    std::sort(std::begin(values), std::end(values));

    for (auto it = std::begin(values);
         it != std::end(values);
         ++it) {
        std::cout << *it << ' ';
    }

    std::cout << '\n';
}
```

خروجی:

```
1 2 5 7 9
```

نکته مهم این است که `std::sort` به Random Access Iterator نیاز دارد. بنابراین، وجود `std::begin` و `std::end` به تنهایی به این معنا نیست که هر Container را می‌توان با `std::sort` مرتب کرد.

برای مثال، Iteratorهای `std::list` از نوع Bidirectional هستند و برای `std::sort` مناسب نیستند؛ برای مرتب‌سازی یک `std::list` باید از متد عضو `sort()` استفاده کرد.

### محاسبه مجموع عناصر

برای پردازش داده‌ها می‌توان از `std::accumulate` در Header مربوط به `<numeric>` استفاده کرد.

```
#include <iostream>
#include <iterator>
#include <numeric>
#include <vector>

int main() {
    std::vector<int> values = {10, 20, 30, 40};

    int total = std::accumulate(
        std::begin(values),
        std::end(values),
        0
    );

    std::cout << total << '\n';
}
```

خروجی:

```
100
```

این روش وابستگی الگوریتم به نوع مشخصی از Container را کاهش می‌دهد؛ الگوریتم فقط به محدوده‌ای از Iteratorهای سازگار نیاز دارد.

## استفاده از آرایه‌های داخلی در توابع عمومی

### حفظ اندازه آرایه

یکی از مهم‌ترین مزیت‌های `std::begin` و `std::end`، امکان کار با آرایه‌های داخلی بدون تبدیل ناخواسته آن‌ها به اشاره‌گر است.

برای مثال، در کد زیر آرایه به صورت Reference به تابع منتقل می‌شود:

```
#include <iostream>
#include <iterator>

template <class T, std::size_t N>
void printArray(const T (&values)[N]) {
    for (auto it = std::begin(values);
         it != std::end(values);
         ++it) {
        std::cout << *it << ' ';
    }

    std::cout << '\n';
}

int main() {
    int numbers[] = {3, 6, 9, 12};

    printArray(numbers);
}
```

خروجی:

```
3 6 9 12
```

در این نمونه، اندازه آرایه در پارامتر قالب `N` حفظ می‌شود و تابع می‌تواند محدوده کامل آن را پیمایش کند.

این الگو برای توابع عمومی مفید است؛ زیرا برخلاف پارامترهایی که آرایه را به اشاره‌گر تبدیل می‌کنند، اطلاعات اندازه آرایه را در زمان کامپایل نگه می‌دارد.

### محدودیت تبدیل آرایه به اشاره‌گر

اگر تابعی چنین پارامتری داشته باشد:

```
void process(int values[]);
```

پارامتر `values` در واقع از نوع `int*` خواهد بود. در نتیجه، اندازه آرایه اصلی از طریق این پارامتر قابل تشخیص نیست.

در چنین شرایطی، نمی‌توان انتظار داشت `std::end(values)` اندازه آرایه اصلی را بازیابی کند؛ زیرا `values` دیگر یک آرایه نیست، بلکه یک اشاره‌گر است.

برای پردازش آرایه‌های داخلی، در صورت امکان از Reference به آرایه یا سازوکاری استفاده کنید که اندازه محدوده را به شکل صریح منتقل می‌کند.

## بررسی انواع مختلف Container

### استفاده با std::array

نوع `std::array` از ++C11 یک Container با اندازه ثابت است که رابط استانداردی برای Iteratorها ارائه می‌دهد.

```
#include <iostream>
#include <iterator>
#include <array>

int main() {
    std::array<int, 4> values = {10, 20, 30, 40};

    auto first = std::begin(values);
    auto last = std::end(values);

    while (first != last) {
        std::cout << *first << ' ';
        ++first;
    }

    std::cout << '\n';
}
```

خروجی:

```
10 20 30 40
```

استفاده از `std::begin` و `std::end` در اینجا باعث می‌شود کد به رابط عمومی Iterator وابسته باشد، نه به جزئیات اختصاصی `std::array`.

### استفاده با std::string

رشته‌های استاندارد نیز Iterator دارند و می‌توانند با این توابع استفاده شوند.

```
#include <iostream>
#include <iterator>
#include <string>

int main() {
    std::string text = "Hello";

    for (auto it = std::begin(text);
         it != std::end(text);
         ++it) {
        std::cout << *it << ' ';
    }

    std::cout << '\n';
}
```

خروجی:

```
H e l l o
```

در این مثال، پیمایش بر اساس عناصر `char` انجام می‌شود. برای رشته‌های UTF-8، هر عنصر `char` الزاماً برابر با یک نویسه Unicode نیست؛ بنابراین، این الگو به تنهایی پیمایش معنایی نویسه‌های Unicode را تضمین نمی‌کند.

### استفاده با std::list

نوع `std::list` نیز از Iterator پشتیبانی می‌کند، اما Iteratorهای آن قابلیت دسترسی تصادفی ندارند.

```
#include <iostream>
#include <iterator>
#include <list>

int main() {
    std::list<int> values = {10, 20, 30};

    for (auto it = std::begin(values);
         it != std::end(values);
         ++it) {
        std::cout << *it << ' ';
    }

    std::cout << '\n';
}
```

خروجی:

```
10 20 30
```

این مثال نشان می‌دهد که توابع استاندارد می‌توانند محدوده را برای Containerهایی با انواع مختلف Iterator فراهم کنند، بدون آنکه نوع Iterator را به اشاره‌گر محدود کنند.

## مفهوم ADL و توابع begin و end سفارشی

### مفهوم Argument-Dependent Lookup

مکانیزم Argument-Dependent Lookup یا ADL در ++C امکان می‌دهد هنگام فراخوانی یک تابع بدون Qualification، توابعی که در Namespaceهای مرتبط با نوع آرگومان قرار دارند نیز در فرایند جست‌وجوی نام در نظر گرفته شوند.

این قابلیت در طراحی Generic Code اهمیت دارد؛ زیرا بعضی از انواع سفارشی، توابع `begin` و `end` آزاد را در Namespace خود تعریف می‌کنند، نه به صورت متد عضو.

برای نمونه، اگر یک نوع سفارشی به شکل زیر طراحی شود:

```
namespace custom {

struct Range {
    int* first;
    int* last;
};

int* begin(Range& range) {
    return range.first;
}

int* end(Range& range) {
    return range.last;
}

}
```

می‌توان توابع مربوط به این نوع را با استفاده از ADL فراخوانی کرد:

```
#include <iostream>

namespace custom {

struct Range {
    int* first;
    int* last;
};

int* begin(Range& range) {
    return range.first;
}

int* end(Range& range) {
    return range.last;
}

}

int main() {
    int values[] = {10, 20, 30};

    custom::Range range{values, values + 3};

    using std::begin;
    using std::end;

    for (auto it = begin(range);
         it != end(range);
         ++it) {
        std::cout << *it << ' ';
    }

    std::cout << '\n';
}
```

خروجی:

```
10 20 30
```

در این الگو، عبارت‌های `begin(range)` و `end(range)` می‌توانند توابع موجود در Namespace مربوط به `custom` را از طریق ADL پیدا کنند.

نکته مهم این است که توابع `custom::begin` و `custom::end` در مثال بالا، توابع آزاد سفارشی هستند و جزئی از Standard Library محسوب نمی‌شوند.

### تفاوت std::begin با الگوی ADL

فراخوانی مستقیم `std::begin(range)` فقط Overloadهای موجود در Namespace `std` را بررسی می‌کند. این فراخوانی به خودی خود تابع آزاد `custom::begin` را به عنوان Overload سفارشی انتخاب نمی‌کند.

به همین دلیل، در Generic Code که باید از انواع سفارشی و استاندارد پشتیبانی کند، الگوی زیر معمولاً مناسب‌تر است:

```
using std::begin;
using std::end;

auto first = begin(range);
auto last = end(range);
```

این الگو ابتدا Overloadهای استاندارد را در دسترس قرار می‌دهد و سپس امکان می‌دهد ADL توابع مرتبط با نوع آرگومان را پیدا کند.

در طراحی APIهای عمومی، این تفاوت می‌تواند تعیین‌کننده باشد. با این حال، برای کد معمولی که فقط با Containerهای استاندارد کار می‌کند، استفاده مستقیم از `std::begin` و `std::end` ساده و روشن است.

## نکات مهم درباره Iteratorها و اعتبار محدوده

### معتبر بودن Iteratorها

برای استفاده صحیح از `std::begin` و `std::end`، محدوده باید از نظر Iterator معتبر باشد. این دو تابع تضمین نمی‌کنند که Iteratorهای حاصل در تمام طول اجرای برنامه معتبر باقی بمانند.

برای نمونه، در `std::vector` عملیاتی مانند افزایش ظرفیت از طریق `reserve` یا افزودن عناصر در شرایط خاص ممکن است Iteratorهای قبلی را نامعتبر کند.

```
#include <iterator>
#include <vector>

int main() {
    std::vector<int> values = {1, 2, 3};

    auto first = std::begin(values);
    auto last = std::end(values);

    values.push_back(4);

    // Do not assume that first and last are still valid.
}
```

در این مثال، افزودن عنصر جدید به `std::vector` ممکن است باعث تخصیص مجدد حافظه شود. اگر این اتفاق رخ دهد، Iteratorهای قبلی نامعتبر خواهند شد. حتی در حالتی که تخصیص مجدد انجام نشود، Iterator انتهایی قبلی به دلیل تغییر اندازه Container دیگر انتهای محدوده جدید نیست.

بنابراین، پس از عملیاتی که ممکن است Iteratorها را نامعتبر کند، باید وضعیت اعتبار Iteratorها را بر اساس قواعد همان Container بررسی کرد.

### یکسان بودن محدوده ابتدا و انتها

Iteratorهای ابتدا و انتها باید متعلق به یک محدوده معتبر و سازگار باشند.

مقایسه Iteratorهای متعلق به Containerهای مستقل یا محاسبه فاصله میان آن‌ها، مگر در شرایطی که استاندارد برای آن عملیات را مجاز کرده باشد، معتبر نیست.

برای مثال، نباید از Iterator ابتدای یک `std::vector` و Iterator انتهای یک `std::vector` دیگر برای ساخت یک محدوده واحد استفاده کرد.

### استفاده نکردن از Iterator انتهایی برای خواندن

موقعیت حاصل از `std::end` یک مرز است و نباید به عنوان عنصر واقعی در نظر گرفته شود.

الگوی صحیح پیمایش:

```
for (auto it = std::begin(values);
     it != std::end(values);
     ++it) {
    // Process the current element
}
```

در مقابل، دسترسی مستقیم به `*std::end(values)` برای یک محدوده معمولی معتبر نیست و می‌تواند به رفتار تعریف‌نشده منجر شود.

### توجه به عمر اشیا

Iterator معمولاً مستقل از عمر Container نیست. اگر Container از بین برود، Iteratorهای مربوط به آن دیگر نباید به عنوان دسترسی معتبر به عناصر استفاده شوند.

همین موضوع درباره آرایه‌های محلی نیز صدق می‌کند؛ اشاره‌گرهای حاصل از `std::begin` و `std::end` پس از پایان عمر آرایه قابل استفاده نیستند.

## تفاوت‌های مهم در استانداردهای مختلف ++C

### وضعیت در ++C98 و ++C03

در استانداردهای قدیمی‌تر از ++C11، توابع آزاد استاندارد `std::begin` و `std::end` به شکل معرفی‌شده در ++C11 وجود نداشتند.

با این حال، بسیاری از Containerهای استاندارد متدهای عضو `begin()` و `end()` را ارائه می‌کردند. بنابراین، کدی که مستقیماً از این متدها استفاده می‌کند، می‌تواند در این استانداردهای قدیمی نیز معتبر باشد.

### وضعیت در ++C11

استاندارد ++C11 توابع آزاد `std::begin` و `std::end` را معرفی کرد و امکان استفاده یکپارچه از آرایه‌های داخلی و Containerهای استاندارد را فراهم ساخت.

همچنین `std::array` و توابع `std::cbegin` و `std::cend` از قابلیت‌های مهم مرتبط در همین استاندارد هستند.

### وضعیت در ++C14 و نسخه‌های بعدی

در ++C14 و استانداردهای جدیدتر، `std::begin` و `std::end` همچنان ابزارهای معتبر و پرکاربردی هستند.

با این حال، قابلیت‌های جدیدتری برای کار با محدوده‌ها به زبان و کتابخانه استاندارد اضافه شده‌اند. برای مثال، ++C20 مفهوم Ranges و امکاناتی مانند `std::ranges::begin` و `std::ranges::end` را معرفی کرد.

این ابزارهای جدید برای طراحی Generic Code و کار با Rangeهای متنوع امکانات بیشتری فراهم می‌کنند، اما جایگزینی اجباری برای تمام کاربردهای `std::begin` و `std::end` نیستند.

## مقایسه std::begin با std::ranges::begin

### تفاوت در طراحی

در ++C11، توابع `std::begin` و `std::end` راهی برای دریافت Iterator از Containerها و آرایه‌های داخلی فراهم می‌کنند.

در ++C20، توابع `std::ranges::begin` و `std::ranges::end` در چارچوب Ranges معرفی شدند. این توابع از قواعد و محدودیت‌های مفهومی مربوط به Rangeها پیروی می‌کنند و بخشی از طراحی جدید Standard Library برای پردازش عمومی داده‌ها هستند.

یک نمونه از کاربرد آن‌ها:

```
#include <iostream>
#include <ranges>
#include <vector>

int main() {
    std::vector<int> values = {10, 20, 30};

    auto first = std::ranges::begin(values);
    auto last = std::ranges::end(values);

    while (first != last) {
        std::cout << *first << ' ';
        ++first;
    }

    std::cout << '\n';
}
```

این مثال به ++C20 یا استاندارد جدیدتری نیاز دارد و در ++C11 قابل کامپایل نیست.

تفاوت اصلی در این است که امکانات Ranges برای تعامل با مفاهیم استاندارد Range و Iterator طراحی شده‌اند و محدود به همان الگوی ساده توابع آزاد ++C11 نیستند.

### چه زمانی از هرکدام استفاده کنیم؟

برای پروژه‌هایی که باید با ++C11 سازگار باشند، `std::begin` و `std::end` انتخاب‌های طبیعی هستند.

برای پروژه‌های ++C20 یا جدیدتر که از مفاهیم Ranges استفاده می‌کنند، `std::ranges::begin` و `std::ranges::end` می‌توانند گزینه مناسبی باشند؛ به‌خصوص هنگامی که می‌خواهیم از محدودیت‌های نوعی و قابلیت‌های جدید کتابخانه استاندارد استفاده کنیم.

انتخاب نهایی باید با استاندارد هدف پروژه، نوع Range مورد استفاده و نیازهای طراحی API هماهنگ باشد.

## اشتباهات رایج در استفاده از این توابع

### فرض کردن اینکه end به آخرین عنصر اشاره می‌کند

این برداشت نادرست است. تابع `std::end` موقعیت بلافاصله پس از آخرین عنصر را برمی‌گرداند و آن موقعیت معمولاً قابل dereference نیست.

### استفاده از std::end برای اشاره‌گر خام

اگر یک اشاره‌گر خام به `std::begin` یا `std::end` داده شود، نمی‌توان انتظار داشت اندازه آرایه اصلی بازیابی شود.

اشاره‌گر خام فقط آدرس یک شیء یا موقعیت حافظه را نگه می‌دارد و به تنهایی اندازه محدوده را مشخص نمی‌کند.

### استفاده از std::sort برای هر نوع Container

داشتن Iterator به ابتدا و انتها تضمین نمی‌کند که الگوریتم `std::sort` قابل استفاده باشد. این الگوریتم به Random Access Iterator نیاز دارد.

بنابراین، باید علاوه بر وجود محدوده، الزامات Iterator الگوریتم انتخاب‌شده را نیز در نظر گرفت.

### فراموش کردن const بودن داده‌ها

نوع Iterator حاصل از `std::begin` به نوع آرگومان بستگی دارد. برای Containerهای `const`، Iterator مناسب دسترسی ثابت برگردانده می‌شود و نمی‌توان عناصر را از طریق آن تغییر داد.

### فرض کردن پایداری Iteratorها

پس از تغییر ساختار Container، ممکن است Iteratorها نامعتبر شوند. نباید بدون بررسی قواعد اعتبار Iteratorهای Container، از مقادیر ذخیره‌شده قبلی استفاده کرد.

## توصیه‌های طراحی برای کد حرفه‌ای

### ترجیح دادن محدوده‌های استاندارد

در الگوریتم‌های عمومی، بهتر است به جای اتکا به اندیس‌های اختصاصی یک Container، در صورت مناسب بودن نیازمندی‌ها از محدوده‌های Iterator استفاده شود.

این رویکرد وابستگی الگوریتم به نوع خاص داده را کاهش می‌دهد و امکان استفاده مجدد از آن را افزایش می‌دهد.

### استفاده از auto برای Iteratorها

نوع Iterator در Containerهای مختلف می‌تواند متفاوت باشد. استفاده از `auto` اغلب خوانایی کد را افزایش می‌دهد و از وابستگی غیرضروری به نوع دقیق Iterator جلوگیری می‌کند.

### استفاده از الگوریتم‌های استاندارد

به جای پیاده‌سازی دستی عملیات متداول مانند جست‌وجو، مرتب‌سازی یا جمع‌کردن عناصر، در صورت سازگاری نیازمندی‌ها با الگوریتم‌های Standard Library، بهتر است از همان الگوریتم‌ها استفاده شود.

### توجه به هزینه و پیچیدگی عملیات

توابع `std::begin` و `std::end` خودشان معمولاً عملیات ساده‌ای هستند؛ اما هزینه پیمایش و الگوریتمی که از آن‌ها استفاده می‌کند، به نوع Iterator و Container بستگی دارد.

برای نمونه، پیمایش `std::vector` و `std::list` از نظر ترتیب دسترسی و ویژگی‌های حافظه یکسان نیست. همچنین الگوریتم‌های نیازمند دسترسی تصادفی را نمی‌توان صرفاً با فراهم کردن ابتدا و انتهای محدوده به تمام Containerها تعمیم داد.

## جمع‌بندی

توابع `std::begin` و `std::end` از قابلیت‌های مهم Standard Library در ++C11 هستند که دسترسی به محدوده‌های داده را برای انواع مختلف Container و آرایه‌های داخلی یکپارچه می‌کنند.

مهم‌ترین نکات این قابلیت‌ها عبارت‌اند از:

- تابع `std::begin` Iterator ابتدای محدوده را برمی‌گرداند.
- تابع `std::end` Iterator موقعیت بلافاصله پس از آخرین عنصر را برمی‌گرداند.
- این دو تابع امکان استفاده از یک الگوی مشترک برای پیمایش Containerها و آرایه‌های داخلی را فراهم می‌کنند.
- استفاده از محدوده‌های نیمه‌باز، طراحی الگوریتم‌های عمومی و پردازش محدوده‌های خالی را ساده می‌کند.
- نوع Iterator حاصل به نوع داده و ویژگی‌های `const` بودن آن وابسته است.
- این توابع اعتبار Iteratorها، سازگاری با الگوریتم خاص یا پایداری Iterator پس از تغییر Container را تضمین نمی‌کنند.
- برای کدهای عمومی که از انواع سفارشی نیز پشتیبانی می‌کنند، در بسیاری از موارد ترکیب `using std::begin` و `using std::end` با فراخوانی بدون Qualification، امکان استفاده از ADL را فراهم می‌کند.
- در پروژه‌های ++C20 و جدیدتر، قابلیت‌های Ranges گزینه‌های پیشرفته‌تری برای طراحی APIهای مبتنی بر محدوده ارائه می‌کنند.

در مجموع، استفاده صحیح از `std::begin` و `std::end` به نوشتن کدی عمومی‌تر، خواناتر و سازگارتر با فلسفه طراحی Standard Library کمک می‌کند و درک دقیق رفتار آن‌ها برای توسعه‌دهندگان حرفه‌ای ++C اهمیت زیادی دارد.

امضاهای دقیق overloadها را اصلاح کنبخش arrayهای const را کامل‌تر کن
