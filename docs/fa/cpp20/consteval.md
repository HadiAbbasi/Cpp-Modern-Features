## `consteval` چیست؟

کلمهٔ کلیدی `consteval` از استاندارد **++C20** وارد زبان ++C شد.

`consteval` برای **تعریف تابع‌هایی** استفاده می‌شود که باید **حتماً در زمان کامپایل اجرا شوند**.

به زبان ساده، وقتی یک تابع را با `consteval` تعریف می‌کنیم، به کامپایلر می‌گوییم:

> «این تابع را فقط و فقط در زمان کامپایل اجرا کن و اجازه نده در زمان اجرای برنامه فراخوانی شود.»

یک مثال ساده:

```cpp
consteval int square(int x)
{
    return x * x;
}

int main()
{
    constexpr int a = square(5);

    return 0;
}
```

در این مثال، کامپایلر می‌داند که `square(5)` باید در زمان کامپایل اجرا شود.

نتیجه نیز از قبل مشخص است:

```text
25
```

بنابراین مقدار `25` می‌تواند از همان زمان کامپایل در برنامه قرار بگیرد.

## چرا `consteval` به وجود آمد؟

برای درک دلیل وجود `consteval` بهتر است ابتدا مشکل `constexpr` را ببینیم.

در ++C می‌توانیم یک تابع را با `constexpr` تعریف کنیم:

```cpp
constexpr int square(int x)
{
    return x * x;
}
```

این تابع **می‌تواند** در زمان کامپایل اجرا شود، اما الزاماً مجبور نیست.

برای مثال:

```cpp
constexpr int a = square(5);
```

در اینجا کامپایلر باید نتیجه را در زمان کامپایل به دست بیاورد.

اما این کد هم کاملاً معتبر است:

```cpp
int x = 10;

int y = square(x);
```

در این حالت مقدار `x` در زمان اجرای برنامه مشخص می‌شود، بنابراین `square` می‌تواند در زمان اجرا هم اجرا شود.

این انعطاف‌پذیری `constexpr` گاهی چیزی نیست که برنامه‌نویس می‌خواهد.

گاهی برنامه‌نویس می‌خواهد مطمئن شود که **یک تابع تحت هیچ شرایطی در زمان اجرا اجرا نمی‌شود**.

اینجاست که `consteval` وارد می‌شود.

---

## `consteval` چه مشکلی را حل می‌کند؟

فرض کنید تابعی داریم که قرار است اطلاعاتی را پردازش کند که حتماً باید در زمان کامپایل مشخص باشند.

برای مثال:

```cpp
consteval int calculate_size(int x)
{
    return x * 10;
}
```

حالا این کد معتبر است:

```cpp
constexpr int size = calculate_size(5);
```

اما این کد مشکل دارد:

```cpp
int x = 5;

int size = calculate_size(x);
```

علت این است که مقدار `x` در زمان اجرای برنامه مشخص می‌شود.

تابع `calculate_size` یک تابع `consteval` است و **حق ندارد در زمان اجرا اجرا شود**.

بنابراین کامپایلر خطا می‌دهد.

این موضوع یکی از مهم‌ترین ویژگی‌های `consteval` است.

با `consteval` می‌توانیم یک **اجبار در زمان کامپایل** ایجاد کنیم.

---

## `consteval` چگونه کار می‌کند؟

فرض کنیم چنین تابعی داریم:

```cpp
consteval int add(int a, int b)
{
    return a + b;
}
```

فراخوانی زیر مشکلی ندارد:

```cpp
int result = add(10, 20);
```

شاید در نگاه اول عجیب باشد.

متغیر `result` یک متغیر معمولی است و `constexpr` نیست.

اما نکته اینجاست که **خود تابع `add` باید در زمان کامپایل اجرا شود**.

کامپایلر می‌تواند نتیجه را محاسبه کند:

```text
10 + 20 = 30
```

و سپس مقدار `30` را برای `result` قرار دهد.

بنابراین این دو موضوع را نباید با یکدیگر اشتباه بگیریم:

```cpp
consteval int add(int a, int b);
```

یعنی:

> «خود تابع باید در زمان کامپایل اجرا شود.»

اما:

```cpp
constexpr int result = add(10, 20);
```

یعنی:

> «مقدار این متغیر باید یک مقدار ثابت در زمان کامپایل باشد.»

## تفاوت `consteval` و `const`

تفاوت `consteval` و `const` بسیار مهم است، چون این دو کلمه اصلاً یک مفهوم را بیان نمی‌کنند.

کلمهٔ `const` معمولاً دربارهٔ **ثابت بودن یک مقدار در زمان اجرای برنامه** صحبت می‌کند.

برای مثال:

```cpp
const int x = 10;
```

بعد از مقداردهی نمی‌توانیم بنویسیم:

```cpp
x = 20;
```

اما `const` لزوماً به این معنی نیست که مقدار حتماً در زمان کامپایل تعیین شده است.

برای مثال:

```cpp
int getNumber()
{
    return 10;
}

const int x = getNumber();
```

در اینجا `x` ثابت است و بعد از مقداردهی نمی‌توان آن را تغییر داد.

اما مقدار آن می‌تواند در زمان اجرای برنامه از نتیجهٔ یک تابع به دست آمده باشد.

در مقابل، `consteval` دربارهٔ **زمان اجرای تابع** صحبت می‌کند.

برای مثال:

```cpp
consteval int getNumber()
{
    return 10;
}
```

این تابع مجبور است در زمان کامپایل اجرا شود.

بنابراین به صورت خیلی خلاصه:

| ویژگی              | `const`                    | `consteval`                    |
| ------------------ | -------------------------- | ------------------------------ |
| مربوط به           | مقدار/شیء                  | تابع                           |
| تغییر مقدار        | معمولاً اجازه داده نمی‌شود | خودش متغیر نیست                |
| الزام زمان کامپایل | ندارد                      | دارد                           |
| از ++C             | قدیمی                      | ++C20                          |
| کاربرد اصلی        | جلوگیری از تغییر           | اجبار به اجرای تابع در کامپایل |

پس مهم‌ترین نکته این است که:

> `const` و `consteval` جایگزین یکدیگر نیستند.

---

## آیا مقدار `consteval` را می‌توان بعداً تغییر داد؟

اینجا یک سوءتفاهم رایج وجود دارد.

`consteval` خودش **مقداری ندارد که بعداً تغییر کند**.

`consteval` برای **تابع** استفاده می‌شود، نه برای متغیر.

برای مثال:

```cpp
consteval int getNumber()
{
    return 10;
}
```

در اینجا `getNumber` یک تابع `consteval` است.

می‌توانیم نتیجهٔ اجرای آن را داخل یک متغیر معمولی بریزیم:

```cpp
int x = getNumber();
```

حالا `x` یک متغیر معمولی است.

بنابراین این کار کاملاً ممکن است:

```cpp
x = 20;
```

در اینجا ما مقدار **نتیجهٔ تابع `consteval`** را تغییر داده‌ایم، نه اینکه مقدار `consteval` را تغییر داده باشیم.

مثال کامل:

```cpp
consteval int getNumber()
{
    return 10;
}

int main()
{
    int x = getNumber();

    x = 20;

    return 0;
}
```

این کد معتبر است.

پس اگر بخواهیم دقیق صحبت کنیم:

> نتیجهٔ یک تابع `consteval` می‌تواند داخل یک متغیر معمولی قرار بگیرد و آن متغیر بعداً تغییر کند.

اما:

> خود تابع `consteval` یک مقدار قابل تغییر نیست.

## تفاوت `consteval` و `constexpr`

احتمالاً مهم‌ترین مقایسه در بحث `consteval`، مقایسهٔ آن با `constexpr` است.

فرض کنیم هر دو تابع زیر را داریم:

```cpp
constexpr int square1(int x)
{
    return x * x;
}

consteval int square2(int x)
{
    return x * x;
}
```

تابع `square1` با `constexpr` می‌تواند در زمان کامپایل اجرا شود.

اما اگر شرایط لازم برای اجرای زمان کامپایل وجود نداشته باشد، امکان دارد در زمان اجرا اجرا شود.

برای مثال:

```cpp
int x = 5;

int a = square1(x);
```

این کد می‌تواند معتبر باشد.

اما تابع `square2` با `consteval` چنین انعطافی ندارد:

```cpp
int x = 5;

int b = square2(x);
```

این کد خطا خواهد داشت.

چون `square2` **باید** در زمان کامپایل اجرا شود، اما مقدار `x` تا زمان اجرای برنامه مشخص نمی‌شود.

بنابراین می‌توان این تفاوت را خیلی ساده به شکل زیر به خاطر سپرد:

```text
constexpr  →  «اگر بتوانی، در زمان کامپایل اجرا کن.»

consteval  →  «حتماً باید در زمان کامپایل اجرا کنی.»
```

البته این یک بیان ساده‌شده است، اما برای شروع درک تفاوت این دو بسیار مفید است.

## یک مثال کاربردی‌تر

فرض کنید می‌خواهیم یک مقدار را بر اساس چند ورودی محاسبه کنیم و می‌دانیم این ورودی‌ها باید حتماً در زمان کامپایل مشخص باشند.

می‌توانیم بنویسیم:

```cpp
consteval int buffer_size(int width, int height)
{
    return width * height;
}
```

حالا:

```cpp
constexpr int size = buffer_size(10, 20);
```

مقدار `size` برابر است با:

```text
200
```

اما اگر بخواهیم مقدار را از ورودی کاربر بگیریم:

```cpp
int width;
std::cin >> width;

int size = buffer_size(width, 20);
```

اینجا مشکل داریم.

دلیلش کاملاً مشخص است:

```text
ورودی کاربر
      ↓
زمان اجرای برنامه
      ↓
width مشخص می‌شود
```

اما `consteval` می‌گوید:

```text
من باید همین الان، در زمان کامپایل اجرا شوم.
```

پس چنین فراخوانی‌ای مجاز نیست.

این ویژگی باعث می‌شود اشتباهاتی که ممکن بود فقط در زمان اجرا متوجه آن‌ها شویم، خیلی زودتر و در مرحلهٔ کامپایل مشخص شوند.

---

## `consteval` چه فایده‌ای برای برنامه‌نویس دارد؟

مهم‌ترین فایدهٔ `consteval` این است که **قرارداد بسیار مشخصی برای یک تابع ایجاد می‌کند**.

وقتی برنامه‌نویس چنین چیزی می‌بیند:

```cpp
consteval int calculate(int x)
{
    return x * 2;
}
```

می‌داند که این تابع قرار نیست بخشی از محاسبات زمان اجرای برنامه باشد.

این تابع باید در زمان کامپایل قابل اجرا باشد.

این موضوع می‌تواند برای مواردی مانند:

* محاسباتی که باید در زمان کامپایل انجام شوند
* تولید مقادیر ثابت
* بررسی‌های زمان کامپایل
* ساخت APIهایی که ورودی آن‌ها باید compile-time باشد
* جلوگیری از اجرای ناخواستهٔ محاسبات در زمان اجرا

مفید باشد.

---

## آیا `consteval` باعث سریع‌تر شدن همه چیز می‌شود؟

نه لزوماً.

این تصور که استفاده از `consteval` همیشه باعث سریع‌تر شدن برنامه می‌شود، دقیق نیست.

هدف اصلی `consteval` این نیست که به شکل جادویی برنامه را سریع‌تر کند.

هدف اصلی آن این است که **اجرا را به زمان کامپایل منتقل و این موضوع را اجباری کند**.

اگر یک محاسبه را بتوان در زمان کامپایل انجام داد، دیگر لازم نیست همان محاسبه در زمان اجرای برنامه انجام شود.

اما در بسیاری از موارد، کامپایلر خودش می‌تواند بهینه‌سازی‌های مشابهی انجام دهد.

بنابراین مزیت مهم `consteval` فقط سرعت نیست.

مزیت مهم‌تر آن **تضمین و کنترل زمان اجرای تابع** است.

---

## یک نکتهٔ مهم دربارهٔ کامپایل

وقتی می‌گوییم تابع `consteval` در زمان کامپایل اجرا می‌شود، منظور این نیست که برنامهٔ ++C واقعاً هنگام کامپایل یک نسخهٔ جداگانه از برنامه را اجرا می‌کند.

کامپایلر کد را بررسی و تابع را ارزیابی می‌کند و نتیجه را در فرایند کامپایل به دست می‌آورد.

مثلاً:

```cpp
consteval int multiply(int a, int b)
{
    return a * b;
}

int x = multiply(5, 6);
```

کامپایلر می‌تواند نتیجهٔ `multiply(5, 6)` را هنگام کامپایل محاسبه کند.

نتیجه:

```text
30
```

سپس برنامهٔ نهایی دیگر لازم نیست این تابع را در زمان اجرا برای این فراخوانی اجرا کند.

## یک اشتباه رایج

گاهی `consteval` با این مفهوم اشتباه گرفته می‌شود:

```text
«این مقدار در زمان کامپایل ثابت است و بعداً نمی‌توان آن را تغییر داد.»
```

این تعریف مربوط به `consteval` نیست.

مثلاً:

```cpp
consteval int getValue()
{
    return 100;
}

int x = getValue();

x = 500;
```

این کد از نظر مفهوم کاملاً قابل قبول است.

تابع `getValue` در زمان کامپایل اجرا شده است.

اما `x` یک متغیر معمولی است و می‌تواند بعداً تغییر کند.

اگر هدف شما این باشد که **خود متغیر قابل تغییر نباشد**، موضوع دیگری مطرح است:

```cpp
const int x = getValue();
```

در این حالت `const` جلوی تغییر `x` را می‌گیرد.

اگر بخواهیم مقدار متغیر هم حتماً در زمان کامپایل مشخص باشد، معمولاً `constexpr` مطرح می‌شود:

```cpp
constexpr int x = getValue();
```

پس این سه مفهوم را از هم جدا کنیم:

```text
const
↓
این مقدار را بعداً تغییر نده.

constexpr
↓
این مقدار باید یک مقدار ثابت قابل ارزیابی در زمان کامپایل باشد.

consteval
↓
این تابع باید حتماً در زمان کامپایل اجرا شود.
```

---

## چه زمانی از `consteval` استفاده کنیم؟

بهترین زمان استفاده از `consteval` زمانی است که می‌خواهیم **به شکل قطعی تضمین کنیم یک تابع فقط در زمان کامپایل فراخوانی می‌شود**.

اگر فقط می‌خواهیم کامپایلر در صورت امکان محاسبات را در زمان کامپایل انجام دهد، معمولاً `constexpr` انتخاب انعطاف‌پذیرتری است.

مثلاً:

```cpp
constexpr int square(int x)
{
    return x * x;
}
```

برای یک تابع عمومی که هم می‌تواند با مقادیر زمان کامپایل و هم با مقادیر زمان اجرا کار کند، `constexpr` مناسب‌تر است.

اما:

```cpp
consteval int square(int x)
{
    return x * x;
}
```

برای زمانی مناسب است که **عدم اجرای تابع در زمان اجرا بخشی از قرارداد تابع باشد**.

## جمع‌بندی

`consteval` یکی از قابلیت‌های ++C20 است که برای **اجباری کردن اجرای یک تابع در زمان کامپایل** به وجود آمده است.

مهم‌ترین نکته این است که `consteval` برای **تابع** استفاده می‌شود، نه برای متغیر.

تفاوت اصلی آن با `constexpr` این است که:

```text
constexpr
→ تابع می‌تواند در زمان کامپایل اجرا شود.

consteval
→ تابع باید در زمان کامپایل اجرا شود.
```

همچنین `consteval` با `const` تفاوت اساسی دارد:

```text
const
→ یک مقدار را بعد از مقداردهی غیرقابل تغییر می‌کند.

consteval
→ اجرای یک تابع را به زمان کامپایل محدود می‌کند.
```

در نتیجه اگر در جایی دیدید:

```cpp
consteval int calculate(int x)
{
    return x * 2;
}
```

باید این جمله را در ذهن داشته باشید:

> **«هر بار که این تابع را صدا می‌زنم، کامپایلر باید بتواند آن را در زمان کامپایل اجرا کند.»**

اگر مقدار ورودی فقط در زمان اجرای برنامه مشخص شود، فراخوانی تابع `consteval` مجاز نیست.

پس `consteval` ابزاری برای **تغییرناپذیر کردن یک مقدار** نیست؛ ابزاری برای **اجباری کردن محاسبات در زمان کامپایل** است.
