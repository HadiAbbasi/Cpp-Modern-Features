# معرفی `std::midpoint` در ++C20

## مقدمه

محاسبهٔ نقطهٔ میانی دو مقدار عددی، در نگاه اول عملی ساده به نظر می‌رسد؛ کافی است دو مقدار را با یکدیگر جمع کنیم و حاصل را بر دو تقسیم کنیم. بااین‌حال، عبارت `(a + b) / 2` همیشه ایمن نیست. جمع دو عدد صحیح بزرگ ممکن است باعث سرریز (Overflow) شود و در محاسبات ممیز شناور نیز ممکن است مقدار میانی قابل نمایش باشد، اما حاصل جمع از محدودهٔ قابل نمایش نوع خارج شود.

تابع `std::midpoint` که در استاندارد ++C20 به کتابخانهٔ استاندارد اضافه شده است، برای حل این مسئله طراحی شده است. این تابع نقطهٔ میانی دو مقدار عددی یا دو اشاره‌گر متعلق به یک آرایه را محاسبه می‌کند و برای هر overload، قواعد مشخصی دربارهٔ سرریز، گرد کردن و اعتبار ورودی‌ها دارد.

این قابلیت بخشی از Standard Library است، نه یک قابلیت زبانی یا افزونهٔ اختصاصی کامپایلر. اعلان آن در سرآیند `<numeric>` قرار دارد.

## معرفی و امضای تابع

تابع `std::midpoint` دارای دو overload اصلی است:

```
#include <numeric>

template<class T>
constexpr T midpoint(T a, T b) noexcept;

template<class T>
constexpr T* midpoint(T* a, T* b);
```

در overload نخست، نوع `T` باید یک نوع حسابی (Arithmetic Type) به‌جز `bool` باشد. بنابراین انواع صحیح و ممیز شناور استاندارد، از جمله `int`، `unsigned int`، `long long`، `float`، `double` و `long double`، قابل استفاده هستند.

در overload دوم، نوع اشاره‌گر باید به یک نوع کامل از نوع شیء (Object Type) اشاره کند. هر دو اشاره‌گر باید متعلق به یک آرایه باشند. اشاره‌گر به عنصر فرضی یک آرایهٔ تک‌عنصری و اشاره‌گر one-past-the-end نیز در چارچوب قواعد استاندارد Pointer Arithmetic قابل استفاده هستند.

نکتهٔ مهم این است که تابع برای دو ورودی با انواع متفاوت، یک نوع مشترک را به‌صورت خودکار انتخاب نمی‌کند. هر دو آرگومان باید با پارامترهای یک overload سازگار باشند. بنابراین بهتر است نوع ورودی‌ها را یکسان نگه دارید و در صورت نیاز، تبدیل نوع را آگاهانه انجام دهید.

## بررسی دلیل وجود `std::midpoint`

### خطر سرریز در محاسبات صحیح

عبارت متداول زیر ممکن است پیش از تقسیم بر دو سرریز کند:

```
int middle = (a + b) / 2;
```

برای مثال، اگر هر دو ورودی نزدیک بیشینهٔ نوع صحیح باشند، جمع آن‌ها ممکن است در همان نوع قابل نمایش نباشد. در انواع صحیح بدون علامت، نتیجه به‌صورت پیمانه‌ای (Modulo) محاسبه می‌شود؛ در انواع صحیح علامت‌دار، سرریز باعث رفتار تعریف‌نشده (Undefined Behavior) خواهد شد.

حتی بازنویسی عبارت به شکل زیر نیز یک راه‌حل عمومی و کامل نیست:

```
int middle = a + (b - a) / 2;
```

در این نسخه ممکن است تفریق `b - a` سرریز کند؛ برای مثال زمانی که `a` منفی و `b` مثبت باشد و فاصلهٔ آن‌ها از محدودهٔ قابل نمایش نوع بیشتر شود.

بنابراین تغییر ترتیب عملیات به‌تنهایی تضمین ایمنی ایجاد نمی‌کند.

### خطر سرریز در محاسبات ممیز شناور

در محاسبات Floating-Point نیز عبارت `(a + b) / 2` ممکن است جمعی بزرگ‌تر از بیشینهٔ مقدار قابل نمایش تولید کند؛ حتی اگر میانگین ریاضی دو ورودی کاملاً در محدودهٔ نوع قرار داشته باشد.

تابع `std::midpoint` برای جلوگیری از چنین سرریزی در محاسبهٔ نقطهٔ میانی تعریف شده است.

### محاسبهٔ میانهٔ اشاره‌گرها

برای پیدا کردن عنصر میانی یک آرایه، معمولاً از عبارتی مانند `first + (last - first) / 2` استفاده می‌شود. این روش به تفریق دو اشاره‌گر وابسته است و نتیجهٔ تفریق باید در `std::ptrdiff_t` قابل نمایش باشد.

استفاده از overload اشاره‌گری `std::midpoint` امکان محاسبهٔ نقطهٔ میانی را بدون نیاز به نوشتن مستقیم این تفریق فراهم می‌کند.

## بررسی رفتار overload عددی

### محاسبات با انواع صحیح

برای ورودی‌های صحیح، نتیجه نصف مجموع ریاضی دو ورودی است و هیچ سرریزی رخ نمی‌دهد.

اگر مجموع دو ورودی عددی فرد باشد، نتیجه به سمت آرگومان نخست (`a`) گرد می‌شود.

این قاعده به این معناست که در حالت نیمهٔ صحیح، عدد صحیح نزدیک‌تر به آرگومان نخست انتخاب خواهد شد. بنابراین رفتار تابع لزوماً معادل گرد کردن همیشگی به پایین یا همیشگی به سمت صفر نیست.

```
#include <iostream>
#include <numeric>

int main() {
    std::cout << std::midpoint(2, 5) << '\n';
    std::cout << std::midpoint(5, 2) << '\n';
    std::cout << std::midpoint(-2, 1) << '\n';
    std::cout << std::midpoint(1, -2) << '\n';
}
```

خروجی:

```
3
4
-1
0
```

در دو فراخوانی نخست، مجموع برابر ۷ است. چون نتیجهٔ دقیق ۳٫۵ خواهد بود، فراخوانی اول به سمت ۲ و فراخوانی دوم به سمت ۵ گرد می‌شود.

این ویژگی نشان می‌دهد که جابه‌جایی ترتیب آرگومان‌ها می‌تواند نتیجهٔ نهایی را تغییر دهد.

### نمونهٔ جلوگیری از سرریز

نمونهٔ زیر نشان می‌دهد که `std::midpoint` در نزدیکی بیشینهٔ یک نوع بدون علامت چگونه از خطای جمع جلوگیری می‌کند:

```
#include <cstdint>
#include <iostream>
#include <limits>
#include <numeric>

int main() {
    const std::uint32_t a =
        std::numeric_limits<std::uint32_t>::max();

    const std::uint32_t b = a - 2;

    std::cout << "Unsafe expression: " << (a + b) / 2 << '\n';
    std::cout << "Safe midpoint: " << std::midpoint(a, b) << '\n';
}
```

در عبارت نخست، جمع در نوع `std::uint32_t` انجام می‌شود و به علت رفتار پیمانه‌ای نوع بدون علامت، نتیجهٔ نادرستی به دست می‌آید.

در مقابل، تابع `std::midpoint` مقدار میانی صحیح را بدون سرریز محاسبه می‌کند.

### محاسبات با انواع ممیز شناور

برای ورودی‌های ممیز شناور، نتیجه نصف مجموع ریاضی دو ورودی است.

استاندارد تضمین می‌کند که در محاسبهٔ `std::midpoint` سرریز رخ ندهد و حداکثر یک عملیات Inexact انجام شود.

این تضمین به معنی دقیق بودن همیشگی نتیجه یا حذف تمام خطاهای گرد کردن نیست. محدودیت‌های معمول نمایش دودویی اعداد اعشاری همچنان وجود دارند.

```
#include <iomanip>
#include <iostream>
#include <limits>
#include <numeric>

int main() {
    const double a = std::numeric_limits<double>::max();
    const double b = a;

    const double middle = std::midpoint(a, b);

    std::cout << std::setprecision(17) << middle << '\n';
}
```

در این مثال، میانگین ریاضی دو ورودی برابر خود مقدار ورودی است. جمع مستقیم `a + b` می‌تواند از محدودهٔ `double` خارج شود، اما `std::midpoint` نتیجه را بدون سرریز محاسبه می‌کند.

### محدودیت استفاده از نوع `bool`

اگرچه `bool` در دسته‌بندی کلی انواع Arithmetic قرار می‌گیرد، overload عددی `std::midpoint` صراحتاً آن را مستثنا می‌کند.

بنابراین فراخوانی مستقیم این تابع با دو مقدار `bool` معتبر نیست. در صورت نیاز، می‌توان مقادیر منطقی را ابتدا به یک نوع عددی مناسب تبدیل کرد:

```
#include <numeric>

int main() {
    const bool a = false;
    const bool b = true;

    const int middle = std::midpoint(
        static_cast<int>(a),
        static_cast<int>(b)
    );
}
```

## بررسی رفتار overload اشاره‌گری

### محاسبهٔ اشاره‌گر میانی

overload دوم نقطهٔ میانی دو اشاره‌گر متعلق به یک آرایه را محاسبه می‌کند.

اگر اشاره‌گر نخست به اندیس `i` و اشاره‌گر دوم به اندیس `j` اشاره کنند، اندیس نتیجه مطابق رابطهٔ زیر تعیین می‌شود:

\\[ i + \frac{j-i}{2} \\]

تقسیم در این رابطه به سمت صفر قطع می‌شود. در نتیجه، اگر فاصلهٔ دو اندیس فرد باشد، عنصر انتخاب‌شده به سمت اشاره‌گر نخست نزدیک‌تر خواهد بود.

```
#include <iostream>
#include <numeric>

int main() {
    int values[] = {10, 20, 30, 40, 50, 60};

    int* first = values;
    int* last = values + 5;

    int* middle = std::midpoint(first, last);

    std::cout << *middle << '\n';
}
```

خروجی:

```
30
```

در این مثال، `first` به اندیس صفر و `last` به اندیس پنج اشاره می‌کند. اندیس میانی برابر دو است.

### استفاده از اشاره‌گر One-past-the-end

در الگوریتم‌های مبتنی بر بازه، انتهای محدوده معمولاً با اشاره‌گر one-past-the-end نمایش داده می‌شود.

این اشاره‌گر به یک عنصر واقعی اشاره نمی‌کند، اما ساخت و استفاده از آن برای نمایش انتهای آرایه مجاز است. چنین اشاره‌گری می‌تواند به‌عنوان یکی از ورودی‌های `std::midpoint` استفاده شود؛ به شرط آن‌که هر دو اشاره‌گر متعلق به همان آرایه باشند.

```
#include <iostream>
#include <numeric>

int main() {
    int values[] = {4, 8, 12, 16, 20};

    int* first = values;
    int* last = values + 5;

    int* middle = std::midpoint(first, last);

    if (middle != last) {
        std::cout << *middle << '\n';
    }
}
```

### محدودیت تعلق اشاره‌گرها به یک آرایه

هر دو اشاره‌گر باید به عناصر یک آرایهٔ واحد مربوط باشند و رابطهٔ معتبر موردنیاز Pointer Arithmetic را داشته باشند.

اگر اشاره‌گرها به دو آرایهٔ مستقل اشاره کنند، رفتار برنامه تعریف‌نشده خواهد بود.

این تابع ابزاری برای محاسبهٔ فاصلهٔ عددی میان آدرس‌های دلخواه حافظه نیست و نباید برای میان‌یابی اشاره‌گرهای نامرتبط استفاده شود.

### تفاوت با تفریق مستقیم اشاره‌گرها

روش متداول زیر را در نظر بگیرید:

```
auto* middle = first + (last - first) / 2;
```

این عبارت به تفریق اشاره‌گرها وابسته است. نتیجهٔ تفریق باید در `std::ptrdiff_t` قابل نمایش باشد.

در شرایطی که اندازهٔ آرایه از `PTRDIFF_MAX` بیشتر باشد، تفریق مستقیم ممکن است قابل استفاده نباشد؛ حتی اگر اشاره‌گرها متعلق به یک آرایه باشند.

استفاده از `std::midpoint(first, last)` انتخاب استاندارد مناسب‌تری برای این هدف است.

## بررسی ویژگی‌های `constexpr` و `noexcept`

### قابلیت ارزیابی در زمان کامپایل

هر دو overload از زمان ++C20 قابلیت `constexpr` دارند. بنابراین در صورت ثابت بودن ورودی‌ها و معتبر بودن عملیات در ارزیابی ثابت، می‌توان از آن‌ها در Constant Expression استفاده کرد.

```
#include <numeric>

constexpr int middle = std::midpoint(10, 20);

static_assert(middle == 15);

constexpr int values[] = {2, 4, 6, 8, 10};

constexpr const int* pointerMiddle =
    std::midpoint(values, values + 5);

static_assert(*pointerMiddle == 6);
```

این ویژگی برای محاسباتی که باید در زمان کامپایل انجام شوند، از جمله ساختارهای دادهٔ ثابت و بررسی‌های `static_assert`، کاربرد دارد.

### تضمین مربوط به استثناها

overload عددی با `noexcept` اعلان شده است و هیچ استثنایی پرتاب نمی‌کند.

overload اشاره‌گری در امضای استاندارد `noexcept` نیست، اما برای ورودی معتبر، عملیات عادی اشاره‌گری انجام می‌دهد و استثنای معمولی پرتاب نمی‌کند.

نباید نبودن `noexcept` در امضای overload اشاره‌گری را با تضمین رفتار برای ورودی نامعتبر اشتباه گرفت. نقض پیش‌شرط‌های اشاره‌گری ممکن است به Undefined Behavior منجر شود، نه الزاماً به پرتاب Exception.

## کاربردهای عملی در برنامه‌نویسی

### استفاده در جست‌وجوی دودویی

یکی از شناخته‌شده‌ترین کاربردهای محاسبهٔ نقطهٔ میانی، Binary Search است.

در پیاده‌سازی مبتنی بر اندیس، استفاده از `(low + high) / 2` ممکن است در صورت بزرگ بودن اندیس‌ها باعث سرریز شود.

جایگزین ایمن و خوانا، استفاده از `std::midpoint` است:

```
#include <numeric>
#include <vector>

int binarySearch(const std::vector<int>& values, int target) {
    std::size_t low = 0;
    std::size_t high = values.size();

    while (low < high) {
        const std::size_t middle = std::midpoint(low, high);

        if (values[middle] < target) {
            low = middle + 1;
        } else if (values[middle] > target) {
            high = middle;
        } else {
            return static_cast<int>(middle);
        }
    }

    return -1;
}
```

در این نمونه، بازه به شکل نیمه‌باز `[low, high)` تعریف شده است.

این طراحی باعث می‌شود مقدار `high` بتواند برابر `values.size()` باشد، بدون آن‌که درون حلقه به‌عنوان اندیس عنصر استفاده شود.

در پروژه‌های واقعی، نوع بازگشتی تابع بهتر است متناسب با اندازهٔ کانتینر انتخاب شود. استفاده از `int` در این مثال صرفاً برای ساده نگه داشتن نمونه است.

### پردازش بازه با اشاره‌گر

در کدهای سطح پایین یا الگوریتم‌هایی که از بازهٔ اشاره‌گری استفاده می‌کنند، overload اشاره‌گری می‌تواند عنصر میانی را بدون نوشتن تفریق دستی اشاره‌گرها به دست دهد.

بااین‌حال، در کد مدرن ++C معمولاً Iteratorها، `std::span` و الگوریتم‌های استاندارد بر مدیریت مستقیم اشاره‌گر ترجیح دارند. استفاده از اشاره‌گر باید با نیاز واقعی سطح پایین برنامه توجیه شود.

### کاربرد در الگوریتم‌های Divide and Conquer

در الگوریتم‌های Divide and Conquer، بازه‌ها به بخش‌های کوچک‌تر تقسیم می‌شوند.

استفاده از `std::midpoint` برای محاسبهٔ مرز تقسیم، از خطاهای ناشی از جمع دو کران جلوگیری می‌کند و هدف کد را نیز واضح‌تر نشان می‌دهد.

### کاربرد در محاسبات عددی و هندسی

در محاسباتی که نقطهٔ میانی دو مختصات یا دو مقدار عددی موردنیاز است، `std::midpoint` گزینه‌ای مناسب برای محاسبهٔ میانگین است.

بااین‌حال، این تابع جایگزین کامل عملیات Interpolation نیست. برای درون‌یابی بین دو مقدار با پارامتر دلخواه، قابلیت مرتبط `std::lerp` در ++C20 مناسب‌تر است.

## مقایسهٔ روش‌های محاسبهٔ نقطهٔ میانی

| روش                   | مزیت                                                                     | محدودیت                                                 |
| --------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------- |
| `(a + b) / 2`         | ساده و آشنا                                                              | احتمال سرریز در جمع                                     |
| `a + (b - a) / 2`     | در بسیاری از حالت‌ها از سرریز جمع جلوگیری می‌کند                         | احتمال سرریز تفریق؛ محدودیت `ptrdiff_t` برای اشاره‌گرها |
| `std::midpoint(a, b)` | تضمین استاندارد جلوگیری از سرریز در overload عددی و پشتیبانی از اشاره‌گر | فقط برای انواع و پیش‌شرط‌های مشخص تعریف شده است         |

در انتخاب روش مناسب، نباید صرفاً به این نکته توجه کرد که یک عبارت روی معماری و کامپایلر فعلی درست کار می‌کند.

تضمین‌های استاندارد و دامنهٔ ورودی‌های معتبر اهمیت بیشتری دارند.

## تفاوت میان `std::midpoint` و `std::lerp`

تابع `std::midpoint` نقطهٔ میانی دو مقدار را محاسبه می‌کند؛ یعنی حالت خاصی از Interpolation با پارامتر نصف را ارائه می‌دهد.

در مقابل، تابع `std::lerp(a, b, t)` برای محاسبهٔ درون‌یابی خطی با پارامتر `t` طراحی شده است.

```
#include <iostream>
#include <numeric>

int main() {
    const double a = 10.0;
    const double b = 30.0;

    std::cout << std::midpoint(a, b) << '\n';
    std::cout << std::lerp(a, b, 0.25) << '\n';
}
```

خروجی:

```
20
15
```

برای محاسبهٔ نقطهٔ میانی از `std::midpoint` استفاده کنید؛ برای درون‌یابی با ضریب دلخواه، `std::lerp` انتخاب مناسب‌تری است.

هر دو قابلیت در ++C20 به کتابخانهٔ استاندارد اضافه شده‌اند و در سرآیند `<numeric>` قرار دارند.

## نکات مهم و خطاهای رایج

- اهمیت ترتیب آرگومان‌ها: در محاسبات صحیح با مجموع فرد، گرد کردن به سمت آرگومان نخست انجام می‌شود؛ بنابراین `std::midpoint(a, b)` الزاماً با `std::midpoint(b, a)` برابر نیست.
- انتخاب آگاهانهٔ نوع ورودی: تابع نوع دو ورودی را به یک نوع مشترک تبدیل نمی‌کند. تبدیل ضمنی یا صریح پیش از فراخوانی می‌تواند دامنه و دقت محاسبه را تغییر دهد.
- محدودیت نوع `bool`: این نوع ورودی معتبر overload عددی نیست و در صورت نیاز باید به نوع عددی مناسب تبدیل شود.
- اعتبار اشاره‌گرها: استفاده از اشاره‌گرهای متعلق به دو آرایهٔ مستقل، پیش‌شرط تابع را نقض می‌کند.
- توجه به بازه‌های نیمه‌باز: اشاره‌گر میانی الزاماً همان عنصری نیست که یک الگوریتم با قرارداد متفاوت انتظار دارد. معنای اندیس‌ها و شرط توقف را دقیق مشخص کنید.
- محدودیت `constexpr`: این قابلیت به معنی امکان ارزیابی تمام ورودی‌ها در زمان کامپایل نیست؛ ورودی‌ها و عملیات باید شرایط Constant Expression را برآورده کنند.
- عدم جایگزینی کنترل محدوده: تابع `std::midpoint` از سرریز در محاسبهٔ میانه جلوگیری می‌کند، اما معتبر بودن اندیس‌ها، اندازهٔ کانتینر و دسترسی به عناصر همچنان مسئولیت برنامه‌نویس است.
- نبود overload عمومی برای انواع سفارشی: این تابع برای انواع Arithmetic به‌جز `bool` و اشاره‌گرهای واجد شرایط تعریف شده است. برای انواع عددی سفارشی باید عملیات متناظر را با قرارداد و تضمین‌های مناسب طراحی کنید.

# معرفی `std::midpoint` در ++C20

## مقدمه

محاسبهٔ نقطهٔ میانی دو مقدار عددی در نگاه اول ساده به نظر می‌رسد؛ کافی است دو مقدار را با یکدیگر جمع کنیم و حاصل را بر دو تقسیم کنیم. بااین‌حال، عبارت `(a + b) / 2` همیشه ایمن نیست. جمع دو عدد صحیح بزرگ ممکن است باعث سرریز (Overflow) شود و در محاسبات ممیز شناور نیز ممکن است حاصل جمع از محدودهٔ قابل نمایش نوع خارج شود، حتی اگر میانگین نهایی قابل نمایش باشد.

تابع `std::midpoint` که در استاندارد ++C20 به کتابخانهٔ استاندارد اضافه شده است، برای حل این مسئله طراحی شده است. این تابع نقطهٔ میانی دو مقدار عددی یا دو اشاره‌گر متعلق به یک آرایه را محاسبه می‌کند و برای هر overload، قواعد مشخصی دربارهٔ سرریز، گرد کردن و اعتبار ورودی‌ها دارد.

این قابلیت بخشی از Standard Library است، نه یک قابلیت زبانی یا افزونهٔ اختصاصی کامپایلر. اعلان آن در سرآیند `<numeric>` قرار دارد.

## معرفی و امضای تابع

تابع `std::midpoint` دارای دو overload اصلی است:

```
#include <numeric>

template<class T>
constexpr T midpoint(T a, T b) noexcept;

template<class T>
constexpr T* midpoint(T* a, T* b);
```

در overload نخست، نوع `T` باید یک نوع حسابی (Arithmetic Type) به‌جز `bool` باشد. بنابراین انواع صحیح و ممیز شناور استاندارد، از جمله `int`، `unsigned int`، `long long`، `float`، `double` و `long double` قابل استفاده هستند.

در overload دوم، نوع اشاره‌گر باید به یک نوع کامل از نوع شیء (Object Type) اشاره کند. هر دو اشاره‌گر باید متعلق به یک آرایه باشند. اشاره‌گر به عنصر فرضی یک آرایهٔ تک‌عنصری و اشاره‌گر one-past-the-end نیز در چارچوب قواعد استاندارد Pointer Arithmetic قابل استفاده هستند.

نکتهٔ مهم این است که تابع برای دو ورودی با انواع متفاوت، یک نوع مشترک را به‌صورت خودکار انتخاب نمی‌کند. هر دو آرگومان باید با پارامترهای یک overload سازگار باشند. بنابراین بهتر است نوع ورودی‌ها را یکسان نگه دارید و در صورت نیاز، تبدیل نوع را آگاهانه انجام دهید.

## بررسی دلیل وجود `std::midpoint`

### خطر سرریز در محاسبات صحیح

عبارت متداول زیر ممکن است پیش از تقسیم بر دو سرریز کند:

```
int middle = (a + b) / 2;
```

برای مثال، اگر هر دو ورودی نزدیک بیشینهٔ نوع صحیح باشند، جمع آن‌ها ممکن است در همان نوع قابل نمایش نباشد. در انواع صحیح بدون علامت، نتیجه به‌صورت پیمانه‌ای (Modulo) محاسبه می‌شود؛ در انواع صحیح علامت‌دار، سرریز باعث رفتار تعریف‌نشده (Undefined Behavior) خواهد شد.

حتی بازنویسی عبارت به شکل زیر نیز یک راه‌حل عمومی و کامل نیست:

```
int middle = a + (b - a) / 2;
```

در این نسخه ممکن است تفریق `b - a` سرریز کند؛ برای مثال زمانی که `a` منفی و `b` مثبت باشد و فاصلهٔ آن‌ها از محدودهٔ قابل نمایش نوع بیشتر شود.

بنابراین تغییر ترتیب عملیات به‌تنهایی تضمین ایمنی ایجاد نمی‌کند.

### خطر سرریز در محاسبات ممیز شناور

در محاسبات Floating-Point نیز عبارت `(a + b) / 2` ممکن است جمعی بزرگ‌تر از بیشینهٔ مقدار قابل نمایش تولید کند؛ حتی اگر میانگین ریاضی دو ورودی کاملاً در محدودهٔ نوع قرار داشته باشد.

تابع `std::midpoint` برای جلوگیری از چنین سرریزی در محاسبهٔ نقطهٔ میانی تعریف شده است.

### محاسبهٔ میانهٔ اشاره‌گرها

برای پیدا کردن عنصر میانی یک آرایه، معمولاً از عبارتی مانند `first + (last - first) / 2` استفاده می‌شود. این روش به تفریق دو اشاره‌گر وابسته است و نتیجهٔ تفریق باید در `std::ptrdiff_t` قابل نمایش باشد.

استفاده از overload اشاره‌گری `std::midpoint` امکان محاسبهٔ نقطهٔ میانی را بدون نیاز به نوشتن مستقیم این تفریق فراهم می‌کند.

## بررسی رفتار overload عددی

### محاسبات با انواع صحیح

برای ورودی‌های صحیح، نتیجه نصف مجموع ریاضی دو ورودی است و هیچ سرریزی رخ نمی‌دهد.

اگر مجموع دو ورودی عددی فرد باشد، نتیجه به سمت آرگومان نخست (`a`) گرد می‌شود.

این قاعده به این معناست که در حالت نیمهٔ صحیح، عدد صحیح نزدیک‌تر به آرگومان نخست انتخاب خواهد شد. بنابراین رفتار تابع لزوماً معادل گرد کردن همیشگی به پایین یا همیشگی به سمت صفر نیست.

```
#include <iostream>
#include <numeric>

int main() {
    std::cout << std::midpoint(2, 5) << '\n';
    std::cout << std::midpoint(5, 2) << '\n';
    std::cout << std::midpoint(-2, 1) << '\n';
    std::cout << std::midpoint(1, -2) << '\n';
}
```

خروجی:

```
3
4
-1
0
```

در دو فراخوانی نخست، مجموع برابر ۷ است. چون نتیجهٔ دقیق ۳٫۵ خواهد بود، فراخوانی اول به سمت ۲ و فراخوانی دوم به سمت ۵ گرد می‌شود.

این ویژگی نشان می‌دهد که جابه‌جایی ترتیب آرگومان‌ها می‌تواند نتیجهٔ نهایی را تغییر دهد.

### نمونهٔ جلوگیری از سرریز

نمونهٔ زیر نشان می‌دهد که `std::midpoint` در نزدیکی بیشینهٔ یک نوع بدون علامت چگونه از خطای جمع جلوگیری می‌کند:

```
#include <cstdint>
#include <iostream>
#include <limits>
#include <numeric>

int main() {
    const std::uint32_t a =
        std::numeric_limits<std::uint32_t>::max();

    const std::uint32_t b = a - 2;

    std::cout << "Unsafe expression: " << (a + b) / 2 << '\n';
    std::cout << "Safe midpoint: " << std::midpoint(a, b) << '\n';
}
```

در عبارت نخست، جمع در نوع `std::uint32_t` انجام می‌شود و به علت رفتار پیمانه‌ای نوع بدون علامت، نتیجهٔ نادرستی به دست می‌آید.

در مقابل، تابع `std::midpoint` مقدار میانی صحیح را بدون سرریز محاسبه می‌کند.

### محاسبات با انواع ممیز شناور

برای ورودی‌های ممیز شناور، نتیجه نصف مجموع ریاضی دو ورودی است.

استاندارد تضمین می‌کند که در محاسبهٔ `std::midpoint` سرریز رخ ندهد و حداکثر یک عملیات Inexact انجام شود.

این تضمین به معنی دقیق بودن همیشگی نتیجه یا حذف تمام خطاهای گرد کردن نیست. محدودیت‌های معمول نمایش دودویی اعداد اعشاری همچنان وجود دارند.

```
#include <iomanip>
#include <iostream>
#include <limits>
#include <numeric>

int main() {
    const double a = std::numeric_limits<double>::max();
    const double b = a;

    const double middle = std::midpoint(a, b);

    std::cout << std::setprecision(17) << middle << '\n';
}
```

در این مثال، میانگین ریاضی دو ورودی برابر خود مقدار ورودی است. جمع مستقیم `a + b` می‌تواند از محدودهٔ `double` خارج شود، اما `std::midpoint` نتیجه را بدون سرریز محاسبه می‌کند.

### محدودیت استفاده از نوع `bool`

اگرچه `bool` در دسته‌بندی کلی انواع Arithmetic قرار می‌گیرد، overload عددی `std::midpoint` صراحتاً آن را مستثنا می‌کند.

بنابراین فراخوانی مستقیم این تابع با دو مقدار `bool` معتبر نیست. در صورت نیاز، می‌توان مقادیر منطقی را ابتدا به یک نوع عددی مناسب تبدیل کرد:

```
#include <numeric>

int main() {
    const bool a = false;
    const bool b = true;

    const int middle = std::midpoint(
        static_cast<int>(a),
        static_cast<int>(b)
    );
}
```

## بررسی رفتار overload اشاره‌گری

### محاسبهٔ اشاره‌گر میانی

overload دوم نقطهٔ میانی دو اشاره‌گر متعلق به یک آرایه را محاسبه می‌کند.

اگر اشاره‌گر نخست به اندیس `i` و اشاره‌گر دوم به اندیس `j` اشاره کنند، اندیس نتیجه مطابق رابطهٔ زیر تعیین می‌شود:

\\[ i + \frac{j-i}{2} \\]

تقسیم در این رابطه به سمت صفر قطع می‌شود. در نتیجه، اگر فاصلهٔ دو اندیس فرد باشد، عنصر انتخاب‌شده به سمت اشاره‌گر نخست نزدیک‌تر خواهد بود.

```
#include <iostream>
#include <numeric>

int main() {
    int values[] = {10, 20, 30, 40, 50, 60};

    int* first = values;
    int* last = values + 5;

    int* middle = std::midpoint(first, last);

    std::cout << *middle << '\n';
}
```

خروجی:

```
30
```

در این مثال، `first` به اندیس صفر و `last` به اندیس پنج اشاره می‌کند. اندیس میانی برابر دو است.

### استفاده از اشاره‌گر One-past-the-end

در الگوریتم‌های مبتنی بر بازه، انتهای محدوده معمولاً با اشاره‌گر one-past-the-end نمایش داده می‌شود.

این اشاره‌گر به یک عنصر واقعی اشاره نمی‌کند، اما ساخت و استفاده از آن برای نمایش انتهای آرایه مجاز است. چنین اشاره‌گری می‌تواند به‌عنوان یکی از ورودی‌های `std::midpoint` استفاده شود؛ به شرط آن‌که هر دو اشاره‌گر متعلق به همان آرایه باشند.

```
#include <iostream>
#include <numeric>

int main() {
    int values[] = {4, 8, 12, 16, 20};

    int* first = values;
    int* last = values + 5;

    int* middle = std::midpoint(first, last);

    if (middle != last) {
        std::cout << *middle << '\n';
    }
}
```

### محدودیت تعلق اشاره‌گرها به یک آرایه

هر دو اشاره‌گر باید به عناصر یک آرایهٔ واحد مربوط باشند و رابطهٔ معتبر موردنیاز Pointer Arithmetic را داشته باشند.

اگر اشاره‌گرها به دو آرایهٔ مستقل اشاره کنند، رفتار برنامه تعریف‌نشده خواهد بود.

این تابع ابزاری برای محاسبهٔ فاصلهٔ عددی میان آدرس‌های دلخواه حافظه نیست و نباید برای میان‌یابی اشاره‌گرهای نامرتبط استفاده شود.

### تفاوت با تفریق مستقیم اشاره‌گرها

روش متداول زیر را در نظر بگیرید:

```
auto* middle = first + (last - first) / 2;
```

این عبارت به تفریق اشاره‌گرها وابسته است. نتیجهٔ تفریق باید در `std::ptrdiff_t` قابل نمایش باشد.

در شرایطی که اندازهٔ آرایه از `PTRDIFF_MAX` بیشتر باشد، تفریق مستقیم ممکن است قابل استفاده نباشد؛ حتی اگر اشاره‌گرها متعلق به یک آرایه باشند.

استفاده از `std::midpoint(first, last)` انتخاب استاندارد مناسب‌تری برای این هدف است.

## بررسی ویژگی‌های `constexpr` و `noexcept`

### قابلیت ارزیابی در زمان کامپایل

هر دو overload از زمان ++C20 قابلیت `constexpr` دارند. بنابراین در صورت ثابت بودن ورودی‌ها و معتبر بودن عملیات در ارزیابی ثابت، می‌توان از آن‌ها در Constant Expression استفاده کرد.

```
#include <numeric>

constexpr int middle = std::midpoint(10, 20);

static_assert(middle == 15);

constexpr int values[] = {2, 4, 6, 8, 10};

constexpr const int* pointerMiddle =
    std::midpoint(values, values + 5);

static_assert(*pointerMiddle == 6);
```

این ویژگی برای محاسباتی که باید در زمان کامپایل انجام شوند، از جمله ساختارهای دادهٔ ثابت و بررسی‌های `static_assert` کاربرد دارد.

### تضمین مربوط به استثناها

overload عددی با `noexcept` اعلان شده است و هیچ استثنایی پرتاب نمی‌کند.

overload اشاره‌گری در امضای استاندارد `noexcept` نیست، اما برای ورودی معتبر، عملیات عادی اشاره‌گری انجام می‌دهد و استثنای معمولی پرتاب نمی‌کند.

نبودن `noexcept` در امضای overload اشاره‌گری را نباید با تضمین رفتار برای ورودی نامعتبر اشتباه گرفت. نقض پیش‌شرط‌های اشاره‌گری ممکن است به Undefined Behavior منجر شود، نه الزاماً به پرتاب Exception.

## کاربردهای عملی در برنامه‌نویسی

### استفاده در جست‌وجوی دودویی

یکی از شناخته‌شده‌ترین کاربردهای محاسبهٔ نقطهٔ میانی، Binary Search است.

در پیاده‌سازی مبتنی بر اندیس، استفاده از `(low + high) / 2` ممکن است در صورت بزرگ بودن اندیس‌ها باعث سرریز شود.

جایگزین ایمن و خوانا، استفاده از `std::midpoint` است:

```
#include <numeric>
#include <vector>

int binarySearch(const std::vector<int>& values, int target) {
    std::size_t low = 0;
    std::size_t high = values.size();

    while (low < high) {
        const std::size_t middle = std::midpoint(low, high);

        if (values[middle] < target) {
            low = middle + 1;
        } else if (values[middle] > target) {
            high = middle;
        } else {
            return static_cast<int>(middle);
        }
    }

    return -1;
}
```

در این نمونه، بازه به شکل نیمه‌باز `[low, high)` تعریف شده است.

این طراحی باعث می‌شود مقدار `high` بتواند برابر `values.size()` باشد، بدون آن‌که درون حلقه به‌عنوان اندیس عنصر استفاده شود.

در پروژه‌های واقعی، نوع بازگشتی تابع بهتر است متناسب با اندازهٔ کانتینر انتخاب شود. استفاده از `int` در این مثال صرفاً برای ساده نگه داشتن نمونه است.

### پردازش بازه با اشاره‌گر

در کدهای سطح پایین یا الگوریتم‌هایی که از بازهٔ اشاره‌گری استفاده می‌کنند، overload اشاره‌گری می‌تواند عنصر میانی را بدون نوشتن تفریق دستی اشاره‌گرها به دست دهد.

بااین‌حال، در کد مدرن ++C معمولاً Iteratorها، `std::span` و الگوریتم‌های استاندارد بر مدیریت مستقیم اشاره‌گر ترجیح دارند. استفاده از اشاره‌گر باید با نیاز واقعی سطح پایین برنامه توجیه شود.

### کاربرد در الگوریتم‌های Divide and Conquer

در الگوریتم‌های Divide and Conquer، بازه‌ها به بخش‌های کوچک‌تر تقسیم می‌شوند.

استفاده از `std::midpoint` برای محاسبهٔ مرز تقسیم، از خطاهای ناشی از جمع دو کران جلوگیری می‌کند و هدف کد را نیز واضح‌تر نشان می‌دهد.

### کاربرد در محاسبات عددی و هندسی

در محاسباتی که نقطهٔ میانی دو مختصات یا دو مقدار عددی موردنیاز است، `std::midpoint` گزینه‌ای مناسب برای محاسبهٔ میانگین است.

بااین‌حال، این تابع جایگزین کامل عملیات Interpolation نیست. برای درون‌یابی بین دو مقدار با پارامتر دلخواه، قابلیت مرتبط `std::lerp` در ++C20 مناسب‌تر است.

## مقایسهٔ روش‌های محاسبهٔ نقطهٔ میانی

| روش                   | مزیت                                                                     | محدودیت                                                 |
| --------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------- |
| `(a + b) / 2`         | ساده و آشنا                                                              | احتمال سرریز در جمع                                     |
| `a + (b - a) / 2`     | در بسیاری از حالت‌ها از سرریز جمع جلوگیری می‌کند                         | احتمال سرریز تفریق؛ محدودیت `ptrdiff_t` برای اشاره‌گرها |
| `std::midpoint(a, b)` | تضمین استاندارد جلوگیری از سرریز در overload عددی و پشتیبانی از اشاره‌گر | فقط برای انواع و پیش‌شرط‌های مشخص تعریف شده است         |

در انتخاب روش مناسب، نباید صرفاً به این نکته توجه کرد که یک عبارت روی معماری و کامپایلر فعلی درست کار می‌کند.

تضمین‌های استاندارد و دامنهٔ ورودی‌های معتبر اهمیت بیشتری دارند.

## تفاوت میان `std::midpoint` و `std::lerp`

تابع `std::midpoint` نقطهٔ میانی دو مقدار را محاسبه می‌کند؛ یعنی حالت خاصی از Interpolation با پارامتر نصف را ارائه می‌دهد.

در مقابل، تابع `std::lerp(a, b, t)` برای محاسبهٔ درون‌یابی خطی با پارامتر `t` طراحی شده است.

```
#include <iostream>
#include <numeric>

int main() {
    const double a = 10.0;
    const double b = 30.0;

    std::cout << std::midpoint(a, b) << '\n';
    std::cout << std::lerp(a, b, 0.25) << '\n';
}
```

خروجی:

```
20
15
```

برای محاسبهٔ نقطهٔ میانی از `std::midpoint` استفاده کنید؛ برای درون‌یابی با ضریب دلخواه، `std::lerp` انتخاب مناسب‌تری است.

هر دو قابلیت در ++C20 به کتابخانهٔ استاندارد اضافه شده‌اند و در سرآیند `<numeric>` قرار دارند.

## نکات مهم و خطاهای رایج

- اهمیت ترتیب آرگومان‌ها: در محاسبات صحیح با مجموع فرد، گرد کردن به سمت آرگومان نخست انجام می‌شود؛ بنابراین `std::midpoint(a, b)` الزاماً با `std::midpoint(b, a)` برابر نیست.
- انتخاب آگاهانهٔ نوع ورودی: تابع نوع دو ورودی را به یک نوع مشترک تبدیل نمی‌کند. تبدیل ضمنی یا صریح پیش از فراخوانی می‌تواند دامنه و دقت محاسبه را تغییر دهد.
- محدودیت نوع `bool`: این نوع ورودی معتبر overload عددی نیست و در صورت نیاز باید به نوع عددی مناسب تبدیل شود.
- اعتبار اشاره‌گرها: استفاده از اشاره‌گرهای متعلق به دو آرایهٔ مستقل، پیش‌شرط تابع را نقض می‌کند.
- توجه به بازه‌های نیمه‌باز: اشاره‌گر میانی الزاماً همان عنصری نیست که یک الگوریتم با قرارداد متفاوت انتظار دارد. معنای اندیس‌ها و شرط توقف را دقیق مشخص کنید.
- محدودیت `constexpr`: این قابلیت به معنی امکان ارزیابی تمام ورودی‌ها در زمان کامپایل نیست؛ ورودی‌ها و عملیات باید شرایط Constant Expression را برآورده کنند.
- عدم جایگزینی کنترل محدوده: تابع `std::midpoint` از سرریز در محاسبهٔ میانه جلوگیری می‌کند، اما معتبر بودن اندیس‌ها، اندازهٔ کانتینر و دسترسی به عناصر همچنان مسئولیت برنامه‌نویس است.
- نبود overload عمومی برای انواع سفارشی: این تابع برای انواع Arithmetic به‌جز `bool` و اشاره‌گرهای واجد شرایط تعریف شده است. برای انواع عددی سفارشی باید عملیات متناظر را با قرارداد و تضمین‌های مناسب طراحی کنید.

## بررسی سازگاری و تشخیص پشتیبانی

قابلیت `std::midpoint` از ++C20 در کتابخانهٔ استاندارد معرفی شده است.

برای استفاده از آن، باید حالت ++C20 یا جدیدتر برای کامپایل فعال باشد و پیاده‌سازی Standard Library نیز این قابلیت را ارائه کند.

پشتیبانی زبان توسط کامپایلر و پشتیبانی کتابخانهٔ استاندارد دو موضوع مرتبط اما مجزا هستند. صرف فعال کردن گزینهٔ ++C20 در کامپایلر، در یک کتابخانهٔ قدیمی الزاماً وجود همهٔ امکانات کتابخانه را تضمین نمی‌کند.

ماکروی Feature-test مربوط به این قابلیت، `__cpp_lib_interpolate` است که مقدار آن `201902L` خواهد بود. این ماکرو برای قابلیت‌های Interpolation شامل `std::midpoint` و `std::lerp` تعریف شده است.

```
#include <numeric>

#if defined(__cpp_lib_interpolate) && __cpp_lib_interpolate >= 201902L
    // std::midpoint and std::lerp are available
#else
    #error "The standard library does not provide C++20 interpolation utilities"
#endif
```

برای استفاده از این ماکرو، سرآیند `<numeric>` را وارد کنید.

در سامانه‌های Build نیز بهتر است استاندارد زبان و نسخهٔ کتابخانهٔ استاندارد مورد استفاده به‌صورت مستقل بررسی شوند.
