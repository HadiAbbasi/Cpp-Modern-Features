# آموزش جامع `std::format` در ++C20

## معرفی قابلیت قالب‌بندی `std::format`

قابلیت `std::format` که در استاندارد ++C20 به کتابخانهٔ استاندارد اضافه شد، روشی مدرن، نوع‌آگاه (Type-safe) و توسعه‌پذیر برای تبدیل مقادیر به رشته‌های متنی فراهم می‌کند. این قابلیت با هدف ساده‌تر کردن ساخت رشته‌ها، بهبود خوانایی کد و کاهش خطاهای رایج در قالب‌بندی متن طراحی شده است.

پیش از معرفی این قابلیت، توسعه‌دهندگان معمولاً از روش‌هایی مانند `std::printf`، عملگر درج `operator<<` در جریان‌های ورودی و خروجی، یا کتابخانه‌های جانبی مانند `{fmt}` استفاده می‌کردند. هر یک از این روش‌ها مزایا و محدودیت‌های خود را دارند؛ برای مثال، `std::printf` به قالب‌های مبتنی بر رشته و تطبیق دستی نوع آرگومان‌ها وابسته است، در حالی که `std::ostringstream` برای ساخت رشته‌های پیچیده اغلب به کد طولانی و کم‌خوانا منجر می‌شود.

قابلیت `std::format` تلاش می‌کند مزایای قالب‌بندی مبتنی بر format string را با سیستم نوع‌دهی ++C ترکیب کند.

```
#include <format>
#include <iostream>
#include <string>

int main() {
    std::string name = "Alice";
    int age = 30;

    std::string message = std::format(
        "Name: {}, Age: {}",
        name,
        age
    );

    std::cout << message << '\n';
}
```

خروجی برنامه به شکل زیر است:

```
Name: Alice, Age: 30
```

در این مثال، آکولادهای `{}` محل قرارگیری آرگومان‌ها را مشخص می‌کنند. تابع `std::format` مقادیر را با توجه به نوع آن‌ها به متن تبدیل می‌کند و رشتهٔ نهایی را به‌صورت یک `std::string` برمی‌گرداند.

## اهداف و مزایای طراحی

قابلیت `std::format` صرفاً شکل کوتاه‌تری برای اتصال رشته‌ها نیست؛ بلکه یک سازوکار استاندارد برای کنترل نحوهٔ نمایش مقادیر ارائه می‌دهد.

مهم‌ترین مزایای این قابلیت عبارت‌اند از:

- ایمنی نوع (Type Safety): قالب‌بندی با نوع واقعی آرگومان‌ها سازگار است و بسیاری از خطاهای ناسازگاری نوع را در زمان کامپایل آشکار می‌کند.
- خوانایی بیشتر: قالب متن و مقادیر مورد استفاده در آن در یک عبارت مشخص قرار می‌گیرند.
- کنترل دقیق خروجی: امکان تعیین عرض، دقت، مبنای عددی، تراز، علامت و نحوهٔ نمایش اعداد وجود دارد.
- قابلیت توسعه: می‌توان برای انواع سفارشی، قالب‌بندی اختصاصی تعریف کرد.
- کاهش وابستگی به جریان‌های ورودی و خروجی: برای تولید رشته نیازی به ساخت یک `std::ostringstream` نیست.
- استانداردسازی: کد مبتنی بر این API در پیاده‌سازی‌های سازگار با استاندارد قابل استفاده است، هرچند پشتیبانی عملی کتابخانه‌ها ممکن است متفاوت باشد.

با وجود این مزایا، `std::format` جایگزین تمام امکانات `iostream`، سیستم‌های logging یا APIهای ورودی و خروجی نیست. انتخاب مناسب به نیاز برنامه بستگی دارد.

## پیش‌نیازها و پشتیبانی کامپایلر

قابلیت `std::format` بخشی از کتابخانهٔ استاندارد است که در ++C20 معرفی شده است. بنابراین، استفاده از آن به دو شرط وابسته است: فعال بودن استاندارد مناسب در کامپایلر و وجود پیاده‌سازی قابل استفاده از این بخش در کتابخانهٔ استاندارد.

برای نمونه، می‌توان از دستورات زیر استفاده کرد:

```
g++ -std=c++20 main.cpp -o app
```

```
clang++ -std=c++20 main.cpp -o app
```

```
cl /std:c++20 /EHsc main.cpp
```

این دستورات صرفاً استاندارد زبان را انتخاب می‌کنند و تضمین نمی‌کنند که نسخهٔ نصب‌شدهٔ کتابخانه تمام امکانات `std::format` را پیاده‌سازی کرده باشد.

پشتیبانی از این قابلیت در نسخه‌های مختلف GCC، Clang، MSVC، کتابخانهٔ `libstdc++` و کتابخانهٔ `libc++` متفاوت بوده است. به‌ویژه در نسخه‌های اولیهٔ پشتیبان ++C20، ممکن است برخی اجزای کتابخانه هنوز در دسترس نباشند.

برای بررسی وضعیت واقعی، بهتر است یک برنامهٔ آزمایشی کوچک با `#include <format>` و یک فراخوانی سادهٔ `std::format` کامپایل شود. در پروژه‌های بزرگ نیز باید نسخهٔ کامپایلر و کتابخانهٔ استاندارد در CI مشخص و آزمایش شود.

برای تشخیص قابلیت کتابخانه در زمان کامپایل، می‌توان از macro استاندارد `__cpp_lib_format` استفاده کرد. این macro در نسخه‌های مختلف استاندارد مقادیر متفاوتی دارد؛ مقدار `201907L` نشان‌دهندهٔ قابلیت پایهٔ معرفی‌شده در ++C20 است و مقادیر جدیدتر به اصلاحات و قابلیت‌های بعدی مربوط می‌شوند.&#x20;

```
#include <format>

#if defined(__cpp_lib_format) && __cpp_lib_format >= 201907L

```

این بررسی وجود قابلیت پایه را ارزیابی می‌کند و تضمین‌کنندهٔ پشتیبانی از تمام اصلاحات استاندارد نیست. در پروژه‌هایی که به امکانات خاص نسخه‌های جدید نیاز دارند، باید مقدار دقیق macro و قابلیت موردنظر بررسی شود.

## ساختار رشته‌های قالب‌بندی

### مفهوم Replacement Field

هر بخش از رشتهٔ قالب‌بندی که قرار است با مقدار یک آرگومان جایگزین شود، یک `replacement field` نام دارد. شکل پایهٔ این بخش به صورت `{}` است.

```
#include <format>
#include <iostream>

int main() {
    auto text = std::format(
        "{} scored {} points.",
        "Alice",
        95
    );

    std::cout << text << '\n';
}
```

خروجی برنامه به شکل زیر است:

```
Alice scored 95 points.
```

در این مثال، فیلد اول با آرگومان اول و فیلد دوم با آرگومان دوم جایگزین می‌شود. ترتیب جایگزینی به‌صورت پیش‌فرض از چپ به راست است و لازم نیست نوع آرگومان‌ها از قبل در رشته مشخص شود.

### مفهوم شناسهٔ آرگومان

برای تعیین صریح آرگومانی که باید در یک فیلد استفاده شود، می‌توان از شناسهٔ عددی آرگومان (Argument ID) استفاده کرد. شماره‌گذاری از صفر شروع می‌شود.

```
#include <format>
#include <iostream>

int main() {
    std::cout << std::format(
        "{1} is learning {0}.",
        "C++20",
        "Alice"
    ) << '\n';
}
```

خروجی برنامه به شکل زیر است:

```
Alice is learning C++20.
```

این روش زمانی مفید است که ترتیب نمایشی مقادیر با ترتیب طبیعی پارامترها یکسان نباشد یا یک آرگومان چند بار استفاده شود.

```
#include <format>
#include <iostream>

int main() {
    int value = 42;

    std::cout << std::format(
        "Decimal: {0}, Hex: {0:#x}, Octal: {0:#o}",
        value
    ) << '\n';
}
```

خروجی برنامه به شکل زیر است:

```
Decimal: 42, Hex: 0x2a, Octal: 052
```

در یک رشتهٔ قالب‌بندی، باید از یک روش مشخص برای شماره‌گذاری استفاده کرد. ترکیب فیلدهای خودکار مانند `{}` با فیلدهای دارای شناسه مانند `{0}` مجاز نیست و باعث خطای قالب‌بندی می‌شود.&#x20;

### نحوهٔ نمایش آکولادهای معمولی

از آنجا که آکولادها در رشتهٔ قالب‌بندی معنای ویژه دارند، برای نمایش یک آکولاد واقعی باید آن را escape کرد.

```
#include <format>
#include <iostream>

int main() {
    std::cout << std::format(
        "Configuration: {{\"enabled\": {}}}",
        true
    ) << '\n';
}
```

خروجی برنامه به شکل زیر است:

```
Configuration: {"enabled": true}
```

در این ساختار، `{{` به `{` و `}}` به `}` تبدیل می‌شود. استفاده از آکولاد تکی و نامعتبر می‌تواند موجب خطای کامپایل یا، در قالب‌های زمان اجرا، بروز استثنا شود.

## دستور زبان Format Specification

### ساختار کلی مشخصات قالب‌بندی

برای کنترل نحوهٔ نمایش مقدار، می‌توان بعد از شناسهٔ آرگومان از `:` و سپس یک `format specification` استفاده کرد.

ساختار کلی فیلد به شکل زیر است:

```
{arg-id:format-spec}
```

در این ساختار، `arg-id` اختیاری است و `format-spec` قواعد مخصوص نوع آرگومان را دنبال می‌کند. برای انواع پایه و رشته‌ها، قالب استاندارد معمولاً از اجزای زیر تشکیل می‌شود:

```
[[fill]align][sign]["#"]["0"][width]["." precision][type]
```

این نمایش خلاصه‌ای از دستور زبان است؛ ترتیب دقیق اجزا و معتبر بودن هر گزینه به نوع داده بستگی دارد.

| مؤلفه       | کاربرد                                                    |
| ----------- | --------------------------------------------------------- |
| `fill`      | تعیین کاراکتر پرکنندهٔ فضای خالی                          |
| `align`     | تعیین تراز چپ، راست یا مرکز                               |
| `sign`      | کنترل نمایش علامت عدد                                     |
| `#`         | فعال کردن نمایش جایگزین در قالب‌های پشتیبانی‌شده          |
| `0`         | استفاده از صفر برای پر کردن عرض عدد                       |
| `width`     | تعیین حداقل عرض خروجی                                     |
| `precision` | کنترل دقت یا تعداد کاراکترهای نمایش داده‌شده، بسته به نوع |
| `type`      | انتخاب قالب نمایش، مانند اعشاری، هگزادسیمال یا علمی       |

درک این اجزا باعث می‌شود بدون نوشتن منطق اضافی برای تبدیل و تراز رشته‌ها، خروجی‌های منظم تولید کنید.

### کاربرد تراز و عرض

برای تعیین حداقل عرض یک فیلد، می‌توان عددی را در مشخصات قالب‌بندی قرار داد. کاراکترهای پیش‌فرض برای پر کردن فضای خالی، معمولاً فاصله هستند.

```
#include <format>
#include <iostream>

int main() {
    std::cout << std::format("|{:10}|", "cat") << '\n';
    std::cout << std::format("|{:<10}|", "cat") << '\n';
    std::cout << std::format("|{:^10}|", "cat") << '\n';
    std::cout << std::format("|{:>10}|", "cat") << '\n';
}
```

خروجی برنامه به شکل زیر است:

```
|cat       |
|cat       |
|   cat    |
|       cat|
```

برای تراز می‌توان از `<` برای چپ، `>` برای راست و `^` برای مرکز استفاده کرد. در حالت پیش‌فرض، رشته‌ها معمولاً چپ‌چین و اعداد راست‌چین هستند.

توجه داشته باشید که `width` حداقل عرض فیلد است، نه حداکثر آن. اگر مقدار طولانی‌تر از عرض تعیین‌شده باشد، معمولاً کل مقدار نمایش داده می‌شود.

### کاربرد کاراکتر پرکننده

با تعیین یک کاراکتر پیش از علامت تراز، می‌توان فضای خالی را با کاراکتر دلخواه پر کرد.

```
#include <format>
#include <iostream>

int main() {
    std::cout << std::format("{:*^12}", "status") << '\n';
    std::cout << std::format("{:.>8}", 42) << '\n';
}
```

خروجی برنامه به شکل زیر است:

```
***status***
......42
```

در این مثال، `*` و `.` به‌ترتیب کاراکترهای پرکننده هستند. استفاده از این قابلیت برای ساخت گزارش‌های متنی، ستون‌های جدولی و خروجی‌های کنسولی مفید است.

### کاربرد نمایش علامت اعداد

برای کنترل علامت اعداد، می‌توان از گزینه‌های `+`، `-` و فاصله استفاده کرد.

```
#include <format>
#include <iostream>

int main() {
    std::cout << std::format("{:+d}", 42) << '\n';
    std::cout << std::format("{:+d}", -42) << '\n';
    std::cout << std::format("{: d}", 42) << '\n';
    std::cout << std::format("{: d}", -42) << '\n';
}
```

خروجی برنامه به شکل زیر است:

```
+42
-42
 42
-42
```

در اینجا، علامت `+` برای نمایش علامت مثبت و منفی هر دو عدد استفاده می‌شود. گزینهٔ فاصله، برای اعداد مثبت یک فاصله در نظر می‌گیرد، اما علامت منفی را حفظ می‌کند.

### کاربرد نمایش صفر در ابتدای عدد

برای پر کردن عرض عدد با صفر، می‌توان از گزینهٔ `0` استفاده کرد.

```
#include <format>
#include <iostream>

int main() {
    std::cout << std::format("{:08d}", 123) << '\n';
    std::cout << std::format("{:+08d}", 123) << '\n';
    std::cout << std::format("{:08d}", -123) << '\n';
}
```

خروجی برنامه به شکل زیر است:

```
00000123
+0000123
-0000123
```

صفرهای ابتدایی در این حالت بخشی از نمایش متنی هستند و نوع یا مقدار عدد را تغییر نمی‌دهند. در کاربردهایی مانند تولید شناسهٔ نمایشی یا شمارهٔ فاکتور می‌توان از این روش استفاده کرد، اما برای نمایش شناسه‌هایی که صفرهای ابتدایی در معنای آن‌ها اهمیت دارند، نگهداری داده به شکل رشته اغلب مناسب‌تر است.

### کاربرد مبناهای عددی

قابلیت `std::format` برای اعداد صحیح، نمایش در مبناهای مختلف را پشتیبانی می‌کند.

```
#include <format>
#include <iostream>

int main() {
    int value = 255;

    std::cout << std::format("Decimal: {:d}", value) << '\n';
    std::cout << std::format("Hex: {:x}", value) << '\n';
    std::cout << std::format("HEX: {:X}", value) << '\n';
    std::cout << std::format("Octal: {:o}", value) << '\n';
    std::cout << std::format("Binary: {:b}", value) << '\n';
    std::cout << std::format("Binary prefix: {:#b}", value) << '\n';
}
```

خروجی برنامه به شکل زیر است:

```
Decimal: 255
Hex: ff
HEX: FF
Octal: 377
Binary: 11111111
Binary prefix: 0b11111111
```

در این مثال، `d` نمایش ده‌دهی، `x` و `X` نمایش هگزادسیمال، `o` نمایش هشت‌هشتی و `b` نمایش دودویی را انتخاب می‌کنند. گزینهٔ `#` نیز در قالب‌های پشتیبانی‌شده پیشوند مناسب را اضافه می‌کند.

این قابلیت در توسعهٔ ابزارهای debugging، تحلیل bitmaskها، بررسی مقادیر رجیسترها و تولید گزارش‌های فنی مفید است.

### کاربرد دقت اعداد اعشاری

برای اعداد ممیز شناور، گزینهٔ `precision` امکان کنترل تعداد ارقام قابل نمایش را فراهم می‌کند. معنای دقیق دقت به نوع قالب‌بندی بستگی دارد.

```
#include <format>
#include <iostream>

int main() {
    double value = 3.141592653589793;

    std::cout << std::format("{:.2f}", value) << '\n';
    std::cout << std::format("{:.5f}", value) << '\n';
    std::cout << std::format("{:.4e}", value) << '\n';
    std::cout << std::format("{:.6g}", value) << '\n';
}
```

خروجی برنامه به شکل زیر است:

```
3.14
3.14159
3.1416e+00
3.14159
```

در این مثال، `f` قالب ثابت، `e` قالب علمی و `g` قالب عمومی را انتخاب می‌کند. در قالب عمومی، دقت معمولاً تعداد ارقام معنادار را کنترل می‌کند، نه تعداد ارقام بعد از ممیز.

نکتهٔ مهم این است که قالب‌بندی عدد با گرد کردن برای نمایش تفاوت دارد با گرد کردن و ذخیرهٔ مقدار در یک متغیر جدید. `std::format` مقدار اصلی را تغییر نمی‌دهد و رشتهٔ حاصل صرفاً نمایش متنی آن است.

### کاربرد اعداد بسیار کوچک و بزرگ

برای گزارش‌گیری علمی یا بررسی مقادیر با دامنهٔ بزرگ، قالب علمی خوانایی بیشتری ایجاد می‌کند.

```
#include <format>
#include <iostream>

int main() {
    double large = 123456789.0;
    double small = 0.0000012345;

    std::cout << std::format("{:e}", large) << '\n';
    std::cout << std::format("{:g}", large) << '\n';
    std::cout << std::format("{:g}", small) << '\n';
}
```

خروجی دقیق ممکن است بر اساس قالب انتخاب‌شده و مقدار دقت متفاوت باشد. برای قالب علمی، خروجی به‌صورت ضریب و توان ده نمایش داده می‌شود؛ قالب عمومی نیز بین نمایش ثابت و علمی بر اساس قواعد استاندارد انتخاب می‌کند.

### کاربرد نمایش مقدارهای Boolean

مقادیر `bool` در قالب‌بندی استاندارد به‌طور پیش‌فرض به شکل متنی `true` و `false` نمایش داده می‌شوند. با این حال، اگر مشخصات قالب‌بندی عددی مناسب انتخاب شود، می‌توان نمایش عددی آن‌ها را درخواست کرد.

```
#include <format>
#include <iostream>

int main() {
    bool enabled = true;

    std::cout << std::format("Enabled: {}", enabled) << '\n';
    std::cout << std::format("Numeric: {:d}", enabled) << '\n';
}
```

خروجی برنامه به شکل زیر است:

```
Enabled: true
Numeric: 1
```

این تفاوت در خروجی‌های configuration و logging اهمیت دارد. نمایش متنی برای خوانایی انسان و نمایش عددی برای قالب‌های سازگار با پروتکل‌ها یا داده‌های عددی مناسب‌تر است.

### نکات مربوط به رشته‌ها و precision

در قالب‌بندی رشته‌ها، می‌توان حداقل عرض و تعداد کاراکترهای خروجی را کنترل کرد.

```
#include <format>
#include <iostream>
#include <string>

int main() {
    std::string text = "modern C++ formatting";

    std::cout << std::format("{:.6}", text) << '\n';
    std::cout << std::format("{:>12.6}", text) << '\n';
}
```

خروجی برنامه به شکل زیر است:

```
modern
      modern
```

برای رشته‌ها، `precision` حداکثر تعداد واحدهای کاراکتری قابل نمایش را کنترل می‌کند؛ این موضوع با عرض حداقل تفاوت دارد.

در متن‌های Unicode، نباید فرض کرد که هر کاراکتر قابل مشاهده دقیقاً یک واحد از رشته است. به‌ویژه در UTF-8، یک نویسه ممکن است چند بایت داشته باشد و بعضی نویسه‌های ترکیبی نیز از چند code point ساخته می‌شوند. بنابراین، محدود کردن precision لزوماً به معنای محدود کردن تعداد نویسه‌های قابل مشاهده نیست.

## قالب‌بندی پویا و استفاده از آرگومان‌ها به‌عنوان پارامتر

### تعیین عرض و دقت با مقادیر متغیر

در بعضی کاربردها، عرض یا دقت خروجی از تنظیمات برنامه، ورودی کاربر یا محاسبات دیگر به دست می‌آید. برای این شرایط، می‌توان شناسهٔ آرگومان را داخل مشخصات قالب‌بندی قرار داد.

```
#include <format>
#include <iostream>

int main() {
    int width = 10;
    int precision = 3;
    double value = 3.14159265;

    std::cout << std::format(
        "{0:{1}.{2}f}",
        value,
        width,
        precision
    ) << '\n';
}
```

خروجی برنامه به شکل زیر است:

```
     3.142
```

در این مثال، آرگومان اول مقدار اصلی، آرگومان دوم عرض و آرگومان سوم دقت را مشخص می‌کند. این روش به شما اجازه می‌دهد ساختار رشته را ثابت نگه دارید و فقط پارامترهای نمایش را تغییر دهید.

نکتهٔ مهم این است که مقادیر پویای عرض و دقت نیز باید با قواعد نوعی و نحوی قالب‌بندی سازگار باشند. مقادیر منفی یا بسیار بزرگ ممکن است به خطا یا تخصیص حافظهٔ قابل توجه منجر شوند؛ بنابراین، در کدهای حساس باید محدودهٔ آن‌ها کنترل شود.

### تفاوت رشتهٔ قالب‌بندی ثابت و پویا

یکی از ویژگی‌های مهم `std::format`، بررسی رشتهٔ قالب‌بندی در زمان کامپایل است. در فراخوانی متداول، رشته باید با نوع `std::format_string` سازگار باشد؛ این سازوکار اجازه می‌دهد خطاهای بسیاری از رشته‌های ثابت پیش از اجرای برنامه شناسایی شوند.

```
#include <format>
#include <string>

int main() {
    int value = 42;

    std::string valid = std::format("Value: {}", value);

    // The following call has an invalid format specifier for an integer.
    // std::string invalid = std::format("{:s}", value);
}
```

در مثال بالا، مشخصهٔ `s` برای نمایش رشته است و با آرگومان عدد صحیح سازگار نیست. در پیاده‌سازی‌های منطبق با بررسی زمان کامپایل، چنین فراخوانی‌ای باید با تشخیص خطا مواجه شود.

در مقابل، گاهی رشتهٔ قالب‌بندی در زمان کامپایل معلوم نیست؛ برای مثال، ممکن است از یک فایل پیکربندی بارگذاری شود. در چنین شرایطی باید از رابط‌های مخصوص قالب‌بندی پویا استفاده کرد.

### کاربرد `std::vformat` برای قالب‌های زمان اجرا

تابع `std::vformat` نسخه‌ای از سازوکار قالب‌بندی است که به‌جای دریافت مستقیم بستهٔ آرگومان‌های نوع‌دار در قالب یک template، از آرگومان‌های type-erased استفاده می‌کند.

```
#include <format>
#include <iostream>
#include <string>

int main() {
    std::string pattern = "User: {}, Score: {:.1f}";
    std::string result = std::vformat(
        pattern,
        std::make_format_args("Alice", 98.5)
    );

    std::cout << result << '\n';
}
```

خروجی برنامه به شکل زیر است:

```
User: Alice, Score: 98.5
```

در این مثال، `pattern` یک رشتهٔ معمولی است که در زمان اجرا در دسترس قرار دارد. تابع `std::make_format_args` یک بستهٔ آرگومان برای استفاده در قالب‌بندی ایجاد می‌کند.

باید توجه داشت که `std::make_format_args` معمولاً ارجاع‌هایی به آرگومان‌ها نگه می‌دارد، نه نسخه‌هایی مستقل و مالک آن‌ها. بنابراین، بستهٔ آرگومان‌ها را نباید به شکلی ذخیره یا منتقل کرد که طول عمر مقادیر اصلی از آن کوتاه‌تر باشد.

### مدیریت خطاهای قالب‌بندی پویا

در قالب‌های زمان اجرا، خطاهایی مانند آکولاد نامعتبر، تعداد نامناسب آرگومان‌ها یا مشخصهٔ ناسازگار با نوع داده ممکن است هنگام اجرای برنامه آشکار شوند.

```
#include <format>
#include <iostream>
#include <string>

int main() {
    std::string pattern = "Value: {:s}";

    try {
        std::string result = std::vformat(
            pattern,
            std::make_format_args(42)
        );

        std::cout << result << '\n';
    } catch (const std::format_error& error) {
        std::cerr << "Formatting error: " << error.what() << '\n';
    }
}
```

در این مثال، مشخصهٔ `s` با نوع آرگومان صحیح سازگار نیست؛ بنابراین قالب‌بندی با خطا مواجه می‌شود.

برای کدهایی که قالب از بیرون برنامه دریافت می‌شود، بهتر است خطاهای قالب‌بندی در مرز مناسب برنامه مدیریت شوند. با این حال، نباید همهٔ استثناها را به `std::format_error` محدود کرد؛ برای نمونه، شکست تخصیص حافظه ممکن است `std::bad_alloc` ایجاد کند.

### تغییرات استاندارد در قالب‌های پویا

در نسخهٔ پایهٔ ++C20، تابع `std::format` برای قالب‌های معمولی از بررسی زمان کامپایل استفاده می‌کند و `std::vformat` برای قالب‌های زمان اجرا مناسب است.

در ++C26، قابلیت `std::runtime_format` معرفی شده است تا بتوان یک رشتهٔ زمان اجرا را مستقیماً به رابط‌های معمول قالب‌بندی منتقل کرد. این قابلیت در پیاده‌سازی‌های پشتیبان در بسیاری از موارد جایگزین ساده‌تری برای استفادهٔ مستقیم از `std::vformat` خواهد بود.

```
#include <format>
#include <iostream>
#include <string>

int main() {
    std::string pattern = "Value: {}";

    std::cout << std::format(
        std::runtime_format(pattern),
        42
    ) << '\n';
}
```

این نمونه به ++C26 و کتابخانه‌ای با پشتیبانی از `std::runtime_format` نیاز دارد؛ نباید آن را به‌عنوان کدی قابل کامپایل با همهٔ پیاده‌سازی‌های ++C20 در نظر گرفت.

### تولید رشته با `std::format`

تابع `std::format` یک رشتهٔ جدید تولید می‌کند و آن را برمی‌گرداند.

```
#include <format>
#include <string>

int main() {
    std::string message = std::format(
        "Request {} completed in {} ms",
        17,
        24.5
    );
}
```

این روش برای ساخت پیام، تولید متن خروجی، ایجاد کلیدهای نمایشی و آماده‌سازی داده برای لایه‌های دیگر برنامه مناسب است.

### نوشتن مستقیم با `std::format_to`

تابع `std::format_to` خروجی قالب‌بندی را از طریق یک `output iterator` می‌نویسد و یک رشتهٔ جدید به‌صورت خودکار برنمی‌گرداند.

```
#include <format>
#include <iterator>
#include <iostream>
#include <string>

int main() {
    std::string output;
    output.reserve(128);

    auto it = std::format_to(
        std::back_inserter(output),
        "ID={:04}, Name={}",
        23,
        "Alice"
    );

    std::cout << output << '\n';
}
```

خروجی برنامه به شکل زیر است:

```
ID=0023, Name=Alice
```

در این مثال، `std::back_inserter` امکان افزودن کاراکترها به انتهای رشته را فراهم می‌کند. فراخوانی `reserve` نیز ظرفیت اولیه را افزایش می‌دهد تا در صورت مناسب بودن اندازه، تعداد تخصیص‌های حافظه کاهش یابد.

مقدار بازگشتی `std::format_to`، iterator قرارگرفته بعد از آخرین کاراکتر نوشته‌شده است. این تابع برای نوشتن در bufferها یا ترکیب چند بخش متنی در یک خروجی مشترک مفید است.

### محدود کردن خروجی با `std::format_to_n`

تابع `std::format_to_n` برای زمانی طراحی شده است که می‌خواهید حداکثر تعداد مشخصی کاراکتر در مقصد نوشته شود.

```
#include <format>
#include <iostream>
#include <iterator>
#include <string>

int main() {
    std::string output;

    auto result = std::format_to_n(
        std::back_inserter(output),
        5,
        "Hello, {}!",
        "world"
    );

    std::cout << output << '\n';
    std::cout << result.size << '\n';
}
```

خروجی برنامه به شکل زیر است:

```
Hello
13
```

در این مثال، تنها پنج کاراکتر نخست نوشته می‌شود، اما `result.size` تعداد کل کاراکترهایی را نشان می‌دهد که در صورت نبود محدودیت تولید می‌شدند.

این تفاوت برای محاسبهٔ اندازهٔ موردنیاز و مدیریت bufferها مهم است. البته `std::format_to_n` به‌تنهایی رشته را در یک مقصد از پیش تخصیص‌یافته و محدود قرار نمی‌دهد؛ iterator مقصد باید رفتار مناسب خود را داشته باشد.

### محاسبهٔ اندازه با `std::formatted_size`

تابع `std::formatted_size` تعداد کاراکترهای موردنیاز برای تولید خروجی قالب‌بندی‌شده را محاسبه می‌کند.

```
#include <format>
#include <iostream>

int main() {
    auto size = std::formatted_size(
        "Name={}, ID={:06}",
        "Alice",
        42
    );

    std::cout << size << '\n';
}
```

خروجی برنامه به شکل زیر است:

```
18
```

این تابع زمانی مفید است که اندازهٔ خروجی باید پیش از نوشتن مشخص شود. در صورت استفاده از آن همراه با قالب‌بندی مجدد، باید هزینهٔ محاسبهٔ دوباره را نیز در نظر گرفت؛ به‌ویژه اگر formatter سفارشی محاسبات پرهزینه انجام دهد.

### مقایسهٔ کاربرد توابع اصلی

| تابع                  | کاربرد اصلی                                           | نوع خروجی                       |
| --------------------- | ----------------------------------------------------- | ------------------------------- |
| `std::format`         | تولید رشتهٔ جدید                                      | `std::string` یا `std::wstring` |
| `std::format_to`      | نوشتن در iterator مقصد                                | iterator انتهایی                |
| `std::format_to_n`    | نوشتن با محدودیت تعداد کاراکتر                        | iterator و اندازهٔ کامل خروجی   |
| `std::formatted_size` | محاسبهٔ اندازهٔ خروجی                                 | اندازهٔ عددی                    |
| `std::vformat`        | قالب‌بندی با آرگومان‌های type-erased و قالب زمان اجرا | `std::string` یا `std::wstring` |
| `std::vformat_to`     | قالب‌بندی پویا در iterator مقصد                       | iterator انتهایی                |

انتخاب تابع مناسب به این بستگی دارد که آیا به یک رشتهٔ مستقل نیاز دارید، آیا مقصد از قبل مشخص است و آیا محدودیت حافظه یا اندازهٔ خروجی اهمیت دارد.

## پشتیبانی از Locale و قالب‌بندی محلی

### مفهوم Locale در قالب‌بندی

در بسیاری از برنامه‌ها، نمایش اعداد و مقادیر وابسته به زبان یا منطقه است. برای مثال، جداکنندهٔ گروه‌های عددی و شیوهٔ نمایش اعشار در Localeهای مختلف می‌تواند متفاوت باشد.

تابع `std::format` به‌صورت پیش‌فرض از قالب‌بندی locale-specific استفاده نمی‌کند. اگر بخواهید قواعد یک `std::locale` مشخص در قالب‌بندی دخالت کنند، می‌توانید Locale را به‌عنوان آرگومان جداگانه ارائه دهید.

```
#include <format>
#include <iostream>
#include <locale>

int main() {
    std::locale loc("");

    std::cout << std::format(
        loc,
        "{:L}",
        1234567.89
    ) << '\n';
}
```

در این مثال، `std::locale("")` تلاش می‌کند Locale محیط را انتخاب کند و گزینهٔ `L` قالب‌بندی محلی را برای نوع مربوط فعال می‌کند.

خروجی دقیق به Locale موجود در محیط، تنظیمات سیستم و پشتیبانی کتابخانه بستگی دارد. برای جلوگیری از وابستگی ناخواسته به محیط اجرا، بهتر است Locale موردنیاز را به‌صورت صریح انتخاب کنید.

### محدودیت‌های Locale

قالب‌بندی محلی برای گزارش‌های مالی، برنامه‌های دسکتاپ و خروجی‌هایی که برای کاربران منطقه‌ای تولید می‌شوند مفید است؛ اما برای داده‌های machine-readable مانند پروتکل‌های شبکه، فایل‌های پیکربندی یا قالب‌های ذخیره‌سازی باید محتاط بود.

در چنین مواردی، تغییر جداکننده‌ها یا قواعد عددی ممکن است باعث ناسازگاری با مصرف‌کنندهٔ داده شود. همچنین، `std::format` به‌تنهایی یک سیستم کامل برای ترجمهٔ پیام‌ها یا مدیریت متن‌های چندزبانه نیست.

## قالب‌بندی نوع‌های سفارشی با `std::formatter`

### دلیل استفاده از Formatter سفارشی

در یک برنامهٔ حرفه‌ای، داده‌ها همیشه از نوع‌های پایه مانند `int` و `double` نیستند. ممکن است نوع‌هایی مانند `Point`، `User`، `Version` یا `ErrorCode` تعریف شده باشند و لازم باشد نمایش متنی مشخصی داشته باشند.

برای این منظور، کتابخانهٔ استاندارد امکان تخصصی‌سازی قالب `std::formatter` را فراهم می‌کند. این سازوکار اجازه می‌دهد نوع سفارشی با `std::format` سازگار شود، بدون اینکه منطق تبدیل رشته در همهٔ نقاط برنامه تکرار شود.

### پیاده‌سازی Formatter برای یک نوع ساده

در مثال زیر، نوع `Point` دارای دو مختصات است و formatter سفارشی آن را به شکل `(x, y)` نمایش می‌دهد.

```
#include <format>
#include <iostream>

struct Point {
    int x;
    int y;
};

template <>
struct std::formatter<Point> : std::formatter<int> {
    auto format(const Point& point, std::format_context& ctx) const {
        return std::format_to(
            ctx.out(),
            "({}, {})",
            point.x,
            point.y
        );
    }
};

int main() {
    Point point{10, 20};

    std::cout << std::format("Position: {}", point) << '\n';
}
```

خروجی برنامه به شکل زیر است:

```
Position: (10, 20)
```

در این پیاده‌سازی، `std::formatter<Point>` از formatter عدد صحیح ارث‌بری می‌کند. این کار برای نمونه‌ای که از مشخصه‌های عدد صحیح استفاده نمی‌کند، صرفاً راهی برای فراهم کردن یک پیاده‌سازی ساده از `parse` است.

تابع `format` مسئول نوشتن نمایش نهایی در خروجی است و `ctx.out()` iterator خروجی را فراهم می‌کند.

نکتهٔ طراحی مهم این است که formatter سفارشی باید قراردادهای کتابخانه را رعایت کند. اگر formatter قرار است گزینه‌های قالب‌بندی اختصاصی مانند `{:#}` یا `{:x}` را بپذیرد، باید parser و رفتار آن گزینه‌ها را نیز به‌درستی پیاده‌سازی کند؛ صرف ارث‌بری از formatter یک نوع دیگر، بدون طراحی آگاهانه، به معنای پشتیبانی صحیح از همهٔ مشخصه‌ها نیست.

### پیاده‌سازی Parser برای گزینه‌های سفارشی

برای نمونه، می‌توان formatterای تعریف کرد که نمایش یک نوع `Point` را در دو حالت عادی و فشرده پشتیبانی کند. در این مثال، گزینهٔ `s` برای نمایش فشرده استفاده می‌شود.

```
#include <format>
#include <iostream>

struct Point {
    int x;
    int y;
};

template <>
struct std::formatter<Point> {
    bool compact = false;

    constexpr auto parse(std::format_parse_context& ctx) {
        auto it = ctx.begin();
        auto end = ctx.end();

        if (it != end && *it == 's') {
            compact = true;
            ++it;
        }

        if (it != end && *it != '}') {
            throw std::format_error("Invalid Point format");
        }

        return it;
    }

    auto format(const Point& point, std::format_context& ctx) const {
        if (compact) {
            return std::format_to(
                ctx.out(),
                "{},{}",
                point.x,
                point.y
            );
        }

        return std::format_to(
            ctx.out(),
            "Point({}, {})",
            point.x,
            point.y
        );
    }
};

int main() {
    Point point{10, 20};

    std::cout << std::format("{}\n", point);
    std::cout << std::format("{:s}\n", point);
}
```

خروجی برنامه به شکل زیر است:

```
Point(10, 20)
10,20
```

در این مثال، تابع `parse` مشخصهٔ قالب‌بندی را بررسی می‌کند و در صورت مشاهدهٔ گزینهٔ `s` حالت فشرده را فعال می‌سازد. تابع `format` سپس بر اساس این حالت، خروجی مناسب را تولید می‌کند.

این الگو برای نوع‌هایی که چند نمایش متنی معتبر دارند مفید است؛ برای مثال، نمایش عادی یک مسیر، نمایش فشردهٔ یک شناسه یا قالب متفاوت یک نوع داده در logها.

### نکات طراحی Formatter سفارشی

هنگام پیاده‌سازی formatter باید چند نکته را در نظر گرفت:

- قواعد Parser: تابع `parse` باید محل پایان مشخصات را به‌درستی تشخیص دهد و ورودی نامعتبر را رد کند.
- رفتار ثابت: خروجی باید به وضعیت داخلی یا mutable پنهان وابسته نباشد، مگر اینکه چنین رفتاری آگاهانه طراحی شده باشد.
- ایمنی نوع: formatter نباید نوع داده را به‌شکلی نامعتبر تفسیر کند یا فرض‌های نادرست دربارهٔ محدودهٔ مقادیر داشته باشد.
- هزینهٔ اجرا: ساخت رشته‌های میانی غیرضروری را کاهش دهید و در صورت امکان مستقیماً به iterator خروجی بنویسید.
- قرارداد مشخصه‌ها: هر گزینه‌ای که پشتیبانی می‌شود باید رفتار مستند و آزمون‌پذیر داشته باشد.

برای انواعی که در یک API عمومی یا کتابخانهٔ مشترک استفاده می‌شوند، formatter سفارشی می‌تواند بخشی از قرارداد نمایش نوع باشد؛ به همین دلیل، تغییر قالب خروجی آن ممکن است روی تست‌ها، logها و ابزارهای وابسته تأثیر بگذارد.

## پشتیبانی از انواع استاندارد و قابلیت‌های نسخه‌های جدید

### قالب‌بندی تاریخ و زمان با `<chrono>`

از امکانات مهم ++C20، پشتیبانی از قالب‌بندی بسیاری از انواع زمان در کتابخانهٔ `<chrono>` است. این قابلیت اجازه می‌دهد مقادیر زمانی بدون تبدیل‌های دستی و متعدد به رشته تبدیل شوند.

```
#include <chrono>
#include <format>
#include <iostream>

int main() {
    using namespace std::chrono;

    year_month_day date = 2026y / October / 28d;
    sys_time<milliseconds> timestamp{
        sys_days{date}.time_since_epoch()
    };

    std::cout << std::format(
        "{:%Y-%m-%d}",
        date
    ) << '\n';

    std::cout << std::format(
        "{:%Y-%m-%d %H:%M:%S}",
        timestamp
    ) << '\n';
}
```

خروجی برنامه به شکل زیر است:

```
2026-10-28
2026-10-28 00:00:00
```

در این مثال، `%Y` سال، `%m` ماه، `%d` روز، `%H` ساعت، `%M` دقیقه و `%S` ثانیه را مشخص می‌کنند.

نکتهٔ مهم این است که قالب‌بندی زمان با تفسیر منطقهٔ زمانی یکسان نیست. یک `sys_time` زمان را بر اساس ساعت سیستم (Unix time) نمایش می‌دهد و برای نمایش زمان محلی یا زمان یک منطقهٔ زمانی مشخص باید تبدیل مناسب انجام شود.

پشتیبانی دقیق از انواع زمانی و برخی مشخصه‌های پیشرفته به نسخهٔ کتابخانهٔ استاندارد وابسته است؛ بنابراین، برای کدهای قابل‌حمل باید نسخهٔ هدف کامپایلر و کتابخانه بررسی شود.

### قالب‌بندی مجموعه‌ها در ++C23

استاندارد ++C23 پشتیبانی قالب‌بندی از مجموعه‌ای از انواع استاندارد مانند برخی Rangeها، `std::pair` و `std::tuple` را گسترش داده است. این قابلیت در کتابخانه‌های دارای پشتیبانی مناسب اجازه می‌دهد برخی داده‌های مرکب مستقیماً قالب‌بندی شوند.

```
#include <format>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> values{10, 20, 30};

    std::cout << std::format("Values: {}", values) << '\n';
}
```

این مثال به پیاده‌سازی پشتیبان از قالب‌بندی Rangeها در ++C23 نیاز دارد. در ++C20، نباید فرض کرد که `std::vector` به‌صورت مستقیم قابل قالب‌بندی است.

برای سازگاری با ++C20، می‌توان مجموعه را به‌صورت دستی پیمایش کرد و عناصر را با `std::format_to` به خروجی افزود. این روش همچنین کنترل بیشتری روی جداکننده‌ها، قالب عناصر و نحوهٔ نمایش مجموعه فراهم می‌کند.

### تفاوت قابلیت‌های ++C20، ++C23 و ++C26

قابلیت `std::format` در نسخه‌های بعدی استاندارد تکامل یافته است؛ به همین دلیل، دانستن نسخهٔ معرفی هر قابلیت برای توسعهٔ کتابخانه‌های قابل‌حمل اهمیت دارد.

| استاندارد | قابلیت‌های مرتبط                                                                                             |
| --------- | ------------------------------------------------------------------------------------------------------------ |
| ++C20     | توابع پایهٔ قالب‌بندی، `std::formatter`، قالب‌بندی نوع‌های پایه، `std::vformat` و توابع نوشتن در iterator    |
| ++C23     | اصلاحات قالب‌بندی، بهبود بررسی رشته‌های قالب‌بندی و پشتیبانی از انواع مرکب و Rangeها در پیاده‌سازی‌های مربوط |
| ++C26     | معرفی `std::runtime_format` و گسترش امکانات مرتبط با قالب‌بندی در کتابخانهٔ استاندارد                        |

وجود یک قابلیت در متن استاندارد به این معنا نیست که همهٔ نسخه‌های قدیمی کامپایلرها آن را پیاده‌سازی کرده‌اند. به همین دلیل، برای پروژه‌های چندسکویی باید علاوه بر انتخاب استاندارد زبان، امکانات واقعی کتابخانه نیز آزمایش شوند.&#x20;

## مدیریت خطاها و ملاحظات ایمنی

### انواع خطاهای قالب‌بندی

قالب‌بندی ممکن است به دلایل مختلفی شکست بخورد. مهم‌ترین حالت‌ها عبارت‌اند از:

- خطای زمان کامپایل: رشتهٔ ثابت با نوع آرگومان یا دستور زبان قالب‌بندی سازگار نیست.
- خطای زمان اجرا: رشتهٔ پویای قالب‌بندی معتبر نیست یا مشخصه‌ای نامناسب دارد.
- خطای تخصیص حافظه: حافظهٔ موردنیاز برای ساخت خروجی در دسترس نیست.
- خطای formatter سفارشی: پیاده‌سازی formatter ممکن است در صورت مواجهه با داده یا وضعیت نامعتبر استثنا ایجاد کند.

در فراخوانی‌های عادی `std::format`، رشته‌های قالب‌بندی ثابت می‌توانند پیش از اجرای برنامه بررسی شوند. این مزیت باعث کاهش بسیاری از خطاهای رایج می‌شود، اما به معنای حذف تمام خطاهای زمان اجرا نیست.

### خطرات استفاده از رشتهٔ قالب‌بندی غیرقابل‌اعتماد

رشتهٔ قالب‌بندی فقط یک متن معمولی نیست؛ بلکه می‌تواند ساختار قالب‌بندی را کنترل کند. بنابراین، اگر کاربر یا منبع خارجی اجازه داشته باشد قالب دلخواه خود را وارد کند، باید رفتار آن را به‌دقت مدیریت کرد.

برای نمونه، قالب نامعتبر می‌تواند باعث استثنا شود و عرض یا دقت بسیار بزرگ می‌تواند مصرف منابع را افزایش دهد. در یک سرویس عمومی، این موضوع ممکن است به اختلال عملکرد یا مصرف غیرضروری حافظه منجر شود.

توصیه‌های عملی عبارت‌اند از:

- اعتبارسنجی ورودی: قالب‌های دریافتی از منابع خارجی را معتبر و محدود نگه دارید.
- محدود کردن منابع: عرض و دقت پویای قابل‌استفاده را به محدوده‌های منطقی محدود کنید.
- مدیریت استثناها: خطاهای قابل‌انتظار قالب‌بندی را در مرز مناسب برنامه مدیریت کنید.
- جدا کردن داده از قالب: اگر هدف صرفاً نمایش ورودی کاربر است، آن ورودی را به‌عنوان آرگومان قرار دهید، نه به‌عنوان رشتهٔ قالب‌بندی.

برای مثال، روش زیر از نظر طراحی مناسب‌تر است:

```
#include <format>
#include <iostream>
#include <string>

int main() {
    std::string user_input = "User supplied text: {}";

    std::cout << std::format(
        "Input: {}",
        user_input
    ) << '\n';
}
```

در این کد، آکولادهای داخل ورودی کاربر به‌عنوان دستور قالب‌بندی تفسیر نمی‌شوند؛ زیرا ورودی کاربر یک آرگومان معمولی است. این الگو احتمال خطاهای ناشی از اشتباه گرفتن داده و قالب را کاهش می‌دهد.

### تفاوت قالب‌بندی با Escape کردن برای HTML و SQL

قابلیت `std::format` به‌خودی‌خود داده‌ها را برای HTML، SQL، JSON یا shell ایمن نمی‌کند. این تابع صرفاً رشته را بر اساس قواعد قالب‌بندی تولید می‌کند.

برای مثال، قرار دادن دادهٔ ورودی کاربر در یک رشتهٔ SQL با استفاده از `std::format`، جایگزین parameterized query نیست. به همین ترتیب، تولید HTML یا JSON نیازمند رعایت قواعد escaping و encoding مربوط به آن قالب است.

در نتیجه، `std::format` باید برای ساخت رشته‌های متنی عمومی استفاده شود؛ اما برای تولید خروجی‌های دارای قواعد امنیتی یا ساختاری مشخص، باید از ابزار و API مناسب همان قالب استفاده کرد.

## مقایسه با روش‌های دیگر ساخت رشته

### مقایسه با `std::printf`

روش `std::printf` از قالب‌هایی مانند `%d`، `%s` و `%f` استفاده می‌کند. این API قدیمی همچنان برای برخی رابط‌های C، کتابخانه‌های موجود و برنامه‌هایی که باید با کد C تعامل کنند مفید است.

```
#include <cstdio>

int main() {
    int id = 42;
    double score = 98.5;

    std::printf("ID: %d, Score: %.1f\n", id, score);
}
```

در مقابل، روش `std::format` نوع آرگومان‌ها را از خود مقادیر استنباط می‌کند و در بسیاری از موارد بررسی ناسازگاری‌ها را در زمان کامپایل انجام می‌دهد.

```
#include <format>
#include <iostream>

int main() {
    int id = 42;
    double score = 98.5;

    std::cout << std::format(
        "ID: {}, Score: {:.1f}\n",
        id,
        score
    );
}
```

برای کدهای جدید ++C، استفاده از `std::format` معمولاً انتخاب مناسبی برای ساخت رشته است. با این حال، `std::printf` همچنان در برخی محیط‌های محدود، رابط‌های سازگار با C و کدهای قدیمی کاربرد دارد.

### مقایسه با `std::ostringstream`

روش `std::ostringstream` از سیستم جریان‌های ورودی و خروجی برای ساخت رشته استفاده می‌کند. این روش انعطاف‌پذیر است و از انواع زیادی که عملگر درج مناسب دارند پشتیبانی می‌کند.

```
#include <iomanip>
#include <iostream>
#include <sstream>
#include <string>

int main() {
    std::ostringstream stream;

    stream << "Value: "
           << std::fixed
           << std::setprecision(2)
           << 3.14159;

    std::string result = stream.str();

    std::cout << result << '\n';
}
```

در مقابل، معادل این کد با `std::format` کوتاه‌تر و معمولاً خواناتر است:

```
#include <format>
#include <iostream>

int main() {
    std::cout << std::format(
        "Value: {:.2f}",
        3.14159
    ) << '\n';
}
```

با این حال، `std::ostringstream` برای کدهایی که از قبل به manipulators، جریان‌ها یا عملگرهای درج سفارشی وابسته‌اند، همچنان مفید است. همچنین، نباید فرض کرد که `std::format` در تمام شرایط سریع‌تر از جریان‌هاست؛ عملکرد به نوع داده، پیاده‌سازی و الگوی استفاده بستگی دارد.

### مقایسه با کتابخانهٔ `{fmt}`

کتابخانهٔ `{fmt}` یکی از منابع مهم طراحی قابلیت قالب‌بندی استاندارد ++C بوده است و همچنان امکانات کاربردی خود را دارد. رابط‌های اصلی آن شباهت زیادی به `std::format` دارند.

مزیت `std::format` این است که بخشی از کتابخانهٔ استاندارد است و برای استفاده از قابلیت‌های پایه نیازی به وابستگی خارجی ندارد. از طرف دیگر، `{fmt}` می‌تواند برای پروژه‌هایی که به قابلیت‌های خاص آن یا پشتیبانی از محیط‌های قدیمی‌تر نیاز دارند، انتخاب مناسبی باشد.

برای انتخاب بین این دو، باید به موارد زیر توجه کرد:

- سازگاری: آیا نسخهٔ کتابخانهٔ استاندارد محیط هدف، امکانات موردنیاز را پشتیبانی می‌کند؟
- قابلیت‌ها: آیا پروژه به امکاناتی نیاز دارد که فقط در نسخه یا کتابخانهٔ خاصی موجود است؟
- وابستگی‌ها: آیا افزودن یک کتابخانهٔ خارجی برای پروژه قابل‌قبول است؟
- عملکرد: آیا اندازه‌گیری واقعی نشان می‌دهد یکی از گزینه‌ها برای بار کاری موردنظر مناسب‌تر است؟

## نکات عملکرد و بهینه‌سازی

### کاهش تخصیص حافظه

تابع `std::format` یک رشتهٔ جدید تولید می‌کند؛ بنابراین، در کاربردهایی که حجم زیادی از رشته‌ها به‌صورت مکرر ساخته می‌شوند، هزینهٔ تخصیص حافظه ممکن است مهم باشد.

برای کنترل بهتر حافظه می‌توان از `std::format_to` همراه با یک buffer قابل استفادهٔ مجدد بهره گرفت. با این حال، استفاده از iterator مناسب و مدیریت صحیح ظرفیت مقصد ضروری است.

### پرهیز از ساخت رشته‌های میانی

در حلقه‌هایی که داده‌های زیادی را قالب‌بندی می‌کنند، بهتر است در صورت نیاز چند بخش متن مستقیماً به مقصد مشترک نوشته شوند، به‌جای اینکه ابتدا چند رشتهٔ مستقل ساخته و سپس به یکدیگر متصل شوند.

این تصمیم باید بر اساس اندازه‌گیری انجام شود؛ زیرا ساده‌سازی زودهنگام کد ممکن است خوانایی را کاهش دهد بدون اینکه بهبود عملکرد معناداری ایجاد کند.

### استفاده از Benchmark

برای مقایسهٔ `std::format`، `std::printf`، `std::ostringstream` و `{fmt}` باید شرایط آزمایش یکسان باشد. عواملی مانند نسخهٔ کامپایلر، کتابخانهٔ استاندارد، بهینه‌سازی‌ها، تعداد تخصیص‌ها و اندازهٔ خروجی بر نتیجه تأثیر دارند.

در نتیجه، هیچ‌یک از این روش‌ها را نباید بدون Benchmark مناسب، به‌صورت مطلق سریع‌ترین گزینه دانست.

## اشتباهات رایج در استفاده از `std::format`

### ناسازگاری مشخصه با نوع داده

استفاده از مشخصهٔ قالب‌بندی نامناسب برای نوع آرگومان می‌تواند به خطای کامپایل یا خطای زمان اجرا منجر شود. برای مثال، مشخصهٔ `x` برای نمایش هگزادسیمال عدد صحیح مناسب است، اما نباید آن را به‌طور خودکار برای همهٔ انواع داده معتبر دانست.

### ترکیب شماره‌گذاری خودکار و دستی

ترکیب `{}` با `{0}` در یک رشتهٔ قالب‌بندی مجاز نیست. برای جلوگیری از این خطا، بهتر است در هر رشته یک روش شماره‌گذاری انتخاب شود.

### فرض پشتیبانی کامل از ++C20

صرف استفاده از `-std=c++20` تضمین نمی‌کند که همهٔ اجزای `std::format` در کتابخانهٔ نصب‌شده در دسترس باشند. برای قابلیت‌های جدیدتر نیز باید استاندارد مناسب و پشتیبانی واقعی کتابخانه بررسی شود.

### اشتباه گرفتن دقت با تغییر مقدار

تنظیم precision، مقدار عددی اصلی را تغییر نمی‌دهد. اگر قرار است نتیجهٔ محاسباتی گرد شود و در متغیر ذخیره شود، باید این کار جداگانه انجام گیرد.

### استفاده از قالب‌بندی برای جایگزینی Serialization

ساخت رشته با `std::format` به معنای تولید JSON معتبر، پیام شبکه‌ای معتبر یا دادهٔ قابل‌ذخیره با قرارداد مشخص نیست. برای چنین اهدافی باید قواعد فرمت موردنظر رعایت شوند.
