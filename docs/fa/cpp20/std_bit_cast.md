# راهنمای جامع `std::bit_cast` در ++C20

## مقدمه

قابلیت `std::bit_cast` یکی از امکانات مهم کتابخانهٔ استاندارد ++C20 است که امکان ساختن یک مقدار از نوعی متفاوت، بر اساس نمایش بیتی یک شیء موجود را فراهم می‌کند.

این قابلیت در سربرگ `<bit>` تعریف شده و برای موقعیت‌هایی طراحی شده است که برنامه‌نویس به جای تبدیل عددی یک مقدار، به نمایش بیتی آن نیاز دارد.

برای مثال، فرض کنید یک متغیر از نوع `float` دارید و می‌خواهید بیت‌های تشکیل‌دهندهٔ آن را به‌صورت یک مقدار `std::uint32_t` مشاهده کنید.

روش معمول تبدیل نوع با `static_cast` چنین کاری انجام نمی‌دهد؛ زیرا `static_cast` مقدار عددی را تبدیل می‌کند، نه نمایش بیتی آن را.

در مقابل، تابع `std::bit_cast` بیت‌های نمایش شیء مبدأ را برای ساختن یک مقدار از نوع مقصد استفاده می‌کند.

این تفاوت در برنامه‌نویسی سطح پایین، تحلیل داده‌های باینری، بررسی نمایش عددهای اعشاری، توسعهٔ ابزارهای Debugging و پیاده‌سازی الگوریتم‌هایی که مستقیماً با بیت‌ها سروکار دارند، اهمیت زیادی دارد.

## معرفی قابلیت `std::bit_cast`

تابع `std::bit_cast` در ++C20 به‌عنوان بخشی از کتابخانهٔ استاندارد و در سربرگ `<bit>` معرفی شد.

امضای اصلی این تابع به شکل زیر است:

```
template<class To, class From>
constexpr To bit_cast(const From& from) noexcept;
```

در این تعریف:

- پارامتر `To` نوع مقصد است.
- پارامتر `From` نوع مبدأ است.
- پارامتر `from` شیئی است که نمایش بیتی آن برای ساخت مقدار مقصد استفاده می‌شود.
- مقدار بازگشتی، یک شیء جدید از نوع `To` است.

برای استفاده از این تابع، دو شرط اساسی باید برقرار باشند:

- اندازهٔ نوع مبدأ و مقصد باید یکسان باشد.
- هر دو نوع باید شرط `TriviallyCopyable` را داشته باشند.

به بیان دیگر:

```
sizeof(To) == sizeof(From)
```

و:

```
std::is_trivially_copyable_v<To>
std::is_trivially_copyable_v<From>
```

اگر این الزامات برقرار نباشند، فراخوانی تابع معتبر نخواهد بود.

### نخستین مثال

مثال زیر نحوهٔ تبدیل نمایش بیتی یک مقدار `float` به یک مقدار `std::uint32_t` را نشان می‌دهد:

```
#include <bit>
#include <cstdint>
#include <iostream>

int main() {
    float value = 1.0f;

    std::uint32_t bits =
        std::bit_cast<std::uint32_t>(value);

    std::cout << std::hex << bits << '\n';
}
```

در پیاده‌سازی‌های متداول که از نمایش IEEE 754 برای `float` استفاده می‌کنند، خروجی به شکل زیر خواهد بود:

```
3f800000
```

این مقدار نمایش بیتی عدد `1.0f` است، نه تبدیل عددی آن به یک عدد صحیح.

نکتهٔ مهم این است که استاندارد ++C تضمین نمی‌کند تمام پیاده‌سازی‌ها از نمایش IEEE 754 برای `float` استفاده کنند. بنابراین خروجی این مثال وابسته به ویژگی‌های پیاده‌سازی است.

## درک مفهوم Object Representation و Value Representation

برای استفادهٔ صحیح از `std::bit_cast`، آشنایی با دو مفهوم مهم در مدل حافظهٔ ++C ضروری است.

### مفهوم Object Representation

اصطلاح `Object Representation` به مجموعهٔ بیت‌هایی اشاره دارد که یک شیء در حافظه اشغال می‌کند.

برای مثال، اگر یک نوع داده چهار بایت فضا اشغال کند، نمایش شیء آن شامل ۳۲ بیت است.

```
#include <cstdint>

int main() {
    std::uint32_t value = 42;
}
```

در این مثال، اگر `std::uint32_t` در پیاده‌سازی مورد استفاده وجود داشته باشد، شیء `value` دقیقاً ۳۲ بیت فضا اشغال می‌کند.

### مفهوم Value Representation

اصطلاح `Value Representation` به مجموعهٔ بیت‌هایی اشاره دارد که برای تعیین مقدار یک شیء استفاده می‌شوند.

در بعضی انواع داده، تمام بیت‌های نمایش شیء الزاماً در تعیین مقدار نقش ندارند.

بخشی از بیت‌ها ممکن است به‌عنوان `Padding Bits` استفاده شوند.

برای مثال، یک نوع داده ممکن است ۶۴ بیت فضا اشغال کند، اما تمام این بیت‌ها در نمایش مقدار آن استفاده نشوند.

این تفاوت هنگام کار با `std::bit_cast` اهمیت زیادی دارد؛ زیرا نتیجهٔ عملیات به نمایش مقدار نوع مقصد وابسته است و وضعیت بیت‌های padding نیز باید در نظر گرفته شود.

### مفهوم Padding Bits

بیت‌های padding بخشی از فضای اشغال‌شده توسط یک شیء هستند که برای نمایش مقدار آن استفاده نمی‌شوند.

وجود چنین بیت‌هایی می‌تواند باعث شود دو شیء با مقدار یکسان، نمایش شیء متفاوتی داشته باشند.

بنابراین نباید فرض کرد که مقایسهٔ کامل بایت‌های دو شیء همیشه معادل مقایسهٔ مقدار آن‌ها است.

این موضوع در استفاده از `std::bit_cast`، مقایسهٔ باینری اشیا و طراحی serialization اهمیت دارد.

## تفاوت تبدیل عددی و تبدیل بیتی

یکی از مهم‌ترین نکات در استفاده از `std::bit_cast`، تشخیص تفاوت آن با تبدیل‌های معمول نوع است.

برای روشن شدن موضوع، مثال زیر را بررسی کنید:

```
#include <bit>
#include <cstdint>
#include <iostream>

int main() {
    float value = 3.0f;

    int numericValue = static_cast<int>(value);

    std::uint32_t bitRepresentation =
        std::bit_cast<std::uint32_t>(value);

    std::cout << numericValue << '\n';

    std::cout << std::hex
              << bitRepresentation << '\n';
}
```

در این برنامه دو عملیات متفاوت انجام می‌شود.

عملیات اول: تبدیل عددی

```
int numericValue = static_cast<int>(value);
```

در این حالت، مقدار عددی `3.0f` به عدد صحیح `3` تبدیل می‌شود.

عملیات دوم: تبدیل نمایش بیتی

```
std::uint32_t bitRepresentation =
    std::bit_cast<std::uint32_t>(value);
```

در این حالت، بیت‌های نمایش `float` برای ساخت یک مقدار `std::uint32_t` استفاده می‌شوند.

در پیاده‌سازی‌های متداول مبتنی بر IEEE 754، نمایش بیتی `3.0f` برابر است با:

```
0x40400000
```

بنابراین این دو عملیات کاربرد یکسانی ندارند.

قاعدهٔ انتخاب به این صورت است:

- برای تبدیل مقدار عددی، از `static_cast` استفاده کنید.
- برای ساخت مقدار جدید از نمایش بیتی یک شیء، از `std::bit_cast` استفاده کنید.

## کاربرد در بررسی نمایش بیتی float

یکی از کاربردهای مهم `std::bit_cast` بررسی نمایش داخلی عددهای اعشاری است.

در بسیاری از سیستم‌های مدرن، نوع `float` از قالب IEEE 754 استفاده می‌کند.

در این قالب، نمایش یک مقدار `float` شامل سه بخش اصلی است:

- `Sign Bit`: تعیین‌کنندهٔ علامت عدد.
- `Exponent`: نمایش توان.
- `Fraction`: نمایش بخش کسری یا significand.

برای عددهای معمولی در قالب IEEE 754 با دقت تکی، این بخش‌ها به شکل زیر سازمان‌دهی می‌شوند:

| بخش      | تعداد بیت |
| -------- | --------- |
| Sign     | 1         |
| Exponent | 8         |
| Fraction | 23        |
| مجموع    | 32        |

با استفاده از `std::bit_cast` می‌توان نمایش بیتی این مقادیر را بررسی کرد.

```
#include <bit>
#include <cstdint>
#include <iostream>
#include <limits>

int main() {
    static_assert(sizeof(float) == sizeof(std::uint32_t));

    float value = 1.5f;

    std::uint32_t bits =
        std::bit_cast<std::uint32_t>(value);

    std::uint32_t sign = (bits >> 31) & 0x1;

    std::uint32_t exponent = (bits >> 23) & 0xFF;

    std::uint32_t fraction = bits & 0x7FFFFF;

    std::cout << "Sign: " << sign << '\n';

    std::cout << "Exponent: " << exponent << '\n';

    std::cout << "Fraction: " << fraction << '\n';
}
```

این مثال فرض می‌کند نمایش `float` با قالب IEEE 754 و ساختار ۳۲ بیتی مورد انتظار سازگار است.

نکتهٔ مهم این است که `sizeof(float) == sizeof(std::uint32_t)` فقط برابری اندازه را بررسی می‌کند و به‌تنهایی سازگاری قالب‌های نمایش را تضمین نمی‌کند.

برای بررسی یکی از ویژگی‌های مهم قالب اعشاری می‌توان از عبارت زیر استفاده کرد:

```
std::numeric_limits<float>::is_iec559
```

البته این بررسی نیز جایگزین مستندسازی و اعتبارسنجی تمام فرض‌های مربوط به پلتفرم نیست.

## کاربرد در بررسی NaN و Infinity

مقادیر `NaN` و `Infinity` در محاسبات اعشاری اهمیت ویژه‌ای دارند.

در IEEE 754، نمایش بیتی این مقادیر با مقادیر عددی معمولی متفاوت است.

با استفاده از `std::bit_cast` می‌توان نمایش این مقادیر را بررسی کرد.

```
#include <bit>
#include <cstdint>
#include <iostream>
#include <limits>

int main() {
    float infinity = std::numeric_limits<float>::infinity();

    float nan = std::numeric_limits<float>::quiet_NaN();

    auto infinityBits =
        std::bit_cast<std::uint32_t>(infinity);

    auto nanBits =
        std::bit_cast<std::uint32_t>(nan);

    std::cout << std::hex << infinityBits << '\n';

    std::cout << nanBits << '\n';
}
```

در این مثال، مقدارهای بیتی به نمایش داخلی مقادیر ویژه وابسته هستند.

برای تحلیل دقیق NaN باید به مفاهیمی مانند موارد زیر توجه کرد:

- `Quiet NaN`
- `Signaling NaN`
- `NaN Payload`
- Sign Bit
- Exponent Field
- Fraction Field

بسته به پیاده‌سازی و عملیات انجام‌شده، نمایش دقیق NaN می‌تواند متفاوت باشد.

بنابراین نباید فرض کرد تمام پیاده‌سازی‌ها برای NaN یک الگوی بیتی یکسان دارند.

## کاربرد در تبدیل معکوس و بازیابی مقدار

یکی دیگر از کاربردهای `std::bit_cast` تبدیل نمایش بیتی یک مقدار به نوع دیگری و سپس بازیابی مقدار اولیه است.

برای مثال:

```
#include <bit>
#include <cstdint>

constexpr float original = 1.5f;

constexpr std::uint32_t bits =
    std::bit_cast<std::uint32_t>(original);

constexpr float restored =
    std::bit_cast<float>(bits);

static_assert(restored == original);
```

در این مثال ابتدا نمایش بیتی `original` به یک مقدار صحیح منتقل می‌شود.

سپس همان بیت‌ها برای ساخت یک مقدار `float` جدید استفاده می‌شوند.

برای نوع‌های ساده و نمایش‌های معتبر، این روش امکان بازیابی مقدار را فراهم می‌کند.

با این حال، نباید آن را بدون توجه به padding، بیت‌های نامعین و قواعد نمایش نوع‌ها به تمام انواع داده تعمیم داد.

همچنین مقایسهٔ عددی با `==` الزاماً برابری کامل نمایش بیتی را اثبات نمی‌کند؛ برای مثال، `+0.0f` و `-0.0f` از نظر مقایسهٔ عددی برابر هستند، اما در IEEE 754 نمایش بیتی متفاوتی دارند.

## استفاده از std::bit_cast در constexpr

یکی از ویژگی‌های مهم `std::bit_cast`، پشتیبانی از `constexpr` است.

این قابلیت اجازه می‌دهد در شرایط مجاز، تبدیل نمایش بیتی در زمان کامپایل انجام شود.

برای مثال:

```
#include <bit>
#include <cstdint>

constexpr std::uint32_t bits = 0x3F800000u;

constexpr float value =
    std::bit_cast<float>(bits);
```

در پیاده‌سازی مناسب، این عملیات می‌تواند در زمان کامپایل ارزیابی شود.

با این حال، `constexpr` بودن تابع به معنی مجاز بودن تمام فراخوانی‌ها در زمان کامپایل نیست.

### محدودیت‌های ارزیابی ثابت

در ارزیابی `constexpr`، محدودیت‌های مشخصی برای نوع‌های مبدأ و مقصد وجود دارد.

از جمله موارد مهم می‌توان به موارد زیر اشاره کرد:

- نوع‌های `union` برای این کاربرد مجاز نیستند.
- نوع‌های pointer و pointer-to-member محدودیت دارند.
- نوع‌های `volatile` مجاز نیستند.
- وجود عضو داده‌ای از نوع reference در ساختار نوع می‌تواند مانع ارزیابی ثابت شود.
- قواعد مربوط به بیت‌های نامعین و معتبر بودن نمایش مقصد همچنان اعمال می‌شوند.

بنابراین ممکن است یک فراخوانی در زمان اجرا معتبر باشد، اما نتوان همان عملیات را در یک عبارت `constexpr` انجام داد.

برای کدهای قابل‌حمل، باید قابلیت ارزیابی ثابت را در محیط کامپایل هدف بررسی کرد.

## بررسی TriviallyCopyable

یکی از الزامات اصلی `std::bit_cast`، `TriviallyCopyable` بودن هر دو نوع مبدأ و مقصد است.

این مفهوم در مدل شیء ++C اهمیت زیادی دارد.

یک نوع `TriviallyCopyable` نوعی است که عملیات کپی و جابه‌جایی نمایش شیء آن از قواعد مشخصی پیروی می‌کند و برای عملیات سطح پایین مربوط به نمایش شیء مناسب است.

برای بررسی این ویژگی می‌توان از type trait زیر استفاده کرد:

```
#include <type_traits>
#include <iostream>

struct Point {
    float x;
    float y;
};

struct NonTrivial {
    NonTrivial() {}

    int value;
};

int main() {
    std::cout
        << std::is_trivially_copyable_v<Point>
        << '\n';

    std::cout
        << std::is_trivially_copyable_v<NonTrivial>
        << '\n';
}
```

در این مثال، نوع `Point` یک نوع ساده و trivially copyable است.

اما در مورد `NonTrivial`، سازندهٔ تعریف‌شده به‌صورت user-provided باعث می‌شود نوع موردنظر در این مثال trivially copyable نباشد.

نکتهٔ مهم این است که `TriviallyCopyable` بودن به معنای بی‌خطر بودن هرگونه تفسیر دلخواه از بیت‌های نوع نیست.

این ویژگی فقط یکی از پیش‌شرط‌های استفاده از `std::bit_cast` است.

## استفاده از std::bit_cast برای ساخت نوع‌های سفارشی

این تابع فقط محدود به نوع‌های عددی نیست.

می‌توان از آن برای نوع‌های سفارشی نیز استفاده کرد، به شرط آن‌که الزامات مربوط به اندازه و `TriviallyCopyable` بودن برقرار باشند.

برای مثال:

```
#include <bit>
#include <cstdint>
#include <iostream>

struct RGB {
    std::uint8_t red;
    std::uint8_t green;
    std::uint8_t blue;
    std::uint8_t alpha;
};

int main() {
    std::uint32_t packed = 0xFF112233;

    static_assert(sizeof(RGB) == sizeof(std::uint32_t));

    RGB color = std::bit_cast<RGB>(packed);

    std::cout << static_cast<int>(color.red) << '\n';
    std::cout << static_cast<int>(color.green) << '\n';
    std::cout << static_cast<int>(color.blue) << '\n';
    std::cout << static_cast<int>(color.alpha) << '\n';
}
```

این مثال از نظر اندازه و نوع داده می‌تواند معتبر باشد، اما ترتیب بایت‌های حاصل به endianness سامانه وابسته است.

در نتیجه، نباید فرض کرد مقدار `0xFF112233` در تمام معماری‌ها به ترتیب یکسانی در اعضای `RGB` قرار می‌گیرد.

برای کدهای قابل‌حمل، بهتر است ترتیب فیلدها به‌صورت صریح استخراج شود:

```
#include <cstdint>

struct RGB {
    std::uint8_t red;
    std::uint8_t green;
    std::uint8_t blue;
    std::uint8_t alpha;
};

RGB unpackColor(std::uint32_t packed) {
    return {
        static_cast<std::uint8_t>((packed >> 24) & 0xFF),
        static_cast<std::uint8_t>((packed >> 16) & 0xFF),
        static_cast<std::uint8_t>((packed >> 8) & 0xFF),
        static_cast<std::uint8_t>(packed & 0xFF)
    };
}
```

این روش ترتیب موردنظر را مستقل از ترتیب بایت‌های حافظه مشخص می‌کند.

## تفاوت با reinterpret_cast

یکی از دلایل مهم معرفی `std::bit_cast`، فراهم کردن راهی استاندارد و امن‌تر برای انتقال نمایش بیتی میان نوع‌های مختلف است.

پیش از ++C20، برنامه‌نویسان گاهی از `reinterpret_cast` برای بازتفسیر حافظه استفاده می‌کردند.

برای مثال:

```
float value = 1.0f;

auto bits = *reinterpret_cast<std::uint32_t*>(&value);
```

این روش برای دسترسی به شیء `float` از طریق یک lvalue از نوع `std::uint32_t` استفاده می‌کند.

چنین دسترسی‌ای می‌تواند با قواعد `Strict Aliasing` و دسترسی مجاز به اشیا تعارض داشته باشد و به رفتار تعریف‌نشده منجر شود.

در مقابل:

```
std::uint32_t bits =
    std::bit_cast<std::uint32_t>(value);
```

یک مقدار جدید از نوع مقصد تولید می‌کند و برای این کار نیازی به دسترسی به شیء مبدأ از طریق یک نوع نامرتبط ندارد.

البته این دو ابزار هدف یکسانی ندارند.

`reinterpret_cast` برای برخی تبدیل‌های pointer و عملیات‌های سطح پایین مرتبط با آدرس حافظه کاربرد دارد؛ اما `std::bit_cast` برای ساخت مقدار جدید از نمایش بیتی شیء طراحی شده است.

بنابراین نباید تصور کرد `std::bit_cast` جایگزین تمام کاربردهای `reinterpret_cast` است.

## تفاوت با std::memcpy

پیش از معرفی `std::bit_cast`، یکی از روش‌های استاندارد برای کپی نمایش بیتی میان دو شیء هم‌اندازه، استفاده از `std::memcpy` بود.

برای مثال:

```
#include <cstdint>
#include <cstring>

float convertToFloat(std::uint32_t bits) {
    float result;

    static_assert(sizeof(result) == sizeof(bits));

    std::memcpy(&result, &bits, sizeof(result));

    return result;
}
```

این روش برخلاف دسترسی از طریق pointer نامرتبط، برای انتقال نمایش شیء از قواعد مجاز `memcpy` استفاده می‌کند.

با معرفی ++C20، تابع `std::bit_cast` راهی مستقیم‌تر و خواناتر برای همین هدف فراهم کرد.

مقایسهٔ این دو روش:

| ویژگی                            | `std::bit_cast`     | `std::memcpy`            |
| -------------------------------- | ------------------- | ------------------------ |
| نسخهٔ استاندارد                  | ++C20               | ++C98                    |
| نوع خروجی                        | مقدار از نوع مقصد   | کپی حافظه                |
| نیاز به اندازهٔ برابر            | بله                 | برای الگوی موردنظر بله   |
| نیاز به TriviallyCopyable        | بله، برای هر دو نوع | قواعد کپی شیء متفاوت است |
| پشتیبانی از constexpr            | در شرایط مجاز       | خیر، در ++C20            |
| خوانایی برای تبدیل بیتی          | بالا                | پایین‌تر                 |
| کاربرد در نسخه‌های قدیمی‌تر زبان | خیر                 | بله                      |

برای کدهای جدید ++C20، معمولاً `std::bit_cast` انتخاب مناسب‌تری است؛ اما `std::memcpy` همچنان برای انتقال عمومی داده‌های باینری و سازگاری با نسخه‌های قدیمی‌تر کاربرد دارد.

## ارتباط با std::endian

یکی از موضوعات مهم هنگام کار با نمایش بیتی، مفهوم `Endianness` است.

ترتیب بایت‌ها مشخص می‌کند که بایت‌های یک مقدار چندبایتی چگونه در حافظه قرار می‌گیرند.

دو ترتیب رایج عبارت‌اند از:

- `Little Endian`
- `Big Endian`

در ++C20، ابزار `std::endian` در سربرگ `<bit>` معرفی شد.

با استفاده از آن می‌توان ترتیب بایت‌های native سیستم را بررسی کرد.

```
#include <bit>
#include <iostream>

int main() {
    if constexpr (
        std::endian::native == std::endian::little
    ) {
        std::cout << "Little Endian\n";
    }
    else if constexpr (
        std::endian::native == std::endian::big
    ) {
        std::cout << "Big Endian\n";
    }
    else {
        std::cout << "Mixed Endian\n";
    }
}
```

نکتهٔ مهم این است که `std::endian::native` الزاماً در تمام پیاده‌سازی‌ها برابر `little` یا `big` نیست.

همچنین `std::bit_cast` ترتیب بایت‌ها را تغییر نمی‌دهد و عملیات تبدیل Endianness انجام نمی‌دهد.

بنابراین اگر داده‌ای از شبکه یا فایل دریافت می‌کنید، باید ترتیب بایت‌های آن را جداگانه مدیریت کنید.

## ارتباط با std::byteswap

تابع `std::byteswap` در استاندارد ++C23 و در سربرگ `<bit>` معرفی شد.

هدف این تابع معکوس کردن ترتیب بایت‌های یک مقدار صحیح است.

برای مثال:

```
#include <bit>
#include <cstdint>
#include <iostream>

int main() {
    std::uint32_t value = 0x12345678;

    auto reversed = std::byteswap(value);

    std::cout << std::hex << reversed << '\n';
}
```

خروجی:

```
78563412
```

این تابع برای مدیریت ترتیب بایت‌ها در پروتکل‌های شبکه، قالب‌های فایل و داده‌های باینری مفید است.

توجه داشته باشید که `std::byteswap` برای نوع‌های صحیح قابل استفاده است و نوع موردنظر نباید padding bits داشته باشد.

این تابع مکمل `std::bit_cast` است، نه جایگزین آن.

## محدودیت‌ها و رفتارهای تعریف‌نشده

استفاده از `std::bit_cast` به معنای امکان تبدیل ایمن هر مجموعه بیت به هر نوع داده نیست.

چند محدودیت مهم باید در نظر گرفته شوند.

### معتبر بودن نمایش مقصد

اگر نمایش بیتی حاصل نتواند یک مقدار معتبر از نوع مقصد را نمایش دهد، رفتار برنامه تعریف‌نشده خواهد بود.

برای مثال، نباید فرض کرد هر الگوی دلخواه ۳۲ بیتی الزاماً یک نمایش معتبر برای هر نوع `float` است.

### بیت‌های Padding

اگر نوع مقصد دارای padding bits باشد، مقدار این بیت‌ها لزوماً مشخص نیست.

بنابراین نباید نتیجه را به شکلی مصرف کرد که به مقدار مشخصی برای بیت‌های padding وابسته باشد.

### بیت‌های نامعین

وجود بیت‌های نامعین در نمایش شیء مبدأ می‌تواند روی نتیجه تأثیر بگذارد.

اصلاحیهٔ CWG 2482 که با پیشنهاد P1272R4 مرتبط است، قواعد مربوط به بیت‌های نامعین در `std::bit_cast` را برای ++C20 روشن‌تر کرد.

در نتیجه، نباید حافظهٔ مقداردهی‌نشده را به‌عنوان منبع قابل‌اعتماد برای ساخت مقدار مقصد در نظر گرفت.

### اندازهٔ متفاوت نوع‌ها

اگر اندازهٔ دو نوع متفاوت باشد، `std::bit_cast` قابل استفاده نیست.

برای مثال:

```
float value = 1.0f;

// Invalid: source and destination sizes may differ.
auto result = std::bit_cast<std::uint64_t>(value);
```

این کد به دلیل برابر نبودن اندازه‌ها در پیاده‌سازی‌های معمول، معتبر نیست.

### محدودیت‌های Pointer

`std::bit_cast` ابزار عمومی برای تبدیل pointerها نیست.

حتی اگر دو نوع pointer اندازهٔ یکسانی داشته باشند، این موضوع به معنای مجاز بودن تبدیل بیتی آن‌ها نیست.

قواعد مربوط به pointer، اعتبار نمایش، طول عمر اشیا و ارزیابی ثابت باید جداگانه در نظر گرفته شوند.

## استفاده در Serialization و Deserialization

یکی از اشتباه‌های رایج، استفاده از `std::bit_cast` برای تبدیل مستقیم داده‌های خارجی به ساختارهای پیچیده است.

برای مثال، ممکن است برنامه‌نویس بخواهد دادهٔ دریافت‌شده از شبکه را مستقیماً به یک struct تبدیل کند.

این کار معمولاً راهکار مناسبی نیست؛ زیرا مسائل مختلفی وجود دارند:

- `Endianness`
- `Padding`
- `Alignment`
- اندازهٔ نوع‌ها
- تفاوت ABI
- اعتبار دادهٔ ورودی
- تفاوت نمایش نوع‌ها در معماری‌های مختلف

تابع `std::bit_cast` هیچ‌یک از این مسائل را به‌صورت خودکار حل نمی‌کند.

برای نمونه، اگر یک پروتکل شبکه شامل یک عدد ۳۲ بیتی Big Endian باشد، باید ابتدا چهار بایت آن را دریافت کنید، ترتیب آن‌ها را به شکل مناسب تبدیل کنید و سپس مقدار عددی را بسازید.

در چنین شرایطی، استفاده از یک parser صریح و کنترل‌شده معمولاً انتخاب قابل‌حمل‌تری است.

## نکات مهم در طراحی API

هنگام استفاده از `std::bit_cast` در طراحی کتابخانه‌ها و APIهای سطح پایین، چند نکته اهمیت دارد.

- شفافیت فرض‌ها: اگر کد به IEEE 754 یا Endianness خاصی وابسته است، این فرض‌ها را مستند کنید.
- بررسی اندازه: از `static_assert` برای بررسی برابر بودن اندازه‌ها استفاده کنید.
- بررسی نوع‌ها: در صورت نیاز، از `std::is_trivially_copyable_v` برای اعتبارسنجی نوع‌ها استفاده کنید.
- پرهیز از وابستگی به ABI: نمایش داخلی structها را قالب پایدار ذخیره‌سازی یا انتقال داده در نظر نگیرید.
- اعتبارسنجی ورودی: قبل از ساخت مقادیر از داده‌های خارجی، اعتبار و کامل بودن داده‌ها را بررسی کنید.
- پرهیز از فرض‌های پنهان: یکسان بودن اندازهٔ دو نوع الزاماً به معنی یکسان بودن معنا یا قالب نمایش آن‌ها نیست.

## بررسی پشتیبانی کامپایلر و کتابخانه

برای استفاده از `std::bit_cast` به پشتیبانی ++C20 در compiler و کتابخانهٔ استاندارد نیاز دارید.

صرفاً فعال کردن گزینهٔ زبان ++C20 تضمین نمی‌کند تمام قابلیت‌های کتابخانهٔ استاندارد در دسترس باشند.

برای بررسی پشتیبانی کتابخانه می‌توان از Feature-test Macro استفاده کرد:

```
#include <bit>

#if defined(__cpp_lib_bit_cast) && \
    __cpp_lib_bit_cast >= 201806L

// std::bit_cast is available.

#else

// std::bit_cast is not available.

#endif
```

مقدار استاندارد Feature-test Macro برای این قابلیت برابر `201806L` است.

این روش برای کتابخانه‌هایی که باید با چند نسخه از compiler و standard library سازگار باشند، مفید است.

## مقایسهٔ ابزارهای مرتبط

جدول زیر به انتخاب ابزار مناسب برای عملیات‌های مختلف کمک می‌کند.

| نیاز                          | ابزار پیشنهادی                           | استاندارد        |

## اشتباه‌های رایج برنامه‌نویسان

### اشتباه گرفتن تبدیل بیتی و عددی

استفاده از `static_cast` به جای `std::bit_cast` باعث می‌شود مقدار عددی تبدیل شود، نه نمایش بیتی آن.

### فرض یکسان بودن نمایش float در تمام سیستم‌ها

استاندارد ++C تضمین نمی‌کند تمام پیاده‌سازی‌ها از قالب IEEE 754 استفاده کنند.

### استفاده از reinterpret_cast برای دسترسی به نمایش شیء

دسترسی به یک شیء از طریق نوع نامرتبط ممکن است قوانین Strict Aliasing را نقض کند.

### استفاده برای تبدیل مستقیم داده‌های شبکه

تبدیل مستقیم structها به داده‌های شبکه بدون مدیریت Endianness و Padding می‌تواند باعث خطاهای جدی شود.

### نادیده گرفتن بیت‌های نامعین

مقداردهی‌نشدن حافظه یا وجود بیت‌های نامعین می‌تواند اعتبار نتیجه را تحت تأثیر قرار دهد.

### تصور جایگزینی کامل memcpy

تابع `std::bit_cast` برای ساخت مقدار از نمایش بیتی طراحی شده است؛ اما `std::memcpy` کاربردهای گسترده‌تری در کپی داده و مدیریت حافظه دارد.

## جمع‌بندی

قابلیت `std::bit_cast` در ++C20 راهکاری استاندارد برای ساخت یک مقدار از نوع مقصد بر اساس نمایش بیتی یک شیء مبدأ فراهم می‌کند.

این قابلیت به‌ویژه در کاربردهای زیر مفید است:

- بررسی نمایش داخلی عددهای اعشاری
- تحلیل بیت‌های IEEE 754
- ساخت ابزارهای Debugging
- توسعهٔ کتابخانه‌های سطح پایین
- پیاده‌سازی الگوریتم‌های وابسته به نمایش بیتی
- تبدیل نمایش اشیای trivially copyable

با این حال، استفادهٔ صحیح از آن نیازمند درک دقیق مفاهیمی مانند `Object Representation`، `Value Representation`، `TriviallyCopyable`، `Padding Bits`، `Endianness` و قواعد مربوط به نمایش معتبر نوع‌ها است.

در نهایت، باید به خاطر داشت که `std::bit_cast` یک ابزار تخصصی برای کار با نمایش بیتی اشیا است، نه یک راهکار عمومی برای تبدیل نوع، مدیریت حافظه یا پردازش داده‌های خارجی.
