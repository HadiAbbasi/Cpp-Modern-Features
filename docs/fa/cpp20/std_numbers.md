# معرفی کتابخانه `std::numbers` در ++C20

## مقدمه

یکی از نیازهای رایج در برنامه‌نویسی علمی، مهندسی، شبیه‌سازی، پردازش
سیگنال، گرافیک کامپیوتری و محاسبات ریاضی، استفاده از ثابت‌های ریاضی است.
مقادیری مانند عدد پی، عدد نپر، ریشه دوم دو و لگاریتم‌های طبیعی، در بسیاری
از الگوریتم‌ها و فرمول‌های ریاضی نقش اساسی دارند.

در نسخه‌های قدیمی‌تر ++C، برنامه‌نویسان معمولاً این مقادیر را به‌صورت دستی
تعریف می‌کردند، از ماکروهای موجود در بعضی محیط‌ها استفاده می‌کردند یا به
کتابخانه‌های خارجی وابسته می‌شدند. این روش‌ها مشکلاتی مانند وابستگی به
پلتفرم، نبود Type Safety، احتمال تعریف مجدد و محدودیت در استفاده از
انواع داده مختلف را به همراه داشتند.

استاندارد ++C20 با معرفی Header جدیدی به نام `<numbers>`، راهکاری
استاندارد و Type-Safe برای دسترسی به مجموعه‌ای از ثابت‌های ریاضی فراهم
کرد.

این قابلیت در فضای نام `std::numbers` قرار دارد و شامل ثابت‌هایی مانند
`pi`، `e`، `sqrt2` و نسخه‌های Template آن‌ها است.

کتابخانه `std::numbers` به توسعه‌دهندگان اجازه می‌دهد بدون تعریف دستی
ثابت‌های ریاضی، از مقادیر استاندارد و قابل استفاده با انواع مختلف داده‌های
ممیز شناور بهره ببرند.

## معرفی کتابخانه std::numbers

کتابخانه `std::numbers` بخشی از Standard Library در ++C20 است که برای
ارائه ثابت‌های ریاضی پرکاربرد طراحی شده است.

برای استفاده از این قابلیت باید Header زیر را وارد برنامه کنید:

``` cpp
#include <numbers>
```

تمام ثابت‌های این کتابخانه در فضای نام زیر قرار دارند:

``` cpp
std::numbers
```

یک نمونه ساده از استفاده این کتابخانه:

``` cpp
#include <iostream>
#include <numbers>

int main() {
    constexpr double radius = 5.0;

    constexpr double area =
        std::numbers::pi * radius * radius;

    std::cout << "Area: " << area << '\n';
}
```

در این مثال، مقدار عدد پی از طریق `std::numbers::pi` دریافت شده است.

استفاده از این ثابت‌ها باعث می‌شود کد خواناتر باشد و به تعریف دستی مقادیر
تقریبی مانند `3.14159` نیازی نداشته باشد.

## دلیل معرفی std::numbers

### مشکلات تعریف دستی ثابت‌های ریاضی

در بسیاری از برنامه‌های قدیمی، ثابت‌های ریاضی به شکل زیر تعریف می‌شدند:

``` cpp
constexpr double PI = 3.14159265358979323846;
constexpr double E = 2.71828182845904523536;
```

این روش برای برنامه‌های کوچک قابل استفاده است، اما در پروژه‌های بزرگ
مشکلاتی ایجاد می‌کند.

-   **تکرار تعریف:** ممکن است چند بخش از پروژه یک ثابت مشابه را با
    مقادیر متفاوت تعریف کنند.
-   **نگهداری دشوار:** تغییر یا اصلاح ثابت‌ها نیازمند بررسی چندین محل در
    پروژه است.
-   **وابستگی به نوع داده:** تعریف یک مقدار برای `double` لزوماً برای
    محاسبات `float` یا `long double` مناسب نیست.
-   **نبود استاندارد مشترک:** کتابخانه‌های مختلف ممکن است از نام‌گذاری یا
    مقادیر متفاوتی استفاده کنند.
-   **احتمال خطای انسانی:** وارد کردن اشتباه ارقام ثابت‌های طولانی
    می‌تواند باعث خطاهای محاسباتی شود.

### محدودیت ماکروهای قدیمی

در برخی محیط‌ها از ماکروهایی مانند `M_PI` استفاده می‌شود:

``` cpp
#include <cmath>

double circumference = 2.0 * M_PI * radius;
```

اما `M_PI` یک ثابت استاندارد قابل اتکا در تمام پیاده‌سازی‌های ++C نیست و
دسترسی به آن ممکن است به پلتفرم، کتابخانه C یا تنظیمات کامپایلر وابسته
باشد.

در مقابل، `std::numbers::pi` بخشی از Standard Library استاندارد ++C20
است.

### مزایای طراحی استاندارد

کتابخانه `std::numbers` چند مزیت مهم دارد:

-   ارائه ثابت‌های ریاضی شناخته‌شده با نام‌های استاندارد.
-   پشتیبانی از `constexpr` برای استفاده در زمان کامپایل.
-   ارائه نسخه‌های Template برای انواع ممیز شناور.
-   جلوگیری از وابستگی به ماکروهای غیراستاندارد.
-   بهبود خوانایی و قابلیت نگهداری کد.
-   امکان استفاده مستقیم در الگوریتم‌های Generic Programming.

## مفهوم ثابت‌های ریاضی در ++C

ثابت‌های ریاضی مقادیری هستند که در یک مسئله یا الگوریتم مقدار مشخصی دارند
و برخلاف متغیرهای معمولی نباید در طول اجرای برنامه تغییر کنند.

برای مثال، عدد پی نسبت محیط دایره به قطر آن است و در محاسبات هندسی
کاربرد دارد.

در ++C می‌توان ثابت‌ها را با `const` یا `constexpr` تعریف کرد.

تفاوت مهم این دو در زمان ارزیابی مقدار است:

-   `const` تغییرناپذیری مقدار را تضمین می‌کند، اما به‌تنهایی الزام نمی‌کند
    که مقدار حتماً در زمان کامپایل محاسبه شود.
-   `constexpr` برای مقادیری استفاده می‌شود که باید در زمان کامپایل قابل
    ارزیابی باشند.

ثابت‌های `std::numbers` از نوع `inline constexpr` هستند؛ بنابراین هم
تغییرناپذیرند و هم برای استفاده در Constant Expression مناسب هستند.

## ساختار و اعضای کتابخانه

فضای نام `std::numbers` شامل دو گروه اصلی از ثابت‌ها است:

-   ثابت‌های غیر Template که از نوع `double` هستند.
-   Variable Templateهایی که امکان دریافت ثابت با نوع ممیز شناور موردنظر
    را فراهم می‌کنند.

برای نمونه، `std::numbers::pi` از نوع `double` است و
`std::numbers::pi_v<float>` نسخه‌ای از همان ثابت با نوع `float` را ارائه
می‌دهد.

### ثابت‌های غیر Template

اعضای غیر Template این کتابخانه عبارت‌اند از:

  نام            مفهوم ریاضی                          مقدار تقریبی
  -------------- ----------------------------- -------------------
  `e`            عدد نپر، پایه لگاریتم طبیعی     2.718281828459045
  `log2e`        لگاریتم پایه دو از e            1.442695040888963
  `log10e`       لگاریتم پایه ده از e            0.434294481903252
  `pi`           عدد پی                          3.141592653589793
  `inv_pi`       معکوس عدد پی                    0.318309886183791
  `inv_sqrtpi`   معکوس ریشه دوم پی               0.564189583547756
  `ln2`          لگاریتم طبیعی دو                0.693147180559945
  `ln10`         لگاریتم طبیعی ده                2.302585092994046
  `sqrt2`        ریشه دوم دو                     1.414213562373095
  `sqrt3`        ریشه دوم سه                     1.732050807568877
  `inv_sqrt3`    معکوس ریشه دوم سه               0.577350269189626
  `egamma`       ثابت اویلر--ماسکرونی            0.577215664901533
  `phi`          نسبت طلایی                      1.618033988749895

این مقادیر برای استفاده عمومی در محاسبات ریاضی در نظر گرفته شده‌اند.
ارقام جدول صرفاً نمایش تقریبی هستند و نباید به‌عنوان تعریف دستی دقیق‌تر از
ثابت استاندارد تلقی شوند.

### نسخه‌های Template

برای هر یک از ثابت‌های بالا، یک Variable Template متناظر با پسوند `_v`
وجود دارد. این Templateها در فضای نام `std::numbers` تعریف شده‌اند.

برای مثال:

``` cpp
std::numbers::pi
std::numbers::pi_v<float>
std::numbers::pi_v<double>
std::numbers::pi_v<long double>
```

نسخه‌های Template امکان می‌دهند نوع مقدار با نوع محاسبات هماهنگ شود.

نام‌های Template به این صورت هستند:

``` cpp
std::numbers::e_v<T>
std::numbers::log2e_v<T>
std::numbers::log10e_v<T>
std::numbers::pi_v<T>
std::numbers::inv_pi_v<T>
std::numbers::inv_sqrtpi_v<T>
std::numbers::ln2_v<T>
std::numbers::ln10_v<T>
std::numbers::sqrt2_v<T>
std::numbers::sqrt3_v<T>
std::numbers::inv_sqrt3_v<T>
std::numbers::egamma_v<T>
std::numbers::phi_v<T>
```

در این الگو، `T` باید یکی از انواع ممیز شناور استاندارد باشد؛ مانند
`float`، `double` یا `long double`.

## بررسی ثابت‌های مهم ریاضی

### عدد پی با pi

عدد پی یکی از شناخته‌شده‌ترین ثابت‌های ریاضی است. این عدد نسبت محیط هر
دایره به قطر آن را نشان می‌دهد.

فرمول محیط دایره:

\[ C = 2`\pi `{=tex}r \]

فرمول مساحت دایره:

\[ A = `\pi `{=tex}r\^2 \]

نمونه استفاده:

``` cpp
#include <iostream>
#include <numbers>

int main() {
    constexpr double radius = 4.0;

    constexpr double circumference =
        2.0 * std::numbers::pi * radius;

    constexpr double area =
        std::numbers::pi * radius * radius;

    std::cout << circumference << '\n';
    std::cout << area << '\n';
}
```

ثابت `pi` در محاسبات هندسی، توابع مثلثاتی، پردازش سیگنال و شبیه‌سازی
کاربرد فراوان دارد.

### عدد نپر با e

عدد نپر که با نماد ریاضی (e) شناخته می‌شود، پایه لگاریتم طبیعی است.

این ثابت در رشد و کاهش نمایی، معادلات دیفرانسیل، احتمال، آمار و مدل‌سازی
سیستم‌های پیوسته کاربرد دارد.

برای نمونه، تابع رشد نمایی معمولاً به شکل زیر نوشته می‌شود:

\[ f(t) = e\^{kt} \]

نمونه استفاده:

``` cpp
#include <cmath>
#include <iostream>
#include <numbers>

int main() {
    constexpr double growthRate = 0.15;
    constexpr double time = 3.0;

    const double result =
        std::exp(growthRate * time);

    std::cout << result << '\n';
}
```

در این مثال از `std::exp` برای محاسبه تابع نمایی استفاده شده است. ثابت
`e` نیز زمانی مفید است که فرمول به‌صورت مستقیم به پایه نمایی نیاز داشته
باشد.

### لگاریتم‌های مرتبط با e

ثابت `log2e` برابر لگاریتم پایه دو از عدد نپر است:

\[ `\log`{=tex}\_2(e) \]

ثابت `log10e` نیز لگاریتم پایه ده از عدد نپر را نشان می‌دهد:

\[ `\log`{=tex}\_{10}(e) \]

این مقادیر در تبدیل بین پایه‌های لگاریتمی و بعضی محاسبات علمی مفید هستند.

برای مثال، با استفاده از رابطه تغییر پایه می‌توان لگاریتم طبیعی را به
لگاریتم پایه دو تبدیل کرد:

\[ `\ln`{=tex}(x) = `\log`{=tex}\_2(x) `\times `{=tex}`\ln`{=tex}(2) \]

یا:

\[ `\log`{=tex}\_2(x) = `\ln`{=tex}(x) `\times `{=tex}`\log`{=tex}\_2(e)
\]

در عمل، برای محاسبه لگاریتم بهتر است از توابع استاندارد `<cmath>` مانند
`std::log`، `std::log2` و `std::log10` استفاده کنید. ثابت‌های
`std::numbers` جایگزین این توابع نیستند.

### لگاریتم طبیعی دو و ده

ثابت `ln2` مقدار لگاریتم طبیعی دو و ثابت `ln10` مقدار لگاریتم طبیعی ده
را ارائه می‌کند.

این مقادیر در تحلیل الگوریتم‌ها، محاسبات اطلاعاتی، تبدیل لگاریتم‌ها و بعضی
الگوریتم‌های عددی کاربرد دارند.

برای نمونه:

\[ `\ln`{=tex}(10x) = `\ln`{=tex}(10) + `\ln`{=tex}(x) \]

در چنین رابطه‌هایی می‌توان از `std::numbers::ln10` استفاده کرد.

### ریشه دوم دو و سه

ثابت `sqrt2` مقدار ریشه دوم دو و `sqrt3` مقدار ریشه دوم سه را ارائه
می‌کنند.

این مقادیر در هندسه، محاسبات برداری، فاصله اقلیدسی، گرافیک سه‌بعدی و
الگوریتم‌های عددی استفاده می‌شوند.

برای مثال، طول قطر یک مربع با ضلع (a) برابر است با:

\[ d = a`\sqrt{2}`{=tex} \]

نمونه:

``` cpp
#include <iostream>
#include <numbers>

int main() {
    constexpr double side = 10.0;

    constexpr double diagonal =
        side * std::numbers::sqrt2;

    std::cout << diagonal << '\n';
}
```

### ثابت‌های معکوس

کتابخانه دو ثابت `inv_pi` و `inv_sqrtpi` و همچنین `inv_sqrt3` را ارائه
می‌کند.

این نام‌ها به‌ترتیب به معکوس عدد پی، معکوس ریشه دوم پی و معکوس ریشه دوم سه
اشاره دارند.

برای مثال:

\[ `\text{inv\_pi}`{=tex} = `\frac{1}{\pi}`{=tex} \]

و:

\[ `\text{inv\_sqrtpi}`{=tex} = `\frac{1}{\sqrt{\pi}}`{=tex} \]

این مقادیر در فرمول‌های احتمال، توزیع‌های آماری، پردازش سیگنال و محاسبات
علمی قابل استفاده هستند.

وجود این ثابت‌ها باعث می‌شود در مواردی که فرمول مستقیماً به این مقادیر نیاز
دارد، لازم نباشد آن‌ها را در هر محل به‌صورت دستی محاسبه یا تعریف کنید.

### ثابت اویلر--ماسکرونی با egamma

ثابت `egamma` با نماد (`\gamma`{=tex}) شناخته می‌شود و به ثابت
اویلر--ماسکرونی اشاره دارد.

این مقدار در نظریه اعداد، تحلیل مجانبی، توابع خاص ریاضی و بعضی مباحث
تحلیل ریاضی ظاهر می‌شود.

این ثابت را نباید با عدد نپر `e` اشتباه گرفت؛ این دو مقدار و کاربردهای
متفاوتی دارند.

### نسبت طلایی با phi

ثابت `phi` نسبت طلایی را نشان می‌دهد:

\[ `\varphi `{=tex}= `\frac{1 + \sqrt{5}}{2}`{=tex} \]

این مقدار در هندسه، دنباله فیبوناچی، طراحی و برخی مسائل ریاضی کاربرد
دارد.

در کد می‌توان آن را به شکل زیر به کار برد:

``` cpp
#include <iostream>
#include <numbers>

int main() {
    constexpr double goldenRatio =
        std::numbers::phi;

    std::cout << goldenRatio << '\n';
}
```

## نحوه استفاده از ثابت‌های Template

یکی از ویژگی‌های مهم `std::numbers`، فراهم کردن نسخه‌های Template برای
ثابت‌ها است.

### تفاوت نسخه معمولی و نسخه Template

ثابت زیر از نوع `double` است:

``` cpp
constexpr double value = std::numbers::pi;
```

اما در صورت نیاز به `float` می‌توان از نسخه Template استفاده کرد:

``` cpp
constexpr float value = std::numbers::pi_v<float>;
```

همچنین برای محاسبات با `long double`:

``` cpp
constexpr long double value =
    std::numbers::pi_v<long double>;
```

این قابلیت در کدهای Generic و کتابخانه‌هایی که با چند نوع ممیز شناور کار
می‌کنند اهمیت زیادی دارد.

### چرا نوع داده اهمیت دارد؟

در محاسبات ممیز شناور، نوع داده بر دقت، محدوده نمایش و هزینه محاسبات
تأثیر می‌گذارد.

انواع رایج عبارت‌اند از:

  -----------------------------------------------------------------------
  نوع                                 ویژگی کلی
  ----------------------------------- -----------------------------------
  `float`                             دقت و فضای ذخیره‌سازی کمتر در مقایسه
                                      با `double` در پیاده‌سازی‌های متداول

  `double`                            انتخاب رایج برای بیشتر محاسبات
                                      عمومی

  `long double`                       ممکن است دقت یا محدوده بیشتری داشته
                                      باشد؛ ویژگی دقیق آن وابسته به
                                      پیاده‌سازی است
  -----------------------------------------------------------------------

استفاده از نسخه Template ثابت باعث می‌شود نوع ثابت با نوع موردنظر هماهنگ
باشد و از تبدیل‌های ضمنی غیرضروری جلوگیری شود.

البته نباید فرض کرد که `long double` در تمام پلتفرم‌ها الزاماً دقت بیشتری
از `double` دارد؛ این موضوع به پیاده‌سازی وابسته است.

### نمونه مقایسه انواع داده

``` cpp
#include <iostream>
#include <numbers>
#include <type_traits>

int main() {
    constexpr auto piFloat =
        std::numbers::pi_v<float>;

    constexpr auto piDouble =
        std::numbers::pi_v<double>;

    constexpr auto piLongDouble =
        std::numbers::pi_v<long double>;

    static_assert(
        std::is_same_v<decltype(piFloat), const float>
    );

    static_assert(
        std::is_same_v<decltype(piDouble), const double>
    );

    static_assert(
        std::is_same_v<decltype(piLongDouble), const long double>
    );

    std::cout << piFloat << '\n';
    std::cout << piDouble << '\n';
    std::cout << piLongDouble << '\n';
}
```

در این مثال، `auto` نوع هر متغیر را از نوع ثابت مربوطه استنتاج می‌کند.
همچنین `static_assert` نوع‌های استنتاج‌شده را در زمان کامپایل بررسی می‌کند.

## کاربرد constexpr در std::numbers

تمام ثابت‌های `std::numbers` قابلیت استفاده در Constant Expression را
دارند.

این ویژگی به این معنا است که می‌توان از آن‌ها در جاهایی استفاده کرد که
مقدار باید در زمان کامپایل مشخص باشد.

برای مثال:

``` cpp
#include <array>
#include <numbers>

constexpr double radius = 3.0;

constexpr double area =
    std::numbers::pi * radius * radius;

constexpr std::array<double, 3> values = {
    std::numbers::pi,
    std::numbers::e,
    std::numbers::sqrt2
};

int main() {
    return area > 0.0 && values[0] > 3.0 ? 0 : 1;
}
```

در این نمونه، مقدار `area` و عناصر آرایه در زمان کامپایل قابل محاسبه
هستند.

### استفاده در Templateها

مقادیر `constexpr` می‌توانند در Contextهایی که به Constant Expression
نیاز دارند استفاده شوند.

برای نمونه:

``` cpp
#include <numbers>

template <double Value>
struct ConstantHolder {
    static constexpr double value = Value;
};

using PiHolder = ConstantHolder<std::numbers::pi>;

int main() {
    static_assert(PiHolder::value > 3.14);
}
```

در این مثال از Non-type Template Parameter با نوع `double` استفاده شده
است؛ این قابلیت از ++C20 پشتیبانی می‌شود.

### استفاده در static_assert

می‌توان روابط ساده‌ای را با استفاده از ثابت‌های این کتابخانه در زمان
کامپایل بررسی کرد:

``` cpp
#include <numbers>

static_assert(std::numbers::pi > 3.14);
static_assert(std::numbers::sqrt2 > 1.4);

int main() {
}
```

این روش برای بررسی فرضیات ریاضی در کدهای Template و کتابخانه‌های عددی
مفید است.

## کاربرد در توابع ریاضی و cmath

کتابخانه `std::numbers` ثابت‌های ریاضی را فراهم می‌کند، در حالی که Header
استاندارد `<cmath>` توابع ریاضی را در اختیار برنامه‌نویس قرار می‌دهد.

این دو مکمل یکدیگر هستند.

برای نمونه، برای محاسبه سینوس یک زاویه باید از `std::sin` استفاده کنید و
برای تبدیل درجه به رادیان می‌توانید از `std::numbers::pi` کمک بگیرید.

``` cpp
#include <cmath>
#include <iostream>
#include <numbers>

int main() {
    constexpr double degrees = 90.0;

    constexpr double radians =
        degrees * std::numbers::pi / 180.0;

    const double result = std::sin(radians);

    std::cout << result << '\n';
}
```

در این مثال، مقدار زاویه به رادیان تبدیل شده است؛ زیرا توابع مثلثاتی
استاندارد مانند `std::sin` زاویه را بر حسب رادیان دریافت می‌کنند.

### تبدیل درجه به رادیان

رابطه تبدیل درجه به رادیان به شکل زیر است:

\[ `\text{radians}`{=tex} = `\text{degrees}`{=tex}
`\times `{=tex}`\frac{\pi}{180}`{=tex} \]

برای جلوگیری از تکرار فرمول می‌توان یک تابع کمکی تعریف کرد:

``` cpp
#include <numbers>

constexpr double degreesToRadians(double degrees) {
    return degrees * std::numbers::pi / 180.0;
}

int main() {
    constexpr double angle =
        degreesToRadians(180.0);

    static_assert(angle > 3.14);
}
```

### تبدیل رادیان به درجه

رابطه معکوس به شکل زیر است:

\[ `\text{degrees}`{=tex} = `\text{radians}`{=tex}
`\times `{=tex}`\frac{180}{\pi}`{=tex} \]

نمونه پیاده‌سازی:

``` cpp
#include <numbers>

constexpr double radiansToDegrees(double radians) {
    return radians * 180.0 / std::numbers::pi;
}

int main() {
    constexpr double angle =
        radiansToDegrees(std::numbers::pi);

    static_assert(angle > 179.0);
}
```

## طراحی توابع Generic با ثابت‌های ریاضی

در کتابخانه‌نویسی مدرن، معمولاً بهتر است توابع تا حد امکان با انواع داده
مختلف کار کنند.

نسخه‌های Template در `std::numbers` این امکان را فراهم می‌کنند که ثابت
موردنیاز را با نوع محاسبات هماهنگ کنید.

برای نمونه:

``` cpp
#include <numbers>
#include <type_traits>

template <typename T>
constexpr T circleArea(T radius) {
    static_assert(std::is_floating_point_v<T>);

    return std::numbers::pi_v<T> * radius * radius;
}

int main() {
    constexpr float areaFloat = circleArea(2.0f);
    constexpr double areaDouble = circleArea(2.0);
    constexpr long double areaLongDouble =
        circleArea(2.0L);

    static_assert(areaFloat > 12.0f);
    static_assert(areaDouble > 12.0);
    static_assert(areaLongDouble > 12.0L);
}
```

در این نمونه، تابع برای انواع ممیز شناور طراحی شده است و ثابت پی را
متناسب با نوع ورودی انتخاب می‌کند.

استفاده از `static_assert` باعث می‌شود اگر نوع نامناسبی به تابع داده شود،
خطا در زمان کامپایل گزارش شود.

### محدود کردن نوع با Concepts

در ++C20 می‌توان برای بیان محدودیت نوع از Concepts استفاده کرد.

``` cpp
#include <concepts>
#include <numbers>

template <std::floating_point T>
constexpr T circleArea(T radius) {
    return std::numbers::pi_v<T> * radius * radius;
}

int main() {
    constexpr double area = circleArea(3.0);
    static_assert(area > 28.0);
}
```

در این پیاده‌سازی، `std::floating_point` از Header `<concepts>` استفاده
می‌کند و مشخص می‌کند که نوع ورودی باید یک نوع ممیز شناور باشد.

این روش از نظر بیان محدودیت‌های Generic Programming شفاف‌تر از بررسی دستی
نوع با `static_assert` است.

## کاربردهای عملی در پروژه‌های واقعی

### محاسبات هندسی

در محاسبات مربوط به دایره، کره، استوانه و سایر شکل‌های هندسی، عدد پی و
ریشه‌های دوم کاربرد فراوانی دارند.

برای مثال، حجم کره از رابطه زیر به دست می‌آید:

\[ V = `\frac{4}{3}`{=tex}`\pi `{=tex}r\^3 \]

نمونه:

``` cpp
#include <numbers>

constexpr double sphereVolume(double radius) {
    return (4.0 / 3.0) *
           std::numbers::pi *
           radius * radius * radius;
}

int main() {
    constexpr double volume = sphereVolume(2.0);
    static_assert(volume > 33.0);
}
```

### گرافیک کامپیوتری

در گرافیک دوبعدی و سه‌بعدی، تبدیل زاویه‌ها، چرخش اشیا، محاسبات هندسی و
تولید مختصات از کاربردهای رایج عدد پی و ریشه‌های دوم هستند.

برای نمونه، محاسبه مختصات یک نقطه روی دایره:

\[ x = r`\cos`{=tex}(`\theta`{=tex}) \]

\[ y = r`\sin`{=tex}(`\theta`{=tex}) \]

نمونه:

``` cpp
#include <cmath>
#include <numbers>
#include <utility>

std::pair<double, double> pointOnCircle(
    double radius,
    double angleRadians
) {
    return {
        radius * std::cos(angleRadians),
        radius * std::sin(angleRadians)
    };
}

int main() {
    const auto point = pointOnCircle(
        5.0,
        std::numbers::pi / 4.0
    );
}
```

### پردازش سیگنال

در پردازش سیگنال، فرمول‌های مبتنی بر توابع مثلثاتی، فرکانس زاویه‌ای و
تبدیل فوریه بسیار رایج هستند.

رابطه فرکانس زاویه‌ای به شکل زیر است:

\[ `\omega `{=tex}= 2`\pi `{=tex}f \]

در این رابطه، (f) فرکانس بر حسب هرتز و (`\omega`{=tex}) فرکانس زاویه‌ای
بر حسب رادیان بر ثانیه است.

نمونه:

``` cpp
#include <numbers>

constexpr double angularFrequency(double frequency) {
    return 2.0 * std::numbers::pi * frequency;
}

int main() {
    constexpr double omega = angularFrequency(50.0);
    static_assert(omega > 314.0);
}
```

### محاسبات آماری و علمی

ثابت‌های `pi`، `e` و `inv_sqrtpi` در بعضی فرمول‌های توزیع‌های آماری و توابع
ویژه ظاهر می‌شوند.

برای مثال، تابع چگالی توزیع نرمال استاندارد به شکل زیر است:

\[ f(x) = `\frac{1}{\sqrt{2\pi}}`{=tex}e^{-x^2/2} \]

در چنین کاربردهایی، استفاده از ثابت‌های استاندارد می‌تواند فرمول را
خواناتر کند؛ البته پیاده‌سازی کامل یک الگوریتم آماری به ملاحظات عددی
بیشتری نیاز دارد.

## محدودیت‌ها و نکات مهم

### محدود بودن مجموعه ثابت‌ها

`std::numbers` مجموعه‌ای از ثابت‌های ریاضی شناخته‌شده را ارائه می‌کند، نه
تمام ثابت‌های ممکن در ریاضیات.

اگر پروژه به ثابت‌های تخصصی‌تری مانند ثابت کاتالان، ثابت آپری یا مقادیر
وابسته به یک حوزه خاص نیاز داشته باشد، باید آن‌ها را از منبع مناسب دیگری
تأمین کنید یا در پروژه تعریف کنید.

### وابستگی به پشتیبانی ++C20

این Header از استاندارد ++C20 معرفی شده است. بنابراین کامپایلر و
Standard Library مورد استفاده باید از این قابلیت پشتیبانی کنند.

صرفاً نصب یک کامپایلر جدید کافی نیست؛ نسخه کتابخانه استاندارد نیز باید
قابلیت موردنظر را پیاده‌سازی کرده باشد.

برای مثال، باید استاندارد زبان را در تنظیمات کامپایل فعال کنید:

``` bash
g++ -std=c++20 main.cpp -o app
```

یا در محیط Clang:

``` bash
clang++ -std=c++20 main.cpp -o app
```

در Visual C++ نیز می‌توان از گزینه زیر استفاده کرد:

``` bash
cl /std:c++20 /EHsc main.cpp
```

پشتیبانی دقیق به نسخه کامپایلر و Standard Library وابسته است.

### دقت محاسبات ممیز شناور

استفاده از ثابت استاندارد به معنای حذف خطاهای ممیز شناور نیست.

انواع `float`، `double` و `long double` محدودیت‌های دقت و نمایش دارند.
عملیات ریاضی روی این مقادیر ممکن است با خطای گرد کردن همراه باشد.

بنابراین در محاسبات حساس نباید برابری دقیق دو مقدار ممیز شناور را بدون
بررسی شرایط مسئله فرض کرد.

برای نمونه، این الگو همیشه برای مقایسه نتایج محاسبات ممیز شناور مناسب
نیست:

``` cpp
if (result == expected) {
    // Exact equality
}
```

در بسیاری از کاربردها بهتر است اختلاف دو مقدار با یک Tolerance مناسب
بررسی شود:

``` cpp
#include <cmath>
#include <numbers>

bool approximatelyEqual(double a, double b) {
    constexpr double tolerance = 1e-10;
    return std::abs(a - b) <= tolerance;
}

int main() {
    const double value = std::sin(std::numbers::pi);

    const bool isApproximatelyZero =
        approximatelyEqual(value, 0.0);
}
```

مقدار Tolerance باید متناسب با مقیاس داده، الگوریتم و نیاز دقت انتخاب
شود. مقدار ثابت بالا صرفاً یک نمونه آموزشی است و برای همه مسائل مناسب
نیست.

### تفاوت دقت انواع داده

نسخه Template ثابت، مقدار را در نوع درخواستی ارائه می‌کند؛ اما این موضوع
به معنی تولید دقت نامحدود نیست.

برای مثال، `pi_v<float>` نمی‌تواند تمام دقت قابل نمایش در `long double`
را حفظ کند.

بنابراین نوع ثابت را متناسب با نوع محاسبات انتخاب کنید و از تبدیل‌های
غیرضروری بین انواع مختلف پرهیز کنید.

### تفاوت پیاده‌سازی‌ها

ویژگی‌های دقیق انواع ممیز شناور، به‌خصوص `long double`، ممکن است بین
پلتفرم‌ها و کامپایلرها متفاوت باشد.

همچنین نباید فرض کرد که نمایش متنی ثابت‌ها در تمام محیط‌ها دقیقاً یکسان
است؛ قالب‌بندی خروجی به روش تبدیل عدد به رشته و تنظیمات Stream نیز وابسته
است.

## اشتباهات رایج

### فراموش کردن Header

برای استفاده از ثابت‌های این کتابخانه باید `<numbers>` را وارد کنید.

``` cpp
#include <numbers>
```

نبود این Header باعث می‌شود کامپایلر اعلان‌های مربوط به `std::numbers` را
در دسترس نداشته باشد.

### اشتباه گرفتن فضای نام

ثابت‌ها در فضای نام `std::numbers` قرار دارند، نه مستقیماً در `std`.

بنابراین شکل صحیح استفاده:

``` cpp
std::numbers::pi
```

و شکل نادرست:

``` cpp
std::pi
```

است.

### استفاده از نام Template بدون تعیین نوع

برای استفاده از Variable Template باید نوع موردنظر مشخص شود:

``` cpp
std::numbers::pi_v<float>
```

نوشتن `std::numbers::pi_v` بدون تعیین نوع، استفاده مورد انتظار از این
Template نیست.

### تصور اینکه pi_v یک تابع است

عضو `pi_v<T>` یک Variable Template است، نه Function Template.

بنابراین به شکل متغیر استفاده می‌شود:

``` cpp
constexpr float value = std::numbers::pi_v<float>;
```

نه به شکل فراخوانی تابع.

### استفاده از ثابت نامتناسب با نوع محاسبات

اگر الگوریتم با `float` طراحی شده است، استفاده از `pi_v<float>` می‌تواند
انتخاب روشن‌تری نسبت به استفاده از `pi` و تبدیل ضمنی آن باشد.

البته در بسیاری از عبارات، قواعد تبدیل نوع زبان همچنان اعمال می‌شوند و
انتخاب نوع مناسب باید با توجه به کل عبارت انجام شود.

### اشتباه گرفتن عدد نپر و ثابت اویلر--ماسکرونی

`e` و `egamma` دو ثابت کاملاً متفاوت هستند.

-   `e` پایه لگاریتم طبیعی است.
-   `egamma` ثابت اویلر--ماسکرونی است.

اشتباه گرفتن این دو می‌تواند باعث خطا در فرمول‌های علمی شود.

### فرض پشتیبانی از همه انواع عددی

Variable Templateهای این کتابخانه برای انواع ممیز شناور استاندارد طراحی
شده‌اند. نباید فرض کرد که می‌توان آن‌ها را مستقیماً برای انواع صحیح، انواع
سفارشی یا کلاس‌های عددی دلخواه به کار برد.

اگر یک نوع عددی سفارشی در پروژه وجود دارد، باید سازوکار مناسب برای ارائه
ثابت‌های موردنیاز آن نوع طراحی شود.

## نکات طراحی برای توسعه‌دهندگان حرفه‌ای

### انتخاب نوع ثابت بر اساس نوع محاسبات

در طراحی APIهای عددی، بهتر است نوع ثابت‌ها با نوع داده اصلی الگوریتم
هماهنگ باشد.

برای نمونه، در یک تابع Template می‌توان از `pi_v<T>` استفاده کرد تا نوع
ثابت از نوع پارامتر تابع پیروی کند.

### جلوگیری از تعریف مجدد ثابت‌های استاندارد

اگر ثابت موردنیاز در `std::numbers` وجود دارد، تعریف مجدد آن با نام‌های
متفاوت معمولاً ضرورتی ندارد.

استفاده مستقیم از ثابت استاندارد، خوانایی و یکپارچگی پروژه را افزایش
می‌دهد.

### استفاده از نام کامل در کد کتابخانه‌ای

در پروژه‌های کوچک ممکن است استفاده از `using namespace std::numbers;`
وسوسه‌انگیز باشد؛ اما در Headerهای عمومی و کتابخانه‌ها بهتر است از نام
کامل استفاده شود:

``` cpp
constexpr double area =
    std::numbers::pi * radius * radius;
```

این کار از آلودگی فضای نام و احتمال تداخل نام‌ها جلوگیری می‌کند.

### توجه به قرارداد واحدها

ثابت `pi` به‌تنهایی مشخص نمی‌کند که زاویه‌ها در یک API بر حسب درجه هستند یا
رادیان.

از آنجا که توابع مثلثاتی استاندارد از رادیان استفاده می‌کنند، بهتر است
قرارداد واحدها در نام‌گذاری توابع، مستندات و نوع داده‌ها روشن باشد.

در پروژه‌های بزرگ‌تر می‌توان از Strong Typeها یا کتابخانه‌های Units برای
جلوگیری از ترکیب ناخواسته درجه و رادیان استفاده کرد.

### توجه به پایداری عددی

وجود ثابت‌های دقیق‌تر، به‌تنهایی یک الگوریتم را از نظر عددی پایدار نمی‌کند.

برای مثال، در محاسباتی که شامل تفریق دو مقدار بسیار نزدیک هستند، ممکن
است Cancellation رخ دهد. در چنین مواردی باید الگوریتم مناسب انتخاب شود،
نه اینکه صرفاً تعداد ارقام ثابت افزایش یابد.

## بررسی استاندارد و سازگاری

قابلیت `std::numbers` در ++C20 به Standard Library اضافه شده است و بخشی
از امکانات زبان به معنای Keyword یا Syntax جدید نیست؛ بلکه یک قابلیت
کتابخانه استاندارد است.

بنابراین سه موضوع را باید از هم تفکیک کرد:

-   **نسخه زبان:** پروژه باید با استاندارد ++C20 یا جدیدتر کامپایل شود.
-   **پیاده‌سازی کتابخانه:** کتابخانه استاندارد همراه کامپایلر باید
    Header `<numbers>` و اعضای آن را ارائه کند.
-   **تنظیمات ساخت:** گزینه استاندارد زبان باید در Build System فعال شده
    باشد.

در پروژه‌های مبتنی بر CMake می‌توان استاندارد موردنیاز را به شکل زیر مشخص
کرد:

``` cmake
cmake_minimum_required(VERSION 3.20)

project(NumbersExample LANGUAGES CXX)

add_executable(numbers_example main.cpp)

target_compile_features(numbers_example PRIVATE cxx_std_20)
```

این تنظیم نیازمندی استاندارد زبان را برای Target مشخص می‌کند؛ با این حال،
نسخه کامپایلر و کتابخانه استاندارد همچنان باید از قابلیت پشتیبانی کنند.

## جمع‌بندی

کتابخانه `std::numbers` یکی از امکانات کاربردی Standard Library در ++C20
است که مجموعه‌ای از ثابت‌های ریاضی پرکاربرد را به‌شکل استاندارد و Type-Safe
ارائه می‌کند.

مهم‌ترین ویژگی‌های آن عبارت‌اند از:

-   فراهم کردن ثابت‌هایی مانند `pi`، `e`، `sqrt2` و `phi`.
-   ارائه نسخه‌های `constexpr` برای استفاده در زمان کامپایل.
-   پشتیبانی از Variable Templateهایی مانند `pi_v<T>`.
-   امکان هماهنگ کردن نوع ثابت با نوع محاسبات ممیز شناور.
-   حذف نیاز به تعریف دستی بسیاری از ثابت‌های متداول.
-   کاهش وابستگی به ماکروهای غیراستانداردی مانند `M_PI`.

برای استفاده از این قابلیت کافی است Header `<numbers>` را وارد کرده و
ثابت موردنظر را از فضای نام `std::numbers` دریافت کنید.

در کدهای Generic و کتابخانه‌های عددی، استفاده از نسخه‌های Template مانند
`std::numbers::pi_v<T>` معمولاً انتخاب مناسبی است؛ زیرا نوع ثابت را با
نوع محاسبات هماهنگ می‌کند.

در نهایت باید توجه داشت که `std::numbers` جایگزین توابع ریاضی `<cmath>`
یا الگوریتم‌های عددی تخصصی نیست. این کتابخانه فقط ثابت‌های ریاضی استاندارد
را فراهم می‌کند و دقت نهایی محاسبات همچنان به نوع داده، الگوریتم و
ویژگی‌های پیاده‌سازی وابسته خواهد بود.
