آشنایی با nullptr در ++C

تعریف: در ++C، اشاره‌گر تهی به اشاره‌گری گفته می‌شود که به هیچ آدرس معتبر حافظه‌ای اشاره نمی‌کند.

گذار از NULL و 0 به nullptr

در نسخه‌های قدیمی ++C، یعنی پیش از استاندارد C++11، و همچنین در زبان C، معمولاً از دو روش زیر برای نمایش اشاره‌گر تهی استفاده می‌شد: 

int* ptr = 0;
int* ptr = NULL;

مشکل: مقادیر 0 و NULL معمولاً مقادیر عددی هستند، نه یک نوع واقعی برای اشاره‌گر. این موضوع، به‌ویژه هنگام استفاده از سربارگذاری تابع، می‌تواند باعث ابهام و ایجاد خطاهای دشوار شود. 

#include <iostream>

void foo(int value) {
    std::cout << "تابع دارای پارامتر int فراخوانی شد\n";
}

void foo(int* pointer) {
    std::cout << "تابع دارای پارامتر اشاره‌گر فراخوانی شد\n";
}

int main() {
    foo(NULL);
}

در این مثال، کامپایلر ممکن است NULL را به‌عنوان یک مقدار عددی در نظر بگیرد و تابع دارای پارامتر int را انتخاب کند؛ یا در برخی شرایط، با ابهام در انتخاب تابع مواجه شود.

معرفی nullptr در C++11

از زمان معرفی استاندارد C++11، کلمهٔ کلیدی nullptr برای حل این مشکل به شکلی ایمن و صریح به زبان ++C اضافه شد.

  • نوع مستقل: nullptr یک مقدار ثابت از نوع std::nullptr_t است.
  • ایمنی نوع: این مقدار می‌تواند به انواع مختلف اشاره‌گر تبدیل شود، اما به انواع عددی مانند int یا char تبدیل نمی‌شود.
  • رفع ابهام در سربارگذاری: هنگام استفاده از nullptr، کامپایلر می‌تواند تابعی را که پارامتر اشاره‌گر دارد، به‌درستی انتخاب کند. 
foo(nullptr);

در این حالت، تابع دارای پارامتر اشاره‌گر بدون ابهام انتخاب می‌شود.

استفادهٔ ایمن از nullptr

در ++C مدرن، زمانی که یک اشاره‌گر هنوز به شیء معتبری اشاره نمی‌کند، آن را با nullptr مقداردهی اولیه کنید: 

int* myPointer = nullptr;

پیش از دسترسی به مقدار اشاره‌گر یا تغییر داده‌ای که به آن اشاره می‌کند، معتبر بودن اشاره‌گر را بررسی کنید: 

if (myPointer != nullptr) {
    *myPointer = 10;
} else {
    // اشاره‌گر تهی است.
}

در ++C می‌توان بررسی کوتاه‌تر زیر را نیز به کار برد: 

if (myPointer) {
    *myPointer = 10;
}

اگر مقدار اشاره‌گر تهی نباشد، شرط برقرار خواهد بود؛ در غیر این صورت، یعنی زمانی که مقدار آن nullptr باشد، شرط اجرا نمی‌شود.

خلاصهٔ مقایسه

ویژگی nullptr در C++11 NULL و 0
نوع داده std::nullptr_t نوع عددی مانند int
ایمنی نوع بسیار ایمن و صریح ضعیف‌تر و مستعد ایجاد ابهام در سربارگذاری
استاندارد پیشنهادی ++C مدرن، یعنی C++11 و نسخه‌های جدیدتر کدهای قدیمی ++C و زبان C
تبدیل به نوع عددی به‌صورت مستقیم به نوع‌هایی مانند int تبدیل نمی‌شود معمولاً از ابتدا یک مقدار عددی است
رفتار در سربارگذاری تابع تابع دارای پارامتر اشاره‌گر را به‌صورت واضح انتخاب می‌کند ممکن است باعث انتخاب نادرست یا ابهام شود

نتیجه: در برنامه‌های ++C مدرن، همیشه استفاده از nullptr نسبت به NULL و 0 توصیه می‌شود.
